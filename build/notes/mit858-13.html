Secure Channels

Summary

Lecture 13 asks: how do two parties that share no secret establish one? The answer is a protocol
run over a network you already know is hostile — which is why secure channel protocols are so
subtle, and why every one of them has been broken at least once.

Key ideas

  • Key agreement (Diffie-Hellman) establishes a shared secret without transmitting it
  • Authentication is the hard part: DH alone is vulnerable to a man in the middle
  • Signatures and certificates bind an identity to a key
  • Forward secrecy: compromise of the long-term key must not decrypt old traffic
  • Ephemeral DH: a fresh key pair per session, which is what buys forward secrecy
  • The transcript matters: everything exchanged is authenticated, including the handshake itself
  • The lecture's preparation reading is the SSL 3.0 analysis (Joux), which is why TLS 1.3 removed
    the old constructions entirely

The problem, stated precisely

1. Alice and Bob want a shared secret, over a network Eve controls
2. A naive key exchange lets Eve insert herself in the middle
3. So every exchange needs authentication, and the authentication itself
   needs keys - which is circular

TLS breaks the circle with certificates: a certificate authority vouches that
this public key belongs to this name. Bob verifies the chain rather than
trusting Alice's claim.

Why ephemeral keys

static DH:
  session key = g^(ab), derived from ONE long-lived pair
  -> if Alice's private key leaks in 2026, ALL past traffic decrypts

ephemeral DH:
  fresh a', b' per session
  session key = g^(a'b')
  -> the long-term key only authenticated the handshake;
     it cannot decrypt recorded traffic  (forward secrecy)

Forward secrecy is the property to demand from anything carrying long-lived
confidential data. TLS 1.3 and WireGuard both provide it by default. A
static-RSA key exchange does not — that was the flaw in TLS 1.2's common
configuration.

What must be authenticated

Not just the session key. The entire transcript: client hello, server
hello, certificates, the negotiated parameters, the finished messages. If any
field is unauthenticated, Eve can alter it.

The SSL 3.0 flaws were exactly this: fields in the handshake were not covered
by the integrity check, letting an attacker downgrade the cipher.

Terminology

Term Meaning
Key agreement Agreeing a shared secret over a hostile channel
Diffie-Hellman Exponential key agreement
Man in the middle Eve inserts herself between the parties
Authentication Proving a party is who it claims to be
Digital signature Private key signs, public key verifies
Certificate A CA's signature binding a key to an identity
Forward secrecy Long-term compromise does not reveal past traffic
Ephemeral key Key used for one session, then discarded
Transcript The full ordered list of exchanged messages
Downgrade attack Forcing both parties onto weaker parameters
Truncation attack Hiding messages by dropping from the transcript
Nonce Unique per message; prevents replay

python3 - <<'PY'
import ssl, socket, threading, subprocess, tempfile, os
print("  generating a self-signed cert...")
subprocess.run("""openssl req -x509 -newkey rsa:2048 -keyout /tmp/lab.key -out /tmp/lab.crt \
  -days 1 -nodes -subj '/CN=localhost' 2>/dev/null""", shell=True)

ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
ctx.load_cert_chain("/tmp/lab.crt", "/tmp/lab.key")
print(f"  minimum version we will accept: {ssl.TLSVersion.TLSv1_2}")

srv = socket.socket(); srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("127.0.0.1", 8443)); srv.listen(1)
def serve():
    try:
        c, _ = srv.accept()
        with ctx.wrap_socket(c, server_side=True) as s:
            s.sendall(b"hello over TLS\n")
    except Exception as e:
        print("  server:", type(e).__name__)
threading.Thread(target=serve, daemon=True).start()

cctx = ssl.create_default_context()
cctx.check_hostname = False
cctx.verify_mode = ssl.CERT_NONE
with socket.create_connection(("127.0.0.1", 8443), timeout=3) as raw:
    with cctx.wrap_socket(raw, server_hostname="localhost") as s:
        print(f"  negotiated: {s.version()}  cipher: {s.cipher()[0]}")
        print(f"  peer cert subject: {dict(x[0] for x in s.getpeercert().get('subject',[]))}")
        print(f"  received  : {s.recv(64)!r}")
os.remove("/tmp/lab.crt"); os.remove("/tmp/lab.key")

# --- 5. a real handshake in Python, on loopback ---
cat > handshake.py <<'PY'
#!/usr/bin/env python3
"""Create a TLS server and client on loopback and print what was negotiated."""
import ssl, socket, threading, subprocess, os, tempfile

d = tempfile.mkdtemp()
crt, key = f"{d}/c.crt", f"{d}/c.key"
subprocess.run(["openssl","req","-x509","-newkey","rsa:2048","-keyout",key,
                "-out",crt,"-days","1","-nodes","-subj","/CN=localhost"],
               capture_output=True)

srv = socket.socket(); srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("127.0.0.1", 8444)); srv.listen(1)

ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
ctx.load_cert_chain(crt, key)
print(f"  server minimum TLS version : {ctx.minimum_version}")

def serve():
    try:
        c,_ = srv.accept()
        with ctx.wrap_socket(c, server_side=True) as s:
            s.sendall(b"hello over TLS\n")
    except Exception as e:
        print("  server error:", type(e).__name__, e)

threading.Thread(target=serve, daemon=True).start()

cctx = ssl.create_default_context()
cctx.check_hostname = False
cctx.verify_mode = ssl.CERT_NONE
with socket.create_connection(("127.0.0.1",8444), timeout=5) as raw:
    with cctx.wrap_socket(raw, server_hostname="localhost") as s:
        print(f"  negotiated version         : {s.version()}")
        print(f"  negotiated cipher          : {s.cipher()[0]}")
        print(f"  peer certificate present  : {s.getpeercert(binary_form=True) is not None}")
        print(f"  server side temp key       : {s.server_hostname}")
        print(f"  payload received           : {s.recv(64)!r}")

srv.close()
for f in (crt,key): os.remove(f)
os.rmdir(d)

# What a secure channel must get right

## Attacks the protocol must defeat
1. **Passive eavesdropper** -> confidentiality (encryption)
2. **Active MITM** -> authentication, and the transcript must be covered
3. **Replay** -> nonces and sequence numbers
4. **Downgrade** -> the negotiation must be authenticated *after* it completes
5. **Truncation** -> the finished MAC covers every message
6. **Key compromise later** -> forward secrecy (ephemeral keys)
7. **Compromised CA** -> the client must actually verify the chain
8. **Traffic analysis** -> padding, size leaks (TLS does not fully solve this)

## The SSL 3.0 lesson (the lecture's preparation reading)
- The handshake had fields not covered by the finished MAC
- An attacker could alter the cipher suite to a weaker one
- This is why TLS 1.3 removed the old constructions entirely rather than
  patching them

## TLS 1.3's simplifications
- removed static RSA and static DH (forward secrecy is mandatory)
- removed CBC modes (padding oracle class of attacks)
- removed compression (CRIME)
- zero-RTT early data reintroduced replay risk, so it is for idempotent
  requests only
- fewer cipher suites, less negotiation, fewer places for bugs

## The takeaway
Security protocols fail at the edges of the specification, not in the core
math. Every field that is exchanged but not authenticated is a hole.
EOF
