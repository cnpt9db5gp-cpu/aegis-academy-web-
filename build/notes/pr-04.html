Credentials on Disk: Config Files, History, SSH Keys

Summary

Credentials are everywhere on a Linux host, and almost none of them are encrypted. This lecture is
the enumeration pattern that finds them — and the hardening advice that stops them being there.

Key ideas

  • Config files for services often contain plaintext passwords, tokens, or keys
  • Shell history records every command, including ones with passwords inline
  • SSH keys: authorized_keys is a persistence mechanism and a lateral movement vector
  • Process environment (/proc/PID/environ) leaks secrets to any local user for the same UID
  • Backups and temp files are the classic place credentials get left behind
  • .env, config.yml, settings.py, wp-config.php, *.bak, *.old are all worth grepping

Terminology

Term Meaning
Plaintext credential Stored without hashing — the finding
SSH key pair Private key on disk, public key in authorized_keys
authorized_keys Where a key may log in from — also a persistence path
known_hosts Remembered server keys, useful for host-key verification
/proc/PID/environ A process's environment variables
Credential exposure Secrets discoverable on the filesystem
History file ~/.bash_history, ~/.python_history
Backup artefact file.bak, file~, file.old, file.swp
Secret scanning Grepping for key patterns before committing

Kali commands

# --- the one-liner that finds most plaintext credentials ---
sudo grep -rIl --exclude-dir={proc,sys,dev,run,var/lib/docker} \
  -E "(password|passwd|pwd|secret|api[_-]?key|token|BEGIN [A-Z ]*PRIVATE KEY)" \
  /etc /opt /srv /home /var/www 2>/dev/null | head -30

# --- history ---
ls -la ~/.bash_history ~/.zsh_history ~/.python_history ~/.mysql_history 2>/dev/null
tail -50 ~/.bash_history 2>/dev/null | grep -iE "pass|token|key|curl -u|mysql -p"
history | grep -iE "sudo|pass" | head

# --- environment of a running process ---
tr '\0' '\n' < /proc/1/environ 2>/dev/null | head
sudo ls -l /proc/*/environ 2>/dev/null | head -5
tr '\0' '\n' < "$(pgrep -u postgres | head -1 | sed 's|^|/proc/|')/environ" 2>/dev/null

# --- ssh material ---
ls -la ~/.ssh/ 2>/dev/null
cat ~/.ssh/config 2>/dev/null
cat ~/.ssh/authorized_keys 2>/dev/null
sudo find / -name "authorized_keys" -o -name "id_rsa" -o -name "id_ed25519" 2>/dev/null | head -15

# --- hashes, and the offline attack surface ---
sudo grep -vE '^[^:]*:[!*]?:' /etc/shadow | cut -d: -f1,2 | head

# --- backups and leftovers ---
sudo find / \( -name "*.bak" -o -name "*~" -o -name "*.old" -o -name "*.swp" -o -name "*.save" \) \
  -type f 2>/dev/null | head -20
sudo find / -name ".env" -o -name "*.env" -o -name "config.php" -o -name "settings.py" 2>/dev/null | head

# --- secret scanning your own git history ---
git log -p --all | grep -iE "(password|secret|api[_-]?key|BEGIN .*PRIVATE KEY)" | head

Field lab

Objective: find credential exposure on your own machine, verify what is actually usable, and
harden what you found.

mkdir -p ~/aegis/labs/pr-04 && cd ~/aegis/labs/pr-04

# --- 1. the broad grep ---
sudo grep -rIl --exclude-dir={proc,sys,dev,run,share,locale,man} \
  -E "(password|passwd|secret|api[_-]?key|token|BEGIN [A-Z ]*PRIVATE KEY)" \
  /etc /opt /srv /home /var/www 2>/dev/null | head -40 | tee 01-grep-hits.txt
echo "$(wc -l < 01-grep-hits.txt) files mention a credential keyword"

# --- 2. history: is it a problem? ---
{
  echo "=== history files present ==="
  ls -la ~/.bash_history ~/.python_history ~/.mysql_history 2>/dev/null || echo "  (none)"
  echo
  echo "=== credential-shaped commands in MY history ==="
  grep -iE "pass|token|key|mysql -p|psql.*-W|curl -u|--user" ~/.bash_history 2>/dev/null | head -10 \
    || echo "  (nothing found)"
  echo
  echo "=== is HISTFILE set? ==="
  echo "  HISTFILE=${HISTFILE:-<unset>}"
  echo "  HISTSIZE=${HISTSIZE:-<unset>}"
  echo "  HISTCONTROL=${HISTCONTROL:-<unset>}"
} 2>&1 | tee 02-history.txt

# --- 3. process environments, readable by root and sometimes by you ---
{
  echo "=== environ of my own processes ==="
  for p in $(pgrep -u $(id -u) | head -10); do
    if [ -r /proc/$p/environ ]; then
      vars=$(tr '\0' '\n' < /proc/$p/environ 2>/dev/null | grep -ciE "pass|token|secret|key")
      [ "$vars" -gt 0 ] && echo "  PID $p ($(cat /proc/$p/comm)): $vars credential-ish var(s)"
    fi
  done
  echo
  echo "=== and the famous one: everything running as root ==="
  sudo bash -c 'for p in $(pgrep -u 0 | head -20); do
      n=$(tr "\0" "\n" < /proc/$p/environ 2>/dev/null | grep -ciE "pass|token|secret|api")
      [ "$n" -gt 0 ] && echo "  root PID $p ($(cat /proc/$p/comm)): $n"
    done'
} 2>&1 | tee 03-environ.txt

# --- 4. ssh material on this machine ---
{
  echo "=== my ~/.ssh ==="
  ls -la ~/.ssh/ 2>/dev/null
  echo
  echo "=== authorised_keys files anywhere (persistence + lateral movement) ==="
  sudo find / -name authorized_keys -type f 2>/dev/null | head -10
  echo
  echo "=== private keys on disk ==="
  sudo find / \( -name "id_rsa" -o -name "id_ed25519" -o -name "*.pem" \) -type f 2>/dev/null | head -15
  echo
  echo "=== permissions on my private key (600 is required) ==="
  ls -l ~/.ssh/id_* 2>/dev/null
} 2>&1 | tee 04-ssh.txt

# --- 5. the hash surface ---
{
  echo "=== local accounts with a real hash ==="
  sudo awk -F: 'length($2) > 3 {print "  " $1 " : " substr($2,1,16) "... (" length($2) " chars, type " substr($2,1,3) ")"}' /etc/shadow | head
  echo
  echo "=== which algorithm, and is it appropriate? ==="
  echo "  \$1/\$2 = MD5 (fast, wrong)  \$y = yescrypt (good)  \$6 = SHA-512"
  echo
  echo "=== the attack surface these represent ==="
  echo "  Any of these hashes found on a backup or a colleague's machine is an offline target."
} 2>&1 | tee 05-hashes.txt

# --- 6. VERIFY what is actually usable (the important part) ---
echo "=== test each finding rather than trusting it ==="
while read -r f; do
  [ -r "$f" ] || continue
  # try to find a credential-shaped assignment
  hit=$(grep -oE "(password|passwd|secret|token)[[:space:]]*[=:][[:space:]]*['\"]?[^'\"[:space:]]+" "$f" 2>/dev/null | head -1)
  if [ -n "$hit" ]; then
    echo "  $f -> $hit"
  fi
done < 01-grep-hits.txt | head -15 | tee 06-verified.txt

echo
echo "Note: report the FILE and the LINE, never the secret value itself."

# --- 7. harden your own machine ---
echo
echo "=== hardening, applied to your own account ==="
cat >> ~/.bashrc <<'EOF'

# --- AEGIS hardening ---
export HISTCONTROL=ignorebothspace   # do not record commands beginning with a space
export HISTSIZE=10000
export HISTFILESIZE=20000
umask 077                           # new files private by default
EOF
echo "  HISTCONTROL, larger history, umask 077 appended to ~/.bashrc"
echo
echo "  umask 077 means: new files get 600, new directories 700."
echo "  That alone prevents a whole class of accidental exposure."
echo
echo "=== and a pre-commit secret scan for any repo you keep ==="
# Prefer ~/aegis/tools/; fall back to the current directory if that
# tree does not exist. mkdir -p first so the redirect target is real -
# otherwise the first `cat` fails and the shell reads the heredoc into
# the fallback, which is confusing to debug.
mkdir -p ~/aegis/tools
if cat > ~/aegis/tools/secret_scan.sh 2>/dev/null <<'EOF'
#!/usr/bin/env bash
# Fail if anything looks like a credential is about to be committed.
set -euo pipefail
PAT='(password|passwd|secret|api[_-]?key|token)[[:space:]]*[=:][[:space:]]*["'\'']?[^"'\''[:space:]]{6,}|BEGIN [A-Z ]*PRIVATE KEY|AKIA[0-9A-Z]{16}'
if git diff --cached | grep -nIE "$PAT"; then
  echo "POSSIBLE SECRET STAGED - commit aborted" >&2; exit 1
fi
echo "no obvious secrets staged"
EOF
then
  DEST=~/aegis/tools/secret_scan.sh
else
  cat > secret_scan.sh <<'EOF2'
#!/usr/bin/env bash
# Fail if anything looks like a credential is about to be committed.
set -euo pipefail
PAT='(password|passwd|secret|api[_-]?key|token)[[:space:]]*[=:][[:space:]]*["'\'']?[^"'\''[:space:]]{6,}|BEGIN [A-Z ]*PRIVATE KEY|AKIA[0-9A-Z]{16}'
if git diff --cached | grep -nIE "$PAT"; then
  echo "POSSIBLE SECRET STAGED - commit aborted" >&2; exit 1
fi
echo "no obvious secrets staged"
EOF2
  DEST=./secret_scan.sh
fi
chmod +x "$DEST" 2>/dev/null || true
echo "  $DEST written - run it before any commit"

Step 6 is the professional habit. A finding is "file X line 12 contains a plaintext
credential for service Y". It is never "here is the password".

Record: 06-verified.txt.
