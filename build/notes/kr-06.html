Building an Isolated Lab Range

Summary

Everything else in AEGIS says "your own machine" or "your lab VM". This lecture is how you make
that true. A range is a small private network — Kali as the attacker, one or more
intentionally vulnerable VMs as targets, connected on a host-only adapter that has no
route to the internet or to your real network.

Build this once. It converts every "is this legal?" question in the remaining 180 lectures into
a settled yes.

The architecture

  ┌─────────────────────────────┐
  │  KALI (attacker)            │   running AEGIS, nmap, metasploit, wireshark
  │  adapter1: NAT   10.0.2.15  │   for apt updates
  │  adapter2: hostonly 192.168.56.1 │  <-- the lab network
  └──────────────┬──────────────┘
                 │  vboxnet0, isolated, no route anywhere else
     ┌───────────┴───────────┐
     ▼                       ▼
 ┌──────────┐          ┌──────────┐
 │ vuln01   │          │ vuln02   │
 │ Metasplo │          │ DVWA /   │
 │ itable3  │          │ Juice    │
 │ .101     │          │ Shop     │
 │          │          │ .102     │
 └──────────┘          └──────────┘

The critical property: there is no route from the lab network to your home LAN or the
internet. If you accidentally scan too wide, nothing outside the range is reachable.

Target 1: Metasploitable3

The workhorse. Real (old) services, deliberately vulnerable, and explicitly intended for this.

Why Metasploitable exists: it turns "is this legal?" into "is this a legal use of the
provided target?" — the most defensible answer in security.

# Download the official image (SourceForge), then on your Kali host:
VBoxManage import metasploitable3_ubuntu_v4.4.6-64.zip \
  --name vuln01 --vsys 0 --register

VBoxManage modifyvm vuln01 --memory 1024 --cpus 2
VBoxManage modifyvm vuln01 --nic1 hostonly --hostonlyif vboxnet0

# Optional: expose the web UI to your Kali host only
VBoxManage modifyvm vuln01 --natpf1 "web,tcp,127.0.0.1,8080,,80"

VBoxManage startvm vuln01 --headless

Wait for boot, then discover its address the legitimate way:

# passive-ish: watch ARP on the host-only interface
sudo arp-scan --interface=vboxnet0 --localnet 2>/dev/null
# or let nmap find it (this IS your first recon exercise)
sudo nmap -sn 192.168.56.0/24

Then snapshot it before you touch anything:

VBoxManage snapshot vuln01 take "pristine" --description "fresh import"

Reverting is VBoxManage snapshot vuln01 restore "pristine". This single command is why
virtualisation is non-negotiable for this curriculum.

Target 3: the Tier 1 privilege-escalation box

A plain Ubuntu VM you deliberately misconfigure. This is how the linux-privesc-doctrine labs
have something to escalate against.

VBoxManage import ubuntu-24.04-server-amd64.vdi --name vuln03 --vsys 0 --register
VBoxManage modifyvm vuln03 --memory 1024 --nic1 hostonly --hostonlyif vboxnet0

Then, from Kali, using deliberate misconfigurations:

# 1. world-writable cron directory
sudo mkdir -p /opt/backup && sudo chmod 777 /opt/backup
# 2. SUID copy of a shell (the classic misconfiguration)
sudo cp /bin/bash /tmp/rootshell && sudo chmod u+s /tmp/rootshell
# 3. writable service file
sudo chmod o+w /etc/cron.d/backup
# 4. weak sudo rule for the lab user
echo 'vuln ALL=(ALL) NOPASSWD: /usr/bin/tee /etc/cron.d/planted' | sudo tee /etc/sudoers.d/vuln
sudo chmod 440 /etc/sudoers.d/vuln

Snapshot after configuring, named misconfigured. Then never touch it again — the labs
will escalate it repeatedly and you will want a clean reset.

The isolation proof

Before you scan anything, verify the network actually is isolated:

# On Kali host
ip -br addr | grep vboxnet0
ip route | grep 192.168.56

# In a target VM (should FAIL - there is no default route out)
ping -c1 8.8.8.8

# From Kali host, confirm the real LAN is a DIFFERENT subnet
ip route | grep default

The check that matters: 192.168.56.0/24 (host-only) and your real LAN must be different
subnets. If your home LAN is also 192.168.56.0/24, renumber the host-only network:

VBoxManage hostonlyif ipaddr vboxnet0 192.168.77.1

Field lab

Objective: stand up a two-host range and produce proof that it is isolated.

mkdir -p ~/aegis/labs/kr-06 && cd ~/aegis/labs/kr-06

# 1. Create the isolated network
VBoxManage hostonlyif create
VBoxManage hostonlyif ipaddr vboxnet0 192.168.56.1
VBoxManage list hostonlyifs | tee 01-hostonly.txt

# 2. Confirm Kali is attached to it
ip -br addr | grep vboxnet0
ip route | grep 192.168.56 | tee 02-routes.txt

# 3. Prove the isolation - record the FAILING result, it is the evidence
{
  echo "=== host-only subnet ==="; ip route | grep 192.168.56
  echo "=== real LAN ==="; ip route | grep default
  echo "=== can a lab host reach the internet? (should fail) ==="
} > 03-isolation.txt

# 4. Once targets are running, discover them the legitimate way
sudo nmap -sn 192.168.56.0/24 | tee 04-discovery.txt

# 5. Full port and service inventory of your own range (this is a real assessment)
sudo nmap -sV -sC -p- 192.168.56.101 -oN 05-vuln01-scan.txt
less 05-vuln01-scan.txt

# 6. Record the baseline for later comparison
{
  echo "range created: $(date -Iseconds)"
  echo "subnet: 192.168.56.0/24 (host-only vboxnet0)"
  echo "attacker: $(hostname) $(ip -br addr show vboxnet0 | awk '{print $3}')"
} | tee 00-RANGE-README.txt

The assessment in step 5 is a real skill. Reading an nmap scan and understanding what each
line means is Tier 2 work. Do it now so that Tier 2 is review, not first contact.

Record: in your scratchpad, note the open ports on vuln01. You will meet them again in
doc-03 and pr-01, and recognising them fast is what makes enumeration fast.

Self-test

  1. What is the single most important property your lab network must have, and how do you test it?
  2. Why does Metasploitable exist as a legal artefact?
  3. You accidentally scanned your university network while trying to scan your range. What
    controls should have prevented it, and which one actually failed?
  4. What does a snapshot buy you that rm -rf recovery does not?
  5. Your host-only network is 192.168.56.0/24 and your home LAN is also 192.168.56.0/24.
    What happens, and how do you fix it?
