Offline Password Attacks: john, hashcat, rules and wordlists

Summary

The most common offensive skill in an engagement. The content is mostly not about cracking — it is
about identifying the hash, estimating whether the attack is worth running, and
reporting the result responsibly.

The discipline: cracking someone's password hash is a finding about
their password, not a licence to log in as them. If you find a password,
you stop.

The five steps, in order

  1. IDENTIFY   what hash is this? (format, length, prefix)
  2. CLASSIFY   is it fast or slow? (this decides everything)
  3. CHOOSE     wordlist + rules + masks, in that priority order
  4. RUN        offline, with the right mode, measure throughput
  5. REPORT     the finding is the PASSWORD POLICY, not the password

  STEP 2 IS THE ONE PEOPLE SKIP.
    md5     : 10^10 - 10^11 / sec on a GPU  -> a 8-char complex pw: minutes
    bcrypt  : 10^4 - 10^5 / sec              -> a 8-char complex pw: centuries
    Knowing this BEFORE you start tells you whether the engagement
    will conclude in ten minutes or never.

import hashlib, base64, binascii, re, string
candidates = [
 "f1a7e3c9d2b84056a3c59e8f1b7d2049",
 "5baa61e4c9b93f3f0682250b6cf8331b7ee68fd8",
 "2b241deea77f25e559b9031c651cb798a14efd61f6b3ae5d3b25f4d1a4d0e5b7",
 "$2b$12$LQv3c1yqBWVHxkd0LHAkCOYz6Ttxkc1oBOLVFa0hUlHd0jmQpMDr",
 "$6$rounds=5000$saltsalt$hashvaluelongenoughhere000000000",
]
def classify(h):
    out = []
    if re.fullmatch(r'[0-9a-f]{32}', h): out.append(("MD5", "128-bit, no prefix"))
    if re.fullmatch(r'[0-9a-f]{40}', h): out.append(("SHA-1", "160-bit, no prefix"))
    if re.fullmatch(r'[0-9a-f]{64}', h): out.append(("SHA-256", "256-bit, no prefix"))
    if re.fullmatch(r'[0-9a-f]{128}', h): out.append(("SHA-512", "512-bit, no prefix"))
    if re.fullmatch(r'[0-9a-f]{56}', h): out.append(("SHA-224", "224-bit"))
    if h.startswith("$2"): out.append(("bcrypt", "SLOW - deliberately"))
    if h.startswith("$6$") or h.startswith("$5$"): out.append(("sha512crypt/sha256crypt", "SLOW"))
    if h.startswith("$1$"): out.append(("md5crypt", "medium - legacy"))
    if h.startswith("$pbkdf2"): out.append(("PBKDF2", "parameterised"))
    if h.startswith("$argon2"): out.append(("Argon2", "SLOW and memory-hard - best"))
    if h.startswith("$y$"): out.append(("yescrypt", "SLOW and memory-hard"))
    if h.startswith("$s0$"): out.append(("Solar Designer", "SLOW"))
    if h.startswith("{SSHA}") or h.startswith("$sha1$"): out.append(("Salted SHA-1", "weak"))
    if h.startswith("$DCC2$"): out.append(("DCC2 (MS Cache)", "pass-the-hash capable"))
    if len(h) == 13 and len(set(h)) == 13 and all(c in string.ascii_letters+string.digits for c in h):
        out.append(("DEScrypt / traditional crypt", "8-char limit, CRACKED"))
    return out

for h in candidates:
    print(f"\n  {h[:60]}{'...' if len(h)>60 else ''}")
    for name, note in classify(h):
        print(f"    -> {name:<26} {note}")
    if not classify(h): print("    -> (no match)")

python3 - <<'PY' 2>&1 | tee 03-benchmark.txt
import hashlib, time, secrets, statistics
print("  === measured on THIS machine, single core (a GPU is ~1000x) ===\n")
tests = [
    ("md5",    lambda p: hashlib.md5(p.encode()).hexdigest()),
    ("sha1",   lambda p: hashlib.sha1(p.encode()).hexdigest()),
    ("sha256", lambda p: hashlib.sha256(p.encode()).hexdigest()),
    ("sha512", lambda p: hashlib.sha512(p.encode()).hexdigest()),
]
print(f"  {'algo':<10} {'candidates/sec':<18} {'8-char complex pw (this core)'}")
print("  " + "-"*70)
for name, fn in tests:
    t = time.perf_counter(); n = 0
    while time.perf_counter() - t < 0.5:
        fn("guesser" + str(n) + "!Aa"); n += 1
    dt = time.perf_counter() - t
    rate = n / dt
    # 62^8 / rate, scaled to one core, then x1000 for a GPU
    space = 62 ** 8
    t_gpu = space / (rate * 1000)
    print(f"  {name:<10} {rate:>15,.0f}   {t_gpu:>18,.0f} s  (~{t_gpu/86400:.0f} days on 1 GPU)")
try:
    import bcrypt
    t = time.perf_counter(); n = 0
    while time.perf_counter() - t < 0.5:
        bcrypt.hashpw(b"guess" + str(n).encode(), bcrypt.gensalt(rounds=8)); n += 1
    rate = n / (time.perf_counter() - t)
    t_gpu = (62**8) / (rate * 1000)
    print(f"  {'bcrypt':<10} {rate:>15,.0f}   {t_gpu:>18,.0f} s  (~{t_gpu/(86400*365):.0f} years on 1 GPU)")
except ImportError:
    print("  bcrypt     (pip install bcrypt)")
print()
print("  The ratio between the first row and the last is the entire")
print("  argument for Argon2id over MD5, and it is a 5-figure number.")

Step 3: the attack ladder, in order

  TRY IN THIS ORDER. Most real passwords die at step 1 or 2.

  1. THE WORDLIST, AS-IS
     rockyou.txt, or the org's own leaked wordlist from a breach.
     Tested: 80% of real-world passwords come from the top 10^4.

  2. THE WORDLIST WITH RULES
     john --rules  or  hashcat -r best64.rule
     Capitalisation, leet (a -> @, e -> 3), appending digits/years,
     duplicating. This finds maybe 20% more. It is usually the
     difference between "one cracked" and "several cracked".

  3. A MASK
     hashcat -a 3 ?u?l?l?l?l?l?l?l?l?d?d?d?d
     Tells hashcat to search the SPACE, not a list. Use when you
     know the shape: "eight lowercase letters, one capital, four digits"
     is the single most common corporate pattern.

  4. A TARGETED LIST
     the org name, the current year, the username, the department,
     a leaked wordlist. Combine with rules.

  5. A CUSTOM RULES FILE
     only after the above. Rules are cheap to write and very effective
     for a specific organisation.

  6. GIVE UP AND WRITE IT UP
     This is a legitimate outcome. "We cracked 3 of 40 hashes after
     4 hours; the remaining 37 use bcrypt at cost 12, which is not
     practically attackable with the resources available. The finding
     is that 3 of 40 use an unsalted MD5" is a complete and useful
     report.

# --- john, with rules ---
john --wordlist=/usr/share/wordlists/rockyou.txt \
     --rules --format=raw-md5 hashes.txt

# --- hashcat: mode 0 = straight, 3 = brute/mask, best64 rule ---
hashcat -m 0 -a 0 hashes.txt /usr/share/wordlists/rockyou.txt
hashcat -m 0 -a 0 hashes.txt rockyou.txt -r /usr/share/hashcat/rules/best64.rule
hashcat -m 0 -a 3 hashes.txt '?u?l?l?l?l?l?l?l?l?d?d?d?d' --increment

# --- hashcat: the session, saved, resumed, and monitored ---
hashcat --session=aegis -m 1000 hashes.txt rockyou.txt   # -m 1000 = NTLM
watch -n5 'hashcat --session=aegis --status'

# --- what you should have tried FIRST for a specific org ---
cat > targeted.txt <<'EOF'
EOF
for t in aegis Acme acme2026 Acme2026! acme2026 Password1 Welcome1 Winter2026 \
         "$company" "${company}123" "${company}!" "P@ssw0rd" "Password123" \

Step 5: the rules of engagement for cracking

  1. GET WRITTEN PERMISSION. Cracking the client's password hashes is
     explicitly out of scope in most contracts. If it is not in the
     ROE, it is not in the engagement.

  2. NEVER USE A RECOVERED PASSWORD.
     Finding "alice's password is Summer2023!" is a finding about the
     password POLICY. Logging in as alice is a different act, usually
     unauthorised, and always a career-ending one.

  3. HASHES YOU DID NOT HAVE LEGAL POSSESSION OF (a breach corpus
     download, someone's database) are not yours to crack. Ever.

  4. PROTECT THE OUTPUT. Cracked passwords are personal data AND they
     are the client's credentials. Encrypt the pot file. Delete it on
     the contractual schedule. Never paste it into a report.

  5. DO NOT CRACK THE SAME HASH TWICE. Keep a pot file and a session
     so work is not repeated. Cracking a bcrypt hash at cost 14 twice
     wastes an hour of GPU time you could have spent on the slow hashes.

  6. MEASURE AND REPORT THE POLICY, not the wins. "4 of 41 accounts
     use a password from the top 10,000; 3 of those are the same
     password on multiple accounts" is the finding. The individual
     passwords are evidence you do not include.

Step 6: what goes in the report

  ## F-xx · Password storage and policy permits offline cracking

  Risk
    41 of 41 stored passwords use an unsalted fast hash (MD5). All 41
    were recovered in 4 minutes using a standard wordlist and rules
    available in every commodity tool. Four users share the same
    password across multiple accounts, including one shared with the
    service account.

  Prerequisites
    Read access to the password store (obtained as an authenticated
    low-privilege user via F-02).

  Evidence
    - Hash format identified as unsalted MD5 (no prefix, 32 hex chars)
    - 4 of 41 cracked with a 14M wordlist plus a 14-rule file
      (wordlist and rules are in the appendices)
    - Recovery rate: 10% in 4 minutes, consistent with a top-10k
      password distribution
    - Crack results are NOT reproduced in this report and are stored
      in the encrypted evidence archive, deleted on <date>

  Business impact
    A single database read - through SQL injection, a backup file, a
    misconfigured S3 bucket, or a disgruntled employee - reveals every
    password. Users reuse passwords, so this also threatens other
    services. Four accounts sharing a password indicates no reuse
    detection.

  Remediation
    1. Migrate to Argon2id (or bcrypt at cost >= 12) with per-user
       salts. [Owner: Platform, Immediate]
    2. Force a reset on migration; do not import the old hashes
    3. Enforce MFA on all accounts, especially service and admin
    4. Enforce a 14-character minimum and check new passwords against
       a breach corpus (not a simple complexity rule)
    5. Deploy credential-stuffing detection on all external services

  Re-test
    Included at +30 days: confirm the new hash format and re-run a
    controlled crack to demonstrate the change in cost.

Terminology

Term Meaning
Hash identification Naming the algorithm from the format
hashid The default identification tool
Wordlist A list of candidate passwords
Rule A mutation applied to each wordlist entry
Mask A shape specification for a brute-force space
Mode hashcat's -m code for a hash type
Pot file Where cracked hashes accumulate; do not lose it
Session hashcat's resumable state
Fast vs slow hash Decides whether cracking is possible at all
Salt Per-user random value; defeats rainbow tables
Pass-the-hash Authenticating with the hash, not the password
Cracking rate Candidates per second; the number that matters
-a 0/-a 3 Straight / brute-force attack mode

import hashlib, os, secrets, string

# A realistic corporate password set, generated so we know the answers.
users = [
    ("alice",   "Summer2023!"),
    ("bob",     "P@ssw0rd"),
    ("carol",   "welcome"),
    ("dan",     "qwerty123"),
    ("erin",    "Monkey123"),
    ("frank",   "Acme2026"),
    ("grace",   "letmein"),
    ("heidi",   "iloveyou"),
    ("ivan",    "123456"),
    ("judy",    "Admin@123"),
]
rows = []
for u, p in users:
    # the WRONG way: unsalted fast hash. This is the finding.
    rows.append(f"{u}:{hashlib.md5(p.encode()).hexdigest()}")
open("unsalted_md5.txt","w").write("\n".join(rows) + "\n")

# the RIGHT way: per-user salt + slow hash
try:
    import bcrypt
    out = []
    for u, p in users:
        salt = bcrypt.gensalt(rounds=12)
        h = bcrypt.hashpw(p.encode(), salt)
        out.append(f"{u}:{h.decode()}")
    open("bcrypt12.txt","w").write("\n".join(out) + "\n")
    print("  built bcrypt cost-12 hashes for comparison")
except ImportError:
    print("  (pip install bcrypt for the bcrypt set)")

print(f"  built {len(users)} lab accounts")
print("  These are SYNTHETIC accounts with KNOWN passwords, generated for")
print("  this exercise. No third-party hash is cracked in this note.")
print()
print("  the point of the lab: the SAME 10 passwords are")
print("    minutes   against unsalted_md5.txt")
print("    centuries against bcrypt12.txt")
print("  The policy is the finding.")
