Block Ciphers, Modes of Operation and Security Notions

Summary

A block cipher is a permutation on 128-bit blocks. That is all it is — a function with no
security properties of its own. Everything about how you use it is called a mode of
operation, and nearly every real-world crypto failure is a bad mode.

The course's framing: the block cipher is the primitive, the mode is the
protocol, and the protocol is what has security properties.

Companion to cs161-02's IND-CPA. This note covers modes in depth;
that one covers the definition they must satisfy.

The block cipher itself

  AES: 128-bit blocks, 128/192/256-bit keys
        operates on ONE block, independently
        is a permutation: every input has exactly one output
        has NO security property on its own beyond being hard to invert
        without the key

  THE PADDING PROBLEM:
        plaintext is not a multiple of 16 bytes
        ISO 10126 / PKCS#7 adds bytes of value n, n+1 times
        if the padding is valid on decryption, you learn something

  THE TIV (random initialisation vector):
        AES-CTR and AES-GCM accept a random IV.
        with a uniform random IV over a large space, the scheme is
        IND-CPA secure for very many messages. That is the formal
        justification for "use a random IV".

The five modes, and what each one is good for

  MODE     SCRAMBLES?   RANDOMISED?   INTEGRITY?   USE IT FOR
  ECB      no           no            no           NOTHING
  CBC      yes          yes (IV)      no           legacy only
  CTR      yes          yes (nonce)   no           bulk data, disk
  CFB/OFB  yes          yes (IV)      no           legacy streaming
  GCM      yes          yes (nonce)   YES          almost everything

ECB, and why it is the textbook example

  ECB encrypts each block independently:

    plaintext : [P1][P2][P3][P4]
    ciphertext: [E(P1)][E(P2)][E(P3)][E(P4)]

  Identical plaintext blocks give identical ciphertext blocks, always.
  So the structure of the plaintext is VISIBLE in the ciphertext.

  For a picture of a penguin, you can see the penguin. Not because you
  decrypted anything, but because you can see where the colours repeat.

  ECB FAILS IND-CPA trivially and it is the most famous image in
  cryptography. Run the demo.

# ECB vs CBC, the actual difference, in 20 lines
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.backends import default_backend
import os, collections
key = os.urandom(32); iv = os.urandom(16)
# "records" where several are identical - like a database, like a filesystem
pt = b"".join([b"user:alice:role:a"]*6 + [b"user:bob__:role:_"]*6)
def enc(m, data):
    c = Cipher(algorithms.AES(key), m, backend=default_backend())
    e = c.encryptor(); e.update(data) or None
    return e.update(b"") if False else e.__class__ and _run(e, data)
def _run(e, data): return e.update(data) + (e.finalize() if e.finalize else b"")
# (simplified for readability)
def run(mode, ivb, data):
    c = Cipher(algorithms.AES(key), mode(ivb), backend=default_backend())
    e = c.encryptor(); ct = e.update(data) + e.finalize()
    return ct
ecb = run(modes.ECB(), None, pt)
cbc = run(modes.CBC(), iv, pt)
for name, ct in (("ECB", ecb), ("CBC", cbc)):
    blocks = [ct[i:i+16] for i in range(0, len(ct), 16)]
    d = collections.Counter(blocks)
    print(f"  {name}: {len(blocks)} blocks, {len(d)} distinct, "
          f"max repeat {max(d.values())}x")
print(f"\n  plaintext has 12 identical pairs. ECB shows it. CBC does not.")

CBC

  C1 = E(P1 XOR IV)
  C2 = E(P2 XOR C1)
  ...

  Properties:
    + identical plaintext blocks give DIFFERENT ciphertext (chaining)
    - serial: block N cannot be encrypted until block N-1 is done
    - a corrupted ciphertext block corrupts the NEXT plaintext block too
    - bit flipping: flip a bit in C1, and P2 changes in a chosen way
    - NO integrity: the attacker CAN modify your plaintext predictably

  BIT FLIPPING, precisely:
    C1 = E(P1 XOR IV)
    P1' = D(C1) XOR IV'      where IV' is the attacker's
    So: the attacker cannot change C1, but they can choose IV' to
    control P1 arbitrarily.
    In a session token, flipping "role=user" into "role=adm " is a
    textbook CBC attack. This is why CBC needs a MAC.

CTR

  Ci = Pi XOR E(k, nonce || counter_i)

  + parallelisable (the whole point, for disk and network throughput)
  + random access: decrypt block N without touching blocks 1..N-1
  + no padding (XOR a keystream, so length need not be a multiple)
  - the counter MUST NOT REPEAT under a key (nonce reuse = keystream reuse)
  - NO integrity (the attacker XORs whatever they like into your plaintext)

  THE COUNTER RULE:
    if the counter is w bits and the block is 128 bits, you may encrypt
    2^w messages under one key. 32-bit counters => birthday collision at
    2^16 messages. Choose the counter width accordingly, or rotate keys.

GCM: the one you should default to

  GCM is CTR mode plus GHASH (a polynomial MAC over GF(2^128)).

  YOU GET: confidentiality AND integrity in one pass, with an
  optional additional authenticated data (AAD) field.

  THE CATASTROPHE: GCM's authentication strength degrades FAST with
  message reuse under one nonce.
    nonce reuse #1:  ~1/2^32 forgery chance
    nonce reuse #2:  ~1/2^24
    (each reuse gives an independent equation)
  So a few thousand reused nonces degrades it meaningfully.

  This is the reason libraries have an explicit "never reuse a nonce"
  invariant, and the reason random 96-bit nonces exist (birthday at
  2^48 messages is safe enough for realistic volumes).

  THE OTHER FAILURE: if the authentication TAG is not checked, or is
  checked after the plaintext is used, GCM degrades to unauthenticated
  CTR. Verify the tag, first, in constant time.

Security notions, and what they mean in practice

  IND-CPA      an eavesdropper learns nothing
               satisfied by: AES-GCM with a random nonce, AES-CTR
               NOT by: ECB, or CTR with a fixed nonce

  IND-CCA2     an adversary can ask for decryptions and still learns
               nothing; chosen-ciphertext resistant
               satisfied by: GCM (with the tag checked), HMAC-then-encrypt
               NOT by: CBC with no MAC, or anything with a padding oracle

  AEAD         authenticated encryption with associated data: one
               construction that gives both at once
               this is what "encrypt this HTTP header along with the
               body, and prove it was not changed" means

  THE PRACTICAL TRANSLATION:
    - the mode gives you IND-CPA or IND-CCA2
    - the nonce/IV handling decides whether you actually GET it
    - the tag check decides whether an attacker can TELL you are using
      an AEAD at all

Choosing, honestly

  NEW SYSTEM:      AES-256-GCM or ChaCha20-Poly1305. Nothing else.
                   Not because AES is better, but because the mode
                   question disappears when it is not yours to answer.

  LEGACY CBC:      keep it, but add encrypt-then-MAC with a separate key
                   and a constant-time tag comparison.

  NEVER:           ECB. Ever. For any reason, including "the data is
                   small".

Terminology

Term Meaning
Block cipher A permutation on fixed-size blocks
Mode of operation How you apply a block cipher to a message
ECB Independent blocks; leaks structure
CBC Chained with an IV; serial; malleable
CTR Keystream from encrypting a counter; parallel, random access
GCM CTR + GHASH; authenticated encryption
AEAD Authenticated encryption with associated data
Nonce / IV Unique per key for CTR/GCM; random per message for CBC
TIV The "random IV" that makes CTR/CBC IND-CPA secure
Padding oracle Distinguishable padding errors leak the plaintext
Bit flipping Modifying the IV/previous block to control plaintext
IND-CCA2 Resistant to chosen-ciphertext attack
Nonce reuse Two messages under one nonce; catastrophic for GCM

# --- 1. ECB vs CBC: the structure leak, demonstrated ---
python3 - <<'PY' 2>&1 | tee 01-ecb-vs-cbc.txt
import os, collections
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.backends import default_backend

key, iv = os.urandom(32), os.urandom(16)
# six identical blocks, then six different ones - a "table" shape
pt = b"".join([b"user:alice:aa"]*6 + [b"user:bobbob:bb"]*6)

def run(mode, ivb, data):
    c = Cipher(algorithms.AES(key), mode(ivb), backend=default_backend())
    e = c.encryptor()
    return e.update(data) + e.finalize()

for name, ct in (("ECB", run(modes.ECB(), None, pt)),
                 ("CBC", run(modes.CBC(), iv, pt)),
                 ("CTR", run(modes.CTR(iv), None, pt))):
    blocks = [ct[i:i+16] for i in range(0, len(ct), 16)]
    c = collections.Counter(blocks)
    print(f"  {name}: {len(blocks)} blocks -> {len(c)} distinct, "
          f"largest run of identical ciphertext blocks: {max(c.values())}x")
print()
print("  The plaintext has SIX pairs of identical blocks.")
print("  ECB reproduces that structure exactly. CBC and CTR do not.")
print("  An attacker learns this without decrypting anything at all.")
print("  This is precisely why 'ECB fails IND-CPA' - it reveals a")
print("  function of the plaintext, which is the definition of failure.")

# --- 2. CBC bit flipping, done on purpose ---
python3 - <<'PY' 2>&1 | tee 02-bitflip.txt
import os
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.backends import default_backend

key = os.urandom(32)
def enc(iv, pt):
    c = Cipher(algorithms.AES(key), modes.CBC(iv), backend=default_backend()).encryptor()
    return iv, c.update(pt) + c.finalize()
def dec(iv, ct):
    d = Cipher(algorithms.AES(key), modes.CBC(iv), backend=default_backend()).decryptor()
    return d.update(ct) + d.finalize()

pt = b"role=user;admin=0\n"
iv, ct = enc(os.urandom(16), pt)
print(f"  plaintext : {pt}")
print(f"  ciphertext: {ct.hex()}")
print()
print("  Now pretend we are an attacker who cannot decrypt and cannot")
print("  re-encrypt. We cannot touch C1. But we CAN replace the IV,")
print("  because IV is not authenticated and not secret.\n")
# build the desired plaintext, XOR against the original to derive the new IV
want = b"role=user;admin=1\n"
new_iv = bytes(a ^ b ^ c for a, b, c in zip(iv, pt, want))
print(f"  desired   : {want}")
print(f"  new IV    : {new_iv.hex()}")
print(f"  decrypted with that IV: {dec(new_iv, ct)}")
print()
print("  CBC has NO integrity. The attacker did not break AES. They")
print("  changed the IV, and the plaintext changed by their choice.")
print("  A session token is exactly this shape: attacker-chosen fields")
print("  inside a CBC-encrypted blob. Hence: MAC it.")

# --- 4. the tag check, and where it goes wrong ---
cat > 04-tag-order.md <<'EOF'
# Where the tag check goes wrong

```python
# WRONG: decrypt first, verify later
pt = decrypt(ciphertext, key)          # attacker-controlled data, now live
if verify_tag(pt, tag, key): ...
# The decryption already happened. Any error path, any allocation, any
# decompression has already run on unauthenticated data.

# RIGHT: verify first, decrypt second
if not verify_tag(ciphertext, tag, key):
    raise InvalidTag()                 # constant time, no branch on content
pt = decrypt(ciphertext, key)
```

## The three ways GCM is misconfigured

| Mistake | Consequence |
|---|---|
| Tag not verified | AEAD degrades to unauthenticated CTR; the attacker can flip bits in your plaintext with no detection |
| Tag verified after the plaintext is used | You have already acted on forged data (SSRF, SQL, a redirect) |
| Nonce reused | Forgery probability rises roughly 2^4 per reuse |
| Tag compared non-constant-time | A timing oracle on authentication |

## What to look for in a code review

- [ ] the tag is verified before any use of the plaintext
- [ ] the tag comparison is constant time (`hmac.compare_digest`,
      `crypto.verify`, or the AEAD primitive itself — not `==`)
- [ ] the nonce comes from the library, not from a counter you wrote
- [ ] the AAD includes anything that must not be modifiable (a record
      id, a tenant id, a protocol version) — this is the whole point
      of "associated data"
- [ ] the key is 32 bytes and from a CSPRNG

## AAD is underused and it matters

```
  AEAD(plaintext, aad) -> (ciphertext, tag)

  The AAD is authenticated but not encrypted. Put in it:
    - the API endpoint path
    - the user or tenant id
    - a record id or a version number
    - a protocol version

  Then a ciphertext stolen from /user/42 cannot be replayed to
  /user/43, and a downgrade to an old protocol is detected.
```

# --- 5. what the mode table means for an audit ---
cat > 05-audit.sh <<'EOF'
#!/usr/bin/env bash
echo "=== 1. find the crypto in use ==="
grep -rniE "AES|DES|3DES|ChaCha|RC4|Blowfish|cipher|CBC|ECB|GCM|CTR|PKCS" \
     --include="*.py" --include="*.js" --include="*.php" --include="*.go" \
     --include="*.java" --include="*.rb" . 2>/dev/null | head -20 | sed 's/^/  /'

echo; echo "=== 2. flag the mode (ECB and RC4 are instant findings) ==="
grep -rniE "ECB|MODE_ECB|M_ECB|RC4|DES[^C]|/ECB/|DESede" . 2>/dev/null | sed 's/^/  FINDING: /'

echo; echo "=== 3. look for home-grown composition ==="
grep -rniE "encrypt\(.*decrypt\(|pad\(|unpad\(|pkcs|padding" --include="*.py" --include="*.php" . | sed 's/^/  /'

echo; echo "=== 4. look for a manual tag check (it should not exist) ==="
grep -rniE "verify.*tag|check.*tag|== *tag|tag *==" . 2>/dev/null | sed 's/^/  /'

echo; echo "=== 5. nonce/IV handling ==="
grep -rniE "nonce|iv *=|iv=|random_bytes\(16\)|os\.urandom" . 2>/dev/null | head -15 | sed 's/^/  /'
echo
echo "  FLAG: iv = b'\\x00' * 16   or  iv = 0   or  iv = os.urandom(0)"
grep -rniE "iv *= *(b?['\"]0|b['\"]\\\\x00|0 *[,)]|None)" . 2>/dev/null | sed 's/^/  FINDING: /'

echo; echo "=== 6. in the shell, for a config file ==="
grep -rniE "cipher *[:=] *(aes|des|rc4|3des)|mode *[:=] *(ecb|cbc)|iv *[:=]" \
     /etc/ssh/sshd_config /etc/hosts 2>/dev/null | grep -v "^ *#" | sed 's/^/  /'
EOF

Step 1 is the deliverable: three modes, the same plaintext, and the block-structure
comparison. ECB reproduces the plaintext's equality pattern; CBC and CTR do not. That is
IND-CPA failure demonstrated without decrypting anything.

Step 2 is the one that connects to real token formats — CBC bit flipping changes a plaintext
field by choice, using only the ability to set the IV. No key, no decryption.
