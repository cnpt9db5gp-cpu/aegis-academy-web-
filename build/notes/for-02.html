Timeline Analysis: Tying Files, Logs and Registry Together

Summary

A timeline is not a list of timestamps. It is a narrative with a shape — what happened first,
what caused what, and where the gaps are. Building one is the difference between a list of
artefacts and an incident narrative.

The framing: every artefact has a timestamp, and the timestamps disagree. That disagreement is
information: it tells you about clock skew, about deliberate timestomping, and about which source
to trust for which question.

Companion to for-01 (get the image) and ad-08 (what the DC logged).
This note is the analysis that happens between them.

The artefact sources, and what each is authoritative for

  SOURCE              TIMESTAMP IT CARRIES        TRUST IT FOR
  ------------------  -------------------------   -----------------
  MFT ($MFT)          created / modified /       the file system's
                      accessed (4 columns)        own view; 8 fields
  NTFS $UsnJrnl       file create/rename          the FILE SYSTEM's
                      journal, timestamped as     intent - survives
                      they happened               rename-based
                                                   timestomping
  $LogFile            transaction log            what the file
                                                   system did
  Registry hives       LastWriteTime per key      configuration
                                                   changes
  Event logs (evtx)   SystemTime per record       what was logged
                                                   (and by whom)
  Prefetch (.pf)      LastRunTime per executable  execution, and
                      (needs the file too)        the volume it ran from
  Amcache / ShimCache creation times              execution history
  Shimcache            AppId, path, timestamp     what ran, oldest
                                                   first
  NTUSER.DAT          LastLogon, RecentDocs       user activity
  SRUDB / UsnJrnl     session and usage          who was at the
                                                   keyboard
  MFT's $STANDARD_INFORMATION vs $FILE_NAME      the timestomping
                                                   vector itself

  THE RULE: use the least-valuable source to find the event and the
  most-valuable to prove it. Prefetch finds you the time; the event
  log proves it.

Timestomping, and how to catch it

  THE ATTACK: an attacker with write access sets a file's created and
  modified times to look old or to align with a system they were not
  on. Placed in the MFT's timestamps.

  THE CATCH, in order of reliability:

  1. THE $UsnJrnl
     The USN change journal is written by the file system BEFORE
     any user tool can touch a file, and it is append-only.
     A file that appears in the journal at time T but whose MFT says
     time S is timestomped. The journal cannot be edited without
     the volume unmounting cleanly or the attacker disabling it.

  2. THE MFT's OWN INTERNALS
     $STANDARD_INFORMATION has the times an OS sets on creation.
     $FILE_NAME (a separate attribute, and there can be several)
     has the times when THAT NAME was last written.
     If $FILE_NAME's times differ from $STANDARD_INFORMATION's, the
     file was renamed - or timestomped.

  3. THE PARENT DIRECTORY's $MFT
     A file's create time must be >= its parent's modification
     time (a file cannot be created before the directory it is in
     was last modified... except in exactly the timestomping case).
     Violations are candidates.

  4. CREATION TIME > MODIFICATION TIME
     Impossible for an honest file. Usually an artefact of a tool
     that did not set it, so it needs checking - but it is a lead.

  5. $LogFile
     The transaction log records the operations. A file created in
     the journal but absent from $LogFile is a lead.

The clock problem

  EVERY TIMELINE HAS THREE CLOCKS, AND THEY DISAGREE:

    the evidence machine's clock   (may be wrong, or attacker-set)
    your acquisition machine's     (probably right, NTP-synced)
      clock
    the DC's clock                (authoritative for domain events)

  THE PROCEDURE:
    1. record your own clock and whether it is NTP-synced
    2. record the evidence machine's clock and its offset from yours
    3. for domain events, use the DC's clock and its offset
    4. state the offsets in the report

  WHY IT MATTERS, CONCRETELY:
    an attacker sets the clock back 6 months to make their activity
    look like a scheduled maintenance window. Every file they touched
    has a timestamp consistent with that lie. The ONLY way to catch
    it is the USN journal, the MFT internals, and the DC's log -
    which is on a different clock they did not control.

  AND THE INVERSE: a machine with a broken battery has a clock at
  1970. Every file looks ancient. That is not an attack; it is a
  coin cell, and you must not report it as one.

Building the timeline

# --- 1. the merged timeline, with provenance preserved ---
cat > merge.sh <<'EOF'
#!/usr/bin/env bash
# Merge timeline artefacts from every source into one file, keeping the
# SOURCE column intact. The source is never discarded - two artefacts
# with the same timestamp from different sources are two facts.
OUT="timeline/merged/all.csv"
mkdir -p "$(dirname "$OUT")"
echo "timestamp_utc,source,record,detail" > "$OUT"

# 1. file system: the mactime body file from fls/log2timeline.py
if [ -f timeline/raw/mactime.csv ]; then
  awk -F, 'NR>1{printf "%s,mactime,%s,%s\n",$1,$2,$4}' timeline/raw/mactime.csv >> "$OUT"
fi

# 2. the file system's own journal (survives timestomping)
if [ -f timeline/raw/usnjrnl.csv ]; then
  awk -F, 'NR>1{printf "%s,usnjrnl,%s,%s\n",$2,$3,$5}' timeline/raw/usnjrnl.csv >> "$OUT"
fi

# 3. windows event logs
for f in timeline/raw/*.evtx.csv; do
  [ -f "$f" ] || continue
  src=$(basename "$f" .evtx.csv)
  awk -F, -v s="$src" 'NR>1 && $3!="" {printf "%s,%s,%s,%s\n",$3,s,$4,$8}' "$f" >> "$OUT"
fi

# 4. registry key last-write times
if [ -f timeline/raw/registry.csv ]; then
  awk -F, 'NR>1{printf "%s,registry,%s,%s\n",$2,$3,$5}' timeline/raw/registry.csv >> "$OUT"
fi

# 5. prefetch: what ran, and from which volume
if [ -f timeline/raw/prefetch.csv ]; then
  awk -F, 'NR>1{printf "%s,prefetch,%s,%s\n",$3,$1,$2}' timeline/raw/prefetch.csv >> "$OUT"
fi

sort -t, -k1,1 "$OUT" -o "$OUT"
echo "merged -> $OUT ($(($(wc -l < "$OUT")-1)) records)"
echo
echo "THE SOURCE COLUMN IS NOT OPTIONAL."
echo "  Two records at the same second from mactime and from the event"
echo "  log are two facts about one event. Collapsing them loses the"
echo "  ability to cross-check."
EOF
chmod +x merge.sh

# --- 2. the analysis queries ---
cat > analyse.sh <<'EOF'
#!/usr/bin/env bash
# Questions to ask a merged timeline. Each one has found something in
# a real incident.
T="timeline/merged/all.csv"
[ -f "$T" ] || { echo "run merge.sh first"; exit 0; }

echo "=== 1. EXECUTION: what ran, and for the first time? ==="
echo "    (first-run executables are where an investigation starts)"
grep -iE ",prefetch," "$T" | sort -t, -k1,1 | head -20 | sed 's/^/  /'

echo
echo "=== 2. PERSISTENCE: what was configured? ==="
echo "    Run keys, services, scheduled tasks, WMI subscriptions."
echo "    A persistence artefact is a CONFIGURATION change, so it lives"
echo "    in the registry, the MFT, and the event log - not in a file."
grep -iE "CurrentVersion\\\\Run|Image File Execution|Services\\\\|Schedule\\\\TaskCache" "$T" \
  | head -15 | sed 's/^/  /'

echo
echo "=== 3. THE WINDOW: what happened in the smallest possible interval? ==="
echo "    An intrusion has a start and an end. Everything between is"
echo "    the attack. Find the densest cluster and look only there."
sort -t, -k1,1 "$T" | awk -F, '
  {t=substr($1,1,16); c[t]++}
  END{for(k in c) if(c[k]>3) print "  " k ":00  " c[k] " records"}' | sort | head -20

echo
echo "=== 4. THE GAP: what should be there and is not? ==="
echo "    A 3-hour silence at 03:00 followed by a burst is either a"
echo "    break-in-the-night pattern (suspicious) or a scheduled task"
echo "    (innocent). You cannot tell without correlating the OTHER"
echo "    sources for the same window."
sort -t, -k1,1 "$T" | awk -F, '
  {h=substr($1,1,13)}
  h!=p {if(p!="" && c[p]<=1) print "  quiet hour: " p ":00 (" c[p] " records)"
        p=h; c[h]=0}
  {c[h]++}
  END{if(c[p]<=1) print "  quiet hour: " p ":00 (" c[p] " records)"}' | head -10

echo
echo "=== 5. THE CROSS-CHECK: does the MFT agree with the event log? ==="
echo "    A file created at T in mactime should appear in an event log"
echo "    near T. Divergence means timestomping OR a clock offset."
echo
echo "=== 6. THE USER: whose session was this? ==="
grep -iE "logon|4624|4625|session" "$T" | head -15 | sed 's/^/  /'
echo
echo "  Correlate with: SRUDB (who was at the keyboard), NTUSER.DAT"
echo "  (RecentDocs, UserAssist - what they opened), and the logon"
echo "  events. Three sources, one answer."
EOF
chmod +x analyse.sh

print("  === A TIMELINE, AND WHAT IT TELLS YOU ===\n")

                                             "created 4 minutes after the PowerShell prefetch"),
 (t0 + timedelta(days=-2),  "prefetch",  "SVCHOST32.EXE",     "FIRST RUN - NOT a real svchost path"),
 (t0 + timedelta(days=-2),  "eventlog",  "4624",              "logon, type 3, from an unusual source"),
 (t0 + timedelta(days=-2),  "mactime",   "TEMP\\a.dat",       "the encrypted payload"),
 (t0 + timedelta(days=-2),  "registry",  "HKLM\\...\\Image File Execution Options\\a.exe",
                                             "IFEO debugger set - anti-analysis"),
 (t0 + timedelta(days=-1),  "eventlog",  "1102",              "the Security log was CLEARED"),
]

print(f"  {'WHEN (UTC)':<18} {'SOURCE':<10} RECORD")
print("  " + "-"*70)
for ts, src, rec, detail in sorted(events):
    print(f"  {ts:%Y-%m-%d %H:%M}   {src:<10} {rec:<32} {detail}")

print("  === WHAT THE SHAPE TELLS YOU ===")
first_run = [e for e in events if e[1]=="prefetch" and "FIRST RUN" in e[3]]

print("     run is a classic: when the analyst launches it, the debugger")
print("     (their own, or their sandbox) runs instead.")
print()
print("  5. EVENT 1102 IS THE END OF THE EVIDENCE, NOT THE START.")
print("     Someone cleared the Security log. That:")
print("       - DESTROYS the 4624 logon events before it")
print("       - is itself a High-severity finding (anti-forensics)")
print("       - changes your confidence in EVERY other 'no evidence'")

Building a narrative, not a list

  THE STRUCTURE OF A GOOD TIMELINE SECTION:

    1. THE WINDOW, in one sentence, with a date range.
       "Activity occurred between 2026-10-09 02:14 and 2026-10-09 04:31 UTC."

    2. THE FIRST EVENT, and why it is first.
       "The first artefact is a first-run prefetch entry for
        powershell.exe from C:\Users\jdoe\Downloads."

    3. THE SEQUENCE, with the gaps named.
       "4 minutes later a file appeared in %TEMP%. The next first-run
        execution was 19 hours after that."

    4. THE ACTIONS, grouped by intent.
       "Execution (PowerShell), drop (%TEMP%\svchost32.exe),
        persistence (Run key to %TEMP%), anti-forensics (IFEO, then
        event 1102)."

    5. THE CONFIDENCE, and its limits.
       "The Security log was cleared at 04:31. Logon events before
        that point are unavailable. The timeline's start is therefore
        a lower bound, not a fact."

  THE LAST POINT IS THE ONE THAT MAKES A REPORT TRUSTWORTHY. Say what
  you cannot see, and why.
