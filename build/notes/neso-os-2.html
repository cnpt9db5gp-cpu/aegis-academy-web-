I/O Structure and System Calls

Summary

How a program actually gets bytes from a device to itself, and where the OS inserts itself. The
I/O path is the most security-relevant path in any system: every byte a web server serves and
every packet a sniffer reads passed through it.

Key ideas

  • Programmed I/O — CPU polls the device. Slow, simple.
  • Interrupt-driven I/O — device raises an interrupt; CPU handles it later. The standard model.
  • DMA — device writes directly to RAM; CPU is interrupted only at completion.
  • Spooling — a daemon holds a device exclusively (printer), serialising access.
  • The I/O path: device → driver → buffer → kernel → syscall → user buffer.
  • Why it matters: buffer sizes, TOCTOU on device files, and /dev/* permissions are all
    attack surface.

Terminology

Term Meaning
Driver Kernel code controlling one device class
Interrupt Signal from device asking for CPU attention
DMA Direct memory access, bypassing CPU
Buffering Absorbing speed differences between device and CPU
Spooling Daemon-owned exclusive device access
Device file /dev/* node used to talk to a driver
/dev/shm Shared memory tmpfs
ioctl Device-specific control syscall
Blocking / non-blocking Whether a read waits for data
Readahead Kernel prefetching, relevant to forensics

Kali commands

ls -la /dev | head -20
ls -la /dev/sd* /dev/nvme* 2>/dev/null
lsmod | head -10
ls -la /dev/shm/
# device permissions ARE a security boundary
ls -l /dev/mem /dev/kmem /dev/sda 2>/dev/null
# who has raw socket / packet capabilities?
getcap /usr/bin/tcpdump /usr/bin/wireshark /usr/bin/nmap 2>/dev/null
# interrupt-driven IO in action
cat /proc/interrupts | head -5
grep -E "tty|eth|enp" /proc/interrupts | head -5
# buffered IO: compare sequential vs random reads
dd if=/dev/zero of=/tmp/t bs=1M count=64 2>/dev/null
dd if=/tmp/t of=/dev/null bs=4k 2>&1 | tail -1
dd if=/tmp/t of=/dev/null bs=4k iflag=direct 2>&1 | tail -1
rm -f /tmp/t

Field lab

Objective: trace the I/O path from a file read down to the block device, and audit /dev.

mkdir -p ~/aegis/labs/neso-os-2 && cd ~/aegis/labs/neso-os-2

# --- 1. watch a read cross the boundary ---
strace -e trace=openat,read,close /bin/ls 2>&1 | head -12 | tee 01-io-path.txt
echo "That is: syscalls -> kernel -> page cache -> device. Every read, every time."

# --- 2. buffered vs direct, the performance cost of the abstraction ---
sudo dd if=/dev/zero of=/tmp/t bs=1M count=128 conv=fsync 2>/dev/null
{
  echo "=== buffered read (through the page cache) ==="
  dd if=/tmp/t of=/dev/null bs=4k 2>&1 | tail -1
  echo "=== direct read (bypassing cache, reaching the device) ==="
  dd if=/tmp/t of=/dev/null bs=4k iflag=direct 2>&1 | tail -1
  echo "The gap between these two numbers IS the page cache."
} | tee -a 01-io-path.txt
rm -f /tmp/t

# --- 3. audit /dev: who can touch devices directly? ---
{
  echo "=== device nodes and their modes ==="
  ls -la /dev/sd* /dev/nvme* /dev/mem /dev/kmem /dev/shm 2>/dev/null
  echo
  echo "=== block devices ==="
  lsblk -o NAME,MAJ:MIN,SIZE,TYPE,MOUNTPOINT
  echo
  echo "=== capabilities on capture tools ==="
  getcap /usr/bin/tcpdump /usr/bin/nmap /usr/bin/wireshark /usr/bin/ettercap 2>/dev/null
  echo "(empty = these still need root; capabilities would let them run without it)"
} 2>&1 | tee 02-dev-audit.txt

# --- 4. interrupts: the I/O completion path ---
{
  echo "=== interrupt sources ==="
  head -2 /proc/interrupts
  grep -iE "eth|enp|tty" /proc/interrupts | head -5
  echo
  echo "=== softirq (deferred processing) ==="
  grep -E "SOFTIRQ|RCU|SCHED" /proc/interrupts | head -4
} 2>&1 | tee 03-interrupts.txt

# --- 5. the spooling model in practice ---
ls -la /var/spool/ 2>/dev/null
lpstat -p 2>/dev/null || echo "(no cups; the spooling model is the same for any exclusive device)"

02-dev-audit.txt is a real finding sheet. Any device node that is world-writable on a
multi-user machine is a local escalation path, which is exactly what pr-01 hunts for.
