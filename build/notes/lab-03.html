Building a Domain Lab for AD Practice

Summary

An AD lab needs three servers, not one, and the reason is the whole of ad-01: a domain is a
database plus a set of servers. Two domain controllers teach you replication, DCSync
prerequisites and time synchronisation that a single-DC lab cannot.

The framing: build the domain correctly first, including the
things that are harder rather than easier — delegation, preauth flags,
service accounts in privileged groups. A clean AD lab teaches you
that AD attacks do not work.

Companion to lab-01 (the platform) and the whole AD tier. This
note builds the thing you practise on.

The topology

  ┌───────────────────────────────────────────────────────────────┐
  │ 192.168.56.0/24          ("external" in the fiction)          │
  │                                                                │
  │   KALI (host)          DC01              DC02                 │
  │   192.168.56.1         .56.10            .56.11                │
  │                        +10.10.10.5       +10.10.10.6         │
  │                                                               │
  │   WKS01                WKS02            SRV01                  │
  │   .56.20               .56.21           (10.10.10.20 only)    │
  │   domain-joined        domain-joined    dual-homed            │
  │   unprivileged         privileged       app + file server     │
  └───────────────────────────────────────────────────────────────┘

  WHY TWO DCs:
    - replication, so a DC-only lab never teaches anything about it
    - time synchronisation, which Kerberos depends on
    - the ability to TEST a single-DC forest (where DCSync rights are
      a pure finding) before adding a second

  WHY A DUAL-HOMED HOST:
    SRV01 is on 10.10.10.0/24 only. Nothing in 192.168.56.0/24 can
    reach it without a pivot. That makes `ad-06`'s pivoting real.

  WHY A PRIVILEGED WORKSTATION:
    WKS02 is where an admin should log in, and WKS01 is where they
    should NOT. The difference between them is the whole of tiered
    administration, and you cannot practise it in a one-account lab.

# Domain lab plan

```text
  FOREST      aegis.lab
  DOMAIN      aegis.lab
  NETBIOS     AEGIS
  DOMAIN ADMINISTRATOR password: something you will forget, so write
  it in notes/ (and that file is chmod 600)

  SERVERS     DC01 (192.168.56.10, 10.10.10.5)  - first DC, also
               the pivot host into 10.10.10.0/24
               DC02 (192.168.56.11, 10.10.10.6) - second DC, for
               replication
               SRV01 (10.10.10.20)              - app + file server,
               internal only

  WORKSTATIONS WKS01 (192.168.56.20)  domain-joined, unprivileged
               WKS02 (192.168.56.21)  domain-joined, the admin's

  USERS
    alice          unprivileged domain user. The starting point of
                   every capstone scenario.
    bob            unprivileged
    erin           in a privileged group. The target of every
                   privilege-escalation scenario.
    svc-backup     service account, in Backup Operators. SPNs set.
                   Your roasting target.
    svc-web        service account, in a web-app group, SPNs set.
    svc-iis        service account for the app tier
    helpdesk       a group with delegated rights - the realistic
                   misconfiguration that makes paths long

  THE DELIBERATE MISCONFIGURATIONS
    These are what you are going to find, and they are realistic:

    1. svc-backup in a privileged group (ad-01: the most common real
       finding in every assessment)
    2. helpdesk with GenericAll on a group (bh-02's five-hop path)
    3. one account with msDS-UserDoesNotNeedPreAuth (ad-04: AS-REP
       roastable, and findable with NO credentials)
    4. one account with msDS-AllowedToDelegateTo set (ad-02)
    5. SMB signing NOT required (imp-03: relayable)
    6. a weak local administrator password on SRV01
    7. LAPS not deployed

    WRITE THEM DOWN NOW, with their exact state. When you find one
    during an exercise you need to know it was intentional.
EOF

cat > 02-promote.sh <<'EOF'
#!/usr/bin/env bash
# Promote DC01 to the first domain controller. Run INSIDE the VM.
# These are Windows commands; this file documents them.
cat <<'PS1'
=== ON DC01, as Administrator ===

# 1. name the adapters correctly first. This bites everyone.
  #    Rename the NIC on 192.168.56.0/24 to "Lab-External"
  #    Rename the NIC on 10.10.10.0/24   to "Lab-Internal"
  #    Set the metric: External = 5, Internal = 50
  #    (so the host's default route goes via External)

# 2. set the time. Kerberos will not work without it.
  w32tm /config /manualpeerlist:"time.windows.com,0x9" /syncfromflags:manual /update
  w32tm /resync

# 3. hostname and domain
  Rename-Computer -NewName DC01 -Restart
  Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
  Install-ADForest `
    -DomainName "aegis.lab" `
    -DomainNetbiosName "AEGIS" `
    -InstallDns:$true `
    -SafeModeAdministratorPassword (ConvertTo-SecureString "LabAdmin!2019" -AsPlainText -Force) `
    -Force

# 4. FIX THE FUNCTIONAL LEVEL while you are still in a state where
#    you can, because raising it later is much harder.
  Set-ADDomain -Identity aegis.lab -ServerMode Win2012R5

# 5. On DC02, join the SAME forest (not a new domain - a child domain
#    is a different lab):
  Add-WindowsFeature AD-Domain-Services -IncludeManagementTools
  Install-ADDomain `
    -NewDomainName "aegis.lab" `
    -ParentDomainName "aegis.lab" `
    -Credential (Get-Credential) `
    -InstallDns:$true `
    -SafeModeAdministratorPassword (ConvertTo-SecureString "LabAdmin!2019" -AsPlainText -Force) `
    -Force

# 6. On WKS01 and WKS02, join:
  Add-Computer -DomainName aegis.lab -Credential (Get-Credential)

# 7. Point the workstations' DNS at DC01 (192.168.56.10), NOT at
#    8.8.8.8. This is the single most common lab failure.
PS1
EOF
chmod +x 02-promote.sh

cat > 03-misconfig.ps1 <<'PS1'
<#
  The deliberate misconfigurations. Run ONCE on DC01 as Administrator.
  Documented, reproducible, and reversible.

  Each block creates ONE realistic condition that a real assessment
  finds. They are the exercises, and they are listed here so that when
  you find one you know it was put there deliberately.
#>

# --- 1. a service account in a privileged group ---------------------
# The most common high-severity finding in real engagements.
New-ADUser -Name "svc-backup" -SamAccountName "svc-backup" `
  -Path "OU=ServiceAccounts,DC=aegis,DC=lab" `
  -Enabled $true -PasswordNeverExpires $true `
  -AccountPassword (ConvertTo-SecureString "BackupSvc!2019" -AsPlainText -Force)
Add-ADGroupMember -Identity "Backup Operators" -Members "svc-backup"
Set-ADServicePrincipalName -Identity "svc-backup" `
  -HostName "fileserver" -Sets "HOST/dc01.aegis.lab", "HOST/fileserver"
Write-Host "1. svc-backup: in Backup Operators, with SPNs. Roastable."

# --- 2. an account that does not require preauth ---------------------
# AS-REP roastable. FINDABLE WITH NO CREDENTIALS. (ad-04)
New-ADUser -Name "svc-legacy" -SamAccountName "svc-legacy" `
  -Path "OU=ServiceAccounts,DC=aegis,DC=lab" `
  -Enabled $true `
  -AccountPassword (ConvertTo-SecureString "Legacy2019!" -AsPlainText -Force)
Set-ADObject -Identity "svc-legacy" -Replace @{
  msDS-UserDoesNotNeedPreAuth = $true }
Write-Host "2. svc-legacy: preauth disabled. Roasts with no credential."

# --- 3. unconstrained delegation -------------------------------------
# THE finding that has been Critical in every assessment of every large
# Windows estate since 2010. (ad-02)
Set-ADObject -Identity "WEB01" -Replace @{
  msDS-AllowedToDelegateTo = "KEY USE FOR ALL TRUSTED AUTHENTICATION" }
Write-Host "3. WEB01: unconstrained delegation. TGTs for every user."

# --- 4. RC4 Kerberos, so roasting works ------------------------------
# Modern Windows defaults to AES-only. Removing this means your lab
# does not reproduce the roasting exercise. (ad-04)
Set-ADObject -Identity "svc-backup" -Replace @{
  msDS-SupportedEncryptionTypes = 0x4 }    # RC4 only
Set-ADObject -Identity "svc-web"    -Replace @{
  msDS-SupportedEncryptionTypes = 0x4 }
Write-Host "4. svc-backup and svc-web: RC4 only. Roastable."

# --- 5. the helpdesk misconfiguration, a realistic long path ---------
# GenericAll on a group, which chains into privilege. (bh-02)
$helpdesk = New-ADGroup -Name "helpdesk" -GroupCategory Security `
  -Path "OU=Groups,DC=aegis,DC=lab" -PassThru
$itSupport = Get-ADGroup -Identity "IT Support"
$acl = Get-Acl "AD:\$itSupport.DistinguishedName"
$rule = New-Object System.DirectoryServices.ActiveDirectoryAccessRule(
  $helpdesk, "GenericAll", "Allow")
$acl.AddAccessRule($rule)
Set-Acl "AD:\$itSupport.DistinguishedName" $acl
Add-ADGroupMember -Identity $helpdesk -Members "alice", "bob"
Write-Host "5. helpdesk: GenericAll on 'IT Support'. alice can add herself."

# --- 6. a gMSA in a privileged group (the readGMSAPassword target) --
New-ADServiceAccount -Name "gmsa-files" `
  -Path "OU=ServiceAccounts,DC=aegis,DC=lab" `
  -DNSHostName "gmsa-files.aegis.lab" `
  -RestrictToSingleComputer $true -KerberosEncryptionType AES256, AES128
Add-ADGroupMember -Identity "Backup Operators" -Members "gmsa-files$"
Write-Host "6. gmsa-files$: a 120-character password in a privileged"
Write-Host "   group. Readable with ReadGMSAPassword. Uncrackable, and"
Write-Host "   irrelevant, because you can just read it. (bh-02)"

# --- 7. and the accounts --------------------------------------------
foreach ($n in @("alice","bob","erin","svc-web","svc-iis")) {
  $pw = switch ($n) {
    "alice" {"Summer2019!"}; "bob" {"Winter2019!"}
    "erin" {"Admin2019!"}; "svc-web" {"WebSvc!2019"}
    "svc-iis" {"IisSvc!2019"}
  }
  New-ADUser -Name $n -SamAccountName $n -Path "OU=Users,DC=aegis,DC=lab" `
    -Enabled $true -PasswordNeverExpires $true `
    -AccountPassword (ConvertTo-SecureString $pw -AsPlainText -Force)
}
New-ADGroup -Name "IT Support" -GroupCategory Security `
  -Path "OU=Groups,DC=aegis,DC=lab"
Add-ADGroupMember -Identity "IT Support" -Members "erin"
Set-ADServicePrincipalName -Identity "svc-web" `
  -HostName "web01" -Sets "HTTP/web01.aegis.lab"
Set-ADServicePrincipalName -Identity "svc-iis" `
  -HostName "web01" -Sets "HTTP/web02.aegis.lab"

Write-Host ""
Write-Host "=============================================="
Write-Host " LAB MISCONFIGURATIONS IN PLACE"
Write-Host " 1. svc-backup in Backup Operators + SPNs + RC4"
Write-Host " 2. svc-legacy: preauth disabled"
Write-Host " 3. WEB01: unconstrained delegation"
Write-Host " 4. two service accounts: RC4 only"
Write-Host " 5. helpdesk: GenericAll on IT Support"
Write-Host " 6. gmsa-files$ in Backup Operators"
Write-Host " 7. erin in IT Support (alice can add herself)"
Write-Host "=============================================="
Write-Host "TAKE A SNAPSHOT NOW: 04-PRE-EXERCISE"
PS1
echo "written: 03-misconfig.ps1"

Verifying the lab

cat > 04-verify.sh <<'EOF'
#!/usr/bin/env bash
# Does the lab do what you think it does? Run this after building it.
DC="${1:-192.168.56.10}"
U="${2:-alice}"; P="${3:-Summer2019!}"
case "$(echo "$DC" | cut -d. -f1)" in
  192.168.56.*|10.10.10.*) ;;
  *) echo "REFUSED: $DC not in the lab range"; exit 3 ;;
esac
NC=$(ldapsearch -x -H "ldap://$DC" -b "" -s base defaultNamingContext \
     2>/dev/null | grep -m1 "^defaultNamingContext:" | awk '{print $2}')
echo "[scope] $DC in range; anonymous unless stated"
echo
echo "=== 1. the forest exists and is a single domain ==="
ldapsearch -x -H "ldap://$DC" -b "${NC}" -s base \
  "(objectClass=DomainDNS)" dc dnsHostName forestFunctionalityLevel 2>/dev/null \
  | grep -E "^[a-zA-Z]+:" | sed 's/^/  /'
echo
echo "=== 2. THE MISCONFIGURATIONS, each one confirmed ==="
echo "  1. svc-backup in a privileged group:"
ldapsearch -x -H "ldap://$DC" -b "${NC}" "(cn=svc-backup)" memberOf 2>/dev/null \
  | grep "^memberOf:" | sed 's/^/       /'
echo "  2. preauth-disabled accounts (the AS-REP roast list):"
ldapsearch -x -H "ldap://$DC" -b "${NC}" \
  "(userAccountControl:1.2.840.113556.1.4.803:=1048576)" \
  sAMAccountName 2>/dev/null | grep "^sAMAccountName:" | sed 's/^/       /'
echo "  3. delegation:"
ldapsearch -x -H "ldap://$DC" -b "${NC}" "(msDS-AllowedToDelegateTo=*)" \
  sAMAccountName msDS-AllowedToDelegateTo 2>/dev/null \
  | grep -E "^(sAMAccountName|msDS):" | sed 's/^/       /'
echo "  4. RC4-only service accounts:"
ldapsearch -x -H "ldap://$DC" -b "${NC}" "(servicePrincipalName=*)" \
  sAMAccountName msDS-SupportedEncryptionTypes 2>/dev/null \
  | paste - - 2>/dev/null | sed 's/^/       /'
echo "  5. the helpdesk GenericAll (needs a credential to see):"
ldapsearch -x -D "CN=$U,$NC" -w "$P" -H "ldap://$DC" \
  -b "CN=IT Support,OU=Groups,$NC" -s base nTSACL 2>/dev/null >/dev/null \
  && echo "       (readable - the ACL is queryable)" \
  || echo "       (cannot read nTSACL; check your tooling)"
echo "  6. SMB signing on the DC (this is the imp-03 finding):"
nmap -p 445 --script smb2-security-mode "$DC" 2>/dev/null \
  | grep -i "signing" | sed 's/^/       /'
echo
echo "  VERDICT: if items 1-5 returned data, the lab is ready."
echo "  Item 6 should say 'not required' - that IS the finding."
EOF
chmod +x 04-verify.sh
./04-verify.sh 192.168.56.10 2>&1 | tee 05-verify.txt

Step 3 is the deliverable: 03-misconfig.ps1 creates six deliberate misconfigurations, each
labelled with the tier note it exercises — and each realistic. svc-backup in Backup Operators
is "the most common high-severity finding in real engagements"; helpdesk with GenericAll is
bh-02's five-hop path; the gMSA in a privileged group is uncrackable and irrelevant, because
you can just read the password with ReadGMSAPassword.

04-verify.sh confirms each one, and the last check deliberately expects the failure —
SMB signing "not required" is the finding.

Record: 03-misconfig.ps1 and 05-verify.txt.
