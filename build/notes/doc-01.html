How Kali Is Organised: Recon, Scanning, Exploitation, Forensics

Summary

New users see ~3000 executables and assume Kali is a magic box that knows how to hack. It is not.
Kali is a Debian distribution with a curated set of tools, and those tools belong to about a
dozen categories. Learn the categories and Kali stops being a wall of names and starts being
a toolbox you reach into deliberately.

This is the most important conceptual lecture in Tier 0. Everything else here is mechanics.

The engagement lifecycle

Almost every offensive tool maps to a phase. Memorise the phases, not the tools.

        ┌──────────────┐
        │  1. RECON     │  passive: what exists, publicly?
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │  2. ENUMERATION│ active: what is running, on which version?
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │  3. VULN ASSESS│ which known flaws match what I found?
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │  4. EXPLOITATION│ turn a flaw into code execution
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │  5. POST-EXPL │ maintain access, escalate, move laterally
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │  6. REPORTING │ what did I find, what is the risk, what do you fix?
        └──────────────┘

80% of real work is steps 1-3. Beginners want to jump to 4; professionals live in 1-3.

The categories, and what they actually do

Category Tools Question it answers
Information gathering nmap, maltego, theharvester, subfinder What exists out there?
Vulnerability analysis nikto, searchsploit, nessus, nuclei What known flaws match?
Web application burpsuite, sqlmap, ffuf, gobuster, nikto How does this HTTP app break?
Password attacks john, hashcat, hydra, responder What secrets can I recover?
Exploitation metasploit, gdb, pwntools, radare2 How do I get code execution?
Post-exploitation mimikatz, impacket, linpeas, bloodhound, crackmapexec What can I reach from here?
Sniffing / spoofing wireshark, tcpdump, ettercap, bettercap What is crossing the wire?
Forensics volatility, autopsy, foremost, binwalk, exiftool What happened here?
Credential access john, hashcat, mimikatz, responder Where are secrets stored?
Reporting metasploit, faraday, cutycapt How do I prove it?

How to find a tool by purpose

# by name
apt-cache search '^nmap$'
apt-cache search metasploit | head

# by description keyword
apt-cache search "network scanner"
apt-cache search --names-only 'password' | head

# by metapackage - this is the taxonomy, by category
apt-cache search --names-only '^kali-tools-' | sort
apt-cache depends kali-tools-recon          # everything in the recon category
apt-cache depends kali-tools-exploitation   # everything in the exploitation category

# is it installed, and where?
dpkg -S "$(command -v nmap)"
dpkg -l | grep '^ii  kali-tools'

# what does this metapackage pull in? (simulate, never install blindly)
apt-get -s install kali-tools-web | grep '^Inst' | wc -l

The decision you actually make

When a challenge says "the web server is 10.10.10.5:8080", your first question is never "which
tool?" — it is "which phase am I in, and what do I not know yet?"

# phase 0: understand the target
curl -s -I http://127.0.0.1:8080
# phase 1: what's there?       -> recon / enumeration tools
nmap -sV -p- 10.10.10.5
# phase 2: what does it run?   -> version -> CVE
searchsploit apache 2.4.49
# phase 3: does the flaw exist? -> verify before exploiting
curl -s -I http://10.10.10.5/cgi-bin/..%2f..%2f..%2fetc/passwd
# phase 4: get a shell
# phase 5: establish persistence, enumerate the host
# phase 6: write it up

Skipping to phase 4 without phases 1-3 is how people spend six hours on a machine that was
patched. Enumeration is not the boring part; it is the job.

Terminology

Term Meaning
Reconnaissance (recon) Discovering what exists, before touching anything
Enumeration (enum) Identifying services, versions, users, shares on live systems
Fingerprinting Determining the exact software and version behind a port
CVE Public catalogue entry for a vulnerability
Exploit Working code that turns a vulnerability into impact
Payload What the exploit delivers (shell, file, etc.)
Post-exploitation Everything after initial access
Lateral movement Compromising additional hosts
Persistence Surviving reboot while staying quiet
Attack surface Every point where untrusted input can enter

Kali commands

# --- the taxonomy, printed ---
apt-cache search --names-only '^kali-tools-' | cut -d- -f3 | sort -u

# --- what is in each category (simulated, not installed) ---
for cat in recon scanning exploitation post-exploitation forensics reporting \
           password-attacks web-application sniffer credential-stuffing; do
  n=$(apt-get -s install kali-tools-$cat 2>/dev/null | grep -c '^Inst')
  printf "kali-tools-%-22s %s packages\n" "$cat" "$n"
done

# --- what is already installed by category ---
dpkg -l | grep '^ii  kali-tools' | awk '{print $2}' | sort

# --- the single most valuable command in Kali ---
searchsploit --help
searchsploit apache 2.4.49
searchsploit -t apache -t httpd
searchsploit --keyword="kerberoast"   # a technique, not a product

# --- offline CVE data (works with no internet) ---
ls /usr/share/exploitdb/
ls /usr/share/nmap/scripts/ | wc -l
ls /usr/share/seclists/ | head

Field lab

Objective: produce your own taxonomy map, and go from a port number to a candidate exploit
using only offline data.

mkdir -p ~/aegis/labs/doc-01 && cd ~/aegis/labs/doc-01

# --- 1. The taxonomy ---
apt-cache search --names-only '^kali-tools-' | cut -d- -f3 | sort -u | tee 01-taxonomy.txt
echo "categories: $(wc -l < 01-taxonomy.txt)"

# --- 2. Size of each category (simulated - shows what "recon" really means) ---
{
  for cat in $(cat 01-taxonomy.txt); do
    n=$(apt-get -s install kali-tools-$cat 2>/dev/null | grep -c '^Inst')
    printf "%-28s %4s packages\n" "kali-tools-$cat" "$n"
  done
} | sort -k2 -rn | tee 02-category-sizes.txt

# --- 3. Offline exploit knowledge base ---
{
  echo "=== exploitdb entries ==="; searchsploit -c 2>/dev/null | head -5
  echo "=== nmap NSE scripts ==="; ls /usr/share/nmap/scripts/*.nse | wc -l
  echo "=== sample NSE scripts (these ARE automation) ==="
  ls /usr/share/nmap/scripts/ | grep -E 'vuln|enum' | head -20
} | tee 03-offline-db.txt

# --- 4. Port -> service -> CVE chain, entirely offline ---
{
  echo "=== all known exploits for Apache ==="
  searchsploit apache | head -15
  echo
  echo "=== a specific version ==="
  searchsploit "apache 2.4.49"
  echo
  echo "=== by technique rather than product ==="
  searchsploit --keyword=kerberoast | head -10
  searchsploit --keyword="privilege escalation" | head -10
} | tee 04-searchsploit.txt

# --- 5. Practice the lifecycle on YOUR OWN loopback ---
nmap -sV -p- -oN 05-loopback.txt 127.0.0.1 2>/dev/null
{
  echo "PHASE 1-2: what is open on my own machine?"
  grep "open" 05-loopback.txt
  echo
  echo "PHASE 3: which known flaws match these versions?"
  while read -r svc ver; do
    [ -z "$svc" ] && continue
    hits=$(searchsploit "$svc $ver" 2>/dev/null | grep -c " - ")
    printf "  %-12s %-15s %s known exploits\n" "$svc" "$ver" "$hits"
  done < <(grep "open" 05-loopback.txt | awk '{print $2, $3" "$4}')
} | tee 06-lifecycle.txt

# --- 6. NSE scripts are pre-written reconnaissance - read one ---
less /usr/share/nmap/scripts/vulners.nse
nmap -sV --script vuln 127.0.0.1 -oN 07-vulnscan.txt 2>/dev/null
tail -20 07-vulnscan.txt

Step 6 is a revelation if you have not seen it. Nmap's NSE library is hundreds of pre-written
reconnaissance scripts. Reading vulners.nse teaches you how vulnerability scanning is
implemented — and what its blind spots are.

Record: in your scratchpad, keep 02-category-sizes.txt. The next time someone says "just
use Kali for X", you will know which category to reach into.

Self-test

  1. Name the six phases of an engagement and give one tool per phase.
  2. Why is enumeration "the job" rather than a preliminary to it?
  3. How would you find every package in Kali's information-gathering category without installing
    them all?
  4. What does searchsploit give you that a web search does not?
  5. Why is reading an NSE script educational in a way that running it is not?
