Processes, Threads and Process Control

Summary

A process is an executing program with its own resources: address space, open files, credentials.
Threads share everything except the stack and registers.

Security-wise, a process is the unit of isolation and a thread is the unit of shared risk.
Getting this distinction right explains privilege boundaries, ptrace targets, and why memory
corruption in a multithreaded server is catastrophic.

Key ideas

  • Process states: new, ready, running, waiting, terminated.
  • Process Control Block (PCB): PID, state, PC, registers, memory info, open files, credentials.
  • Program vs process: a program on disk is not running; the process is the instance.
  • Threads: shared heap, shared files, per-thread stack.
  • fork(): duplicates the address space (copy-on-write).
  • execve(): replaces the image entirely — a different program in the same PID.
  • Zombie: exited process whose parent has not reaped it.
  • Credentials live per-process: which is why setuid binaries matter.

Terminology

Term Meaning
PID Process identifier
PCB Kernel's per-process record
fork() Create a child process
execve() Replace the current program image
Thread Execution stream sharing an address space
Context switch Saving/restoring CPU state between processes
Zombie Terminated process awaiting reaping
Orphan Process whose parent died
Reaping Parent collecting a child's exit status
Group / session Process groupings for signals and job control
Nice / priority CPU scheduling weight

Field lab

Objective: map the process model on your machine, then observe fork/exec/credential transfer.

mkdir -p ~/aegis/labs/neso-os-3 && cd ~/aegis/labs/neso-os-3

# --- 1. the process inventory ---
{
  echo "=== totals ==="
  echo "processes: $(ps -e --no-headers | wc -l)"
  echo "threads:    $(ps -eL --no-headers | wc -l)"
  echo
  echo "=== my process ==="
  grep -E "^(Name|Pid|PPid|Uid|Gid|Threads)" /proc/self/status
  echo
  echo "=== processes by user ==="
  ps -eo user --no-headers | sort | uniq -c | sort -rn | head
  echo
  echo "=== zombies ==="
  ps -eo pid,ppid,stat,comm | awk '$3 ~ /Z/' | head
  echo "(empty = nothing un-reaped)"
} > 01-processes.txt; cat 01-processes.txt

# --- 2. fork: same program, separate address space ---
cat > forkdemo.c <<'EOF'
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
#include <stdlib.h>
int main(void) {
    int x = 42;
    pid_t p = fork();
    if (p == 0) {                       /* child */
        x = 99;
        printf("child  pid=%d ppid=%d x=%d\n", getpid(), getppid(), x);
        exit(0);
    }
    printf("parent pid=%d child=%d x=%d\n", getpid(), p, x);
    wait(NULL);
    return 0;
}
EOF
gcc -o forkdemo forkdemo.c && ./forkdemo | tee 02-fork.txt
echo "The child changed its own x to 99. The parent still has 42. Separate address spaces."

# --- 3. execve: the SAME pid becomes a different program ---
cat > execdemo.c <<'EOF'
#include <stdio.h>
#include <unistd.h>
int main(void) {
    printf("before exec, pid=%d\n", getpid());
    fflush(stdout);
    execl("/bin/echo", "echo", "AFTER execve, this is /bin/echo, same pid", NULL);
    perror("execl");
    return 1;
}
EOF
gcc -o execdemo execdemo.c && ./execdemo | tee 03-exec.txt
echo "Note: the PID does not change. execve replaces the image, it does not fork."
echo "This is exactly what your shell does when you type a command."

# --- 4. credentials live in the process, not the binary ---
{
  echo "=== my credentials ==="
  grep -E "^(Uid|Gid|CapEff|CapBnd)" /proc/self/status
  echo
  echo "=== a setuid binary: the credential transition ==="
  ls -l /usr/bin/passwd /usr/bin/sudo 2>/dev/null
  echo "  ^ the 's' in the mode means setuid. The kernel swaps UID on execve."
  echo
  echo "=== observe it: who owns my shell's root ==="
  echo "my uid: $(id -u)  effective: $(id -u -n)"
  sudo -u nobody id 2>/dev/null
  echo
  echo "=== setuid and sgid binaries on this machine ==="
  find / -perm -4000 -type f 2>/dev/null | head -10
  find / -perm -2000 -type f 2>/dev/null | head -5
} 2>&1 | tee 04-credentials.txt

# --- 5. threads share the address space ---
cat > threads.c <<'EOF'
#include <pthread.h>
#include <stdio.h>
static int shared = 7;                 /* ONE copy, shared */
static void *w(void *_) { printf("  thread sees shared=%d\n", shared); return 0; }
int main(void) {
    pthread_t t;
    pthread_create(&t, NULL, w, NULL);
    shared = 100;                      /* main changes it */
    pthread_join(t, NULL);
    printf("main has shared=%d\n", shared);
    return 0;
}
EOF
gcc -o threads threads.c -lpthread && ./threads | tee 05-threads.txt
echo "Same variable, one address space. That is why memory bugs cross thread boundaries."

Step 4 connects straight back to pr-02. Every SUID binary is code that will execute with
elevated privilege, chosen by whoever can write the binary or the library it loads.
