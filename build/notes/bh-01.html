Data Collection: SharpHound Enumeration

Summary

BloodHound is two halves: collection (build the graph) and analysis (find the paths). The
collection half is mechanical and is the part you must get right, because a bad collection
produces a graph that lies to you.

The framing that matters: collection is active enumeration. It generates
traffic, it touches every DC, and it may contain every hash on the
domain. So the discipline question comes before the technique question.

Companion to ad-03 (what to collect and why) and bh-02 (reading the
result). This note is the mechanics and the hazards.

What the three collection methods actually do

  GROUP          WHAT IT TOUCHES                 WHAT IT GETS
  ---------------------------------------------------------------------------
  SessionLoop    every host, authenticated       a SESSION per user per host.
                 as you, one at a time,          this is the collection you
                 over SMB/WinRM                   want when you want to see
                                                   who is currently
                                                   authenticated where, and
                                                   the single most valuable
                                                   edge type for relay.

  LocalAdmin     every host, via ADMIN$          the principals that are
                                                   local admin on which
                                                   hosts. A graph edge from
                                                   a user to a machine, so
                                                   "who can take this host".

  ACL            every object, one request       every DACL in the forest.
  (default)      per object via LDAP              This is the expensive one:
                                                   tens of thousands of
                                                   objects. But it is the
                                                   one that finds the paths.

  Group          every group membership           the group graph.
  (part of ACL)                                  Included in ACL collection.

  Trust          every trust                     the cross-domain edges.
                                                   Only meaningful in a
                                                   multi-domain forest.

  RDP            every host, over 3389            who has RDP rights.
                                                   Slow, and rarely worth it
                                                   unless you are hunting for
                                                   a specific privilege.

  SessionLogon   4624 logon events from the DC   who has EVER logged on,
  (timelined)    (the DC already has them)        with timestamps. Very
                                                   cheap, very useful for
                                                   dormant-account analysis.

The honest cost model: ACL is the one that finds privilege-escalation
paths. SessionLoop is the one that finds lateral movement opportunities.
LocalAdmin is the one that turns "you have this hash" into "you have
this host". You usually need all three, and ACL is by far the slowest
because it is one query per object.

SharpHound: the three collection modes

# The Windows collector. Run it on a domain-joined host, or via a
# file share on a DC (which needs SeBackupPrivilege or admin on the DC).

# Default ACL collection (stealthy, no SMB to every host)
SharpHound.exe --CollectionMethods All --DomainController lab.internal \
  --OutputFile /tmp/acl.zip

# ACL + Group only (fastest useful collection)
SharpHound.exe --CollectionMethods Group,ACL --DCOnly lab.internal \
  -o /tmp/acl-group.zip

# SessionLoop: touch every host (LOUD - it authenticates to everything)
SharpHound.exe --CollectionMethods SessionLoop --Domain lab.internal \
  --Threads 12 --SessionLoopTimeout 3000 -o /tmp/session.zip

# All: everything, including local admin on every host (loudest)
SharpHound.exe --CollectionMethods All --Domain lab.internal --Threads 12 \
  -o /tmp/all.zip

# RDS: RDP sessions specifically (rare, slow)
SharpHound.exe --CollectionMethods RDS -o /tmp/rds.zip

# LAPS: enumerate LAPS-deployed local admins (netexec/have 2.7+)
SharpHound.exe --CollectionMethods LAPS -o /tmp/laps.zip

# The Linux collector. Same output, no Windows dependency.
# The method names are the same; the capabilities differ slightly.
bloodhound-python -d lab.internal -u alice -p 'pass' -m All -o /tmp/bh
bloodhound-python -d lab.internal -u alice -p 'pass' -m ACL
bloodhound-python -d lab.internal -u alice -p 'pass' -m Session
bloodhound-python -d lab.internal -u alice -p 'pass' -m DCOnly
bloodhound-python -d lab.internal -u alice -p 'pass' -m Group
bloodhound-python -d lab.internal -u alice -p 'pass' -m LocalAdmin

What is in the output, and why it is sensitive

  A collection zip contains:

    2024-01-15_ACL.zip
      .sqlite     the graph database. Principals, groups, sessions, ACLs
      .json       the raw LDAP responses, in full
      logs        exactly what was queried, and what failed

    WHAT THE .SQLITE CONTAINS:
      every user and computer principal in the forest
      every group and its full membership (transitively, as edges)
      every DACL, as edges, for every object
      every session observed (SessionLoop)
      every local admin relationship (LocalAdmin)

    WHAT IS SENSITIVE ABOUT IT:
      it is a complete map of who has authority over what, in a form
      that can be queried to find the shortest path to domain admin.
      It is essentially an attacker's cheat sheet for YOUR domain.

      If you keep it, keep it encrypted.
      If you delete it, delete it properly, and say so in the report.
      Do not email it. Do not put it in a ticket.

    WHAT IS SENSITIVE ABOUT SessionLoop SPECIFICALLY:
      it does not collect hashes, but it does show WHO IS LOGGED IN
      WHERE, at the moment you looked. That is the operational picture,
      and it can be disruptive-adjacent: an admin session you did not
      know about, on a host you did not know about.

Collection hazards

  1. DETECTION
     SharpHound's LDAP queries are unusual enough to alert on, and
     good organisations alert on them. If you run ACL collection
     against a forest that is watching, you WILL be noticed. That is
     often fine (and often the point - it proves their detection works)
     but it should be a conversation, not a surprise.

  2. LOAD
     ACL collection is tens of thousands of LDAP queries. Against a
     small lab DC this is fine. Against a large production forest from
     a laptop, it can saturate a DC's LDAP threads and cause a
     noticeable delay for real users.
       -> use --threads carefully (default 10 is usually right)
       -> run it from a DC if you have admin there (DCOnly is much
          cheaper: one host, not every host)

  3. SESSION IMPACT
     SessionLoop authenticates to every host. On a host with a
     lockout policy, one bad credential in a loop can lock out
     accounts. On a host with an aggressive EDR, you will see a
     wave of SMB authentications from one source.

  4. LOCKOUT
     BloodHound will not lock out accounts if it reuses one valid
     credential. But if you give it a hash or a list, and it retries,
     it can. Use a single known-good credential.

  5. THE ROE QUESTION
     Collection is enumeration of every object in the domain, with a
     user's rights. In most contracts that is in scope for "internal
     testing". Confirm it, and confirm the source IPs, so the client
     can attribute the traffic and alert appropriately.

Getting the collection right

  1. DO THE SMALLEST COLLECTION THAT ANSWERS YOUR QUESTION
       "is there a privilege path?"       -> ACL, DCOnly
       "can I move laterally?"            -> SessionLoop, LocalAdmin
       "who is dormant?"                  -> SessionLogon (cheap)
     Running All when you needed ACL wastes hours and gets you noticed
     for no benefit.

  2. COLLECT FROM ONE SOURCE, NOT A SPRAY
       One host, one credential, all methods. Twenty queries from one
       box is indistinguishable from one admin's normal activity; the
       same 20 from 20 boxes is a pattern.

  3. COLLECT FROM A DC WHEN YOU CAN
       DCOnly is far cheaper and is the same graph for the ACL
       method. If you have admin on a DC (or DCSync), use it.

  4. COLLECT EARLY, COLLECT ONCE
       AD changes during an engagement. A graph from hour 1 is stale
       by hour 8. Plan for one collection at the start and one at the
       end, and note the timestamp difference in the report.

  5. VALIDATE BEFORE YOU TRUST
       - did any collection error? (the logs)
       - is the object count plausible for the domain size?
       - are the group memberships complete, or did a failure truncate
         the transitive closure?
       - did SessionLoop actually touch the hosts you expected?
     A silently truncated collection produces a graph with false
     negatives, and you will report "no path" when you did not look.

Validating a collection

cat > 01-validate.sh <<'EOF'
#!/usr/bin/env bash
# Does this collection actually cover the domain?
Z="$1"
echo "=== collection contents ==="
unzip -l "$Z" | sed 's/^/  /'
echo
echo "=== errors in the collector log (these matter) ==="
unzip -p "$Z" '*log*' 2>/dev/null | grep -iE "error|denied|fail|exception" \
  | grep -viE "0 error|no error" | head -20 | sed 's/^/  /'
echo
echo "=== object counts from the sqlite (the sanity check) ==="
DB=$(unzip -Z1 "$Z" | grep -m1 '\.sqlite$')
unzip -p "$Z" "$DB" > /tmp/bh.sqlite 2>/dev/null
if [ -f /tmp/bh.sqlite ]; then
  sqlite3 /tmp/bh.sqlite "
    SELECT 'users',        COUNT(*) FROM users
    UNION ALL SELECT 'computers',  COUNT(*) FROM computers
    UNION ALL SELECT 'groups',     COUNT(*) FROM groups
    UNION ALL SELECT 'domains',    COUNT(*) FROM domains
    UNION ALL SELECT 'sessions',   COUNT(*) FROM sessions;
  " 2>/dev/null | sed 's/^/  /'
  echo
  echo "  A users count near zero means the collection failed silently."
  echo "  Compare 'users' against the count from ldapsearch (ad-03)."
  echo
  echo "=== the edge counts, by kind ==="
  sqlite3 /tmp/bh.sqlite "SELECT DISTINCT type, COUNT(*) FROM edge_acl GROUP BY type;
                         SELECT 'sessions', COUNT(*) FROM sessions;" 2>/dev/null | sed 's/^/  /'
  echo
  echo "=== coverage: how many OUs and DCs did it touch? ==="
  sqlite3 /tmp/bh.sqlite "
    SELECT DISTINCT o.distinguishedname
    FROM owned o JOIN baseobjects o ON o.id = o.objectid
    WHERE o.objectid LIKE '%:494' LIMIT 20;" 2>/dev/null | sed 's/^/  /'
  echo
  echo "=== SANITY: is the group graph complete? ==="
  echo "  A transitive GroupMember closure should show a Domain Admin"
  echo "  as a member of a small number of groups. If Domain Admins has"
  echo "  0 members in the graph but the domain has users, the"
  echo "  collection truncated."
fi
rm -f /tmp/bh.sqlite
EOF
chmod +x 01-validate.sh
echo "written: 01-validate.sh"
echo
echo "run: ./01-validate.sh /path/to/collection.zip"

The ingest

  ON THE BLOODHOUND GUI (Windows or the community container):
    File -> Data Import -> upload the zip
    the GUI builds the graph and runs its default queries

  ON THE NEO4J INSTANCE (bloodhound.py has moved to neo4j since 2024):
    import BloodHound.py -d neo4j://<host> -u neo4j -p <pass> <zip>
    or: cypher-shell, or the BloodHound Python API

  THE ONES YOU WANT ON EVERY GRAPH:
    all group membership edges
    all ACL edges with the right types
    all HasSession edges (if you ran SessionLoop)
    all DCSync edges
    all delegation edges (msDS-AllowedToDelegateTo)
    all computer -> DCSync (the shortcut people miss)

Terminology

Term Meaning
SharpHound The C# collector; run on a domain-joined host or a DC
bloodhound-python The Linux collector; same output format
Collection method ACL, SessionLoop, LocalAdmin, Group, Trust, RDP, LAPS
DCOnly Collect from one DC; far cheaper than every host
Group Membership only; the group graph
ACL Every DACL; the expensive and essential one
SessionLoop Authenticate to every host; the session edges
LocalAdmin Who is local admin where
SessionLogon 4624 history from the DC; cheap
.sqlite / .json The graph database and the raw responses
Truncated collection A partial graph with false negatives
Ingest Loading the zip into the GUI or neo4j
Edge type Member, HasSession, GenericAll, WriteDACL, DCSync
Object ID BloodHound's SID:SGUID identifier

# --- 2. the collection commands, with the ROE note ---
cat > 02-collect.sh <<'EOF'
#!/usr/bin/env bash
# Collection against YOUR lab forest only.
# Collection is ACTIVE ENUMERATION of every object in the domain.
# Confirm it is in the ROE and confirm the source IP with the client
# so their monitoring can attribute it and (optionally) alert on it.
set -euo pipefail
DOM="${1:?usage: ./02-collect.sh lab.internal alice}"
USER="${2:?a user}"
OUT="${3:-/tmp/bh-$(date +%Y%m%d-%H%M%S)}"

case "$DOM" in
  *.internal|*.local|*.lab|*.test) echo "[scope] $DOM looks like a lab domain" ;;
  *) echo "REFUSED: $DOM does not look like a lab domain." >&2; exit 3 ;;
esac
echo "[scope] $DOM (lab)"
echo "[roe]   collection enumerates every object. Confirm the ROE."
echo "[note]  ALl and SessionLoop touch every host and will be noticed."
echo

read -r -p "password for $DOM\\$USER: " PW

echo
echo "=== 1. THE MINIMUM THAT ANSWERS 'is there a privilege path?' ==="
echo "    ACL + Group, DCOnly. One DC, no SMB to every host."
bloodhound-python -d "$DOM" -u "$USER" -p "$PW" -m ACL --dc-only \
  --output "$OUT-acl.zip" 2>&1 | tail -5 | sed 's/^/  /'

echo
echo "=== 2. THE MINIMUM THAT ANSWERS 'can I move laterally?' ==="
echo "    SessionLoop + LocalAdmin. This touches every host."
read -r -p "  run it? [y/N] " go
if [ "$go" = "y" ]; then
  bloodhound-python -d "$DOM" -u "$USER" -p "$PW" -m Session \
    --session-timeout 3000 --threads 10 \
    --output "$OUT-session.zip" 2>&1 | tail -5 | sed 's/^/  /'
  bloodhound-python -d "$DOM" -u "$USER" -p "$PW" -m LocalAdmin \
    --output "$OUT-admin.zip" 2>&1 | tail -5 | sed 's/^/  /'
else
  echo "  skipped."
fi

echo
echo "=== 3. the cheap one ==="
echo "    SessionLogon needs only the DC's event log. Dormant accounts."
bloodhound-python -d "$DOM" -u "$USER" -p "$PW" -m SessionLogon \
  --output "$OUT-logon.zip" 2>&1 | tail -3 | sed 's/^/  /'

echo
echo "=== validate before you trust it ==="
echo "  ./01-validate.sh $OUT-acl.zip"
echo
echo "=== HANDLE THESE FILES LIKE THE DOMAIN'S NT HASHES ==="
echo "  they are a complete map of who has authority over what."
echo "  encrypt at rest, do not email, delete on the ROE date."
ls -la "$OUT"-*.zip | sed 's/^/  /'
EOF
chmod +x 02-collect.sh

cat > 04-discipline.md <<'EOF'
# Collection discipline

```text
  BEFORE COLLECTING
  - [ ] the ROE permits domain enumeration
  - [ ] the client knows your source IP(s)
  - [ ] you have told them you are collecting, so their SOC does not
        raise a false alarm
  - [ ] you know whether their detection will alert - and whether that
        is fine (it often is, and often proves their detection works)

  COLLECTION CHOICE
  - [ ] "is there a privilege path?"   -> ACL, DCOnly
  - [ ] "can I move laterally?"        -> SessionLoop + LocalAdmin
  - [ ] "who is dormant?"              -> SessionLogon
  - [ ] I have NOT defaulted to All because it was the first example
        I saw

  VALIDATION
  - [ ] the collector log has no errors, or I understand each one
  - [ ] the user count matches ldapsearch (ad-03)
  - [ ] the group graph is not truncated (Domain Admins has members)
  - [ ] SessionLoop touched the hosts I expected

  HANDLING
  - [ ] the zips are encrypted at rest
  - [ ] they are not in email, not in a ticket, not in the report
  - [ ] a deletion date is recorded in the engagement diary

  TIMING
  - [ ] collected at hour 1 and re-collected at the end
  - [ ] the difference between the two is noted in the report, because
        AD changed and the graph is now stale

The report language for a stale graph

  "Graph collected 2026-10-14 09:20 and 2026-10-14 16:40. No new
   privilege paths appeared between the two collections. The AD graph
   is a point-in-time view: changes made after 16:40 are not reflected.
   The re-test at +30 days includes a fresh collection."

What NOT to do

  - Do not run All against a production forest on a Friday evening
    without warning. SessionLoop authenticates to every host.
  - Do not collect with a credential you obtained by attacking the
    domain, and then hand the collection to the client without
    explaining where the credential came from. That credential is a
    finding; using it to collect is fine; hiding it is not.
  - Do not upload a client's collection to a public BloodHound
    instance, a pastebin, or a shared Grafana. It is the domain's
    entire privilege map.
  - Do not trust a graph that reported "no path to Domain Admin"
    without checking the user count and the Domain Admins membership.
    That result is almost always a truncated collection.

EOF
```

Step 3 is the deliverable: a note that the collection zip is a SQLite database, with the
actual WITH RECURSIVE CTE for shortest-path and the DCSync query. Every question in the next
two notes can be answered with sqlite3 on this box — no Docker, no BloodHound GUI, no
neo4j. And it warns that BloodHound's Domain Admins@LAB.INTERNAL casing is a silent
zero-rows failure that reads as "no path exists".

04-discipline.md is the operational card: minimum collection per question, validation
before trust, and "do not upload a client's collection to a public instance — it is the
domain's entire privilege map."
