ARP, DNS and DHCP in the Wild

Summary

Three protocols you will see in every capture. Each has a distinctive shape, and each has a
distinctive misuse.

Key ideas

  • ARP: request is broadcast, reply is unicast and unsolicited. Every host trusts any reply
  • ARP spoofing: send unsolicited ARPs claiming someone else's IP; caches update silently
  • DNS: UDP/53, a question, an answer, and nothing authenticates either
  • DNS cache poisoning: get a false answer cached at a resolver, and every client inherits it
  • DHCP: Discover/Offer/Request/Acknowledge, all broadcast, all unauthenticated until the client
    configures itself
  • Rogue DHCP wins by answering the Request faster than the real server
  • In a capture, these three stand out by: broadcast destination, and the responder replying
    without being asked

Terminology

Term Meaning
ARP request / reply Who-has / I-am, broadcast / unicast
ARP cache Host's IP→MAC table
Gratuitous ARP Unsolicited announcement of an IP/MAC pair
DNS query / response Question / answer
Recursive resolver Server that queries on your behalf
Cache poisoning Inserting a false record into a cache
DNS hijacking Intercepting resolution entirely
DORA DHCP's four messages
Rogue DHCP Unauthorised server answering clients
DHCP starvation Exhausting the pool so your rogue server answers next

Field lab

Objective: capture all three protocols, identify the shapes, and understand the attacks from
the packets rather than from theory.

# --- PRE-FLIGHT: this lab needs root, so authenticate ONCE, HERE, first ---
# `sudo something &` backgrounds the password PROMPT along with the command.
# With no terminal attached to answer it, sudo fails - and `2>/dev/null`
# then throws away the only clue. The result is a capture file that was
# never written, followed by a screenful of "no such file".
#
# `sudo -v` validates the credential in the FOREGROUND, where you can see
# and answer the prompt. It caches for ~15 minutes, so every backgrounded
# `sudo` below is prompt-free and actually runs.
if ! sudo -v; then
  echo "  sudo is unavailable or the password was wrong - stop here." >&2
  echo "  Everything below needs root. Nothing will be captured." >&2
  exit 1
fi
mkdir -p ~/aegis/labs/pkt-03 && cd ~/aegis/labs/pkt-03

# --- 1. capture all three at once ---
sudo timeout 25 tcpdump -i any -n -e -w three-protos.pcap \
  "arp or udp port 53 or udp port 67 or udp port 68" 2>/dev/null &
TC=$!
sleep 1
ping -c2 127.0.0.1 >/dev/null 2>&1
dig +short localhost @127.0.0.1 >/dev/null 2>&1
ip neigh flush all 2>/dev/null; ping -c1 127.0.0.1 >/dev/null 2>&1
sleep 3
if ip -br addr show vboxnet0 >/dev/null 2>&1; then
  sudo dhclient -r vboxnet0 >/dev/null 2>&1; sleep 1; sudo dhclient vboxnet0 >/dev/null 2>&1 &
  sleep 8
fi
kill $TC 2>/dev/null; wait $TC 2>/dev/null

# --- 2. ARP: request is broadcast, reply is unicast ---
echo "=== ARP ==="
tshark -r three-protos.pcap -Y "arp" -T fields \
  -e arp.src.proto_ipv4 -e arp.src.proto_eth.src -e arp.dst.proto_ipv4 \
  -e arp.dst.proto_eth.dst -e eth.dst 2>/dev/null | head -10 | tee 01-arp.txt
echo
echo "  Look at the last column. A request has a broadcast destination MAC"
echo "  (ff:ff:ff:ff:ff:ff); a reply has a unicast one. A reply arriving with"
echo "  no preceding request is either a gratuitous ARP or an attack."

# --- 3. DNS: query and answer ---
echo
echo "=== DNS ==="
tshark -r three-protos.pcap -Y "dns" -T fields \
  -e dns.flags.response -e dns.qry.name -e dns.a -e dns.flags.rcode 2>/dev/null | head -10 | tee 02-dns.txt
echo
echo "  flags.response 0 = query, 1 = answer."
echo "  An answer with no matching query, or a TTL of 0, is suspicious."

# --- 4. DHCP: DORA, in order ---
echo
echo "=== DHCP (if your lab link produced any) ==="
tshark -r three-protos.pcap -Y "bootp" -T fields \
  -e frame.number -e bootp.type -e bootp.option.dhcp_type -e ip.src -e ip.dst 2>/dev/null | head -10 | tee 03-dhcp.txt
echo
cat <<'EOF'
  1 = Discover (client, broadcast)
  2 = Offer    (server, broadcast or unicast)
  3 = Request  (client, broadcast)   <- the attacker races here
  5 = Ack      (server)
  8 = Release  (client, giving the lease back)
EOF

# --- 5. THE ATTACK, described against the packets you just read ---
cat > 04-attacks.md <<'EOF'
# Three attacks, three packet shapes

## ARP spoofing
You send an ARP *reply* (not a request) claiming "192.168.56.101 is at MY mac".
Every host that receives it updates its cache. No request is needed, so no
host knows anything unusual happened.

In a capture this looks like: unsolicited replies, or replies whose claimed
IP does not match the network they arrived on.

Mitigation: static ARP entries, dynamic ARP inspection, or port security.

## DNS cache poisoning
You answer a resolver's recursive query before the real authoritative server
does, with a forged A record and a TTL of 0 to maximise churn. Every client
using that resolver now resolves the name to your address.

In a capture this looks like: answers to queries the local host did not send,
answers with a much shorter TTL, or answers arriving with no query.

Mitigation: DNSSEC validation, locking down which servers a resolver will
query, and monitoring resolver logs.

## Rogue DHCP
You answer the client's DHCP *Request* faster than the legitimate server, with
a gateway and DNS pointing at you. The client configures itself to route
through the attacker's machine.

In a capture this looks like: an Offer for a MAC address that is not on the
known client list, or a Request answered by two servers.

Mitigation: DHCP snooping on switches, port security on edge ports.
EOF
cat 04-attacks.md

# --- 6. baselines, for later comparison ---
{
  echo "=== ARP volume (poisoning raises this sharply) ==="
  sudo timeout 10 tcpdump -i any -n arp 2>/dev/null | wc -l
  echo "=== ARP replies specifically (poisoning is replies) ==="
  sudo timeout 10 tcpdump -i any -n "arp[6][2] = 2" 2>/dev/null | wc -l
  echo "=== DNS queries ==="
  sudo timeout 10 tcpdump -i any -n "udp port 53 and not arp" 2>/dev/null | wc -l
} 2>&1 | tee 05-baseline.txt
echo
echo "Record these numbers. They are your 'normal' for this machine."

Step 5 is the payoff: each attack is now described in terms of the exact packets you just
captured and read yourself, rather than abstractly.

Self-test

  1. How does an ARP reply differ on the wire from an ARP request?
  2. Why does a gratuitous ARP not require the target to ask anything?
  3. What TTL would a DNS poisoner use, and why?
  4. Which DHCP message does a rogue server race to answer?
  5. Name a mitigation for each of the three attacks.
