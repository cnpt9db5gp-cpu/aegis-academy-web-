Python Basics and Flow Control

Summary

The Python you need for security scripting: variables, types, control flow, functions, and the
collections you will use constantly. Deliberately narrow — no metaclasses, no decorators beyond
recognition. Everything here appears in the labs in py-* and in tools like impacket.

Key ideas

  • Dynamic typing — no declaration, but types still govern what is legal
  • Indentation is syntax — blocks are defined by whitespace, 4 spaces
  • if / elif / else, truthiness rules, the "0" trap
  • for / while, range stop-exclusive, enumerate, zip
  • Functions: parameters, defaults, *args, **kwargs, return values
  • The collections that matter: list, dict, tuple, set, and collections.Counter
  • Exceptions: try/except/else/finally, never a bare except:

Terminology

Term Meaning
Dynamic typing Type attached to the value, not the name
Truthiness What a value coerces to in a boolean context
Mutable Can be changed in place (list, dict, set)
Hashable Usable as a dict key (str, int, tuple)
*args / **kwargs Variadic positional / keyword arguments
Comprehension Inline construction of a collection
F-string f"{x}" formatting
Docstring The string under a def

Field lab

Objective: write a flow-control exercise that parses /etc/passwd and reports on it.

mkdir -p ~/aegis/labs/atb-01 && cd ~/aegis/labs/atb-01

cat > users.py <<'PY'
from collections import Counter

SHELLS = ("/bin/false", "/usr/sbin/nologin", "/bin/sync", "/sbin/shutdown",
          "/usr/bin/nologin", "/dev/null")

def parse(path="/etc/passwd"):
    users = []
    with open(path, errors="replace") as f:
        for line in f:
            if line.startswith("#"):
                continue
            p = line.strip().split(":")
            if len(p) < 7:
                continue
            users.append({"name": p[0], "uid": int(p[2]), "gid": int(p[3]),
                          "home": p[5], "shell": p[6]})
    return users

def login_capable(u):
    return u["shell"] not in SHELLS

def report(users):
    capable = [u for u in users if login_capable(u)]
    by_uid  = Counter(u["uid"] for u in users)
    homes   = Counter(u["home"] for u in capable)
    print(f"  total accounts      : {len(users)}")
    print(f"  possible login      : {len(capable)}")
    print(f"  UID 0 accounts      : {[u['name'] for u in users if u['uid'] == 0]}")
    print(f"  duplicate UIDs      : {[u for u, n in by_uid.items() if n > 1]}")
    print(f"  top home directories : {homes.most_common(3)}")
    return capable

if __name__ == "__main__":
    users = parse()
    capable = report(users)
    with open("login-capable.txt", "w") as f:
        for u in capable:
            f.write(f"{u['name']}\n")
PY

python3 users.py | tee 01-report.txt
echo
echo "=== same output, produced with shell tools ==="
grep -v '^#' /etc/passwd | awk -F: '$(NF) !~ /(nologin|false|sync|shutdown)/ {print $1}' | wc -l
echo
echo "=== validate against the shell version ==="
diff <(python3 -c "

print('\n'.join(u['name'] for u in users.parse() if users.login_capable(u)))") \
     <(grep -v '^#' /etc/passwd | awk -F: '$(NF) !~ /(nologin|false)/ {print $1}' | sort) \
  && echo "identical - your Python matches the awk pipeline"

Note the structure: parse → report → __main__. Each function one job, importable for
reuse. That is the shape of every tool in this course.
