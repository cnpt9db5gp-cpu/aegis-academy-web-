Bandit Levels 0-10: SSH, ls, find, cat, base64

Summary

Bandit is a text-only wargame with 60 levels and no account or VM — you SSH in and solve levels
in order. It is the ideal companion to Tier 0 because it forces you to use ls, find, cat,
grep, pipes and permissions until they stop being frightening.

How it works: connect, read the level description, find the password file for level N, and
read it. The passwords are generated from the previous level's flag, so you cannot skip.

ssh bandit0@bandit.labs.overthewire.org -p 2220

What levels 0-10 actually drill

Levels Skill
0-3 ls, find, cat, hidden files, absolute vs relative paths
4-6 ls -la, reading /etc/passwd, more/cat with hidden directories
7-8 find with -readable, hidden directories, permissions
9-10 strings, grep, find -exec, base64 decoding

Level notes

Level 0 — find and read. The flag is in a file in the home directory.

ls -la
cat readme

Level 1 — the file is hidden. Nothing shows with plain ls.

ls -a          # -a = all, including dotfiles
cat -

Level 2 — hidden files, directories and somewhere else.

ls -la
cat ./-        # read a file whose name starts with a dash
find . -type f
cat ./*readme* # a glob, because you do not know the exact name

Level 3 — find the file, then read it without ls.

find . -type f
cat ./secret   # adjust to whatever find returned
ls -la ./secret # the -a is required if it is hidden

Level 4 — permission denied on a file. This is the first real lesson.

ls -la
cat ./-file        # Permission denied

# who am I, what groups?
id

# what does the mode mean?
#   -rw-r--r--   owner rw, group r, others r   -> "others" cannot read
#   -rw-r-----   owner rw, group r, others ---
sudo cat ./-file   # on this box sudo is allowed and passwordless

You have just encountered the entire privilege model in one line of output. others has no
read bit, which is why you cannot read it. sudo works because this is a single-purpose
challenge machine.

Level 5 — a binary, not a text file.

ls -la
file ./-file                    # identify the type
cat ./-file                     # garbage - it is binary
strings ./-file | grep password # extract printable strings, then filter

strings ./-file alone usually prints the password in the last line.

Level 6 — find a file owned by a user, no permission to read it directly.

find / -user bandit7 -readable 2>/dev/null
cat /home/bandit7/.ssh/id_rsa   # or wherever find points

Two flags worth memorising: -user <name> and -readable / -writable. Redirect stderr to
/dev/null because /proc and restricted directories are noisy.

Level 7 — permissions again, with -ls.

find / -user bandit6 -ls 2>/dev/null | grep -E "bandit7|\.txt"
sudo cat /home/bandit6/.secret

Level 8 — the file is hidden and there are a lot of them.

find / -user bandit6 -group bandit6 -ls 2>/dev/null
sudo cat /home/bandit6/.secret
find . -readable -type f -exec cat {} \; 2>/dev/null | grep -i password

The -exec ... \; form runs a command per result. This is an extremely common enumeration
pattern you will use constantly.

Level 9 — binary again, different tool.

find . -readable -type f -exec strings {} \; 2>/dev/null | grep -i password
strings ./-file | grep -i password

Level 10 — base64. The password is encoded, so you must decode it.

ls -la
cat data.txt
base64 -d data.txt
echo "cGFzc3dvcmQ=" | base64 --decode

Useful variants: base64 -w0 to strip line wrapping, xxd -r -p for hex, base32 -d.

Terminology

Term Meaning
SSH Encrypted remote shell; -p sets the port
Dotfile A hidden file starting with .
ls -a Include entries starting with .
Glob * and ? wildcards expanded by the shell
-- End of options; lets you read files named -foo
Mode bits rwx per owner/group/others
gid / group Whose file is it, and who else may read it
find -exec Run a command per matched file
strings Print printable sequences from a binary
base64 -d Decode; base64 is an encoding, not encryption

Kali commands

# --- the useful flags, drilled ---
ls -la
ls -ld /etc/passwd
cat -A /etc/passwd          # show non-printing characters
find . -maxdepth 2 -type f -name "*.txt"
find / -user bandit0 -group bandit0 -ls 2>/dev/null | head
find / -perm -4000 -type f 2>/dev/null | head      # SUID
find / -writable -type f 2>/dev/null | head        # world/group writable

# --- reading awkward files ---
cat ./-file                 # works because the name is "-file"
cat -- ./-file              # the explicit form
cat ./*readme*              # glob when you do not know the name

# --- strings and encodings ---
strings /bin/ls | head -20
base64 -w0 data.txt
base64 -d data.txt
echo "SGVsbG8=" | base32 -d 2>/dev/null
xxd data.txt | head

Field lab

Objective: clear Bandit levels 0-10 and build a cheat-sheet of the patterns.

mkdir -p ~/aegis/labs/otw-00 && cd ~/aegis/labs/otw-00

# Log every session so you can review what actually worked
{
  echo "=== Bandit 0-10 — $(date -Iseconds) ==="
} > 00-journal.txt

# Connect and work the levels
ssh bandit0@bandit.labs.overthewire.org -p 2220

On the box, keep a running notes file:

# on the Bandit machine
cat > ~/my-notes.txt <<'EOF'
# commands that worked

ls -la                          # reveal hidden files
find / -user X -readable 2>/dev/null
find . -type f -exec strings {} \;
cat ./-file                     # names starting with -
base64 -d file
sudo cat <unreadable>           # permission level
EOF
cat ~/my-notes.txt

When you finish levels 0-10, come back and build your cheat-sheet:

cd ~/aegis/labs/otw-00
cat > 01-patterns.md <<'EOF'
# Bandit 0-10 patterns

| Problem | Command |
|---|---|
| files are hidden | `ls -la` |
| file named `-x` | `cat ./-x` |
| filename unknown | `cat ./*readme*` |
| permission denied | `sudo cat` (understand why first) |
| file is binary | `strings FILE \| grep -i password` |
| find files by owner | `find / -user NAME -readable 2>/dev/null` |
| run cmd on results | `find . -type f -exec CMD {} \;` |
| data is encoded | `base64 -d FILE` |
EOF
cat 01-patterns.md | tee 01-patterns.txt

Record: 01-patterns.md. Every one of those patterns is used in real engagements daily.

Self-test

  1. Why does cat readme fail to find a file that ls -a shows?
  2. What does -rw-r----- permit for "others", and why does cat then fail?
  3. Why is strings the right tool for a binary, and cat the wrong one?
  4. What does find / -user X -readable 2>/dev/null do, and why redirect stderr?
  5. base64 is an encoding, not encryption — what does that mean practically when decoding?
