Memory Safety and Buffer Overflows

Summary

CS161's memory-safety block is the formal counterpart to MIT 6.858's Lab 1. Same bug class, but
presented as a language problem with a taxonomy, which is what makes the fix structural rather
than defensive.

Companion to mit858-04 and ex-01..ex-06. This note is the taxonomy and
the language argument; those are the exploitation mechanics.

The taxonomy

CS161 groups memory-safety bugs into five families. Knowing the list is most
of knowing what to look for.

Bug Definition Typical consequence
Buffer overflow Write/read outside a fixed-size buffer Overwrite adjacent memory
Integer overflow Arithmetic wraps past a type's bound Wrong size, wrong index, undersized allocation
Use after free Reference memory after it was released Dangling pointer, type confusion
Uninitialized memory Read memory never written Information disclosure
Type confusion Treat one type as another Arbitrary read/write via mismatched layout

They are not independent. Integer overflow causes most heap bugs: an
int size computation wraps, an allocation is too small, and the
subsequent write is an overflow.

C specifics that create the bugs

char buf[32];
strcpy(buf, input);                 // unbounded: no size exists in the type
snprintf(buf, sizeof buf, ...);     // bounded: the compiler knows the size

int n = count * sizeof(struct x);    // count * 8 can overflow int
struct x *p = malloc(n);            // -> undersized allocation

free(p); use(p);                    // use-after-free

struct y z; printf("%s", z.s);      // uninitialized read: info leak

The root cause is that C's type system carries no size information. char *
is just an address. A bounds-checked type (char[32]) or a bounds-annotated
pointer is what makes the bug unrepresentable.

Why the mitigations are not enough

canary  -> detects the corruption, after the fact
NX      -> prevents execution, not the write
ASLR    -> makes addresses hard to guess
RELRO   -> protects one specific table

Each is a mitigation of a consequence. None removes the bug, because the
bug is still a bug. CS161's argument is that the only fix that eliminates the
class is a language where the bug cannot be expressed.

Memory-safe languages, honestly

Language Mechanism Residual C-interop risk
Java GC + bounds checks + type checks JNI, sun.misc.Unsafe
C# GC + bounds + no pointer arithmetic unsafe, P/Invoke
Go GC + bounds + no user pointers unsafe, cgo
Rust Ownership + borrowing, checked at compile time unsafe blocks, FFI
Python Reference counting + dynamic typing Everything in C underneath

None are safe by default when interoperating with C. Rust's unsafe and
Go's cgo are escape hatches that concentrate risk rather than removing it,
which is exactly the right design: the unsafe part is small and reviewable.

The bounded-type argument

The structural fix CS161 explores (and the lecture's baggy-bounds reading):

Instead of:  char *p            (size unknown)
Provide:     bounded_ptr<char, 32>
             - carries its bound
             - the compiler requires the bound to be provable at every use
             - the hardware checks it on every access

Now an out-of-bounds access is detected precisely, not probabilistically.
The cost is memory and code size. The benefit is the whole class goes away
for any code that uses the type.

Terminology

Term Meaning
Memory safety No undefined behaviour from memory access
Buffer overflow Access outside a fixed-size buffer
Integer overflow Arithmetic wrapping past a type's bound
Use-after-free Access to released memory
Uninitialized read Reading memory never written
Type confusion One type interpreted as another
Garbage collection Automatic reclamation; removes use-after-free
Ownership Rust's compile-time lifetime discipline
Bounded type A type that carries its own bounds
Undefined behaviour Anything the standard does not specify
Sanitiser Runtime or compile-time detector

Kali commands

# --- find the bugs, don't read for them ---
command -v cppcheck clang gcc
cppcheck --enable=all --inconclusive target.c 2>&1 | head -15

# --- sanitizers are the highest-value tool in this lecture ---
# AddressSanitizer: finds OOB, UAF, leaks, with the exact source line
gcc -g -O0 -fsanitize=address,undefined target.c -o target-asan
ASAN_OPTIONS=detect_leaks=1 ./target-asan "AAAA"

# UndefinedBehaviorSanitizer: integer overflow, misaligned access
gcc -g -O0 -fsanitize=undefined target.c -o target-ubsan
./target-ubsan

# GCC's own warnings for the classic patterns
gcc -Wall -Wextra -Wformat-security -Wstringop-overflow \
    -Warray-bounds=2 -Wnull-dereference -g -c target.c -o /dev/null 2>&1 | head -15

# --- the integer overflow, demonstrated ---
cat > intovf.c <<'EOF'
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
struct rec { char name[8]; int value; };
int main(int argc, char **argv) {
    int count = argc + 2147483640;          /* wraps to a small/negative number */
    printf("  count = %d\n", count);
    size_t n = (size_t)count * sizeof(struct rec);
    printf("  allocation size = %zu\n", n);
    struct rec *p = malloc(n);
    if (!p) { printf("  malloc refused\n"); return 1; }
    strcpy(p[0].name, "AAAAAAAAAAAAAAAAAAAA");   /* overflows the block */
    printf("  wrote past the allocation\n");
    return 0;
}
EOF
gcc -g -O0 -fsanitize=address intovf.c -o intovf 2>/dev/null && ./intovf 2>&1 | head -8
rm -f intovf.c intovf

# --- hardening flags, for when you must ship C ---
{
  echo "=== the flags that make a C binary harder to exploit ==="
  for flags in "-g -O0" \
               "-g -O0 -fstack-protector-strong" \
               "-g -O0 -fstack-protector-strong -pie -fPIE" \
               "-g -O2 -fstack-protector-strong -D_FORTIFY_SOURCE=2 -pie -fPIE -Wformat -Werror=format-security" \
               "-g -O2 -fstack-protector-all -pie -fPIE -Wl,-z,relro,-z,now -fcf-protection=full -mshstk"; do
    printf "  %-30s " "$(echo $flags | cut -c1-28)"
    gcc $flags target.c -o /tmp/h 2>/dev/null && \
      checksec --file=/tmp/h 2>/dev/null | grep -cE "found|full|enabled" | xargs printf "%s protections\n" || echo "did not compile"
  done
  rm -f /tmp/h
}

# --- valgrind, when you cannot use a sanitiser ---
valgrind --leak-check=full --track-origins=yes ./target 2>&1 | head -12

Field lab

Objective: find every memory-safety bug class in a deliberately buggy program, using tools
rather than reading.

mkdir -p ~/aegis/labs/cs161-03 && cd ~/aegis/labs/cs161-03

cat > buggy.c <<'EOF'
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct node { struct node *next; int value; };

void b_overflow(const char *in) {
    char buf[16];
    strcpy(buf, in);                       /* 1. buffer overflow */
}

int b_intoverflow(int n) {
    int total = n * 100;                   /* 2. integer overflow */
    int *p = malloc(total * sizeof(int));
    for (int i = 0; i < total; i++) p[i] = i;
    free(p);
    return total;
}

void b_uaf(void) {
    struct node *a = malloc(sizeof(struct node));
    a->value = 42;
    free(a);
    printf("%d\n", a->value);              /* 3. use after free */
}

void b_uninit(void) {
    int secret[4];
    printf("%d\n", secret[0]);             /* 4. uninitialized read */
}

void b_typeconfusion(void *p) {
    printf("%d\n", *(int *)p);             /* 5. type confusion */
}

int main(int argc, char **argv) {
    int which = argc > 1 ? atoi(argv[1]) : 0;
    switch (which) {
        case 1: b_overflow("AAAAAAAAAAAAAAAA"); break;
        case 2: printf("%d\n", b_intoverflow(100000)); break;
        case 3: b_uaf(); break;
        case 4: b_uninit(); break;
        case 5: { int x = 7; b_typeconfusion(&x); } break;
    }
    return 0;
}
EOF

# --- 1. static analysis finds them without running anything ---
echo "=== cppcheck ==="
cppcheck --enable=warning,style,security,performance buggy.c 2>&1 | head -20 | tee 01-cppcheck.txt

# --- 2. AddressSanitizer finds them at runtime, with the exact line ---
echo
echo "=== AddressSanitizer ==="
gcc -g -O0 -fsanitize=address,undefined buggy.c -o buggy-asan 2>/dev/null
for n in 1 2 3 4 5; do
  echo "  --- trigger $n ---"
  ASAN_OPTIONS=detect_leaks=1 ./buggy-asan $n 2>&1 | grep -E "ERROR|SUMMARY|runtime error|#1 " | head -3 | sed 's/^/    /'
done | tee 02-asan.txt

# --- 3. the integer overflow, isolated ---
cat > intovf.c <<'EOF'
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv) {
    int count = 100000 * 100;          /* 10,000,000 - fits */
    int bad  = argc + 2147483640;      /* wraps on overflow */
    printf("  good count  = %d  -> bytes = %lld\n", count, (long long)count * 4);
    printf("  wrapped     = %d  -> bytes = %lld\n", bad, (long long)bad * 4);
    printf("  size_t value= %zu  (the cast happens AFTER the overflow)\n",
           (size_t)(bad * 4));
    return 0;
}
EOF
gcc -g -O0 -fsanitize=undefined intovf.c -o intovf 2>/dev/null
./intovf 2>&1 | sed 's/^/  /' | tee 03-intov.txt
rm -f intovf.c intovf

# --- 4. the compiler's own warnings ---
echo
echo "=== gcc warnings on the same file ==="
gcc -Wall -Wextra -Wformat-security -Wstringop-overflow -Warray-bounds=2 \
    -Wnull-dereference -g -c buggy.c -o /dev/null 2>&1 | head -20 | tee 04-gcc-warn.txt

# --- 5. valgrind, for the case where you cannot rebuild ---
if command -v valgrind >/dev/null; then
  echo
  echo "=== valgrind ==="
  gcc -g -O0 buggy.c -o buggy 2>/dev/null
  for n in 3 4; do
    echo "  --- trigger $n ---"
    valgrind --leak-check=full --track-origins=yes ./buggy $n 2>&1 \
      | grep -E "Invalid|uninitialised|definitely lost|at 0x" | head -4 | sed 's/^/    /'
  done | tee 05-valgrind.txt
else
  echo "  valgrind not installed: sudo apt install valgrind" | tee 05-valgrind.txt
fi

# --- 6. the hardening ladder ---
echo
echo "=== what the compiler can do for you ==="
{
  echo "  These are not substitutes for fixing the bug. They change what an"
  echo "  attacker can do once it has one."
  echo
  printf "  %-58s %s\n" "FLAG" "EFFECT"
  printf "  %-58s %s\n" "-----" "------"
  printf "  %-58s %s\n" "-Wall -Wextra" "catch the obvious"
  printf "  %-58s %s\n" "-Wformat-security" "format string bugs"
  printf "  %-58s %s\n" "-Wstringop-overflow" "strcpy overflows at compile time"
  printf "  %-58s %s\n" "-fstack-protector-strong" "canary on vulnerable functions"
  printf "  %-58s %s\n" "-D_FORTIFY_SOURCE=2" "bounds-check str/mem functions"
  printf "  %-58s %s\n" "-fPIE -pie" "randomised binary base"
  printf "  %-58s %s\n" "-Wl,-z,relro,-z,now" "read-only GOT"
  printf "  %-58s %s\n" "-fcf-protection=full -mshstk" "shadow stack"
} | tee 06-ladder.txt

# --- 7. the structural argument ---
cat > 07-structural.md <<'EOF'
# The structural argument

You cannot compile your way out of a memory-safety bug. You can only make it
more expensive to exploit.

```text
  fix the bug            -> the only real fix
  bounds-checked types   -> makes a whole bug class unrepresentable
  sanitiser in dev/CI    -> catches the bug at the moment it is written
  canary + NX + ASLR     -> raises the cost after the bug already exists

Use all four, in that order of importance. The last one is what everyone
remembers and the one that matters least.

The review question

Every C function you write should be answerable for:
1. What untrusted data reaches it?
2. What bounds does every access respect?
3. What happens when an allocation fails?
4. Who frees this, and exactly once?

If you cannot answer all four, the function is a finding waiting for a fuzzer.
EOF
cat 07-structural.md
```
