Bandit Levels 30-39: SSH keys, shadow permissions, md5/base32/hex, deeper enumeration

Summary

Levels 30-39 combine everything so far — SSH keys, hash identification, unusual encodings, binary
searching, and harder file searches. These are the levels where Bandit stops being a tutorial and
starts being useful preparation for real work.

Level notes

Level 30 — a password that needs correct file permissions.

ls -la
ssh-keygen -y -f /home/bandit30/.ssh/id_rsa > /tmp/pub
# the mode on the private key matters
chmod 600 /home/bandit30/.ssh/id_rsa
ssh bandit30@localhost -i /home/bandit30/.ssh/id_rsa -p 2220

If you cannot read the key, check its mode and owner before assuming you are stuck.

Level 31 — a base32-encoded password.

cat /etc/shadow | grep bandit31
file bandit31
xxd bandit31                       # recognise the encoding
base32 -d bandit31

-x in base32/base64/xxd means "decode". Learn these three; they appear constantly in
CTFs.

Level 32 — md5 is the hash algorithm here.

find . -type f -exec md5sum {} \; | grep -i bandit32
# identify it properly, then crack
hashid hash.txt
john --wordlist=/usr/share/wordlists/rockyou.txt --show hash.txt
# md5sum -c verifies a checksum, a useful IR habit
md5sum /etc/passwd

hashid before john saves real time — John needs the right format flag for each algorithm.

Level 33 — sshd_config and a writable config.

grep -n "PasswordAuthentication\|PermitRootLogin\|AllowUsers" /etc/ssh/sshd_config
ls -la /etc/ssh/sshd_config
file /etc/ssh/sshd_configd
cat /etc/ssh/sshd_configd/sshd_config

Reading sshd_config is standard enumeration on any Linux server — it tells you whether password
auth is on, whether root login is permitted, and which users may connect.

Level 34 — permissions on a directory nobody can enter.

ls -la /opt
ls -lad /opt/*
# /opt/level34 is d--------- : nobody, including you, can traverse it
sudo ls -la /opt/level34

sudo works in the Bandit environment. In a real engagement, this is the moment you realise
whether your compromised account has any sudo rights at all.

Level 35 — nginx config and a hash in it.

find / -name "nginx.conf" -o -name "*.conf" 2>/dev/null | head
cat /etc/nginx/nginx.conf
nginx -T                        # dump the FULL effective config, including includes
grep -rn "password\|hash" /etc/nginx/
hashid hash.txt && john --show hash.txt

nginx -T / apachectl -S / httpd -t -D DUMP dump the effective config — far more useful
than reading a single file, because it resolves every include.

Level 36 — a base64 blob in a script plus a running service.

ls -la
cat /opt/level36/*
base64 -d payload | bash
xxd payload | head
grep -n "eval\|exec\|system" *.sh      # look for command injection points

grep -n "eval\|exec\|system" *.sh is a one-second audit for the most common script
vulnerability class: passing untrusted input to a shell.

Level 37 — a script that decrypts something.

ls -la
cat level37.sh
xxd bandit37.payload | head
base64 -d bandit37.payload | ...
# read the script properly, then follow what it does

Read the script. A decryption script tells you the algorithm by name — and often the key is
derived from the next level's password, so you solve them in order.

Level 38 — a readable SSH key owned by root.

ls -la /root
ssh-keygen -y -f /root/.ssh/id_rsa
ssh bandit38@localhost -i /root/.ssh/id_rsa

/root is normally drwx------; finding yourself able to read it is the finding.

Level 39 — the final push.

ls -la
cat /opt/level39/level39.py
sed -n '1,40p' /opt/level39/level39.py

Read the source before trying anything. This is the habit Bandit 30-39 is really teaching:
the answer is in the code, not in brute force.

Terminology

Term Meaning
base32 / base64 / hex Encodings; -d or -r decodes
md5sum -c Verify a file against a recorded checksum
hashid Identify a hash algorithm from its format
nginx -T Dump the full effective configuration
sshd_config SSH server configuration; a standard enumeration target
Permission traversal Directory mode d----- blocking all access
xxd Hex dump — the CTF's most-used command
sed -n '1,40p' Print a line range from a script

Kali commands

# --- encodings, the full set ---
base32 -d file; base32 file
base64 -d file; base64 -w0 file
xxd file | head; xxd -r -p file          # hex encode / decode
od -An -tx1z file
echo "SGVsbG8=" | base64 -d

# --- identify and crack a hash ---
hashid hash.txt
hashid --identify hash.txt
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
john --show hash.txt
hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt   # 0 = MD5

# --- sshd enumeration ---
grep -rn "PasswordAuthentication\|PermitRootLogin\|AllowUsers\|Port" /etc/ssh/
sshd -T                       # effective sshd config
nginx -T 2>/dev/null | head -40
apachectl -S 2>/dev/null | head

# --- a one-second script audit ---
grep -rn "eval\|exec\|system\|popen\|os.system\|shell=True" /opt /srv 2>/dev/null | head

# --- permissions, decoded ---
ls -lad /opt/level34 /root /etc/shadow
namei -l /etc/shadow          # walk the whole path, component by component

Field lab

Objective: clear levels 30-39 and build your final "credential hunting" reference.

mkdir -p ~/aegis/labs/otw-03 && cd ~/aegis/labs/otw-03

ssh bandit30@bandit.labs.overthewire.org -p 2220

On the box:

cat >> ~/my-notes.txt <<'EOF'

## 30-39: decoding and config enumeration
base32 -d f        xxd f | head          xxd -r -p f
hashid h.txt      john --show h.txt     hashcat -m 0 h
nginx -T           sshd -T
grep -rn "eval\|exec\|system" *.sh
namei -l /etc/shadow        # why can't I read it?
EOF
cat ~/my-notes.txt

Back on Kali, assemble the complete hunting reference:

cd ~/aegis/labs/otw-03
cat > 01-credential-hunting.md <<'EOF'
# Credential hunting reference

## Encoding
| Task | Command |
|---|---|
| base32 decode | `base32 -d FILE` |
| base64 decode | `base64 -d FILE` |
| hex dump | `xxd FILE \| head` |
| hex decode | `xxd -r -p FILE` |
| from scratch | `od -An -tx1z FILE` |

## Hashes
| Task | Command |
|---|---|
| identify | `hashid HASH` |
| crack (john) | `john --wordlist=/usr/share/wordlists/rockyou.txt --show HASH` |
| crack (hashcat) | `hashcat -m <mode> HASH rockyou.txt` |
| verify | `md5sum FILE` / `sha256sum FILE` |

## Configs
| Task | Command |
|---|---|
| effective sshd | `sshd -T` |
| effective nginx | `nginx -T` |
| ssh settings | `grep -rn "PermitRootLogin\\|PasswordAuth" /etc/ssh/` |
| apache vhosts | `apachectl -S` |

## Search
| Task | Command |
|---|---|
| why unreadable | `namei -l /path` |
| script audit | `grep -rn "eval\|exec\|system\|shell=True" DIR` |
| by owner | `find / -user NAME -readable 2>/dev/null` |
| by mtime | `find / -mmin -60 -type f 2>/dev/null` |
EOF
cat 01-credential-hunting.md | tee 01-credential-hunting.txt

# --- exercise it against your own machine, read-only ---
{
  echo "=== effective sshd configuration (your own box) ==="
  sudo sshd -T 2>/dev/null | grep -E "^(port|permitrootlogin|passwordauthentication|pubkeyauthentication)" \
    || grep -rn "PermitRootLogin\|PasswordAuthentication" /etc/ssh/sshd_config
  echo
  echo "=== why is /etc/shadow unreadable? ==="
  ls -l /etc/shadow
  namei -l /etc/shadow
} | tee 02-own-box.txt

namei -l /etc/shadow is the answer to a question you will be asked constantly: "why can't I
read this?" It walks every component of the path and shows the permission on each.

Record: 01-credential-hunting.md. Keep it. Tier 4 and Tier 6 both depend on it.

Self-test

  1. How do you distinguish base32, base64 and hex data at a glance?
  2. Why identify a hash with hashid before cracking it?
  3. What does nginx -T give you that reading one config file does not?
  4. What does namei -l /path/to/file tell you, and when do you need it?
  5. Why is grep -rn "eval\|exec\|system" *.sh a sensible first check on an unknown script?
