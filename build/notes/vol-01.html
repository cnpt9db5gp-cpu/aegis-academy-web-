Installing Volatility 3 on Kali

Summary

Volatility 3 is a Python framework for memory forensics. Installing it correctly on Kali is
mostly about three things: isolating it from the system Python, getting a symbol table,
and knowing which image formats it reads.

The framing that saves the most time: 80% of Volatility failures are
the symbol table. When a plugin errors with something about
symbols, that is the whole problem, and no amount of reinstalling
fixes it.

Why it is not on Kali by default

  Kali ships vol.py for Volatility 2, which is Python 2 only and
  unmaintained. Volatility 3 is Python 3 and is a separate install.

  Installing it into the system Python risks breaking other Kali
  tools that pin dependencies. So: pipx (isolated) or a venv.

    pipx install volatility3       -> ~/.local/bin/vol.py
    python3 -m venv ~/.venvs/vol3  -> your own, fully controlled

  pipx is the default recommendation. If it breaks, nothing else does.

The install, and the two things that actually matter

{
  echo "=== current state ==="
  command -v vol.py >/dev/null 2>&1 && vol.py --version 2>/dev/null | sed 's/^/  /' \
    || echo "  vol.py not installed"
  python3 -c "import volatility3; print('  module:', volatility3.__file__)" 2>/dev/null \
    || echo "  volatility3 module not present"
  echo "  Kali's python: $(python3 --version 2>&1)"
  echo
  echo "=== install via pipx (isolated; recommended) ==="
  echo "  pipx install volatility3"
  echo "  then: vol.py --version"
  echo
  echo "=== or a venv, if you want full control ==="
  echo "  python3 -m venv ~/.venvs/vol3"
  echo "  source ~/.venvs/vol3/bin/activate"
  echo "  pip install volatility3"
  echo
  echo "=== the two things that actually matter after install ==="
  echo
  echo "  1. THE SYMBOL TABLE. Volatility 3 needs a PDB GUID -> symbol"
  echo "     map, built from a Microsoft symbol server. No symbols ="
  echo "     every plugin fails. This is 80% of 'Volatility is broken'."
  echo
  echo "  2. THE RIGHT IMAGE FORMAT. Volatility 3 reads raw physical"
  echo "     memory, LiME, EWF (EWF-E01), and a few others. It does NOT"
  echo "     read disk images directly; you must run it against a memory"
  echo "     capture, not against a .dd of a disk."
} 2>&1 | tee 01-install.txt

The symbol table, in detail

# --- 2. the symbol table, which is the real content of this note ---
cat > 02-symbols.md <<'MD'
# Symbols: why Volatility 3 fails and how to fix it

```text
  WHAT A SYMBOL TABLE IS

    A Windows kernel contains references to debug symbols by GUID and
    age. To turn those into function names, Volatility needs a map
    from (PDB GUID, age) -> a downloaded .pdb file.

    Microsoft publishes PDBs on symbol servers. Volatility downloads
    the ones it needs, caches them, and uses them to build the map.

    NO NETWORK = NO NEW SYMBOLS = NO PLUGIN WORKS.

  THE FAILURE, and it looks like this:

    ERROR: symbol cache directory not found
    or:  Unsatisfied requirement plugins.WindowsPslist.Pslist: symbol
         cache directory not found
    or:  ValueError: PDB GUID 1234abcd-... not found in cache

  All three are the same problem.

  THE FIX, in order:
    1. run it ONCE on a networked machine, so the cache populates
    2. copy the cache directory to the analysis machine
    3. point --cache-path at the copy

  THE CACHE LOCATION:
    Linux   ~/.cache/volatility3/
    Windows %APPDATA%\volatility3\

  BUILDING IT (needs network, once):
    vol.py --cache-path ~/.cache/volatility3/ windows.info -f image.raw
       ^ this one plugin builds most of the cache as a side effect
    vol.py windows.pslist -f image.raw
       ^ and it adds the kernel's symbols

  IF THE KERNEL IS VERY NEW:
    symbols may not be published yet. Options:
      - wait (a new hotfix can take hours to a day)
      - point at an alternative symbol server:
          --symbols https://msdl.microsoft.com/download/symbols
      - accept that this particular plugin will not work and use
        others that do not need those symbols
MD

# --- the cache, and checking it ---
cat > 03-cache.sh <<'EOF'
#!/usr/bin/env bash
VOL="${VOL:-vol.py}"
CACHE="${VOLCACHE:-$HOME/.cache/volatility3}"
echo "=== the symbol cache ==="
echo "  path: $CACHE"
if [ -d "$CACHE" ]; then
  echo "  size: $(du -sh "$CACHE" 2>/dev/null | cut -f1)"
  echo "  files: $(find "$CACHE" -type f 2>/dev/null | wc -l)"
  echo
  echo "  a cache with a handful of files means the population failed."
  echo "  a cache with thousands means it worked."
  ls "$CACHE" 2>/dev/null | head -10 | sed 's/^/    /'
else
  echo "  NOT PRESENT. Populate it on a networked machine with:"
  echo "    vol.py --cache-path $CACHE windows.info -f <image>"
fi
echo
echo "=== the plugin list (what you can actually run) ==="
$VOL -h 2>&1 | grep -E "^\s+(windows|linux|mac|banners)\." | head -20 | sed 's/^/  /'
echo
echo "=== the config, which is where the defaults live ==="
$VOL -h 2>&1 | grep -A20 "^\s*--\?\(cache\|symbols\|config\)" | head -25 | sed 's/^/  /'
EOF
chmod +x 03-cache.sh
./03-cache.sh 2>&1 | tee 04-cache-check.txt

Image formats

# --- 3. what Volatility will accept ---
{
  echo "=== formats Volatility 3 reads ==="
  cat <<'FORMATS'
    raw      a flat physical memory image. The default and the safest.
             A Windows crash dump is NOT raw; it needs a converter.

    lime     LiME output (the Linux Memory Extractor format).
             format=lime in LiME, or 'lime' as the filename suffix.

    ewf      Expert Witness Format (.E01, .Ex01). What FTK Imager,
             Magnet, and Guymager produce. This is what you will
             usually have from a commercial acquisition tool.

    compressed  Volatility 3 can read xz and gzip-compressed images.

    NOT SUPPORTED: disk images (use TSK), VMDK/VHD directly
      (convert first), and most virtual machine snapshots.
FORMATS
  echo
  echo "=== converting between them ==="
  echo "  ewf -> raw:   ewfverify image.E01 && export EWF=/path/to/image.E01"
  echo "                vol.py windows.info -f image.E01      (vol3 reads EWF natively)"
  echo "  vmdk -> raw:  qemu-img convert -f vmdk -O raw disk.vmdk mem.raw"
  echo "  crash dump:   vol.py -f crash.dmp   (often works; if not, the"
  echo "                'Offset' parameter or a converter is needed)"
  echo
  echo "=== the 'what image is this' check ==="
  file memory.raw memory.E01 crash.dmp 2>/dev/null | sed 's/^/  /'
  echo "  A raw image is 'data'. An EWF says 'EWF' or 'Zip archive'."
  echo "  A crash dump says 'MS Windows memory dump' or 'crash dump'."
} 2>&1 | tee 05-formats.txt

The first run, and what to do when it fails

# --- 4. a diagnostic script ---
cat > 06-diag.sh <<'EOF'
#!/usr/bin/env bash
# Why is Volatility failing? Check these in order.
VOL="${VOL:-vol.py}"
IMG="${1:-}"
CACHE="${VOLCACHE:-$HOME/.cache/volatility3}"

echo "=== 1. is it installed? ==="
command -v "$VOL" >/dev/null 2>&1 && echo "  yes: $VOL" || { echo "  NO"; exit 1; }
$VOL --version 2>&1 | head -1 | sed 's/^/  /'

echo
echo "=== 2. is the image readable? ==="
[ -f "$IMG" ] && echo "  $IMG ($(du -h "$IMG" | cut -f1))" || echo "  NO IMAGE SPECIFIED"
file "$IMG" 2>/dev/null | sed 's/^/  /'
echo "  ^ if this is 'disk partition' it is a DISK image. Volatility"
echo "    does not read disks. You need a memory capture."

echo
echo "=== 3. is the symbol cache populated? ==="
if [ -d "$CACHE" ] && [ "$(find "$CACHE" -type f 2>/dev/null | wc -l)" -gt 100 ]; then
  echo "  yes: $(find "$CACHE" -type f | wc -l) files, $(du -sh "$CACHE" | cut -f1)"
else
  echo "  EMPTY or MISSING. This is the most common cause of failure."
  echo "  Populate it on a networked machine:"
  echo "    $VOL --cache-path $CACHE windows.info -f <some-image>"
fi

echo
echo "=== 4. network (needed only for the FIRST population) ==="
timeout 5 curl -sI https://msdl.microsoft.com >/dev/null 2>&1 \
  && echo "  symbol server reachable" \
  || echo "  NOT reachable. Fine IF the cache is populated."

echo
echo "=== 5. RAM, which people forget ==="
free -h | awk 'NR==2{print "  total: " $2 "  available: " $7}'
echo "  ^ Volatility indexes the image. A 32 GB image wants 32 GB+"
echo "    of RAM. If you have less, the fix is a bigger machine or"
echo "    narrower plugin selection, not patience."

echo
echo "=== 6. try the simplest possible plugin ==="
if [ -f "$IMG" ]; then
  timeout 120 "$VOL" --cache-path "$CACHE" windows.info -f "$IMG" 2>&1 \
    | head -12 | sed 's/^/  /'
  echo
  echo "  if windows.info works, the install is fine and the problem"
  echo "  is the specific plugin or its symbols."
fi
EOF
chmod +x 06-diag.sh
./06-diag.sh 2>&1 | tee 07-diag.txt

Making your own memory image, to practise

# --- 5. a memory image from THIS machine, without a VM ---
cat > 08-make-image.md <<'MD'
# Making a practice memory image

You do not need a VM to practise Volatility. On Linux you can build
a synthetic image with the right structures, and for real practice
you can capture a VM's memory with LiME.

```bash
# IN A LINUX VM (LiME is the kernel module)
# build it:
  sudo apt install linux-headers-$(uname -r)
  git clone https://github.com/504ensicsLabs/LiME /tmp/lime
  cd /tmp/lime/src && make
# capture:
  sudo insmod lime.ko "path=/tmp/mem.lime format=lime compress=0"
# clean up:
  sudo rmmod lime
# then analyse the .lime file with Volatility on any machine
  vol.py linux.pslist -f /tmp/mem.lime

# WHY A VM FOR PRACTICE:
  a Linux image gives you linux.* plugins, which is a smaller set and
  easier to verify. The windows.* plugins are the ones you need for
  an AD environment, and they need a Windows image. CyberDefenders
  (cd-03) provides free memory dumps of real Windows systems, which
  is the correct way to build Windows-specific muscle memory.

# VOLATILITY ON A LINUX HOST ANALYSING A WINDOWS IMAGE IS FINE.
# Volatility analyses an IMAGE. The host it runs on is irrelevant,
# which is exactly why it belongs on a Linux analysis box.
```

```bash
# verifying an image you have been given, before you trust it
sha256sum memory.raw
file memory.raw
# a raw memory image has no magic number; it is 'data'. That is correct.
# The check is the size (roughly the installed RAM) and the fact that
# windows.info parses it at all.
```
