VLANs, Trunking and Inter-VLAN Routing

Summary

VLANs split one physical switch into multiple logical Layer 2 broadcast domains. They are the
control that makes segmentation real — and VLAN hopping is the attack that shows what it is worth.

Key ideas

  • A VLAN is a Layer 2 broadcast domain; the tag lives in an 802.1Q frame header
  • Ports are access (untagged, one VLAN) or trunk (tagged, multiple VLANs)
  • Inter-VLAN traffic requires a router or Layer 3 switch — this is enforced, not convention
  • Native VLAN carries untagged traffic on a trunk; a mismatch is a real misconfiguration
  • Double tagging abuses how a switch handles a frame tagged with the native VLAN
  • Management access (ssh, telnet) to a switch is itself the crown jewel

Terminology

Term Meaning
VLAN Virtual LAN; a Layer 2 broadcast domain
Access port One untagged VLAN for an endpoint
Trunk port Carries several VLANs, 802.1Q tagged
802.1Q tag 4-byte VLAN header: PCP, DEI, VID
Native VLAN VLAN for untagged frames on a trunk
VLAN hopping Reaching another VLAN without routing
Double tagging VLAN hopping using nested tags
Inter-VLAN routing Layer 3 forwarding between VLANs
Management VLAN The network your switch admin interface lives on

Kali commands

# --- is this host in a VLAN? ---
ip -d link show | grep -B1 -A1 vlan
cat /proc/net/vlan/config 2>/dev/null
ls /sys/class/net/*/bridge/ 2>/dev/null | head

# --- create a VLAN interface on Linux (root) ---
ip link add link eth0 name eth0.42 type vlan id 42
ip addr add 192.168.42.5/24 dev eth0.42
ip link set eth0.42 up
ip -d link show eth0.42
ip link del eth0.42          # clean up

# --- 802.1Q module ---
lsmod | grep 8021q
modinfo 8021q 2>/dev/null | head -3

# --- bridging ---
ip link add name br0 type bridge 2>/dev/null && ip link del br0
bridge link show 2>/dev/null
ip -d link show type bridge

# --- see tags on the wire ---
sudo tcpdump -i any -n -e "vlan" 2>/dev/null | head -10
sudo tcpdump -i any -n -e -XX 2>/dev/null | grep -i "vlan" | head -5

Field lab

Objective: create a VLAN, prove the tag exists on the wire, and understand double tagging.

mkdir -p ~/aegis/labs/ccna-05 && cd ~/aegis/labs/ccna-05

# --- 1. if this host has a second interface, build a real VLAN ---
# Use vboxnet0 if the lab is up; otherwise this section is informational.
if ip -br addr show vboxnet0 >/dev/null 2>&1; then
  sudo ip link add link vboxnet0 name vboxnet0.42 type vlan id 42
  sudo ip addr add 192.168.42.5/24 dev vboxnet0.42
  sudo ip link set vboxnet0.42 up
  {
    echo "=== VLAN interface created ==="
    ip -d link show vboxnet0.42
    echo
    echo "=== its address ==="
    ip -br addr show vboxnet0.42
    echo
    echo "=== routing consequences ==="
    ip route get 192.168.42.1
  } 2>&1 | tee 01-vlan.txt
  sudo ip link del vboxnet0.42
  echo "cleaned up"
else
  echo "No vboxnet0. Build the lab first (docs/LAB-SETUP.md) to create real VLANs." | tee 01-vlan.txt
fi

# --- 2. watch the 802.1Q tag on the wire ---
echo
echo "=== in two terminals, with a VLAN interface up ==="
echo "  T1: sudo tcpdump -i vboxnet0 -n -e vlan"
echo "  T2: ping 192.168.42.1"
echo
echo "You will see the VLAN tag in the Ethernet header. 4 bytes, PCP in the top 3 bits."
echo "The frame looks like: [dst 6][src 6][0x8100][pcp/dei/vid 2][real type 2][payload]"

# --- 3. what a VLAN id actually is ---
python3 - <<'PY' | tee 02-tag.txt
import struct
# build an 802.1Q tag by hand: 0x8100 TCI
for vid in [1, 10, 42, 100, 4094]:
    tci = vid & 0x0FFF                       # VLAN id in the low 12 bits
    frame = b"\xff\xff\xff\xff\xff\xff" + b"\x00\x11\x22\x33\x44\x55" \
            + b"\x81\x00" + struct.pack(">H", tci) + b"\x08\x00" + b"payload"
    print(f"  vid={vid:<6} tag bytes = {frame[12:16].hex()}  full frame = {frame.hex()}")
print()
print("  Only 12 bits of VLAN id exist (1-4094). PCP takes 3 bits, DEI 1 bit.")
PY

# --- 4. THE ATTACK, explained (do not run this against anything but your own lab) ---
cat > 03-double-tagging.md <<'EOF'
# Double tagging, in full

## Setup
- VLAN 10 = native VLAN on the trunk, untagged
- VLAN 20 = the target segment
- You are on VLAN 10 (the native VLAN)

## Why it works
1. You send a frame tagged VLAN **20**, containing a frame tagged VLAN **10**.
2. The first switch sees the outer tag (20), strips it, and forwards on VLAN 20...
3. ...but the native-VLAN logic means it processes the *inner* frame first.
4. The second switch strips the remaining tag (10), leaving a normal untagged frame
5. The frame lands on VLAN 20. You have routed yourself there with no router involved.

## Why the fix is not "use passwords"
- Patch the switch firmware / use mitigation: change the native VLAN away from the one you
  occupy, or disable native VLAN tagging entirely.

## Why this still matters
- VLANs are an administrative control, not a security boundary you can rely on alone.
- The lesson generalises: a control that depends on correct configuration everywhere is not
  a control.
EOF
cat 03-double-tagging.md

# --- 5. the security lesson, written out ---
cat > 04-lessons.md <<'EOF'
# VLAN security lessons

- Inter-VLAN routing is the real control. VLANs alone are convenience.
- The native VLAN is the dangerous one: it is implicitly trusted on every trunk.
- Any frame that crosses a trunk must be treated as attacker-controlled.
- A switch's own management interface is the highest-value target in the room.
- Segmentation that depends on configuration is only as strong as the configuration.
EOF
cat 04-lessons.md

Step 3 makes the tag concrete. 0x8100 followed by two bytes where the low 12 bits are the
VLAN id. You can decode any captured frame by hand now.
