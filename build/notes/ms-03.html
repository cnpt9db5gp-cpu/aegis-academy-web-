The Command Line Environment

Summary

This lecture covers the environment a command runs inside: which directories the shell searches
(PATH), which variables it exports, and how to make settings persist. Three tools dominate:
~/.bashrc, ~/.profile, and /etc/environment.

It sounds mundane. It is also where several real attack paths live — an attacker who can append
one line to your ~/.bashrc has persistence; a script that trusts $PATH can be hijacked; and
LD_PRELOAD turns any non-setuid program into your program.

PATH: the search order

When you type nmap, the shell checks each $PATH directory left to right, in order, and
runs the first match. Consequences:

echo $PATH | tr ':' '\n' | nl

# Which one wins if there are two?
type -a nmap

# Proof of concept: hijack a command with a directory earlier in PATH
mkdir -p /tmp/evil
printf '#!/bin/sh\necho "you just ran MY ls, not /bin/ls"\n' > /tmp/evil/ls
chmod +x /tmp/evil/ls
PATH=/tmp/evil:$PATH ls -la      # yes, that works, and it is a real technique

Defence: never put a writable directory early in PATH, and always invoke tools by absolute
path (/usr/bin/passwd, not passwd) in security-critical scripts. /usr/local/sbin and
/usr/local/bin are conventionally root-owned and safe to be early.

Shell variable scope

NAME="nwpcs"            # not exported: only this shell sees it
export NAME="nwpcs"     # exported: child processes see it
echo $NAME               # works either way in this shell
bash -c 'echo $NAME'    # empty: not exported

The three types that matter:

Type Syntax Scope
Shell variable X=1 current shell only
Environment variable export X=1 current shell + children
Local (function) local X=1 that function only

The startup files, precisely

File Read when For
/etc/profile login shells, all users system-wide environment
~/.profile login shells, you your env vars
~/.bashrc interactive non-login shells, you aliases, prompt, functions
/etc/bash.bashrc same, all users system-wide interactive config

The distinction bites: a login shell reads ~/.profile; a terminal you opened reads
~/.bashrc. Put an export in the wrong file and it appears not to work.

# Put this in ~/.bashrc
export EDITOR=vim
export HISTSIZE=10000        # default is usually 1000 - too small for recon
export HISTCONTROL=ignorebothspace   # do not record commands starting with a space
alias ll='ls -alhF'
alias net='ip -br addr; ip route'

$PATH, $?, and other things you will use constantly

ls /nonexistent; echo $?            # 2
true; echo $?                       # 0
nmap 127.0.0.1 2>/dev/null; echo $? # 0

echo $PWD $HOME $USER $UID $$ $PPID $RANDOM
ps -p $$ -o pid,comm               # $$ is this shell's PID

Privilege drop: sudo and environment loss

sudo does not preserve your environment by default. export TARGET=1.2.3.4 then
sudo nmap $TARGET will fail because $TARGET is gone. Three solutions, in order of preference:

sudo TARGET=1.2.3.4 nmap -sn $TARGET        # 1. pass it for one command (best)
sudo -E nmap -sn $TARGET                    # 2. preserve the whole environment (blunt)
sudoedit /etc/environment                   # 3. make it a system default (persistent)

The dangerous ones

# LD_PRELOAD injects a shared library into any program you launch.
# It does NOT work on setuid binaries - which is exactly the defence.
echo $LD_PRELOAD          # should be empty. If it is not, investigate immediately.

# HISTSIZE / HISTCONTROL matter for operational security
echo $HISTFILE            # if HOME is writable this is your problem
set +o history            # stop recording this shell's commands
unset HISTFILE            # hard stop

Kali commands

# --- PATH hygiene ---
echo $PATH | tr ':' '\n' | while read -r d; do
  [ -d "$d" ] && printf "%-40s %s\n" "$d" "$(stat -c '%A %U' "$d" 2>/dev/null)"
done

# find writable directories that are in your PATH (real finding, real risk)
IFS=: read -ra P <<< "$PATH"
for d in "${P[@]}"; do
  [ -d "$d" ] && [ -w "$d" ] && echo "WRITABLE AND IN PATH: $d ($(stat -c %U "$d"))"
done

# --- configuration ---
declare -p PATH HOME USER SHELL
set | grep -cE '^[A-Z_]+='     # how many variables are set
alias
type -a ls

# --- persistence files (what an attacker would target) ---
ls -la ~/.bashrc ~/.profile ~/.bash_profile ~/.zshrc 2>/dev/null
sudo cat /etc/environment
grep -rn "alias\|export" ~/.bashrc | tail -20

# --- start a clean shell, see what you inherited ---
env | sort > /tmp/env-before.txt
bash --noprofile --norc -c 'env | sort' > /tmp/env-clean.txt
diff /tmp/env-before.txt /tmp/env-clean.txt | head -20

Field lab

Objective: understand PATH resolution well enough to demonstrate a hijack, and audit your own
startup files as an attacker would.

mkdir -p ~/aegis/labs/ms-03 && cd ~/aegis/labs/ms-03

# --- 1. PATH resolution order ---
type -a ls nmap python3 2>&1 | tee 01-path-order.txt
echo $PATH | tr ':' '\n' | nl >> 01-path-order.txt

# --- 2. Demonstrate a PATH hijack (harmless, local) ---
mkdir -p hijack
cat > hijack/id <<'EOF'
#!/bin/sh
echo "[!] this is NOT /usr/bin/id"
exec /usr/bin/id "$@"
EOF
chmod +x hijack/id
echo "normal:";  /usr/bin/id -u
echo "hijacked:"; PATH="$PWD/hijack:$PATH" id -u
rm -rf hijack

# --- 3. Audit your PATH for writable directories ---
{
  echo "=== writable dirs in PATH (attack surface) ==="
  IFS=: read -ra P <<< "$PATH"
  for d in "${P[@]}"; do
    if [ -d "$d" ] && [ -w "$d" ]; then
      echo "WRITABLE: $d  owner=$(stat -c %U "$d")"
    fi
  done
  echo "(empty above = good)"
} | tee 02-path-audit.txt

# --- 4. Read your own startup files like an attacker ---
{
  echo "=== files that auto-execute for you ==="
  for f in ~/.bashrc ~/.profile ~/.bash_profile /etc/profile /etc/bash.bashrc /etc/environment; do
    [ -f "$f" ] && { echo "--- $f ---"; grep -vE '^\s*(#|$)' "$f" | tail -15; }
  done
} | tee 03-startup-files.txt

# --- 5. What does an attacker do here? Trace the persistence primitive ---
{
  echo "=== shell startup files, modification times ==="
  ls -la --time-style=long-iso ~/.bashrc ~/.profile 2>/dev/null
  echo
  echo "=== bash history, last 30 (what have I been doing on this box?) ==="
  tail -30 ~/.bash_history 2>/dev/null || echo "(history file absent - HISTFILE unset or cleared)"
} | tee 04-persistence-surface.txt

# --- 6. Environment hygiene check ---
{
  echo "LD_PRELOAD=${LD_PRELOAD:-<empty, good>}"
  echo "HISTFILE=${HISTFILE:-<unset, good>}"
  echo "PATH=${PATH}"
} | tee 05-env-hygiene.txt

# --- 7. Prove sudo drops your environment ---
export TARGET=127.0.0.1
sudo sh -c 'echo "TARGET inside sudo: ${TARGET:-<dropped>}"'
sudo TARGET=127.0.0.1 sh -c 'echo "TARGET passed explicitly: $TARGET"'

Read 04-persistence-surface.txt carefully. Those startup files are exactly what malware
modifies for persistence, and ~/.bashrc is the first place an attacker looks. You now know your
own machine's persistence surface — that knowledge is the whole defensive half of the course.

Record: whether any PATH directory is writable, and what your .bashrc currently contains.
