OS Organization and System Calls

Summary

A system call is the only way a user program asks the kernel to do something. This lecture
covers how the call is made, how the kernel finds the handler, and what happens to arguments on
the way across the boundary.

Security framing: a system call is a trust boundary crossing with arguments supplied by an
untrusted party. Every bug class you will meet later — argument validation failures, integer
overflow in a size argument, races on a shared fd — lives at this interface.

How a syscall happens

x86-64 Linux uses the syscall instruction:

// glibc wrapper (userspace)
long sys_write(int fd, const char *buf, size_t count) {
    long ret;
    __asm__ volatile ("syscall"
        : "=a"(ret) : "a"(1), "D"(fd), "S"(buf), "d"(count)
        : "rcx", "r11", "memory");
    return ret;
}

user space                          kernel space
-----------                         ------------
rdi = fd                            ┌─ validate rdi is a real open descriptor
rsi = buffer                        ├─ validate rsi points to readable memory
rdx = length                        ├─ validate rdx (and check for overflow)
                                     ├─ do the work
syscall                             └─ return value in rax, error as negative errno
  │                                        │
  └──────── rax = 1 (bytes written) ───────┘

Registers carrying arguments: rdi, rsi, rdx, r10, r8, r9 (System V ABI).
rax holds the syscall number going in, and the return value coming out.

The dispatch mechanism

  1. syscall traps to the kernel
  2. The CPU saves registers and enters the kernel
  3. The kernel reads the syscall number from rax
  4. Looks it up in the syscall table — an array of function pointers
  5. Calls the handler with the arguments already in registers
  6. Returns to user space

The syscall table is a security object. A rootkit that hooks it can make every program on the
system lie about what files exist or what a syscall did. That is why strace is considered a
relatively safe analysis technique: it observes the same interface the kernel uses, rather than
faking the kernel's view.

strace is this lecture, runnable

strace -e trace=write ./program
strace -f -e trace=network curl https://example.com
strace -e trace=execve -f /bin/ls
strace -c ./program           # summary counts, grouped

strace -c ls showing thousands of openat calls is the clearest possible illustration of how
much crossing happens per second.

System call design rules

  1. Validate every argument. Pointer, length, and descriptor.
  2. Check for overflow on any length arithmetic: a + b can wrap.
  3. Copy user data into kernel memory rather than trusting the pointer directly.
  4. Never dereference a user pointer that has not been proven to point at user memory.
  5. Return errors, do not crash. A null dereference in the kernel is a full system compromise.

In xv6

Each system call is a function in kernel/syscall.c. The table is explicit, which makes the
whole mechanism readable in about 100 lines. Reading it is the best exercise in this lecture.

Terminology

Term Meaning
System call The user→kernel entry point
Syscall number Index identifying which handler
Syscall table Array of kernel function pointers
errno Negative error code convention
Trap Synchronous transfer of control into the kernel
Argument register rdi, rsi, rdx, r10, r8, r9
Wrapper libc function that issues the syscall
strace Userspace syscall tracer
ltrace Traces library calls instead
Argument validation The kernel's core security job at this boundary

Kali commands

strace -c -f ls 2>&1 | tail -25          # summary by syscall
strace -e trace=network -f curl -s https://example.com 2>&1 | tail -20
strace -e trace=openat -f /usr/bin/chromium 2>&1 | head -20
strace -p $(pgrep -f yourprocess) -f      # attach to a live process

# what does a binary import?
readelf -s /usr/bin/ls | grep UND | head -20
objdump -T /usr/bin/ls | head
nm -D /usr/bin/ls | grep -E "open|read|write|socket"

# syscall numbers on this kernel
ausyscall --dump 2>/dev/null | head -20
cat /usr/include/asm/unistd_64.h 2>/dev/null | head -30

# ltrace for the layer above
ltrace -e 'malloc+free' ./prog

Field lab

Objective: see the syscall boundary from three angles — frequency, content, and tracing a
live process.

mkdir -p ~/aegis/labs/os-03 && cd ~/aegis/labs/os-03

# --- how expensive is the boundary? ---
strace -c /usr/bin/ls 2>&1 | tail -30 | tee 01-syscalls-ls.txt
strace -c -f nmap -sn 127.0.0.1 2>/dev/null | tail -20 | tee 02-syscalls-nmap.txt
echo "ls vs nmap: compare total calls and the top syscalls."

# --- what does a network client actually ask for? ---
strace -e trace=network -f curl -s https://example.com 2>&1 \
  | grep -E "socket|connect|sendto|recvfrom|bind" | head -25 | tee 03-network.txt
echo "Every line here is a trust boundary crossing with user-controlled arguments."

# --- the exec chain from a shell ---
strace -e trace=execve -f bash -c "ls -la" 2>&1 | head -10

# --- attach to a running process ---
sleep 300 &
BGPID=$!
strace -p $BGPID -e trace=none -o /tmp/idle.txt &
sleep 2; kill %2 2>/dev/null
head -5 /tmp/idle.txt
kill $BGPID 2>/dev/null

# --- which syscalls does a binary import? ---
{
  echo "=== undefined (imported) symbols in /usr/bin/ls ==="
  nm -D /usr/bin/ls 2>/dev/null | grep " U " | head -25
  echo
  echo "=== dynamic symbols ==="
  readelf --dyn-syms /usr/bin/ls 2>/dev/null | grep UND | head -15
} | tee 04-imports.txt

# --- syscall table on this machine ---
{
  echo "=== syscall table / vectors ==="
  cat /proc/sys/kernel/syscall 2>/dev/null && echo "(syscall hardening: '1' = no, '2' = seccomp only)"
  echo
  echo "=== seccomp mode of this shell ==="
  grep Seccomp /proc/self/status
} | tee 05-seccomp.txt

/proc/sys/kernel/syscall is worth understanding: 0 = allow everything, 1 = deny all
unknown syscalls (poor man's seccomp), 2 = require seccomp mode. Read the value, then think
about what a binary compiled yesterday does on a kernel that adds a syscall today. That is
sandbox and seccomp in Tier 3.
