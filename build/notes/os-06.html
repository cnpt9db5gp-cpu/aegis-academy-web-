Virtual Memory and Page Tables

Summary

Virtual memory serves three purposes at once: give each process a private, contiguous address
space; let physical RAM be used more efficiently than a naive allocation would allow; and provide
the hardware mechanism for memory protection.

This lecture explains paging, page tables, the TLB, and — from a security angle — exactly how
memory protection is enforced, and how virtual memory became the substrate for exploit mitigations.

Why virtual memory

  • Isolation: process A cannot touch process B's pages
  • Abstraction: programs see a linear address space regardless of physical layout
  • Efficiency: swap, demand paging, copy-on-write
  • Protection: NX (no execute), user/supervisor bit per page

The translation path

virtual address
   ↓ split: [ page number | offset ]
   ↓
Page Directory (top-level index)
   ↓
Page Table (second-level index)
   ↓  ──► physical frame number
physical memory

Every access is a hardware operation, cached by the TLB (translation lookaside buffer).

In xv6 this is deliberately simple: two-level paging where each page is walked in software.
Reading walk.c is the fastest way to understand it.

Page table entries

Each entry carries more than a physical address:

Bit Meaning Security relevance
Present Page is mapped Prevent "access unmapped memory" exploits
Write Page is writable W^X: a page cannot be both writable and executable
User Accessible from user space Kernel pages are supervisor-only
Accessed / Dirty Bookkeeping for eviction —
NX Not executable Blocks shellcode on the stack

W^X and NX are the same idea: a page should be either writable or executable, never both. That
single policy is what forces exploitation to use ROP or ret2libc instead of injected shellcode.

Address space layout (Linux, typical)

0x000000000000  NULL (never mapped)
0x000000400000  binary, libraries
0x00007f...      mmap region: shared libs, thread stacks
0x00007fff...    stack        ← grows DOWN
0x7fffffffe000  PIE binary base (randomised)
0xffffffffff600000  vsyscall page (fixed - a known address to abuse)

Note the two fixed regions. Anything at a known address is a permanent attacker target — you
do not need an information leak against a hardcoded address.

TLB

A hardware cache of recent translations. It makes paging fast, and it is also a side channel:
flushing entries and timing re-fills leaks which addresses were used. That is the basis of
cache-timing attacks and some CPU timing attacks.

Security implications, concretely

  1. NX blocks shellcode on the stack → forces ROP/ret2libc
  2. ASLR randomises the base → forces an information leak first
  3. Canaries block stack smashing → forces a leak before overwriting the return address
  4. All three together → a modern exploit is: leak → leak → chain ROP → win

The exploit chain is a direct consequence of the mitigations. Every lecture in Tier 3 is a
study of one link in that chain.

Terminology

Term Meaning
Virtual address What the program sees
Physical address Where the frame actually lives in RAM
Page Fixed-size block (usually 4 KiB)
Page table Mapping from virtual pages to physical frames
MMU Hardware performing the translation
TLB Cache of recent translations
Present bit Whether a page is mapped
NX / no-execute Page cannot be executed
W^X Writable and executable are mutually exclusive
Demand paging Map pages only when touched
Copy-on-write fork shares pages until either writes
ASLR Randomises base addresses per run

Kali commands

# read your own address space
cat /proc/self/maps
cat /proc/self/maps | wc -l
pmap -x $$ | head -20
pmap -x $$ | tail -3

# which libraries are mapped
grep -E '\.so' /proc/self/maps | awk '{print $6}' | sort -u

# NX status of this shell and of a binary
readelf -l /bin/bash | grep -E 'GNU_STACK|GNU_RELRO'
readelf -lW /bin/bash | grep GNU_STACK

# confirm a stack is not executable
python3 -c "
import ctypes
libc = ctypes.CDLL('libc.so.6')
buf = ctypes.create_string_buffer(64)
addr = ctypes.addressof(buf)
print('stack page is non-executable:', not (libc.mprotect(buf, 64, 7) == 0))
" 2>&1 | tail -2

# ASLR: is this system randomised?
cat /proc/sys/kernel/randomize_va_space     # 2 = full ASLR
sudo sysctl kernel.randomize_va_space        # requires sudo

# page faults and RSS
vmstat 1 3 | head -20
grep -E "VmPeak|VmSize|VmRSS|VmStk" /proc/self/status

Field lab

Objective: read a real address space, confirm NX, and observe ASLR changing between runs.

mkdir -p ~/aegis/labs/os-06 && cd ~/aegis/labs/os-06

# --- 1. your address space ---
{
  echo "=== VMA layout ==="
  head -25 /proc/self/maps
  echo
  echo "=== total VMAs ==="
  wc -l < /proc/self/maps
  echo
  echo "=== the stack (grows down, at the top of the map) ==="
  grep -E '\[stack\]' /proc/self/maps
  echo
  echo "=== memory summary ==="
  grep -E "VmPeak|VmSize|VmRSS|VmStk|VmExe|VmLib" /proc/self/status
} > 01-maps.txt
cat 01-maps.txt

# --- 2. NX: the stack is not executable ---
readelf -lW /bin/bash | grep GNU_STACK
python3 -c "
import ctypes
libc = ctypes.CDLL('libc.so.6')
b = ctypes.create_string_buffer(64)
print('mprotect(RWX) on a stack page ->', libc.mprotect(b, 64, 7))
print('result: -1 means the kernel refused. NX is enforced in hardware.')
" 2>&1 | tail -3 | tee -a 01-maps.txt

# --- 3. ASLR: compare addresses across runs ---
{
  echo "=== ASLR across 6 runs (PIE base and stack) ==="
  for i in $(seq 1 6); do
    python3 -c "
import re
m = [l.split() for l in open('/proc/self/maps') if '[stack]' in l]
for e in open('/proc/self/maps'):
    f = e.split()
    if len(f) > 5 and f[5].endswith('.so') and 'libc' in f[5]:
        print('  libc  base:', f[0].split('-')[0]); break
print('  stack  base:', m[0][0].split('-')[0] if m else '?')
"
  done
} | tee 02-aslr.txt
echo
echo "Different every run = ASLR working. Predicting one of these needs an info leak."

# --- 4. page faults in action ---
vmstat 1 3 2>/dev/null | head -12 | tee 03-vmstat.txt
echo "Note 'f' (faults) climbing while a process allocates: demand paging is real."

# --- 5. W^X on a binary ---
{
  echo "=== GNU_STACK: RW, not E ==="
  readelf -lW /bin/ls | grep -E 'GNU_STACK|GNU_RELRO'
  echo
  echo "=== compare: a binary built with -z execstack ==="
  printf 'int main(){return 0;}\n' > /tmp/x.c
  gcc -z execstack -o /tmp/x-exec /tmp/x.c 2>/dev/null
  gcc -z noexecstack -o /tmp/x-noexec /tmp/x.c 2>/dev/null
  readelf -lW /tmp/x-exec  | grep GNU_STACK
  readelf -lW /tmp/x-noexec| grep GNU_STACK
  echo "RWE = writable AND executable stack. NX off."
  rm -f /tmp/x.c /tmp/x-exec /tmp/x-noexec
} 2>&1 | tee 04-wx.txt

# --- 6. copy-on-write, observed ---
{
  echo "=== a big fork should not double RSS immediately ==="
  python3 -c "
import os, resource
buf = bytearray(200*1024*1024)   # 200 MB touched
def rss(): return resource.getrusage(resource.RUSAGE_SELF).ru_maxrss//1024
print('  parent RSS before fork:', rss(), 'MB')
pid = os.fork()
if pid == 0:
    print('  child RSS right after fork:', rss(), 'MB  <- pages are shared')
    os._exit(0)
os.waitpid(pid, 0)
print('  parent RSS after child exit:', rss(), 'MB')
"
} | tee 05-cow.txt

Step 3 is the number that matters for exploitation. Every run gives a different base. That is
why ex-04 starts with an information leak, and why "just spray the stack with shellcode and hope"
died with NX.

Record: 02-aslr.txt. Run it again tomorrow and compare — the point is that nothing is
predictable.
