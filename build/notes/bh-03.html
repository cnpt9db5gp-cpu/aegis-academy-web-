From Shortest Path to Execution Plan

Summary

The graph gives you a path. The engagement needs a plan: which edge you take first, what it
costs, what it logs, and how you stop. This note is the translation step, and it is the one that
separates a graph tool run from an actual engagement.

The framing that makes it work: a path is a sequence of edge types, and
each edge type has a cost, an artifact, and a log signature. A plan is
the sequence with those three things attached.

What an edge costs

  EDGE                     WHAT IT COSTS YOU         WHAT IT LEAVES
  ---------------------------------------------------------------------------
  MEMBER OF                nothing - it is a fact     nothing
  HasSession + relay       an SMB connection to the   4624 (a new source
                           host, and a writable       session), 5145
                           listener (if SMB relay)    (relayed connection)
  AdminTo + hash read      a credential on the       4624 type 3, 4648
                           host (SeDebug / SeImpersonate)
  GenericAll on a group    one LDAP write             5136 on the group
  GenericWrite + WriteSPN  one LDAP write, then       5136 on the account,
                           the roast (offline, free)  4769 (ticket request)
  WriteDACL on an object   one LDAP write             5136 on the object
  DCSync                   a replication request      4662 + 4663 + 5136 +
                                                     a full-domain event
  Delegation (unc.)       capture a forwarded TGT    4768/4769 from the host
                           from a host you already    (normal-looking)
                           access to
  GPO write                wait for gpupdate (or      5136 on the GPO,
                           force it) then SYSTEM      5145 scheduled task

  THE PATTERN: the cheap edges are read-only (free, nothing logged
  beyond enumeration). The expensive edges are writes (5136) or
  authentications (4624). The most expensive is DCSync, because it is a
  domain-wide event that every monitoring system alerts on.

Turning a path into a plan

  THE PLAN FORMAT, for one path:

  Step 1. Edge: MEMBER OF "Helpdesk"
           Cost:    zero. It is already true.
           Action:  none.
           Evidence: 'Alice is a member of Helpdesk' (from the graph).

  Step 2. Edge: GENERICALL on "IT Support"
           Cost:    one LDAP write. No credential beyond alice's.
           Action:  add alice to "IT Support" via LDAP.
           Logged:  5136 on the IT Support group.
           Reversible: yes - remove her again.

  Step 3. Edge: GENERICWRITE on "SVC-DEPLOY"
           Cost:    one LDAP write (set an SPN on SVC-DEPLOY).
           Action:  set an SPN, then request a service ticket, then
                    crack it offline (cry-d4's method).
           Logged:  5136 on SVC-DEPLOY.
           Note:    this makes the account roastable. If it was not
                    before, you have changed the environment. Record it
                    and restore it.

  Step 4. Edge: MEMBER OF "Domain Admins"
           Cost:    the ticket crack is offline. Minutes to hours.
           Action:  use the recovered credential as SVC-DEPLOY.
           Logged:  nothing on the DC (the ticket is already issued).
           STOP:    the engagement objective is met.

  Total network actions: 2 writes. Total artifacts to clean up: 2.
  Total log events the client's monitoring will see: 2 x 5136.

# --- 1. the planner ---
cat > plan.py <<'PY'
#!/usr/bin/env python3
"""Turn a BloodHound path into an execution plan.

The graph says WHERE. This says HOW, in what order, at what cost,
with what artifact, and when to stop.
"""

EDGE_PLAN = {
 "MEMBER OF":            dict(cost="zero", action="none - it is already true",
                              logs="none", artifact="none"),
 "HAS SESSION":          dict(cost="an SMB connection to the host",
                              action="relay or read the session's credential",
                              logs="4624, 5145", artifact="a relayed session"),
 "ADMINTO":              dict(cost="a privileged credential on the host",
                              action="dump the host, read the hash",
                              logs="4624 type 3", artifact="a credential"),
 "GENERICALL":           dict(cost="one LDAP write",
                              action="add yourself to the object",
                              logs="5136", artifact="a group membership change"),
 "GENERICWRITE":         dict(cost="one LDAP write",
                              action="set an attribute (SPN, script path)",
                              logs="5136", artifact="an attribute change"),
 "WRITEDACL":            dict(cost="one LDAP write",
                              action="grant yourself GenericAll, then act",
                              logs="5136", artifact="an ACL change"),
 "WRITESPN":             dict(cost="one LDAP write, then an offline crack",
                              action="add an SPN, request a ticket, crack it",
                              logs="5136, 4769", artifact="a new SPN"),
 "READGMSAPASSWORD":     dict(cost="one read",
                              action="read the managed password",
                              logs="4660", artifact="a credential in evidence"),
 "DCSYNC":               dict(cost="a domain-wide replication request",
                              action="replicate the directory",
                              logs="4662, 4663, 5136, AND a full-domain event",
                              artifact="every hash in the domain"),
 "ALLOWEDTODELEGATE":    dict(cost="a credential on the delegating host",
                              action="request a ticket as any user",
                              logs="4768, 4769", artifact="a captured TGT"),
 "GENERICALL (GPO)":     dict(cost="one write + one gpupdate cycle",
                              action="add a scheduled task, force the refresh",
                              logs="5136, 5145", artifact="a SYSTEM task on "
                                                            "every host in the OU"),
}

def plan(path, objective="DOMAIN ADMIN"):
    print("=" * 72)
    print(f"EXECUTION PLAN -> {objective}")
    print("=" * 72)
    total_cost = 0
    artifacts = []
    for i, (kind, node) in enumerate(path, 1):
        info = EDGE_PLAN.get(kind, EDGE_PLAN.get(kind.upper(), dict(
            cost="unknown", action="-", logs="-", artifact="-")))
        print(f"\nSTEP {i}: {kind}")
        print(f"  node:     {node}")
        print(f"  cost:     {info['cost']}")
        print(f"  action:   {info['action']}")
        print(f"  logged:   {info['logs']}")
        print(f"  artifact: {info['artifact']}")
        if info["artifact"] != "none":
            artifacts.append(info["artifact"])
        total_cost += 1 if info["cost"] != "zero" else 0
    print("\n" + "-" * 72)
    print(f"TOTAL: {len(path)} edges, {total_cost} requiring an action")
    print(f"ARTIFACTS TO CLEAN UP: {len(artifacts)}")
    for a in artifacts: print(f"  - {a}")
    print("\nSTOP CONDITION:")
    print("  The engagement objective is met. Do not continue past")
    print("  the last edge 'because the next one is interesting'.")
    print("\nREPORTING:")
    print("  The path IS the finding. Report it edge by edge with the")
    print("  two specific remediation actions per edge - not 'review ACLs'.")

path = [("MEMBER OF", "HELPDESK@LAB.INTERNAL"),
        ("GENERICALL", "IT SUPPORT@LAB.INTERNAL"),
        ("GENERICWRITE", "SVC-DEPLOY@LAB.INTERNAL"),
        ("MEMBER OF", "DOMAIN ADMINS@LAB.INTERNAL")]
plan(path)

print("\n\nTHE OTHER PATH, AND WHY IT IS NOT THE ONE TO WALK FIRST:\n")
path2 = [("MEMBER OF", "HELPDESK@LAB.INTERNAL"),
         ("READGMSAPASSWORD", "GMSA-FILES@LAB.INTERNAL"),
         ("DCSYNC", "LAB.INTERNAL")]
plan(path2, "DCSYNC (via gMSA)")
print()
print("  ^ this path is 3 hops, all READS. Zero writes, so ZERO 5136")
print("    events. The client's monitoring sees a normal session and")
print("    nothing else. Compare with path 1, which writes twice and")
print("    leaves two artifacts to clean up.")
print()
print("  USE THE READ-ONLY PATH FIRST. Escalate along the graph only")
print("  if the read-only path is not available.")
PY
python3 plan.py 2>&1 | tee 01-plan.txt

# --- 2. the write-path discipline ---
cat > 02-write-discipline.md <<'EOF'
# Doing writes in a live environment

```text
  A "write" is any change to the directory: group membership, an SPN,
  an ACL, a GPO. Each one is:
    - logged (5136)
    - visible to the client's monitoring
    - a change to their environment you must undo

  THE RULES
  1. PREFER THE READ-ONLY PATH. If a read gets you to the objective,
     use it. It leaves nothing, logs nothing, and cannot be mistaken
     for an incident.
  2. IF YOU MUST WRITE, THE WRITE IS THE FINDING. Do it once, record
     it, screenshot it, undo it. Not twice to "confirm".
  3. NOTIFY BEFORE A DCSYNC. A replication request for the whole
     directory is a domain-wide event. Most SIEMs alert on it. If you
     are going to do it, tell the client first, and confirm the
     "findings" they are about to investigate are yours.
  4. NEVER WRITE A GPO WITHOUT EXPLICIT PERMISSION. A GPO write with a
     scheduled task is SYSTEM on every host in the OU. If the OU
     contains a DC, it is a domain compromise, and an SOC watching
     for that will page. Confirm the ROE permits it, in writing,
     before you do it - not after.
  5. DO NOT ROAST AN ACCOUNT THAT WAS NOT ROASTABLE. Adding an SPN to
     make something crackable CHANGES THE ENVIRONMENT. It is a
     legitimate demonstration of WriteSPN, but it is a change. Record
     it, revert it, and say you did it.
  6. CLEAN UP IMMEDIATELY, NOT AT THE END. If you add alice to a
     group, remove her from it before you do anything else. An
     escalation path you created and forgot is an escalation path
     somebody will use.
```

## The diary entry for a write

```text
  16:22  WRITE: added LAB\alice to "IT Support" via LDAP.
         Purpose: demonstrate the GENERICALL edge in the BH path.
         Evidence: screenshot, LDAP response.
         16:24  REVERTED: removed LAB\alice from "IT Support".
         Verified: group membership back to baseline.
         Client contact: not notified (single group membership, no
         alerting expected; would have notified for DCSync).
```

## What to do when you have to notify

```text
  "I am about to run a DCSync request against DC01. It will produce
   4662/4663 events with the replication GUIDs and a spike in
   replication traffic. It is the step that confirms the finding, and
   it is the step that will definitely alert. Confirm you are happy
   for me to proceed, and I will send you the log line numbers
   immediately afterwards so your SOC can close the ticket."

  Then send the ticket numbers. This single habit - telling the
  client what logs you are about to generate, and telling them which
  to close - is most of what separates a professional engagement from
  an incident.
```

## The verification step that people skip

```text
  AFTER EVERY WRITE, VERIFY THE ENVIRONMENT IS BACK TO BASELINE.

    - the group membership is what it was
    - the SPN is gone
    - the ACL is what it was
    - no scheduled task remains
    - no new computer or user account exists

  If you cannot demonstrate that, you have left a change in a
  production directory and you should tell the client now rather than
  at the end of the engagement.
```
EOF

cat > 03-report.md <<'EOF'
## F-xx · Three-hop path from a standard user to domain administrator

Risk
  Any authenticated user in the "Helpdesk" group (147 accounts) can
  reach Domain Administrator in three steps, using no exploit and no
  privileged tooling:
    1. Add themselves to the "IT Support" group (the group has
       GenericAll granted to Helpdesk)
    2. Write a service principal name to the "svc-deploy" service
       account (IT Support has GenericWrite on it)
    3. Request a service ticket for svc-deploy and recover its
       password offline (the account supports RC4 encryption)

  svc-deploy is a member of Domain Admins. From a standard helpdesk
  account, this is domain administrator.

Prerequisites
  Membership of Helpdesk. Every account in Helpdesk was created for
  non-administrative account support. No user interaction, no exploit,
  no elevated tooling beyond a standard wordlist.

Evidence
  The graph path (from a bloodhound-python ACL collection, timestamp
  2026-10-14 09:20 and re-verified 16:40, unchanged):

    ALICE@LAB.INTERNAL
      MEMBER OF       HELPDESK@LAB.INTERNAL
      GENERICALL      IT SUPPORT@LAB.INTERNAL
      GENERICWRITE    SVC-DEPLOY@LAB.INTERNAL
      MEMBER OF       DOMAIN ADMINS@LAB.INTERNAL

  We demonstrated steps 1 and 2 (adding a test account to IT Support,
  and writing an SPN to a test service account), and did NOT crack the
  resulting ticket or use the recovered credential, to avoid
  unnecessary exposure of the account's password. The path is
  established by the graph and the two write steps.

  Steps 1 and 2 were reverted at 16:24 and verified. See the
  engagement diary.

Business impact
  147 accounts - every helpdesk user - have a one-to-three hop path to
  domain administrator. The Helpdesk group exists so that
  non-administrators can help users; it was never intended to include
  the ability to administer the domain.

Remediation
  1. Change "IT Support" from GenericAll (Full Control) to Read only
     for the Helpdesk group                            [Domain Admins, Immediate]
     Identify why Full Control was granted and to whom; the ACL was
     last modified 2019-03-14 (from the ACL's own metadata).
  2. Remove svc-deploy from Domain Admins. A deployment service account
     should be able to deploy to servers, not administer the domain.
                                                        [Domain Admins, Immediate]
     Expected deployment rights: write to the deploy share, service
     start/stop on the target services. Nothing else.
  3. Set msDS-SupportedEncryptionTypes to AES-only on all service
     accounts, so a written SPN is not immediately roastable
                                                       [Domain Admins, Immediate]
  4. Remove GenericWrite on SVC-DEPLOY from IT Support  [Domain Admins, Immediate]
     No group needs GenericWrite on a service account.
  5. Audit for other GenericAll/GenericWrite grants on user and
     computer objects                                  [Security, 1 sprint]
     Query: edge_acl WHERE target IN (SELECT objectid FROM users)

Re-test
  Included at +30 days: re-collect the graph and confirm the path no
  longer exists from any Helpdesk principal.

Self-test

  1. Why is MEMBER OF "already true" while the other edges cost an action?
  2. What does each edge type leave behind, in the client's logs?
  3. Why is DCSync the most expensive edge, and what do you do about it?
  4. Why should you prefer the read-only path to DCSync over the write path to domain admin?
  5. Why is roasting an account that was not previously roastable a change you must revert?
  6. What is the diary entry for a write, and what are its required fields?
  7. Why notify before DCSync, and what do you send afterwards?
  8. What must you verify after every write?
  9. Why is "review your ACLs" an inadequate recommendation, and what makes the alternative adequate?
