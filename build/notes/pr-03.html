Cron, systemd and PATH Hijacking

Summary

Scheduled tasks and service definitions are where "a user with a small amount of write access
becomes root" lives. A privileged job that runs a script from a writable location, or calls an
interpreter by bare name, is exploitable without any kernel trickery.

Key ideas

  • cron: user crontabs, /etc/crontab, /etc/cron.d/, and the spool directories
  • The rule: a job running as root that touches a path you can write is your job now
  • Argument injection: root's command uses * or $VAR that your shell expands first
  • systemd: unit files define user, binary, and writable config paths
  • PATH for services is often minimal — a bare sh may resolve to your directory
  • Wildcards in privileged commands are a classic, still-live bug class

Terminology

Term Meaning
crontab A user's scheduled task list
Crontab format min hour dom mon dow command
/etc/cron.d System crontabs, must include a user field
Crontab spool /var/spool/cron/crontabs/<user>
Argument injection Controlling parameters a privileged command trusts
systemd unit A declarative service definition
Environment= A unit's environment — PATH is often set explicitly
Wildcard expansion * resolved by your shell, before sudo runs
Shell metacharacter ;, |, &&, backticks used to chain commands

Kali commands

# --- where are scheduled jobs? ---
crontab -l 2>/dev/null || echo "(no user crontab)"
sudo crontab -l -u root 2>/dev/null
sudo ls -la /etc/cron.d/ /etc/cron.daily/ /var/spool/cron/crontabs/ 2>/dev/null
sudo cat /etc/crontab 2>/dev/null | grep -v '^#' | grep -v '^$'
systemctl list-timers --all --no-pager 2>/dev/null | head -10

# --- permissions on every job location ---
sudo stat -c '%A %U:%G %n' /etc/cron.d/* /var/spool/cron/crontabs/* 2>/dev/null
echo "any writable by non-root? -> escalation candidates"

# --- what does each job actually run? ---
sudo grep -rhvE '^\s*(#|$)' /etc/cron.d/ /etc/crontab 2>/dev/null
ps aux | grep -E "cron|systemd" | grep -v grep | head

# --- systemd units that a user can influence ---
systemctl list-unit-files --state=enabled --no-pager 2>/dev/null | head -15
ls -la /etc/systemd/system/ 2>/dev/null | head -15
find /etc/systemd /usr/lib/systemd -writable -type f 2>/dev/null | head
grep -r "Environment=\|ExecStart=" /etc/systemd/system/*.service 2>/dev/null | head -10

# --- writable places a privileged job might reference ---
sudo -n -l 2>/dev/null | grep -E "NOPASSWD|ALL" | head

Field lab

Objective: read every scheduled job and service definition on this machine, and classify each
by exploitability.

mkdir -p ~/aegis/labs/pr-03 && cd ~/aegis/labs/pr-03

{
  echo "================ CRON ================"
  echo "--- user crontab ---"; crontab -l 2>/dev/null || echo "  (none)"
  echo
  echo "--- root crontab ---"; sudo crontab -l -u root 2>/dev/null || echo "  (none/no sudo)"
  echo
  echo "--- /etc/crontab ---"; sudo grep -vE '^\s*(#|$)' /etc/crontab 2>/dev/null
  echo
  echo "--- /etc/cron.d ---"
  sudo ls -la /etc/cron.d/ 2>/dev/null
  sudo grep -rhvE '^\s*(#|$)' /etc/cron.d/ 2>/dev/null
  echo
  echo "--- spool, and who owns it ---"
  sudo ls -la /var/spool/cron/crontabs/ 2>/dev/null
  echo
  echo "--- CLASSIFY each job ---"
  echo "  For every job above ask:"
  echo "   1. Which user does it run as?"
  echo "   2. Does it reference any path I can write?"
  echo "   3. Does it invoke an interpreter or tool by BARE NAME (PATH risk)?"
  echo "   4. Does it use * or \$VAR in a way my shell expands first?"
} 2>&1 | tee 01-cron.txt

{
  echo "================ SYSTEMD ================"
  echo "--- timers ---"; systemctl list-timers --all --no-pager 2>/dev/null | head -10
  echo
  echo "--- user-writable unit files (immediate finding) ---"
  find /etc/systemd /usr/lib/systemd /lib/systemd -writable -type f 2>/dev/null | head
  echo
  echo "--- services with a minimal or writable PATH ---"
  sudo grep -rh "Environment=PATH" /etc/systemd/system/ /lib/systemd/system/ 2>/dev/null | sort -u | head
  echo
  echo "--- ExecStart pointing into a user-writable directory ---"
  sudo grep -rh "ExecStart=" /etc/systemd/system/*.service 2>/dev/null | grep -E "=/tmp|=/home|=/opt" | head
  echo
  echo "--- what do MY user's units say ---"
  systemctl --user list-unit-files --no-pager 2>/dev/null | head -5
  ls -la ~/.config/systemd/user/ 2>/dev/null
} 2>&1 | tee 02-systemd.txt

# --- demonstrate the argument-injection pattern safely ---
echo
echo "================ THE WILDCARD BUG, DEMONSTRATED ================="
cat > cron-demo.sh <<'EOF'
#!/usr/bin/env bash
# Simulates a root cron job:  * * * * * /usr/bin/tar -czf /backup/archive.tar.bak * -C /srv
# The shell expands * BEFORE sudo/root ever runs it. Anything you create gets archived
# by a privileged process, and a file you plant is executed on the next untar.
set -e
WORK=/tmp/cron-demo
rm -rf $WORK; mkdir -p $WORK/srv $WORK/backup
cd $WORK/srv
echo "legitimate data" > data.txt
echo "you do not need to control this command to exploit it" > notes.txt

echo "--- what a root job would tar ---"
# the job runs as root; here we just show the expansion
(cd $WORK/srv && tar -czf $WORK/backup/archive.tar.bak *)
tar -tzf $WORK/backup/archive.tar.bak | sed 's/^/  /'

echo
echo "--- now plant a file whose NAME is a payload path ---"
# archive members are extracted relative to CWD by many untar flows
mkdir -p $WORK/extract
tar -xzf $WORK/backup/archive.tar.bak -C $WORK/extract
ls -la $WORK/extract

echo
echo "The exploit class: a privileged command that archives '*' will archive whatever"
echo "exists at that moment. Combined with an extraction that respects member paths,"
echo "this is arbitrary file write as root. It is still common in real deployments."
rm -rf $WORK
EOF
chmod +x cron-demo.sh && ./cron-demo.sh | tee 03-wildcard.txt

# --- the PATH problem for services, concretely ---
echo
echo "================ SERVICE PATH ================="
echo "your PATH has $(echo $PATH | tr ':' '\n' | wc -l) entries:"
echo "$PATH" | tr ':' '\n' | sed 's/^/  /'
echo
echo "systemd services usually get a SHORT path. Yours:"
systemctl show --property=Environment $(systemctl list-units --type=service --state=running --no-legend | awk 'NR==1{print $1}') 2>/dev/null | head -3
echo
echo "If a service runs 'python3 something.py' with PATH=/usr/bin, you cannot hijack it."
echo "If PATH is unset or includes /tmp or your home, you can."

Step 3 is a bug class that has shipped in production software for decades and still appears in
real cron jobs. Learning to read a cron line for "who, what path, bare name, wildcard" is a
transferable, high-value skill.
