Malware Triage: Static Before Dynamic

Summary

The single most important rule in malware analysis: look at it before you run it. Static
analysis gives you the same answers as dynamic analysis for most samples, without executing a
single instruction of untrusted code on your machine.

The framing: the ratio of effort to information is the entire
methodology question. An analyst who runs a sample to answer "what
does this connect to" when strings would have told them in three
seconds has made a mistake that costs an organisation.

Companion to for-03 (where memory finds the code) and for-06 (writing
a rule for what you find). This note is the analysis of a single file.

The order

  1. HASH IT         and check it against a reputation service
                    before anything else. Everything downstream is
                    about THIS file, identified by THIS hash.

  2. TYPE IT         PE, ELF, Mach-O, script, document, archive
                    "not a PE" is a finding, not a failure

  3. STRUCTURE IT    sections, imports, exports, resources, entropy
                    the imports and the section layout answer most
                    questions

  4. READ THE STRINGS  including the wide (UTF-16) ones

  5. LOOK FOR THE OVERLAY   a PE with a ZIP or a PDF after the last
                    section. Very common, and where the real payload
                    is.

  6. DECODE THE STRINGS   XOR with a single byte, base64, ROT13,
                    PowerShell -enc, a custom scheme

  7. ONLY THEN consider dynamic analysis, and in a sandbox you built

  THE POINT: steps 1-6 need no execution, take minutes, and answer
  "what is it, what does it do, who does it talk to" for the majority
  of samples.

The four questions static analysis answers

  1. WHAT IS IT?
     format, architecture, compiler, packer, build time, signer

  2. WHAT DOES IT DO?
     the imports and the API calls are the behaviour:
       CreateRemoteThread / WriteProcessMemory  -> injection
       VirtualAllocEx / NtUnmapViewOfSection    -> process hollowing
       RegSetValueEx(HKLM\\...\\Run)             -> persistence
       InternetOpenA / WinHttpConnect           -> network
       CryptEncrypt / CryptGenKey               -> ransomware
       FindFirstFile / CopyFile                 -> staging or copy
       IsDebuggerPresent / NtQueryInformation   -> anti-analysis

  3. WHO DOES IT TALK TO?
     URLs, IPs, domains, User-Agent strings, registry paths,
     mutex names, pipe names, service names.
     THE MUTEX NAME IS UNIQUELY IDENTIFYING. A single mutex is often
     enough to find every copy of the family, and to find the report
     where the actor described it.

  4. IS IT PACKED?
     section names (UPX, .themida, random), high entropy, few
     imports, an entry point outside the first section, a tiny import
     table with LoadLibrary and GetProcAddress.

Tools, and what each is for

  HASHING      sha256sum, md5sum, ssdeep (fuzzy matching)
  TYPE         file, and exiftool for documents
  PE PARSING   pefile (python), objdump, readpe, diec
  STRINGS      strings -a (ASCII), strings -el (UTF-16LE)
  DISASSEMBLY  objdump -d, Ghidra, radare2, Cutter
  YARA         yara + rules (for-06)
  SANDBOX      ANY.RUN, Cape, Triage, or your own
  DECODE       CyberChef, and a Python REPL

# --- how to tell, without running anything ---
import hashlib, os, struct, math, collections, sys

def sha256(p):
    h = hashlib.sha256()
    with open(p, "rb") as f:
        for b in iter(lambda: f.read(65536), b""): h.update(b)
    return h.hexdigest()

def entropy(data):
    if not data: return 0.0
    c = collections.Counter(data)
    n = len(data)
    return -sum((v/n) * math.log2(v/n) for v in c.values())

def is_pe(data):
    return data[:2] == b"MZ" and data[0x3c:0x40] != b"\x00\x00\x00\x00"

def pe_sections(data):
    if not is_pe(data): return []
    e_lfanew = struct.unpack_from("<I", data, 0x3c)[0]
    if data[e_lfanew:e_lfanew+4] != b"PE\x00\x00": return []
    coff = e_lfanew + 4
    nsec = struct.unpack_from("<H", data, coff + 2)[0]
    optsz = struct.unpack_from("<H", data, coff + 16)[0]
    sec = coff + 20 + optsz
    out = []
    for i in range(nsec):
        o = sec + i * 40
        name = data[o:o+8].rstrip(b"\x00").decode("latin-1")
        vsize, vaddr, rsize, roff = struct.unpack_from("<IIII", data, o + 8)
        out.append(dict(name=name, vsize=vsize, rawsize=rsize, offset=roff,
                        entropy=entropy(data[roff:roff+rsize]) if rsize else 0.0))
    return out

def overlay_offset(data):
    """The first byte past the last section. Everything after this is
    an overlay: a payload, an archive, or a certificate."""
    secs = pe_sections(data)
    if not secs: return None
    return max(s["offset"] + s["rawsize"] for s in secs)

import os, struct, hashlib, math, collections

# A deliberately benign "sample": a PE-like header with a ZIP overlay.
# It contains no executable code and will not run. It exists to teach
# the four questions.
def build_pe():
    d = bytearray(b"\x00" * 1024)
    d[0:2] = b"MZ"
    struct.pack_into("<I", d, 0x3c, 0x80)
    d[0x80:0x84] = b"PE\x00\x00"
    struct.pack_into("<H", d, 0x84 + 2, 2)      # 2 sections
    struct.pack_into("<H", d, 0x84 + 16, 0xE0)  # optional header size
    secs = [(b".text", 0x400, 0x400, 0x400),
            (b".rsrc", 0x800, 0x200, 0x800)]
    o = 0x84 + 20 + 0xE0
    for name, vsize, rsize, roff in secs:
        struct.pack_into("<8sIIII", d, o, name, vsize, 0, rsize, roff); o += 40
    d[0x400:0x420] = b"\x90" * 32               # .text filler
    return bytes(d)

pe = build_pe()
import zipfile, io
buf = io.BytesIO()
with zipfile.ZipFile(buf, "w", zipfile.ZIP_DEFLATED) as z:

print("  built lab-sample.bin")
print(f"    size            : {len(sample)} bytes")
print(f"    PE part         : {len(pe)} bytes")

# Decoding obfuscated strings

```text
  MALWARE HIDES ITS CONFIGURATION. The methods, cheapest first:

  1. PLAINTEXT        (many do this, in the .rsrc section or appended)
     strings -a and read. 30 seconds.

  2. XOR, SINGLE BYTE   the most common obfuscation there is.
     key is one byte. Brute-force 256 possibilities and score by
     how much of the result is printable.

  3. XOR, MULTI-BYTE   key length 1-16. Score by printability and
     known markers (http://, MZ, .dll, kerberos)

  4. BASE64            standard or custom alphabets.
     Sometimes "base64" then XOR. Sometimes a custom alphabet, which
     you recover by looking at what characters appear.

  5. RC4 / AES         a key is elsewhere in the binary, or on a
     server, or derived from the hostname. Needs a key.

  6. POWERSHELL -ENC    base64 UTF-16LE of a -EncodedCommand.
     Decode it and read the script. This is a presentational
     obfuscation and it is trivially reversible.

  7. BUILD STRINGS     order-dependent, used to avoid static strings.
     You need to understand the program's own call sequence.

  8. CUSTOM            everything else. This is where time goes, and
     it is why dynamic analysis exists.
EOF

What dynamic analysis adds, and when it is worth it

  DYNAMIC ANSWERS, AND ONLY DYNAMIC ANSWERS, CAN:
    the actual network destinations (DNS, and the order of them)
    the files written, and the paths
    the registry keys created
    the process tree, including who it injects into
    the mutex created (and its name, for correlation)
    behaviour that depends on the environment: a sandbox check, a
    domain-joined check, a date check, a geographic check
    the decrypted configuration (many families fetch or derive a key)

  DYNAMIC COSTS:
    execution on your analysis machine (a real risk - not theoretical)
    time (2-10 minutes of observation, at minimum)
    infrastructure (a sandbox is a project)
    the sample's own anti-analysis is now running against you

  THE DECISION:
    if static analysis told you what it is and what it connects to,
    do not run it.
    run it only when you need something only execution can give you:
      - a C2 domain that is only assembled at runtime
      - a key that comes from the environment
      - behaviour that depends on being domain-joined
      - a determination for the report that you cannot otherwise make

  AND WHEN YOU DO, THE RULES:
    never on your primary machine
    a VM snapshot you can revert in one click
    no shared folders, no clipboard, no host mount
    outbound traffic through an isolating proxy (INetSim is free)
    record everything, and account for the sandbox detection in the
    report ("the sample checks for VMware artefacts and exits")

# Before you execute anything

- [ ] a VM, snapshotted, on a host-only network
- [ ] NO shared folders with the host
- [ ] NO clipboard sharing, NO drag-and-drop
- [ ] NO host mount points inside the guest
- [ ] outbound traffic through an isolating responder (INetSim) so
      the sample's domains resolve to *your* sinkhole and it talks to
      you, not to the real actor
- [ ] a snapshot taken, and the revert tested BEFORE you run the sample
- [ ] the sample copied in from a host-only share, then the share
      removed
- [ ] a clock note: many samples refuse to run if the date is wrong,
      so a snapshot's clock matters for reproducibility
- [ ] your notes open on a DIFFERENT machine

The report, for a triage

## Sample triage: <sha256>

**Classification**  <what it is, and what family it belongs to>
**First seen**      <earliest timestamp you found it, with its source>
**Locations**       <every path, with the volume>

**Static indicators**
- mutex:     <name>            <- the best correlator you have
- User-Agent: <string>
- PDB path:  <path>            <- leaks the developer's build directory
- compile:   <timestamp from the PE header, and how confident you are>
- packer:    <name / section names / entropy per section>
- campaign:  <the strings that tie it to a known actor, if any>

**Configuration recovered**
<the decoded config: C2 domains, intervals, the campaign ID, the
mutex, any key material>

**Network indicators**
<domains, IPs, URLs, ports, User-Agent, and where each came from>
<state clearly which are CONFIRMED by dynamic analysis and which are
 inferred from strings - the client needs to know the difference>

**Behaviour**
<what it does, in order, with the API call or artefact that proves
 each step>

**NOT DONE, and why**
<the analysis you did not perform. "The configuration was recovered
 statically; the sample was not executed, because the static
 analysis established the C2 domains and the persistence mechanism
 without it. The unpacked payload was not analysed.">

Terminology

Term Meaning
Static analysis Analysis without executing
Dynamic analysis Analysis by running it, in a sandbox
Triage The first-pass classification, before deep analysis
Overlay Data appended past the last PE section
Entropy Shannon entropy; high = compressed, encrypted, or packed
Import table The APIs the binary calls; a behaviour summary
Packer / crypter Compresses or encrypts the payload; unpacks at runtime
Mutex A named kernel object; uniquely identifies a family
PDB path Leaks the developer's build directory
PDB string \\Build\Project\release\x64\payload.pdb
Imphash A hash of the import table; clusters by capability
ssdeep Fuzzy hash; matches renamed or slightly-modified samples
XOR key The single byte (or few) used to obfuscate strings
Build strings Order-dependent string assembly
INetSim A sinkhole that answers every DNS query locally
Unpacking Dumping the payload from memory at runtime

# --- 5. the full triage script ---
cat > triage.sh <<'EOF'
#!/usr/bin/env bash
# Static triage. NEVER executes the file.
F="${1:?usage: ./triage.sh <file>}"
[ -f "$F" ] || { echo "no such file"; exit 1; }
echo "=============================================================="
echo " STATIC TRIAGE: $F"
echo " (nothing here executes the file)"
echo "=============================================================="

echo; echo "=== 1. IDENTITY ==="
sha256sum "$F" | sed 's/^/  sha256: /'
sha1sum   "$F" | sed 's/^/  sha1  : /'
md5sum    "$F" | sed 's/^/  md5   : /'
ssdeep -b "$F" "$F" 2>/dev/null | tail -1 | sed 's/^/  ssdeep: /' || true
echo "  size  : $(stat -c%s "$F") bytes"

echo; echo "=== 2. TYPE ==="
file "$F" | sed 's/^/  /'
exiftool -s -s -s "$F" 2>/dev/null | head -15 | sed 's/^/  /'

echo; echo "=== 3. STRUCTURE ==="
if objdump -x "$F" >/dev/null 2>&1; then
  objdump -x "$F" 2>/dev/null | grep -A25 "Sections:" | sed 's/^/  /'
  echo
  echo "  --- imports: the behaviour, in API names ---"
  objdump -p "$F" 2>/dev/null | grep -E "DLL Name" | sed 's/^/  /'
else
  readelf -h "$F" 2>/dev/null | sed 's/^/  /' || echo "  (not an ELF)"
fi

echo; echo "=== 4. ENTROPY PER REGION (high = packed) ==="
python3 - "$F" <<'PY'
import sys, math, collections
d = open(sys.argv[1],"rb").read()
if not d: sys.exit()
def ent(b):
    if not b: return 0.0
    c = collections.Counter(b); n = len(b)
    return -sum((v/n)*math.log2(v/n) for v in c.values())
print(f"  whole file : {ent(d):.3f} / 8.0")
for i in range(0, min(len(d), 4*1024*1024), 65536):
    print(f"  offset {i:#08x}: {ent(d[i:i+65536]):.3f}")
PY

echo; echo "=== 5. STRINGS, ASCII then UTF-16 ==="
strings -a -n 6 "$F" | head -30 | sed 's/^/  /'
echo "  --- wide ---"
strings -a -el -n 6 "$F" | head -15 | sed 's/^/  /'

echo; echo "=== 6. INDICATORS, EXTRACTED ==="
strings -a -n 6 "$F" | grep -oiE "https?://[^\"' ]+" | sort -u | sed 's/^/  url   : /'
strings -a -el -n 6 "$F" | grep -oiE "https?://[^\"' ]+" | sort -u | sed 's/^/  url(w): /'
strings -a -n 6 "$F" | grep -oE "\b[0-9]{1,3}(\.[0-9]{1,3}){3}\b" | sort -u | sed 's/^/  ip    : /'
strings -a -n 6 "$F" | grep -oiE "[a-z0-9-]+\.(com|net|org|ru|cn|io|top|xyz|onion)" | sort -u | sed 's/^/  domain: /'
strings -a -n 6 "$F" | grep -oE "\\\\[A-Za-z]:\\\\[^ ]*|HK(LM|CU)\\\\[^ ]*" | head -10 | sed 's/^/  path  : /'
strings -a -n 6 "$F" | grep -oiE "user-agent: *[^\"]*|Mozilla/[0-9.]+" | sort -u | sed 's/^/  ua    : /'
strings -a -n 6 "$F" | grep -oE "[A-Za-z]:\\\\[^ ]*\.pdb" | sed 's/^/  pdb   : /'

echo; echo "=== 7. THE FIRST QUESTION, ANSWERED ==="
echo "  What is it, what does it do, who does it talk to."
echo "  If all three are answered above, you do not need to run it."
EOF
chmod +x triage.sh
./triage.sh lab-sample.bin 2>&1 | tee 05-triage.txt

Step 5 is the deliverable: triage.sh, a single static triage that extracts hash, type,
sections, imports, per-region entropy, both ASCII and UTF-16 strings, and then pulls out URLs,
IPs, domains, registry paths, User-Agents and the PDB string — without executing a byte. It
closes with the decision rule: if all three questions are answered, you don't need to run it.

06-decision.md gives you the paragraph to write either way — including the not performed
version, which is a stronger piece of analysis than "I ran it on my laptop" because it states
what you established, what you did not, and why.
