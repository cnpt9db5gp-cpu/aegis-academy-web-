Buffer Overflow Defences

Summary

This is 6.858's Lab 1 lecture. Buffer overflows have been the dominant remote code execution
bug for thirty years, and every defence here was built in response to a specific attack.

Key ideas

  • Stack canaries (guard values) — detect, do not prevent
  • Non-executable stack (W^X / NX) — prevent direct shellcode, force ROP
  • ASLR / PIE — raise the cost of guessing addresses
  • Safe languages / memory-safe languages — remove the class entirely
  • Baggy bounds checking — the lecture's preparation reading: add redundant bounds metadata
    so out-of-bounds accesses are detected precisely
  • Defences are layered, and each layer shifts the attacker to the next technique

The attack/defence progression

Year Attack Defence Attacker moves to
1988 Morris worm, strcpy overflows safe string functions other unbounded copies
1996 Stack smashing stack canaries leak the canary first
1999 Return-to-libc NX / non-executable stack ROP, ret2libc
2001 Brute-force ASLR ASLR + PIE information leak
2005 Heap overflows heap canaries, safe allocators use-after-free
2010+ Heartbleed-style leaks leak-resistant design side channels

The lesson: each defence works, and each pushes the attacker somewhere else. None eliminates
the underlying memory-safety problem — which is why memory-safe languages are the real answer.

What each defence actually does

Defence Mechanism Detects/prevents Cost
Canary random value before the return address, checked at exit overflow that corrupts it ~1 cycle per function
NX page table forbids execute on stack/heap running injected code essentially free
ASLR randomise load addresses reliably guessing addresses rare address-space exhaustion
PIE randomise the binary base same negligible
Stack protector canary, only on functions needing it partial near zero
Safe functions bounded copies overflow via that function nil
Baggy bounds redundant per-object bounds metadata precise OOB detection memory + complexity

Baggy bounds, the lecture's reading

Instead of one check per access, store an explicit bound with every object reference. A
pointer into the middle of an array carries enough information to know which array it belongs to
and where the bound is.

  • The compiler generates the metadata; the hardware compares on every access
  • Out-of-bounds is detected exactly, not probabilistically
  • Costs memory and code size
  • This is a structural fix rather than a bolt-on

Terminology

Term Meaning
Stack canary Guard value between locals and the return address
__stack_chk_fail Handler invoked on canary mismatch
NX / W^X A page is writable or executable, never both
ASLR Randomised load addresses per process
PIE Position-independent executable
RET2LIBC Return into existing libc functions
ROP Chain instruction sequences ending in ret
Info leak Obtaining an address the binary hid
Baggy bounds Per-reference bounds metadata, checked in hardware
Safe function Bounded copy such as strncpy
Format string bug Attacker data used as a format specifier

Kali commands

# --- audit a binary's defences ---
checksec --file=./target
readelf -s ./target | grep stack_chk_fail
readelf -lW ./target | grep GNU_STACK
readelf -d ./target | grep -E "BIND_NOW|FLAGS"

# --- is the canary actually random and per-thread? ---
# the canary lives at fs:0x28 (the thread control block)
python3 - <<'PY'
import ctypes, struct
# TLS access via the arch_prctl interface is not exposed in ctypes,
# so read it the observable way: compile a tiny probe.
print("  compile: gcc -fstack-protector probe.c -o probe && run it twice")
PY
cat > probe.c <<'EOF'
#include <stdio.h>
#include <stdint.h>
/* read fs:0x28 by hand: the canary slot */
static uint64_t canary(void) {
    uint64_t v;
    __asm__ volatile("mov %%fs:0x28, %0" : "=r"(v));
    return v;
}
void f(void) { char b[8]; volatile char c = b[0]; (void)c; }
int main(void) {
    printf("  canary #1: 0x%016lx\n", canary());
    f();
    printf("  canary #2: 0x%016lx  (same process, must be identical)\n", canary());
    return 0;
}
EOF
gcc -fstack-protector probe.c -o probe && ./probe && echo && ./probe
echo "  ^ same within a process, different between processes"
rm -f probe.c probe

# --- is ASLR on here? ---
cat /proc/sys/kernel/randomize_va_space
sudo sysctl kernel.randomize_va_space
for i in 1 2 3; do
  python3 -c "import ctypes; print('  heap:', hex(ctypes.addressof(ctypes.create_string_buffer(8))))"
done

# --- detect a canary failure in the wild ---
# SIGABRT with the message '*** stack smashing detected ***'
dmesg 2>/dev/null | grep -i "stack smashing\|general protection" | tail -3

# --- compile the same bug three ways and compare ---
printf '#include <string.h>\n#include <stdio.h>\nvoid f(const char*i){char b[16];strcpy(b,i);printf("%%s",b);}\nint main(int c,char**v){f(c>1?v[1]:"x");}\n' > b.c
gcc -O0 -g -fno-stack-protector b.c -o b_weak
gcc -O0 -g -fstack-protector b.c -o b_canary
gcc -O2 -g -fstack-protector -D_FORTIFY_SOURCE=2 b.c -o b_full
for b in b_weak b_canary b_full; do
  printf "  %-9s " "$b"
  ./$b "$(python3 -c 'print("A"*64)')" >/dev/null 2>&1
  echo "exit=$?  $(checksec --file=./$b 2>/dev/null | grep -ci canary) canary-flag"
done
rm -f b.c b_weak b_canary b_full

Field lab

Objective: observe the canary's behaviour directly, measure ASLR, and watch each defence
stop the same attack.

mkdir -p ~/aegis/labs/mit858-04 && cd ~/aegis/labs/mit858-04

# --- 1. READ THE CANARY OUT OF THE THREAD CONTROL BLOCK ---
cat > canary.c <<'EOF'
#include <stdio.h>
#include <stdint.h>
static uint64_t canary(void) {
    uint64_t v;
    __asm__ volatile("mov %%fs:0x28, %0" : "=r"(v));
    return v;
}
void use_stack(void) { volatile char buf[64]; buf[0] = 1; }
int main(void) {
    printf("  canary at entry : 0x%016lx\n", canary());
    use_stack();
    printf("  canary after    : 0x%016lx  (unchanged: it is per-thread, not per-call)\n", canary());
    printf("  low byte        : 0x%02lx  (always zero on Linux x86-64)\n", canary() & 0xff);
    return 0;
}
EOF
gcc -fstack-protector -O0 -g canary.c -o canary && ./canary | tee 01-canary.txt
echo
./canary | sed 's/canary at entry/second run/' | tee -a 01-canary.txt
echo
echo "  Different between runs = randomised. Same within a run = per-thread."
echo "  Low byte always 0x00 = why a naive string overwrite stops there."
rm -f canary.c canary

# --- 3. NX, observed ---
echo
echo "=== NX: can you execute code on the stack? ==="
python3 - <<'PY'
import ctypes
libc = ctypes.CDLL("libc.so.6")
buf = ctypes.create_string_buffer(64)
addr = ctypes.addressof(buf)

print(f"  mprotect(RWX) on a stack page -> {r} ({'refused: NX enforced' if r != 0 else 'granted'})")

# --- 4. ONE BUG, THREE DEFENCES ---
cat > b.c <<'EOF'
#include <string.h>
#include <stdio.h>
#include <unistd.h>
void f(const char *i) { char b[16]; strcpy(b, i); printf("%s\n", b); }
int main(int c, char **v) { if (c > 1) f(v[1]); return 0; }
EOF
gcc -O0 -g -fno-stack-protector          b.c -o b_weak
gcc -O0 -g -fstack-protector-strong       b.c -o b_canary
gcc -O2 -g -fstack-protector-strong -D_FORTIFY_SOURCE=2 -pie -fPIE b.c -o b_full
PAY=$(python3 -c 'print("A"*64)')
{
  echo "=== the same bug, three builds ==="
  for b in b_weak b_canary b_full; do
    echo
    echo "  ---- $b ----"
    checksec --file=./$b 2>/dev/null | grep -E "canary|NX|PIE|RELRO" | sed 's/^/    /'
    ./$b "$PAY" >/dev/null 2>&1; rc=$?
    printf "    overflow exit code : %s\n" "$rc"
    case $rc in
      0)   echo "    outcome           : RETURNED (no crash - corruption may be silent)" ;;
      134) echo "    outcome           : SIGABRT - the canary caught it" ;;
      139) echo "    outcome           : SIGSEGV - corrupted return address" ;;
      *)   echo "    outcome           : other" ;;
    esac
  done
} 2>&1 | tee 03-three-builds.txt
cat 03-three-builds.txt

# --- 5. what each defence forces you to do next ---
cat > 04-escalation.txt <<'EOF'
  canary present  -> leak the canary (over-read or format string) first
  NX present      -> no shellcode on the stack; use ROP or ret2libc
  PIE + ASLR      -> leak a code or libc address first
  Full RELRO      -> GOT is read-only; find another write primitive

  All three -> leak, leak, then ROP.
  That is the modern exploit chain, and every stage exists because of a defence above.
EOF
cat 04-escalation.txt

# --- 6. the honest conclusion ---
cat > 05-conclusion.md <<'EOF'
# Why memory-safe languages are the real answer

Buffer overflow defences are all *detection or cost*. None prevents the write
happening:

- canary: detects after the corruption
- NX: prevents execution, not the write
- ASLR: makes guessing hard, not impossible
- bounds metadata: detects, with overhead

They raise the price of exploitation enormously, and they have shifted the
attacker economy toward **logic bugs and misconfiguration** — which no compiler
flag can find.

Therefore the structural fix is to remove the class of bug:
- memory-safe languages (Rust, Go, Java, C#, Python)
- or, in C, memory-safe abstractions plus aggressive sanitizers in development

Sanitizers are worth calling out: `-fsanitize=address` finds the overflow at
the exact source line on the first run. If you write one line of C, build it
with ASan during development. It costs nothing at runtime in production if you
build without it.
EOF
cat 05-conclusion.md

Step 1 is the standout — reading the canary straight out of fs:0x28 with inline assembly,
and observing it is random per process but constant per thread. That is the mechanism, not a
description of it.
