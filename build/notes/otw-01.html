Bandit Levels 11-20: git, more encoding, pipes, /etc/shadow

Summary

Levels 11-20 introduce git (finding a stashed or deleted password), more encoding work,
/etc/passwd and /etc/shadow parsing, and pipes. The theme is reading data from places a
first-time user does not look: repositories, shadow files, and process output.

Level notes

Level 11 — git has the password in its history.

ls -la
cat .git/config
git log --oneline --all
git show                 # the commit content
git log -p --all         # every commit WITH its diff
cat .git/logs/HEAD       # raw reflog, sometimes more revealing

The lesson: a .git directory is a complete history of the project, including things later
deleted. On a web target, an exposed .git hands over the source. This is exactly the
misconfiguration class from ms-04.

Level 12 — the port is in the gzipped git pack.

ls -la
zcat .git/objects/pack/*.pack.gz | strings | grep port

zcat (or gunzip -c) decompresses to stdout, so it pipes. Compressed data is just more data.

Level 13 — SSH key permission issues.

ls -la
chmod 600 id_rsa
ssh-keygen -y -f id_rsa      # derive the public key without logging in
ssh bandit13@localhost -i id_rsa
chmod 644 id_rsa.pub

chmod 600 is required because SSH refuses overly-permissive private keys — a small but real
example of permissions affecting behaviour.

Level 14 — a crackable hash.

ls -la
cat /etc/shadow | grep bandit14
john --wordlist=/usr/share/wordlists/rockyou.txt --show hash.txt

Or identify it and let hashcat use the GPU:

hashid hash.txt
hashcat -m 1400 hash.txt /usr/share/wordlists/rockyou.txt

Level 15 — find the hash, then the password for it.

find / -readable -type f -exec grep -l "hash" {} \; 2>/dev/null
cat /etc/shadow | grep bandit15
john --wordlist=/usr/share/wordlists/rockyou.txt --show hash.txt

Level 16 — one hash leads to a user's password, which unlocks the next level.

for i in $(seq 0 15); do
  grep bandit$i /etc/shadow
done
john --wordlist=/usr/share/wordlists/rockyou.txt --show hash.txt
ssh bandit15@localhost -p 2220

Level 17 — a crackable password behind an SSHD config and a MySQL user.

ss -tulpn                 # find the running services
cat /etc/ssh/ssh_config   # find the non-standard port
cat /etc/mysql/mariadb.conf.d/mariadb.cnf
# find and crack the hash, then connect to mysql with the recovered password

ss is the modern replacement for netstat and you should use it everywhere.

Level 18 — shell differences.

diff /etc/passwd bandit18 2>/dev/null   # 'diff' the shell builtin vs the binary
type -a diff
which diff

type -a is the command that tells you whether something is a builtin, an alias, or a binary —
and where it lives. Genuinely important when a tool behaves differently than you expect.

Level 19 — a config file with readable credentials.

ls -la
cat /etc/passwd | grep bandit19
ls -la /etc/bandit/ 2>/dev/null
cat /etc/bandit/passwd   # or whatever the readable config points at

Kali commands

# --- git archaeology ---
git log --oneline --all
git log -p --all
git show
cat .git/logs/HEAD
git stash list
git fsck --lost-found         # dangling commits from reset --hard
strings .git/objects/pack/*.pack | grep -i pass

# --- compression into a pipe ---
zcat file.gz | strings | grep pattern
gunzip -c file.gz > out
unzip -p archive.zip file     # extract to stdout without unpacking

# --- hashes, the two-tool approach ---
sudo cat /etc/shadow | grep '^bandit1[4-6]:' | cut -d: -f1,2 > /tmp/h.txt
hashid /tmp/h.txt
john --wordlist=/usr/share/wordlists/rockyou.txt --show /tmp/h.txt
hashcat -m 1311 /tmp/h.txt /usr/share/wordlists/rockyou.txt

# --- where things are ---
type -a diff
command -v diff
which -a diff
ss -tulpn
find /etc -name "*bandit*" -o -name "*.conf" 2>/dev/null | head

Field lab

Objective: clear levels 11-20 and note every place a password hid that you did not expect.

mkdir -p ~/aegis/labs/otw-01 && cd ~/aegis/labs/otw-01

ssh bandit11@bandit.labs.overthewire.org -p 2220

On the box, maintain the journal — the locations are the lesson:

cat >> ~/my-notes.txt <<'EOF'

## Where Bandit hid things (11-20)
- git object database      : .git/objects, .git/logs/HEAD
- compressed               : .git/objects/pack/*.pack.gz (use zcat | strings)
- hashes                   : /etc/shadow (john / hashcat)
- service config           : /etc/ssh/ssh_config, /etc/mysql/*
- shadowed vs built-in     : type -a / command -v / which -a
EOF
cat ~/my-notes.txt

Back on Kali, build the reverse-lookup reference:

cd ~/aegis/labs/otw-01
cat > 01-hiding-places.md <<'EOF'
# Where credentials hide

| Place | How to read it |
|---|---|
| `.git` history | `git log -p --all`, `cat .git/logs/HEAD` |
| `.git` packfiles | `zcat .git/objects/pack/*.pack.gz \| strings` |
| deleted commits | `git fsck --lost-found` |
| `/etc/shadow` | `sudo grep '^user:' /etc/shadow`, then john/hashcat |
| SSH keys | `chmod 600`, then `ssh -i` |
| service configs | `/etc/ssh/`, `/etc/mysql/`, `/etc/apache2/` |
| process list | `ss -tulpn`, `ps aux` |
| environment | `/proc/PID/environ` |
| shell history | `~/.bash_history` |
| compressed files | `zcat`, `unzip -p`, `bzip2 -dc` |
EOF
cat 01-hiding-places.md | tee 01-hiding-places.txt

# --- practise the git archaeology on YOUR OWN repo ---
cd ~/Projects/aegis-academy
{
  echo "=== deleted content still recoverable from git ==="
  git log --oneline | head -10
  echo
  echo "=== search every historical commit for a secret ==="
  git log -p --all | grep -iE "(password|api[_-]?key|BEGIN .*PRIVATE KEY)" | head -5 || echo "  none found"
  echo
  echo "=== this is why .gitignore exists ==="
  git check-ignore -v transcripts/foo.vtt
} | tee -a 02-git-on-aegis.txt

Step 3 on your own repository is the professional habit. A committed secret is still a
secret three years later.

Self-test

  1. Why does an exposed .git directory leak the whole project?
  2. What does zcat file.gz | strings | grep x do, step by step?
  3. Why does SSH refuse a world-readable private key?
  4. What is the difference between type -a diff and which diff?
  5. A secret was committed by mistake. Why is deleting it in a new commit insufficient?
