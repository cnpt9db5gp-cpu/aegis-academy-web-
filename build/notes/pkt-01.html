Capturing on Loopback with tcpdump and BPF Filters

Summary

Capturing is a privilege, and tcpdump is where it starts. Filters are the part worth learning
properly — an unfiltered capture is unusable, and a badly filtered one silently misses the thing
you were looking for.

Key ideas

  • Capture needs CAP_NET_RAW, which is why raw sockets require root
  • BPF (Berkeley Packet Filter) is the compiled filter language inside libpcap
  • Capture filter (what is written to disk) versus display filter (what you look at) —
    confusing them wastes hours
  • tcpdump stores packets to disk first; the display happens later on the file
  • Promiscuous mode is per-interface and required to see other hosts' traffic
  • Snaplen truncates the payload; full packets matter for protocol analysis

Terminology

Term Meaning
BPF The filter language libpcap compiles and attaches
Capture filter Applied at capture time, reduces what is stored
Display filter Applied at read time, e.g. Wireshark/tshark syntax
PCAP libpcap capture file format
Snaplen Bytes captured per packet
Promiscuous Deliver all frames to this host
pcapng The newer, richer capture format
Ring buffer Kernel buffer between NIC and the capture socket

Kali commands

# --- capability check ---
getcap /usr/bin/tcpdump
sudo -n tcpdump --version 2>&1 | head -2

# --- loopback, no root needed in some configs; usually root is required ---
sudo tcpdump -i lo -c 10 2>&1 | head -12

# --- the filters you will actually use ---
sudo tcpdump -i lo "tcp port 80"
sudo tcpdump -i lo "udp and port 53"
sudo tcpdump -i lo "arp"
sudo tcpdump -i lo "icmp"
sudo tcpdump -i lo "host 127.0.0.1 and port 22"
sudo tcpdump -i lo "net 192.168.56.0/24"
sudo tcpdump -i lo "src 127.0.0.1 and dst port 8080"
sudo tcpdump -i lo "tcp[tcpflags] & tcp-syn != 0"      # SYN packets only
sudo tcpdump -i lo "not port 22 and not port 53"        # exclude noise
sudo tcpdump -i lo "tcp port 80 or udp port 53"

# --- save, then read ---
sudo tcpdump -i lo -w capture.pcap -s 0 'tcp port 8080'   # -s 0 = full packets
sudo tcpdump -r capture.pcap -n | head
tcpdump -r capture.pcap -A | head -40                       # ASCII payload

# --- counting, the fastest way to see what is flowing ---
sudo timeout 10 tcpdump -i any -n 2>/dev/null | awk '{print $5}' | sort | uniq -c | sort -rn | head
sudo timeout 10 tcpdump -i any -n 2>/dev/null | grep -c SYN

# --- statistics ---
sudo timeout 10 tcpdump -i any -n 2>/dev/null | tail -5

Field lab

Objective: capture cleanly on loopback, build a filter library, and prove capture-filter
versus display-filter.

# --- PRE-FLIGHT: this lab needs root, so authenticate ONCE, HERE, first ---
# `sudo something &` backgrounds the password PROMPT along with the command.
# With no terminal attached to answer it, sudo fails - and `2>/dev/null`
# then throws away the only clue. The result is a capture file that was
# never written, followed by a screenful of "no such file".
#
# `sudo -v` validates the credential in the FOREGROUND, where you can see
# and answer the prompt. It caches for ~15 minutes, so every backgrounded
# `sudo` below is prompt-free and actually runs.
if ! sudo -v; then
  echo "  sudo is unavailable or the password was wrong - stop here." >&2
  echo "  Everything below needs root. Nothing will be captured." >&2
  exit 1
fi
mkdir -p ~/aegis/labs/pkt-01 && cd ~/aegis/labs/pkt-01

# --- 1. the simplest possible capture ---
sudo timeout 10 tcpdump -i lo -n -c 20 2>&1 | tee 01-basic.txt
echo "  Read the columns: time, source, >, destination, flags, length."

# --- 2. capture with a filter, in one terminal while you generate traffic ---
sudo timeout 20 tcpdump -i lo -n -w 02-filtered.pcap -s 0 'tcp port 8080' 2>/dev/null &
CAP=$!
sleep 1
( nc -l -p 8080 >/dev/null 2>&1 & )
sleep 1
for i in $(seq 1 5); do echo "message $i" | timeout 2 nc 127.0.0.1 8080 2>/dev/null; done
sleep 4; kill $CAP 2>/dev/null; wait $CAP 2>/dev/null
echo "=== capture-filtered file ==="
sudo tcpdump -r 02-filtered.pcap -n 2>/dev/null | head -8
echo
echo "=== how many packets did the filter let through? ==="
sudo tcpdump -r 02-filtered.pcap -n 2>/dev/null | wc -l

# --- 3. THE SAME CAPTURE, read without the filter ---
sudo timeout 15 tcpdump -i lo -n -w 03-all.pcap -s 0 2>/dev/null &
CAP2=$!
sleep 1
( nc -l -p 8080 >/dev/null 2>&1 & )
sleep 1
for i in $(seq 1 5); do echo "message $i" | timeout 2 nc 127.0.0.1 8080 2>/dev/null; done
sleep 4; kill $CAP2 2>/dev/null; wait $CAP2 2>/dev/null
echo "=== unfiltered file: what else was on the wire? ==="
sudo tcpdump -r 03-all.pcap -n 2>/dev/null | head -12
echo
echo "total packets unfiltered: $(sudo tcpdump -r 03-all.pcap -n 2>/dev/null | wc -l)"
echo "total packets filtered  : $(sudo tcpdump -r 02-filtered.pcap -n 2>/dev/null | wc -l)"
echo
echo "That difference is why you filter at capture time: less disk, less noise,"
echo "and no risk of the interesting packet having scrolled past."

# --- 4. build the filter library ---
cat > 04-filters.txt <<'EOF'
# BPF filter library - tcpdump capture filters

# basics
host 10.0.0.5                 # that host, either direction
src host 10.0.0.5
dst port 443
net 192.168.56.0/24           # CIDR works
portrange 4000-4100

# protocol combinations
tcp and port 22
udp and port 53
icmp
arp

# negation (exclude the noise)
not port 5353                 # mDNS noise
not (tcp port 22 or tcp port 53)

# state
tcp[tcpflags] & tcp-syn != 0        # SYNs only (scan detection)
tcp[tcpflags] & tcp-rst != 0        # resets
tcp[tcpflags] & tcp-fin != 0

# byte offsets (rarely needed, but powerful)
ip[0] & 0x0f > 5                 # IP options present

# practical combinations
(host 192.168.56.101) and (tcp port 80 or tcp port 443)
tcp port 445 and greater 100       # only large SMB frames
EOF
cat 04-filters.txt
cat 04-filters.txt | while read -r line; do :; done
echo "  filters written to 04-filters.txt"

# --- 5. is anything suspicious flowing right now? ---
{
  echo "=== SYN-only frames in 10 seconds (scan detection heuristic) ==="
  sudo timeout 10 tcpdump -i any -n "tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0" 2>/dev/null \
    | wc -l
  echo "  (a burst of SYN-without-ACK from one source = a scan)"
  echo
  echo "=== ARP traffic in 10 seconds (spanning tree, discovery, or poisoning) ==="
  sudo timeout 10 tcpdump -i any -n "arp" 2>/dev/null | wc -l
  echo
  echo "=== ICMP traffic (reachability, or tunnelling) ==="
  sudo timeout 10 tcpdump -i any -n "icmp" 2>/dev/null | wc -l
} 2>&1 | tee 05-baseline.txt

Step 5 is the habit worth building — a ten-second baseline of "what is normal here" makes
anomalies obvious later.

Record: 04-filters.txt — keep this, you will use it every session.
