LDAP Enumeration and BloodHound Graph Analysis

Summary

LDAP is the interface to the directory, and it is almost entirely unauthenticated-readable by
default. That is the single most important fact about AD reconnaissance: the majority of the
attack surface can be enumerated with no credentials at all.

The lecture's structure: what LDAP lets you ask anonymously, what it lets
you ask with a user, and why the graph derived from those answers is
what makes AD attacks tractable at all.

LDAP as a query language

  EVERY OBJECT has a DN, a set of attributes, and a class.

  FILTER syntax (RFC 4515):
    (&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=512))
      AND   objectClass=user
      AND   userAccountControl has bit 512 set (normal account)
              ^ "userAccountControl:1.2.840.113556.1.4.803" is the
                extensible match for "bitwise AND contains value"

  KEY BIT VALUES in userAccountControl - you will see these constantly:
    0x0002  ACCOUNTDISABLE
    0x0001  SCRIPT                      (password need not change)
    0x0040  DONT_EXPIRE_PASSWORD
    0x0100  HOMEDIR_REQUIRED
    0x0200  LOCKOUT
    0x0400  PASSWD_NOTREQD
    0x0800  PASSWD_CANT_CHANGE
    0x1000  ENCRYPTED_TEXT_PASSWORD_PWD
    0x2000  TEMP_DUPLICATE_ACCOUNT
    0x4000  NORMAL_ACCOUNT
    0x8000  INTERDOMAIN_TRUST_ACCOUNT
    0x100000 DONT_REQ_PREAUTH          <- AS-REP roastable (ad-04)
    0x200000 TRUSTED_FOR_DELEGATION
    0x400000 PARTIAL_SECRETS_ACCOUNT
    0x800000 AS_REQ_WRITEABLE          <- SipHash-2-4, below

  THE TWO HIGH-VALUE BITS:
    0x100000  DONT_REQ_PREAUTH      -> AS-REP roastable. A finding.
    0x200000  TRUSTED_FOR_DELEGATION -> the account can request
                                       tickets for any user (unconstrained
                                       delegation, ad-02)

What you can ask without credentials

  THE ANONYMOUS SURFACE, and it is often still open:

    rootDSE                     naming contexts, DNS host, functional level
    base object                 the domain's attributes
    configuration container     the forest schema. The whole class list.
    CN=Users / OU=Users         every user object, with attributes
    computer objects            every machine account
    domainDNS objects           dnsHostName, distinguishedName, dc
    SPN attributes              servicePrincipalName on every object
    group memberships           msMemberOf
    the Global Catalog (3268)   a forest-wide copy: every object in every
                                domain, with fewer attributes

  THE ONE THAT MATTERS MOST:
    EVERY OBJECT's msDS-SupportedEncryptionTypes is readable anonymously.
    This tells you, without any credentials, WHICH ACCOUNTS ARE
    KERBEROASTABLE. No SPN enumeration needed for the RC4 ones -
    AES support is visible on the object.

  THE "MIT KERBERO5" SITUATION:
    Modern Windows Server 2022 defaults to AES-only, which removes the
    automatic RC4 service tickets that made roasting trivial.
    To find the exception, query for accounts that still have RC4
    support. Those are the findings.

What a user can read beyond that

  AN AUTHENTICATED USER can additionally:
    - read the members of most groups (msMemberOf is not write-protected
      for reading)
    - read the ACL of most objects (READ_CONTROL is granted to
      Authenticated Users on most objects by default)
    - read the domain controllers list
    - read userAccountControl, pwdLastSet, lastLogonTimestamp for
      everyone -> a dormant-account map

  THE CONSEQUENCE:
    you can build the ENTIRE AD graph, including every ACL edge,
    as a normal user. BloodHound (bh-01, bh-02) does exactly this.

  THE QUESTION THIS RAISES IN AN ASSESSMENT:
    "can a standard user enumerate the entire privilege graph?"
    If yes, that is a Medium finding in its own right, because it
    means an attacker knows exactly which single misconfiguration
    to look for before touching the domain.

The Graph: why the graph, not the list

  A LIST OF ACCOUNTS tells you who exists.
  A LIST OF ACCOUNTS AND GROUPS tells you who is in what.
  A GRAPH tells you who CAN REACH WHAT, and by how few steps.

  THE THREE EDGE TYPES in a BloodHound graph:

    ALLOW      principal --(HasSession/AddKeyCredentialLink)--> object
               or principal --(GenericAll/WriteDACL)--> object
               "this principal can become / act as that object"

    SESSION    user --HasSession--> computer
               "this user is authenticated to that machine right now"
               The most immediately exploitable edge in AD.
               (imp-03 is exactly this: relay a session.)

    GROUP      user --MemberOf--> group --GenericAll--> Domain Admins
               The one everyone starts with. Usually longer than 1 hop.

  THE POWER OF THE GRAPH:
    it is the answer to "what is the SHORTEST path from a normal
    user to Domain Admin", which is the only question that matters.
    Two accounts are in a group nobody has heard of, that group has
    GenericAll on a service account, and that service account has
    WriteDACL on the Domain object. Nobody finds that by reading.
    The graph finds it in one query.

The queries that matter

  THE THREE THAT MATTER

  1. Shortest path from any principal to Domain Admins
       "WHERE can this domain admin exposure come from?"
       Usually one of:
         - a user with an admin-equivalent ACE
         - a service account in Domain Admins
         - a group with GenericAll on a privileged group
         - a computer account with GenericAll (a SHORTCUT: you can
           read a computer's hash and get its privileges)

  2. Shortest path to DOMAIN ADMIN, including DCSync
       "-Edge DCSync" gives every principal that can replicate the
       directory. This is separate from Domain Admin membership and
       is usually the more surprising finding.

  3. All principals with SPNs, or with delegation, or preauth disabled
       "where should I spend my cracking time?"
       These are the objects that pay off.

  THE OTHERS WORTH LEARNING
    - paths to a specific high-value target (a SQL admin, a backup
      administrator, an Exchange admin)
    - "all sessions" -> who is authenticated where, right now
    - "shortest path to DCSync via ACL" -> the LDAP/SMB relay surface
    - "owned" -> what your own compromised principal can reach

Tools, and what each one actually collects

  BLOODHOUND / SHARPHOUND
    the graph. SharpHound (C#, Windows, runs as a domain user),
    SharpHoundPython (Linux, uses ldap + smb), or
    bloodhound-python (Linux, all-ldap / all-bloodhound / all-smbsession)
    Output: a zip containing a .sqlite database and a .json ingest file

  LDAPSEARCH
    the raw queries. No graph. Best for scripted, narrow enumeration.

  NETEXEC / CRACKMAPEXEC
    module collection: SMB signing, LDAP signing, users, groups, shares,
    sessions, delegation, vuln checks. Fast, opinionated, noisy.
    (netexec is the maintained successor to crackmapexec.)

  IMPACKET (imp-01..imp-04)
    the protocol-level work: shares, hashes, tickets, relay.

  THE DIVISION OF LABOUR:
    BloodHound tells you WHERE. Impacket and netexec let you GO there.
    Doing the second without the first means scanning for hours
    to find something the graph would have given you in seconds.

Collection discipline

  COLLECTION IS ACTIVE ENUMERATION. It generates traffic. It can trip
  detection. So:

    - confirm in the ROE that AD enumeration is in scope, and note the
      source IPs you will use so the client's SIEM can attribute it
    - collect from ONE host, not a spray. Twenty queries from one box
      is 1/20th of the traffic of 20 boxes
    - prefer LDAP (port 389) over RPC (port 49152+) where possible;
      LDAP is rate-limited and logged, RPC is neither
    - do not run "all-bloodhound" against production on a Friday
    - store the collection securely. SharpHound output contains the
      group memberships of the entire domain and an offline copy of
      every hash it can read.

  WHAT A COLLECTION CONTAINS, AND WHY IT IS SENSITIVE:
    every user, every group membership, every session, every ACL edge,
    and possibly every machine account hash (with -CollectionMethod
    SessionLoop). That last one is a full hash dump, and it is in the
    zip file sitting on your laptop.

Terminology

Term Meaning
LDAP The directory query protocol; tree-structured, DN-addressed
DN Distinguished name; the LDAP path of an object
Filter RFC 4515 query syntax, with &, |, !, and matches
Extensible match attr:1.2.840.113556.1.4.803:=value for bit tests
userAccountControl The account flags bitfield
DONT_REQ_PREAUTH (0x100000) AS-REP roastable
TRUSTED_FOR_DELEGATION (0x200000) Unconstrained delegation
AS_REQ_WRITEABLE (0x800000) SipHash-2-4 (2018 patch, enabled by default since 2019)
RootDSE The directory's own object; ldapsearch -b "" -s base
Global Catalog (3268) Forest-wide read-only copy
msDS-SupportedEncryptionTypes Which Kerberos encryption an account supports
msMemberOf The group memberships of an object
Graph Principals, groups, sessions and ACLs as edges
HasSession A user is authenticated to a machine now
DCSync edge A principal that can replicate the directory
SharpHound C# collector; bloodhound-python is the Linux one
netexec The maintained fork of crackmapexec

#!/usr/bin/env bash
# ANONYMOUS LDAP enumeration. Read-only, no credentials.
# Requires an explicit DC inside the lab range. There is no default target.
DC="${1:?usage: ./02-anonymous.sh 192.168.56.10}"
b=$(echo "$DC" | cut -d. -f1)
case "$b" in 192.168.56.*|10.10.10.*|127.*) ;;
  *) echo "REFUSED: $DC is outside the lab range." >&2; exit 3 ;; esac

echo "[scope] $DC in range; every query below is ANONYMOUS and read-only"
echo

echo "=== 1. rootDSE: what does this DC tell a stranger? ==="
ldapsearch -x -H "ldap://$DC" -b "" -s base \
  namingContexts defaultNamingContext \
  supportedLDAPVersion supportedControl supportedExtension \
  dnsHostName forestFunctionalityLevel domainFunctionalityLevel \
  2>/dev/null | grep -E "^[a-zA-Z]+:" | sed 's/^/  /'
echo "  ^ if this returns data, anonymous bind is OPEN. Record it."

NC=$(ldapsearch -x -H "ldap://$DC" -b "" -s base defaultNamingContext \
     2>/dev/null | grep -m1 "^defaultNamingContext:" | awk '{print $2}')
echo "  naming context: ${NC:-unknown}"
echo

echo "=== 2. the domain object: functional level, netBIOS name ==="
ldapsearch -x -H "ldap://$DC" -b "${NC:-DC=lab,DC=internal}" -s base \
  dc netbiosname whenCreated objectSid 2>/dev/null | grep -E "^[a-zA-Z]+:" | sed 's/^/  /'
echo

echo "=== 3. the configuration container: the forest schema ==="
echo "  (huge. Just count the classes - it is the schema for everything.)"
ldapsearch -x -H "ldap://$DC" -b "CN=Configuration,${NC:-DC=lab,DC=internal}" \
  "(objectClass=subSchemaSubentry)" dn 2>/dev/null | grep -c "^dn:" \
  | xargs echo "  attributeSchema classes:"
ldapsearch -x -H "ldap://$DC" -b "CN=Configuration,${NC:-DC=lab,DC=internal}" \
  "(objectClass=subSchemaSubentry)" dn 2>/dev/null | grep -c "^dn:" \
  | xargs echo "  classSchema classes:"
echo

echo "=== 4. enabled users, no password - visible anonymously ==="
ldapsearch -x -H "ldap://$DC" -b "${NC:-DC=lab,DC=internal}" \
  "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=512))" \
  sAMAccountName userPrincipalName memberOf 2>/dev/null \
  | grep -E "^(sAMAccountName|memberOf):" | sed 's/^/  /' | head -40
echo "  ^ userAccountControl bit 512 = ACCOUNTDISABLE clear = ENABLED"
echo "    That bitwise filter is the one you will type most often."
echo

echo "=== 5. COMPUTERS: the graph's most important edge type ==="
ldapsearch -x -H "ldap://$DC" -b "${NC:-DC=lab,DC=internal}" \
  "(objectCategory=computer)" dNSHostName operatingSystem sPN 2>/dev/null \
  | grep -E "^(dNSHostName|operatingSystem|sPN):" | sed 's/^/  /'
echo "  ^ the SPNs here are what Kerberoasting targets (ad-04)"
echo

echo "=== 6. GROUP MEMBERSHIPS: the whole map, anonymously ==="
ldapsearch -x -H "ldap://$DC" -b "${NC:-DC=lab,DC=internal}" \
  "(objectCategory=group)" sAMAccountName member 2>/dev/null \
  | grep -E "^(sAMAccountName|member):" | sed 's/^/  /' | head -40
echo

echo "=== 7. the ROASTABLE ACCOUNTS, found with no credentials at all ==="
echo "    msDS-SupportedEncryptionTypes is readable anonymously."
echo "    RC4 support = the value 4, or the absence of the attribute."
echo
ldapsearch -x -H "ldap://$DC" -b "${NC:-DC=lab,DC=internal}" \
  "(userAccountControl:1.2.840.113556.1.4.803:=512)" \
  sAMAccountName msDS-SupportedEncryptionTypes servicePrincipalName 2>/dev/null \
  | paste - - - 2>/dev/null | grep -viE "msDS-SupportedEncryptionTypes: 18|^-" | head -12 | sed 's/^/  /'
echo "  (18 = 0x12 = AES128 + AES256. Anything else, or nothing, = roastable)"
echo

echo "=== 8. ACCOUNTS THAT DO NOT REQUIRE PREAUTH ==="
ldapsearch -x -H "ldap://$DC" -b "${NC:-DC=lab,DC=internal}" \
  "(userAccountControl:1.2.840.113556.1.4.803:=1048576)" \
  sAMAccountName 2>/dev/null | grep "^sAMAccountName:" | sed 's/^/  /'
echo "  ^ bit 1048576 = DONT_REQ_PREAUTH. These are AS-REP roastable."
echo "    Every one of them is a finding: this flag is a legacy"
echo "    interoperability exception that nobody retires."
echo

echo "=== 9. ACCOUNT NAMES AND ACCOUNTS THAT NEVER LOG IN ==="
ldapsearch -x -H "ldap://$DC" -b "${NC:-DC=lab,DC=internal}" \
  "(objectCategory=person)(objectClass=user)" \
  sAMAccountName pwdLastSet lastLogonTimestamp 2>/dev/null \
  | grep -E "^(sAMAccountName|lastLogonTimestamp):" | paste - - 2>/dev/null \
  | grep -iE "1601|0001" | head -8 | sed 's/^/  /'
echo "  ^ accounts whose lastLogonTimestamp is 1601/0001 NEVER LOGGED ON."
echo "    Dormant and service accounts are the ones with stale passwords."
echo "    Some of them still have Domain Admin. That is the finding."
echo

echo "=== 10. the GLOBAL CATALOG on 3268: the forest, for free ==="
ldapsearch -x -H "ldap://$DC:3268" -b "${NC:-DC=lab,DC=internal}" \
  -s base "(objectClass=domainDNS)" dc dnsHostName 2>/dev/null \
  | grep -E "^[a-zA-Z]+:" | sed 's/^/  /'
echo "  ^ 3268 is forest-wide. If it answers anonymously, every domain in"
echo "    the forest is readable from one unauthenticated TCP connection."
EOF

# --- 4. the graph model, built offline ---
cat > 04-graph.py <<'PY'
#!/usr/bin/env python3
"""A miniature AD graph and the queries that matter.

You do not need BloodHound to understand it. Once you can see the
edges on a 40-node graph, the tool is just this with 40,000 nodes.
"""
from collections import defaultdict, deque

class Graph:
    def __init__(self):
        self.out = defaultdict(list)          # principal -> [(kind, target)]
        self.label = {}

    def add_principal(self, name, kind):
        self.label[name] = kind
        self.out.setdefault(name, [])

    def add_edge(self, src, kind, dst):
        self.out[src].append((kind, dst))
        self.out.setdefault(dst, [])

    def shortest_path(self, src, dst, max_depth=8):
        """BFS. The FIRST path is what a real attacker tries."""
        q, seen = deque([(src, [])]), {src}
        while q:
            node, path = q.popleft()
            if len(path) > max_depth: continue
            if node == dst: return path
            for kind, t in self.out[node]:
                if t not in seen:
                    seen.add(t)
                    q.append((t, path + [(kind, t)]))
        return None

    def all_shortest_to(self, dst):
        """Every principal that can reach dst, at any depth."""
        back = defaultdict(list)
        for src, edges in self.out.items():
            for kind, t in edges:
                back[t].append((src, kind))
        reach, q, seen = defaultdict(set), deque([(dst, 0)]), {dst}
        while q:
            node, d = q.popleft()
            if d > 6: continue
            for src, kind in back[node]:
                reach[dst].add((src, d, kind))
                if src not in seen:
                    seen.add(src); q.append((src, d + 1))
        return reach[dst]

g = Graph()
for n, k in [("alice","user"), ("bob","user"), ("carol","user"),
             ("erin","user"), ("svc-backup","user"), ("svc-web","user"),
             ("IT Staff","group"), ("Helpdesk","group"), ("Domain Admins","group"),
             ("Backup Operators","group"), ("WKS01","computer"),
             ("WEB01","computer"), ("DC01","computer")]:
    g.add_principal(n, k)

g.add_edge("alice", "MemberOf", "Helpdesk")
g.add_edge("bob",   "MemberOf", "IT Staff")
g.add_edge("erin",  "MemberOf", "Domain Admins")           # too easy; the graph finds it
g.add_edge("carol", "MemberOf", "Helpdesk")
g.add_edge("svc-web","MemberOf", "Backup Operators")
g.add_edge("IT Staff", "MemberOf", "Domain Admins")
g.add_edge("svc-backup", "GenericAll", "DC01")             # the shortcut
g.add_edge("bob", "WriteDACL", "DC01")                     # a direct one
g.add_edge("alice", "HasSession", "WEB01")
g.add_edge("carol", "HasSession", "WEB01")
g.add_edge("WEB01", "GenericWrite", "svc-web")            # via delegation path
g.add_edge("WKS01", "DCSync", "DC01")
g.add_edge("svc-backup", "DCSync", "DC01")
g.add_edge("svc-backup", "MemberOf", "Domain Admins")

print("  THE GRAPH")
print("  " + "="*66)
for src in sorted(g.out):
    for kind, dst in g.out[src]:
        print(f"    {src:<14} --{kind:<12}--> {dst}")

print("\n  SHORTEST PATH: alice -> Domain Admins")
p = g.shortest_path("alice", "Domain Admins")
for kind, n in p or []:
    print(f"    {n:<16} --{kind}-->")
print()
print("  alice is a member of Helpdesk. She is not in anything")
print("  privileged. But WEB01 has a session of hers, WEB01 can")
print("  GenericWrite on svc-web, svc-web is in Backup Operators,")
print("  and Backup Operators is in Domain Admins. Five hops, and")
print("  nobody would find that by reading a group list.")

print("\n  WHO CAN REACH Domain Admins, AND HOW DEEP")
for src, depth, kind in sorted(g.all_shortest_to("Domain Admins"), key=lambda x: (x[1], x[0])):
    print(f"    depth {depth}  {src:<14} (last edge: {kind})")

print("\n  WHO CAN DCSync - and note it is NOT the same set")
for src, depth, kind in sorted(g.all_shortest_to("DC01"), key=lambda x: (x[1], x[0])):
    if kind == "DCSync":
        print(f"    {src:<14} has DCSync")
print()
print("  svc-backup is in Domain Admins, so it is not surprising.")
print("  WKS01 is not in any group, and it has DCSync.")
print("  A COMPUTER ACCOUNT with DCSync is a Critical finding that")
print("  most hand audits miss, because nobody reads computer objects.")

print("\n  SESSIONS - the edges you can use immediately")
for src, edges in g.out.items():
    for kind, dst in edges:
        if kind == "HasSession":
            print(f"    {src:<14} is authenticated to {dst}")
print()
print("  BloodHound shows this graph. bloodhound-python collects it.")
print("  netexec can enumerate the session edges too, if you have")
print("  administrative rights to the host in question.")

type constantly, and the line that matters most — the absence of msDS-SupportedEncryptionTypes
defaults to RC4, which means roastable. That's a finding you can confirm with no credentials at
all.

Step 4 builds a 13-node graph with a five-hop path from alice to Domain Admins through a
session, a GenericWrite, and a group nesting — plus a computer account with DCSync that
appears in no group list. That's the class of finding that only the graph surfaces.
