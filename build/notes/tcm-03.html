Active Reconnaissance and Network Scanning

Summary

Active recon is where passive recon stops paying: you send packets to the target and observe
what answers. It is the first stage that leaves a trace — logs, IDS alerts, and sometimes a
ticket from the client's SOC.

The engineering content of this lecture is not "type nmap". It is: what does a port scan
actually learn, what does it cost, and what can you infer from a port that is closed, filtered,
or absent?

Companion to ccnad-02 (TCP/IP security problems) and cs161-06
(firewalls). This note is the operational craft.

What a port state tells you

  OPEN       -> something accepted the connection. A service is there.
  CLOSED     -> the host sent RST / ICMP unreachable. Nothing listening,
                but the host is ALIVE and reachable.
  FILTERED   -> no response at all. Either a firewall dropped it, or the
                host is down, or the route is black-holed.
  open|filtered  (UDP) -> no response either way; UDP has no handshake,
                          so this state is normal and nearly useless.

The genuinely useful inference: a filtered TCP port with every other
port closed is a strong signal that a firewall exists and is selectively
allowing or dropping. That tells you where to focus. A host where everything
is filtered is probably down; a host where everything is closed and a
handful are open is a normal host with a small exposed surface.

That distinction is the difference between reading a scan and reading a
network.

Scan types, and what each costs the target

Type Cost Speed Use when
TCP connect (-sT) one full connection each slow you are not root
SYN / half-open (-sS) one SYN each fast default, needs root
UDP (-sU) very heavy very slow only with explicit ROE permission
Ping sweep (-sn) one host per 3 probes fast /24 discovery
Version detect (-sV) a probe per open port medium you need versions
Script scan (-sC) heavy slow default scripts, in scope only
Timing (-T0..-T5) varies varies evasion (rarely justified)

UDP scans deserve their own warning. A -sU scan can saturate a link
and take a host offline, because the scanner sends large payloads and waits
for rate-limited ICMP. A UDP scan is a DoS with a reconnaissance payload.
Never run one without written permission.

The workflow that works

  1. DISCOVER HOSTS   who is here?
  2. PORTS            what is listening?
  3. SERVICE + VERSION what exactly is it? (nmap -sV)
  4. VULNERABILITIES  what is known to be wrong with it?
  5. PRIORITISE       reachability x severity, not severity alone
  6. EXPLOIT          (tcm-04)

Step 5 is the professional step. A CVE with CVSS 9.8 on a host with no
route to your objective and behind three layers of filtering is worth less
than a medium on the box that fronts the database.

Nmap, the actual craft

# The template that works, and why each part is there
nmap -sn 192.168.56.0/24                      # 1. discovery, host only
nmap -sS -T4 --top-ports 1000 -oA 02-top1000 192.168.56.0/24
nmap -sV -sC -p- -oA 03-full 192.168.56.20    # one host, everything
nmap -sU --top-ports 20 --max-rate 50 -oA 04-udp 192.168.56.20   # WRITES FIRST

# Script categories, chosen deliberately rather than by -sC
nmap -sV --script=safe     192.168.56.20   # non-intrusive only
nmap -sV --script=vuln     192.168.56.20   # these SEND traffic; scope them
nmap --script=smb-enum-shares,smb-vuln-ms17-010 -p 445 192.168.56.20

--script=vuln sends real exploit probes. It is active exploitation with a
scanner's UI. It requires explicit scope permission, and a
--script=vuln against an out-of-scope host is your engagement over.

What to actually look for in the output

  HIGH SIGNAL
    version banners that pin an exact vulnerable release
    anonymous/default credentials on a service
    SMB signing not required (relay in tcm-06)
    outdated TLS configuration
    a service on a non-standard port that the asset inventory missed
    a host that appears in scan but not in the client's CMDB  <- a rogue asset

  MEDIUM
    directory listing on a web server
    verbose error pages with stack traces
    missing security headers
    ntp/ntp monlist enabled
    ssh host keys reused across hosts (host key = clone)

  LOW / INFORMATIONAL
    "the scan is detected" banners
    standard banners
    anything that requires you to authenticate to learn

The rogue-asset finding is worth stating explicitly: a scan is an asset
discovery tool as much as a vulnerability tool. Hosts that appear in the
scan but not in the client's inventory are a report finding on their own,
and often the most important one.

Scope discipline, again

  BEFORE every scan:
    [ ] is this address range in the written scope?
    [ ] is this scan type permitted by the ROE?
    [ ] is it inside the time window?
    [ ] has anyone asked you to stop?
    [ ] do you know your source IP, in case you get blocked?

  If any answer is no, do not scan.

Terminology

Term Meaning
Host discovery Finding live hosts in a range
Port scan Finding listening services
Connect scan Full TCP handshake; needs no privilege
SYN / half-open scan Sends SYN only; stealthier, needs root
Filtered No response; firewall or host down
Service fingerprinting Identifying the software and version
Banner grab Reading the service's own greeting
Vulnerability scanner Probing for known weaknesses
SMB signing Prevents SMB relay attacks
Rogue asset A live host absent from the inventory
Scan rate Packets per second; too high looks like an attack
Nmap script An NSE module that speaks a protocol

#!/usr/bin/env bash
# Usage: ./scan.sh <cidr> [extra nmap args...]

RANGE="$1"; shift
BASE=$(echo "$RANGE" | cut -d/ -f1)
in_scope "$BASE" || { echo "REFUSED: $BASE outside the engagement scope." >&2; exit 3; }
echo "[scope] $RANGE is in scope"
echo "[roe]   confirming: full connect scan of in-scope range is PERMITTED"
exec nmap -sT -sV --reason -oA "scan-${BASE}" "$@" "$RANGE"
EOF

# --- 3. why the states differ: a demonstration you control ---
cat > portlab.py <<'PY'
"""Three listeners, three states. All on loopback, all yours."""
import socket, threading, time, subprocess, sys

def listen(port):
    s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(("127.0.0.1", port)); s.listen(5)
    while True:
        try: s.accept()
        except OSError: break

def closed(port):
    s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(("127.0.0.1", port)); s.close()   # bind then release -> RST

# filtered is hard to demo without a firewall; leave that to nftables
for p in (9001, 9002, 9003):
    threading.Thread(target=listen, args=(p,), daemon=True).start()
for p in (9011, 9012):
    closed(p)
time.sleep(0.5)
print("  listeners : 9001 9002 9003   -> should read open")
print("  closed    : 9011 9012        -> should read closed")
print("  filtered  : 9021             -> nothing bound, no rule (loopback)")
PY
python3 portlab.py &
sleep 1
nmap -sT -Pn -p 9001-9003,9011-9012,9021 127.0.0.1 2>&1 | grep -E "^9[0-9]{3}" | sed 's/^/  /' | tee 03-states.txt
wait 2>/dev/null

cat >> 03-states.txt <<'EOF'

  READING THE TABLE
    open      -> a service exists. Version fingerprint next.
    closed    -> host is ALIVE and REACHABLE. This is a positive finding,
                 not a null result: it rules out "host down".
    filtered  -> no answer. Firewall drop, or host down, or no route.
                 You cannot distinguish these without another probe.
  The inference that matters: "everything filtered" and "everything closed"
  describe completely different networks, and only the second one proves
  the host exists.
EOF
cat 03-states.txt

# --- 5. parsing a scan into prioritised work ---
cat > prioritise.py <<'PY'
"""Turn an nmap XML report into a prioritised worklist."""
import xml.etree.ElementTree as ET, sys, glob

def load(path):
    try: return ET.parse(path).getroot()
    except Exception: return None

def score(state, version, cve, reachable):
    # reachability dominates: an unreachable host is not a finding
    if state == "filtered": return 0
    s = 10 if state == "open" else 0
    if cve: s += 40
    if version and any(k in version.lower() for k in
                       ("dev","test","debug","beta","1.0","0.")): s += 15
    if reachable: s += 20
    return s

rows = []
for f in sorted(glob.glob("scan-*.xml")):
    r = load(f)
    if r is None: continue
    for h in r.findall("host"):
        addr = h.find("address").get("addr")
        st = h.find("./status").get("state")
        for p in h.findall("./ports/port"):
            state = p.find("state").get("state")
            ver = (p.find("service").get("version") or "")
            prod = (p.find("service").get("product") or "")
            cve = any("cve" in (e.get("id") or "").lower()
                      for e in p.findall("./script[@id='vulners']/elem"))
            sc = score(state, f"{prod} {ver}", cve, st == "up")
            if sc:
                rows.append((sc, addr, p.get("portid"), state, f"{prod} {ver}".strip()))

rows.sort(reverse=True)
print(f"  {'SCORE':>5}  {'HOST':<16} {'PORT':<6} {'STATE':<9} SERVICE")
print("  " + "-"*64)
for sc, addr, port, state, svc in rows[:20]:
    print(f"  {sc:>5}  {addr:<16} {port:<6} {state:<9} {svc}")
if not rows:
    print("  (no XML reports yet - run ./scan.sh 192.168.56.0/24 first)")
PY
python3 prioritise.py | tee 05-prioritised.txt

Step 3 is the lesson: three listeners and two deliberately-closed ports on loopback, and the
scan correctly distinguishes open from closed. That distinction — the host is alive and
reachable, nothing is listening — is a real finding that a ping sweep alone would miss
entirely.

Step 5 turns a scan into a worklist by refusing to rank unreachable hosts. An unreachable
host with a critical CVE is not a finding; ranking it above live targets is how people waste a
week.
