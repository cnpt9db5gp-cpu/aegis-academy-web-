Cryptography I: Introduction, IND-CPA

Summary

CS161's crypto block starts where MIT 6.858's does: with a definition. Before you can say
an encryption scheme is secure, you must write down what "secure" means and prove the scheme
achieves it.

Companion to cry-01..cry-07 and mit858-13. This note is the formal
foundation; those are the practical applications.

Semantic security (IND-CPA)

The definition that replaced "the ciphertext looks random":

An encryption scheme is IND-CPA secure if, for any PPT adversary A:

  1.  A submits two messages m0, m1
  2.  A receives Enc(k, m_b) for a uniformly random b ∈ {0,1}
  3.  A outputs b'

  Adv_A = |Pr[b' = b] - 1/2|

  A is broken if Adv_A is non-negligible (> 1/poly(λ) for some polynomial)

The intuition: an eavesdropper learns nothing about which of two
messages was encrypted. Not "the plaintext is hard to recover" — nothing at
all, not even partial information.

Why it matters: IND-CPA rules out every cipher that leaks any function
of the plaintext. ECB fails it visibly. A stream cipher with a reused nonce
fails it catastrophically. XOR with a fixed pad fails it trivially.

What the definition rules out, concretely

Scheme Why it fails IND-CPA
One-time pad with a random pad passes — the only classical scheme that does
XOR with a fixed key identical ciphertexts for identical plaintexts
ECB mode block patterns are visible in the ciphertext
AES-CBC with a fixed IV first block is deterministic
AES-CTR/GCM with a reused nonce keystream reuse reveals the XOR of plaintexts
"Encrypt with a hash of the password" deterministic, so equal plaintexts match

Randomness: the hidden requirement

IND-CPA needs:
  - a fresh, uniform, secret nonce for every message
  - nonce uniqueness across ALL messages under a key
  - the nonce to be transmitted (it need not be secret)

Nonce reuse is the most common crypto failure in practice, because it is a
randomness management problem rather than an algorithmic one. It is
nonce-reuse and asrep-roasting in Tier 5, and it is weak-rng in every CTF.

Hash functions: the security you are buying

A hash function for security must have:

  • Preimage resistance: given h(x), finding x is hard
  • Second-preimage resistance: given x, finding y ≠ x with h(y) = h(x) is hard
  • Collision resistance: finding any x ≠ y with h(x) = h(y) is hard

Collision resistance is strictly stronger than second-preimage resistance,
and MD5 and SHA-1 are broken for collisions while remaining second-preimage
resistant. That is exactly why signature schemes break (they need collisions)
while password hashes survive (they do not).

Use Requirement Broken by collisions?
Digital signature collision resistance yes — SHA-1/MD5 fail
Content commitment (git) collision resistance yes
Password storage preimage resistance + slowness no — still fine
Session/token id preimage resistance no

Terminology

Term Meaning
IND-CPA Indistinguishability under chosen-plaintext attack
Semantic security Ciphertext reveals no information about the plaintext
Non-negligible Larger than any inverse polynomial in the security parameter
PPT adversary Probabilistic polynomial time
Nonce Unique per message; must be transmitted, need not be secret
Nonce reuse Catastrophic for stream/CTR modes
Preimage resistance Cannot reverse the hash
Second-preimage Cannot find a second input with the same hash
Collision resistance Cannot find any pair with the same hash
Symmetric / asymmetric One shared key / a key pair
Perfect secrecy One-time pad: ciphertext gives zero information, unconditionally

Kali commands

# --- IND-CPA, demonstrated: ECB leaks structure ---
python3 - <<'PY' | tee 01-ecb-leak.txt
import os, collections
# Encrypt the same 16-byte block twice under ECB
key = os.urandom(16)
def ecb_block(b, k):
    # stand-in for AES-ECB
    return bytes(a ^ c for a, c in zip(b, k))
plain = b"ATTACKATDAWNXX" * 4
ct = b"".join(ecb_block(plain[i:i+16], key) for i in range(0, len(plain), 16))
counts = collections.Counter(ct[i:i+16] for i in range(0, len(ct), 16))
print("  distinct 16-byte ciphertext blocks in the input:",
      len(set(plain[i:i+16] for i in range(0, len(plain), 16))))
print("  distinct 16-byte ciphertext blocks in the output:", len(counts))
print()
print("  ECB preserves equality of plaintexts. IND-CPA requires that it does not.")
for block, n in counts.items():
    if n > 1:
        print(f"    block repeated {n}x: {block.hex()}")

# --- nonce reuse is catastrophic ---
python3 - <<'PY' | tee 02-nonce-reuse.txt
import os
k = os.urandom(32)
c1 = os.urandom(32); c2 = os.urandom(32)
def ctr(key, nonce, pt): return bytes(a ^ b ^ c for a,b,c in zip(key, nonce, pt))
m1 = b"transfer 0100 to alice"
m2 = b"transfer 9900 to mallory"
# same key, SAME nonce - the bug
x1 = ctr(k, c1, m1); x2 = ctr(k, c1, m2)
xored = bytes(a ^ b for a, b in zip(x1, x2))
m1x = bytes(a ^ b for a, b in zip(m1, m2))
print("  m1 XOR m2 :", m1x.decode(errors='replace'))
print("  c1 XOR c2 :", xored.decode(errors='replace'))
print()
print("  IDENTICAL:", xored == m1x)
print()
print("  Reusing a nonce under one key gives the attacker the XOR of every")
print("  plaintext pair. Ciphers like this are a one-time pad: recover one")
print("  message and every other message falls.")
PY
cat 02-nonce-reuse.txt

# --- collision vs preimage: which use case cares? ---
python3 - <<'PY' | tee 03-hash-levels.txt
import hashlib
def show(name, data=b"aegis"):
    for h, lbl in ((hashlib.md5, "md5"), (hashlib.sha1, "sha1"),
                   (hashlib.sha256, "sha256")):
        d = h(data).hexdigest()
        print(f"  {name:<14} {lbl:<7} {d}")
for n in ("aegis", "aegis "):
    show(f"input {n!r}", n.encode())
print()
print("  MD5/SHA-1: COLLISION broken (two different inputs, same hash).")
print("  SHA-256:   collision resistance intact, preimage resistance intact.")
print("  Consequences:")
print("    signatures over MD5/SHA-1 : FORGERY is realistic")
print("    password hashes with MD5  : still 'fine' for preimage, terrible for speed")
print("    git with SHA-1            : two files can share an id -> history rewriting")

# --- randomness quality, which everything rests on ---
python3 - <<'PY' | tee 04-randomness.txt
import os, secrets, collections
# 1. a bad RNG (predictable seed)
import random
r1 = random.Random(1337)
print("  seeded random (predictable):", [r1.randint(0,100) for _ in range(8)])
print("  /dev/urandom               :", [secrets.randbelow(101) for _ in range(8)])
print()
print("  Nonces, session IDs and keys must come from the OS CSPRNG.")
print("  A seeded Mersenne Twister is fine for shuffling a test fixture and")
print("  catastrophic for generating a nonce.")
print()
# entropy sanity
b = os.urandom(4096)
counts = collections.Counter(b)
import math
H = -sum((c/4096)*math.log2(c/4096) for c in counts.values())
print(f"  entropy of 4096 bytes from /dev/urandom: {H:.3f} bits/byte (max 8.0)")
