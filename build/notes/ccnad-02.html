IPv4, IPv6, NAT and Port Forwarding

Summary

NAT is why your laptop is invisible, and port forwarding is how you become visible again. Both
are security-relevant in opposite directions, and both are routinely misconfigured.

Key ideas

  • NAT rewrites addresses at the boundary: private → public. Breaks inbound connections
  • PAT/NAPT: many private addresses share one public via port translation — the common case
  • Port forwarding: the deliberate hole through NAT, mapped from an external port to an internal
    host. Every one is a service you have published
  • IPv6: removes the need for NAT, which removes a layer of obscurity. Scanning a /64 is
    technically feasible and nobody does it
  • IPv6 privacy extensions randomise host identifiers, making host-tracking harder
  • Happy eyeballs / dual stack: hosts often run both, doubling the attack surface quietly

Terminology

Term Meaning
NAT Network Address Translation
PAT / NAPT NAT using port numbers; many-to-one
Port forwarding Explicit NAT rule exposing an internal service
Hairpin NAT A host reaching an internal service via the external address
IPv6 / /64 128-bit addressing; a /64 is standard per site
Privacy extension IPv6 host IDs that rotate
Dual stack IPv4 and IPv6 simultaneously
UPnP Automatically opens ports; a security problem
CGNAT Carrier-grade NAT; you cannot port forward at all

Field lab

Objective: establish what is exposed on your own connection, and understand NAT from the
outside.

mkdir -p ~/aegis/labs/ccnad-02 && cd ~/aegis/labs/ccnad-02

# --- 1. inside vs outside: the NAT proof ---
{
  echo "=== my private addresses ==="
  ip -br addr | grep -v "127.0.0.1" | sed 's/^/  /'
  echo
  echo "=== my public address (what the internet sees) ==="
  pub=$(curl -s --max-time 6 https://api.ipify.org 2>/dev/null)
  echo "  $pub"
  echo
  if [ -n "$pub" ]; then
    python3 - "$pub" <<'PY'
import ipaddress, sys
pub = sys.argv[1]
a = ipaddress.ip_address(pub)
print(f"  is it public?  {a.is_global}")
print(f"  is it private? {a.is_private}")
if not a.is_private and not a.is_loopback:
    print("  -> You are behind NAT. Inbound connections cannot reach you without a forward.")
PY
  else
    echo "  (no outbound connectivity, or the request was blocked)"
  fi
} 2>&1 | tee 01-nat.txt

# --- 2. IPv6, if you have it ---
{
  echo "=== IPv6 global addresses ==="
  ip -6 addr show scope global 2>/dev/null | grep inet6 | sed 's/^/  /'
  if ip -6 addr show scope global 2>/dev/null | grep -q inet6; then
    echo
    echo "=== these are globally routable, with no NAT in front ==="
    echo "  IPv6 reachability test:"
    timeout 8 ping6 -c2 2606:4700:4700::1111 2>&1 | tail -3 | sed 's/^/    /'
    echo
    echo "=== path ==="
    traceroute -6 -n -m5 2606:4700:4700::1111 2>/dev/null | sed 's/^/    /'
  else
    echo "  (no global IPv6 on this host)"
  fi
} 2>&1 | tee 02-ipv6.txt

# --- 3. UPnP: let me check whether my gateway would forward a port for me ---
{
  echo "=== UPnP status ==="
  if command -v upnpc >/dev/null; then
    upnpc -s 2>&1 | head -6
    echo
    echo "=== existing port mappings ==="
    upnpc -l 2>&1 | head -15
  else
    echo "miniupnpc not installed. This is a REAL check worth doing:"
    echo "  sudo apt install miniupnpc && upnpc -l"
    echo
    echo "Why it matters: UPnP lets any local process ask your router to forward"
    echo "a port to any internal host. Malware uses it, and so do attackers."
  fi
} 2>&1 | tee 03-upnp.txt

# --- 4. port forwarding, demonstrated locally without touching a router ---
python3 - <<'PY' | tee 04-forwarding.txt
import socket, threading, time

# A forward is just: listen on an external port, hand traffic to an internal port.
BACKEND_PORT = 9100        # "the internal service"
FRONT_PORT   = 38080       # "the external port"

def backend():
    s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(("127.0.0.1", BACKEND_PORT)); s.listen(1)
    c, _ = s.accept()
    data = c.recv(64); c.sendall(b"HTTP/1.1 200 OK\r\nContent-Length: 3\r\n\r\nhi\n")
    c.close(); s.close()

def forwarder():
    s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(("0.0.0.0", FRONT_PORT)); s.listen(1)     # 0.0.0.0 = reachable by the whole LAN
    c, addr = s.accept()
    b = socket.create_connection(("127.0.0.1", BACKEND_PORT), timeout=2)
    c.sendall(b"GET / HTTP/1.0\r\n\r\n")
    b.sendall(c.recv(64))
    print(f"  forwarded a request from {addr[0]} to 127.0.0.1:{BACKEND_PORT}")
    c.close(); b.close(); s.close()

threading.Thread(target=backend, daemon=True).start()
threading.Thread(target=forwarder, daemon=True).start()
time.sleep(0.4)
print("  now querying the forwarded port from loopback:")
import urllib.request
try:
    print("   ", urllib.request.urlopen(f"http://127.0.0.1:{FRONT_PORT}", timeout=3).read())
except Exception as e:
    print("   ", type(e).__name__, e)
time.sleep(0.3)
PY

echo
echo "=== what I just built, and what it means ==="
cat <<'EOF'
A port forward is a listener on 0.0.0.0 that relays to an internal service. It is
the mechanism behind every published web service, every exposed RDP box, and
every "why is my Ubuntu showing up on shodan" question.

On your router, the same forwarding happens at the edge: it is the only reason
anything behind your NAT is reachable at all. Each rule you add is a decision
to publish that service to the internet.
EOF

# --- 5. check what is listening on your whole LAN-facing surface ---
{
  echo "=== world-reachable listeners on this machine ==="
  ss -tulpn | awk 'NR==1 || $5 ~ /0\.0\.0\.0|\*/' | sed 's/^/  /'
  echo
  n=$(ss -tulpn | awk '$5 ~ /0\.0\.0\.0|\*/' | wc -l)
  echo "  count: $n"
  [ "$n" -gt 1 ] && echo "  each of these is reachable from your entire network."
} | tee 05-exposed.txt

Step 5 is the actionable finding. Anything bound to 0.0.0.0 on your Kali laptop is visible
to your whole Wi-Fi. That is the most common real-world mistake on this machine.
