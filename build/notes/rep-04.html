Remediation Guidance and Executive Summary

Summary

Remediation guidance is where most reports fail. A finding that ends in "should be remediated"
has transferred the entire hard part to the client, who did not ask for it and does not have the
context you have.

The framing: a recommendation the client can put in a sprint is
worth ten recommendations that describe a category of vulnerability.

What makes a remediation usable

  THE FIVE THINGS, and the report must supply all five:

  1. THE ACTION      specific enough to schedule. "Remove the
                     endpoint" - not "improve security".
  2. THE OWNER       a named team, not "the business".
  3. THE EFFORT      a real estimate. "1 sprint" beats "medium".
  4. THE PRIORITY    and a sequence. Four remediations all marked
                     "Immediate" is not prioritisation.
  5. THE VERIFICATION  how the client confirms it is done, and how
                     you will confirm it at re-test.

  AND THE ONE MOST REPORTS OMIT:
  6. THE ALTERNATIVE, when the fix has a cost
     "remove the endpoint (2 days) OR place it behind authentication
      (4 days, ongoing maintenance)". Choosing is the client's job;
     laying out both is yours.

Remediation patterns, by bug class

  SQL INJECTION
    remove the concatenation -> parameterise -> whitelist identifiers
    -> least-privilege DB account -> hide errors
    -> CI lint rule so the next one is caught before release

  XSS
    output-encode per context -> CSP -> HttpOnly + SameSite cookies
    -> a framework that escapes by default -> a lint rule
    NOTE: the first is the fix. The rest reduce impact.

  BROKEN ACCESS CONTROL
    add the ownership predicate TO THE QUERY, not as a post-fetch if:
      SELECT * FROM invoices WHERE id = ? AND owner_id = ?
    why: a check in application code is one `if` away from being
    omitted, and it was. A predicate in the SQL is not optional.

  SMB SIGNING NOT REQUIRED
    GPO: require signing on all hosts -> verify with a scan, per host
    -> consider SMB encryption on sensitive shares
    -> block inbound 445 between workstation segments (the strongest
       control, and the one that stops the LAN attack entirely)

  LDAP SIGNING / CHANNEL BINDING
    GPO on the DCs -> enforce channel binding (KB5012122) -> close
    636/6363 to clients -> verify with an LDAP relay test

  UNCONSTRAINED DELEGATION
    remove it -> constrained delegation bound to named SPNs -> audit
    for msDS-SecurityHistory as well as msDS-AllowedToDelegateTo ->
    run IIS app pools as least-privilege identities, not SYSTEM

  KERBEROASTABLE ACCOUNTS
    gMSA (120 random characters, DC-managed) -> AES-only on service
    accounts -> remove unneeded SPNs -> separate service accounts from
    privileged groups
    NOTE: "set a longer password" is NOT a remediation here.

  GPO WRITE ABUSE
    remove "Create GPOs" from the group -> scope Group Policy Creator
    Owners -> audit every OU's delegation -> enable Advanced GPO
    auditing (5136 on GroupPolicy objects)

  MISSING SECURITY HEADERS
    CSP (nonces, not unsafe-inline) -> HSTS with preload ->
    includeSubDomains -> X-Content-Type-Options -> Referrer-Policy
    NOTE: a CSP nobody can deploy is not a remediation. Name the
    framework (CSP Level 3 nonces) and the deployment step.

  THE PATTERN IN ALL OF THEM:
    remove the specific thing -> reduce the class -> limit the impact
    -> prevent the next one, in code review or CI

## The three things that matter

**1. One request reaches your customer data.** An unauthenticated
HTTP request to WEB-01 returns the customer records table, including
names, email addresses and partial card data. No credentials, no
user interaction, no special tooling. We established this in one
request and stopped there.

**2. Compromising one host compromises all of them.** There is no
segmentation between the web tier, the server tier and the database
tier. We demonstrated movement from a VPN-connected workstation to the
production database, two network segments apart, in under ten
minutes, using only a credential recovered from the first host.
Segmentation is the control that would have limited this. It does not
currently exist.

**3. Nothing here required a sophisticated attacker.** Every finding
used standard tooling. Three of them required none at all — only a
changed number in a request. The two most significant required a
public wordlist that is available for free to anyone.

## What we recommend, in order

| Priority | Action | Owner | Effort |
|---|---|---|---|
| 1 | Remove or authenticate `/admin/records` on WEB-01 | Web Platform | Immediate (2 days) |
| 2 | Require SMB signing domain-wide and block inbound 445 between workstation segments | Domain Admins / Network Ops | Immediate (GPO) |
| 3 | Segment the web tier from the data tier; restrict WinRM to a management VLAN | Network Ops | 2 sprints |
| 4 | Move all service accounts to gMSA and enforce AES-only Kerberos | Domain Admins | 1 sprint |
| 5 | Deploy Credential Guard on all servers and workstations | Endpoint | 1 sprint |

Recommendations 1, 2 and 4 are configuration changes that can be made
by the client's own administrators without further engagement.
Recommendation 3 is the one that materially changes the blast radius
of every other finding, and it is the most expensive. That ordering
is deliberate.

## What we did not test

- Denial of service of any kind. Not authorised, and we would
  recommend against it in a business-hours window regardless.
- Third-party, cloud and SaaS services. Not owned by the client.
- Physical security and social engineering. Out of scope.
- Any host outside the scope annex. Two hosts in the range did not
  respond to any probe and are not assessed either way.
- The effectiveness of the client's detection and response. We
  produced log events; whether they were alerted on is a question
  for the client (see F-11).

## Limitations and caveats

- Findings reflect the state of the systems on 14 October 2026.
- Internal testing was limited to three hours on 14 October, outside
  business hours, to avoid disruption.
- We recovered credential material sufficient to demonstrate impact.
  We did not use any credential outside the in-scope targets, and we
  did not test whether the recovered credentials worked elsewhere.
- Finding F-07 (kernel privilege escalation) could not be reproduced
  on the version deployed. We are reporting it on the basis of the
  version in use at the time of testing and the published advisory.
  If the client has patched since 14 October, this finding should be
  closed.
EOF

# Estimating effort honestly

```text
  THE PROBLEM
    "Medium effort" means nothing. It means the person reading it has
    to go and find out how much work it is, which means they will
    put it in the "someday" column.

  THE SCALE, and it must fit on one line in a table:

    Immediate        hours. A GPO, a config change, removing an
                     endpoint. Someone can do it this week.
    1 sprint         days to a couple of weeks. Code change, a
                     feature flag, a package.
    2 sprints        a quarter. Something with dependencies.
    Programme        a quarter or more, needs its own planning.
    Not scheduled    needs a business decision, not engineering
                     capacity. Say so, and say what the decision is.

  AND THE HONESTY REQUIREMENT
    You do not know the client's codebase or change process. So:

      GOOD   "Remove the endpoint — estimated 2 days of Web Platform
              time. The estimate assumes the endpoint is unused, which
              we could not confirm from the application itself."

      BAD    "Remediation effort: low."

    The parenthetical is the important part. It says what your
    estimate assumes, so the client can tell you the assumption is
    wrong and re-estimate in thirty seconds instead of finding out
    six weeks later.

cat > 04-check-remediation.py <<'PY'
#!/usr/bin/env python3
"""Every remediation row needs: action, owner, effort, priority, verification."""
import sys, re, pathlib

REQUIRED = {
    "action":      r"(?i)remove|disable|require|enable|restrict|rotate|"
                   r"migrate|segment|patch|add|deploy|upgrade|change|set",
    "owner":       r"(?i)web platform|network ops|linux ops|windows ops|"
                   r"domain admins|endpoint|security|it ops|sre|dba",
    "effort":      r"(?i)immediate|sprint|day|week|hour|quarter|programme|"
                   r"program|month",
    "priority":    r"(?i)immediate|high|medium|low|critical|p[0-3]\b",
    "verification":r"(?i)confirm|verify|re-test|retest|scan|test|validate",
}

VAGUE = [
    r"(?i)\bimprove .{0,30}security\b",
    r"(?i)\bharden\b",
    r"(?i)\bbest practice",
    r"(?i)\breview (your |the )?(process|policies)",
    r"(?i)\bincrease awareness\b",
    r"(?i)\bconsider\b",
    r"(?i)\bshould be updated\b",
]

def check(path):
    text = pathlib.Path(path).read_text(errors="ignore")
    rows = [l for l in text.splitlines() if l.strip().startswith("|")
            and l.count("|") >= 4]
    print(f"  {len(rows)} table rows in {path}")
    problems = 0
    for i, row in enumerate(rows, 1):
        if set(row.replace("|","").strip()) <= set("-: "): continue   # separator
        if "Action" in row or "---" in row: continue                   # header
        cells = [c.strip() for c in row.split("|")[1:-1]]
        if len(cells) < 4:
            continue
        missing = []
        joined = " ".join(cells)
        for field, rx in REQUIRED.items():
            if not re.search(rx, joined): missing.append(field)
        vague = [v for v in VAGUE if re.search(v, joined)]
        if missing or vague:
            problems += 1
            print(f"    row {i}: MISSING {', '.join(missing) or '-'}")
            if vague:
                print(f"            VAGUE: {vague}")
    if not problems:
        print("  every row has an action, an owner, an effort, a priority")
        print("  and a verification.")
    return problems

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print(__doc__); sys.exit(0)
    total = sum(check(p) for p in sys.argv[1:])
    print(f"\n  {total} rows need work.")
    print()
    print("  THE ONE THAT MATTERS MOST: 'verification'.")
    print("  A remediation without a stated verification is how a")
    print("  finding gets closed without being fixed, and how a re-test")
    print("  becomes an argument rather than a check.")
    sys.exit(1 if total else 0)
PY
