Shell Tools & Scripting

Summary

Tools become weapons when you chain them. The shell's real power is that every tool's stdout is
data, and you can pipe that into the next tool's stdin. A human reading a 400-line nmap scan
takes minutes; a well-written pipeline extracts the three facts that matter in one second.

This is also where shell scripting stops being optional: reconnaissance automation, evidence
collection, and every tool invocation you will script later.

The six tools that cover 90% of shell work

Tool Job Think of it as
grep select lines SQL WHERE
cut / awk select columns SELECT col
sort / uniq order and dedupe ORDER BY, DISTINCT
head / tail limit rows LIMIT
sed substitute / transform UPDATE
xargs parallelise a for loop that respects spaces

Quoting — the thing that will cost you an hour

V="hello world"

echo "$V"      # "hello world"   <- expansion happens
echo $V        # "hello" "world" -> two arguments! wrong
echo '$V'       # '$V'            <- literal
echo "$V"       # "$V"            <- literal

# The practical rule: ALWAYS quote your variable expansions.
# Unquoted: breaks on spaces, globs, and empty values (nullglob).
ls $V          # ls: cannot access 'world': No such file
ls "$V"        # correct

Why security cares: an unquoted variable in a script that later becomes a command is how
shell injection works. curl $URL where URL contains ; rm -rf / is a real vulnerability class.

Everything is a file descriptor

fd 0 = stdin   fd 1 = stdout   fd 2 = stderr

nmap -sV 127.0.0.1 > out.txt          # stdout to file
nmap -sV 127.0.0.1 2> err.txt        # stderr to file
nmap -sV 127.0.0.1 &> both.txt       # both to one file
nmap -sV 127.0.0.1 2>/dev/null       # throw away progress messages
nmap -sV 127.0.0.1 | grep open       # stdout into another tool

# tee: write to a file AND to the screen - you want both while scanning
nmap -sV 127.0.0.1 | tee scan.txt

2>/dev/null appears in almost every security command in existence, because tools are chatty and
progress bars break pipelines.

Process substitution and command substitution

# command substitution: run one command, use its output as text
HASH=$(sha256sum /etc/passwd | cut -d' ' -f1)
echo "passwd hash: $HASH"

# process substitution: feed a command's output as if it were a file
diff <(sort a.txt) <(sort b.txt)
comm -12 <(sort a.txt) <(sort b.txt)

# here-doc: multi-line text into a command
cat > report-header.txt <<EOF
Engagement: $(hostname)
Date:       $(date +%Y-%m-%d)
Analyst:    $USER
EOF

A real reconnaissance pipeline

This is the pattern you will reuse forever. Scan once, parse carefully, keep the raw output.

# 1. scan, keep raw output (never re-scan because you lost it)
nmap -sV -p- 192.168.56.101 -oN raw-scan.txt -oG raw-scan.gnmap

# 2. what is open?
grep "open" raw-scan.txt

# 3. just the ports, sorted numerically (NOT alphabetically - 22 before 100 matters)
grep "open" raw-scan.txt | awk -F/ '{print $1}' | sort -n

# 4. service -> version pairs, one per line
grep "open" raw-scan.txt | awk '{print $2, $3, $4}'

# 5. write findings out with headers
{
  echo "=== SCAN SUMMARY $(date -Iseconds) ==="
  echo "Target: 192.168.56.101"
  echo
  echo "--- open ports ---"
  grep "open" raw-scan.txt | awk -F/ '{print $1}'
  echo
  echo "--- services ---"
  grep "open" raw-scan.txt | awk '{print $2, $3, $4}'
} > findings.txt

A proper script

#!/usr/bin/env bash
#
# recon.sh - minimal host discovery + service inventory against an authorised target
# Usage: ./recon.sh 192.168.56.0/24
#
set -euo pipefail          # -e exit on error, -u error on unset var, -o pipefail catch pipe fails

TARGET="${1:-}"
OUTDIR="$HOME/aegis/labs/recon-$(date +%Y%m%d-%H%M%S)"

if [[ -z "$TARGET" ]]; then
  echo "usage: $0 <cidr or ip>" >&2
  exit 2
fi

# Refuse anything that is not a private range. This is the scope guard.
case "$TARGET" in
  192.168.*|10.*|172.1[6-9].*|172.2[0-9].*|172.3[01].*|127.*)
    ;;
  *)
    echo "REFUSING: $TARGET is not RFC1918 private space. See docs/RULES-OF-ENGAGEMENT.md" >&2
    exit 3
    ;;
esac

mkdir -p "$OUTDIR"
echo "[*] scanning $TARGET -> $OUTDIR"

# 1. discovery
nmap -sn -oN "$OUTDIR/hosts.txt" "$TARGET" 2>/dev/null | grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' | sort -u > "$OUTDIR/alive.txt"
echo "[+] $(wc -l < "$OUTDIR/alive.txt") hosts alive"

# 2. top ports on everything (fast first pass)
while read -r host; do
  [[ -z "$host" ]] && continue
  echo "[*] $host"
  nmap -sT --top-ports 100 -T4 "$host" -oN "$OUTDIR/$host-top100.txt" 2>/dev/null || true
done < "$OUTDIR/alive.txt"

# 3. summarise
{
  echo "RECON SUMMARY  $(date -Iseconds)"
  echo "target: $TARGET"
  echo
  for f in "$OUTDIR"/*-top100.txt; do
    [[ -e "$f" ]] || continue
    echo "=== $(basename "$f" .txt) ==="
    grep "open" "$f" || echo "  (no open ports in top 100)"
  done
} > "$OUTDIR/SUMMARY.txt"

echo "[+] summary: $OUTDIR/SUMMARY.txt"

Note three things about that script that are worth more than the script itself:

  1. set -euo pipefail — failures are loud.
  2. The RFC1918 guard — the script refuses to scan outside private space. Safety in code.
  3. || true on nmap — a per-host failure does not abort the whole run.

Kali commands

# --- grep: the workhorse ---
grep -i "error" /var/log/syslog
grep -n "sshd" /var/log/auth.log | head
grep -E "^(GET|POST)" access.log
grep -v "127.0.0.1" access.log            # everything EXCEPT local
grep -c "Failed" /var/log/auth.log       # count only

# --- cut / awk / sed ---
cut -d: -f1,7 /etc/passwd                # delimiter is :
awk '{print $1, $2}' access.log          # whitespace-separated
awk -F: '$3==0 {print $1}' /etc/passwd   # only UID 0 accounts
sed -n '10,20p' /etc/passwd              # lines 10-20
sed 's/password//g' input.txt            # substitute
sed -E 's/^([0-9.]+).*/\1/' log.txt      # capture group

# --- sort / uniq / count ---
sort -t' ' -k2 -n scan.txt
sort -u domains.txt
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head

# --- xargs: parallel, but space-safe ---
cat hosts.txt | xargs -n1 -P8 -I{} sh -c 'nmap -sT {} -oN /dev/null; echo "{} done"'
seq 1 10 | xargs -I{} echo "item {}"

# --- job control for real work ---
nmap -sV -p- 192.168.56.101 > scan.txt 2>/dev/null &
echo $! > scan.pid
tail -f scan.txt

# --- the scripts that ship with Kali ---
locate recon   2>/dev/null || find /usr/share -iname "*recon*"
find /usr/share/seclists -iname "*discovery*" -type d

Field lab

Objective: build and run a scoped reconnaissance pipeline against your own lab range.

mkdir -p ~/aegis/labs/ms-02 && cd ~/aegis/labs/ms-02

# --- 1. quoting, demonstrated the painful way ---
V="two words"
echo "UNQUOTED:"; ls $V 2>&1 | head -2
echo "QUOTED:";   ls "$V" 2>&1 | head -2

# --- 2. loopback baseline scan, raw output preserved ---
nmap -sV --version-light -p- 127.0.0.1 -oN raw-loopback.txt 2>/dev/null

# --- 3. parse it five different ways ---
echo "--- open ports (as nmap sees them) ---"
grep "open" raw-loopback.txt | awk -F/ '{print $1}'

echo "--- sorted NUMERICALLY (correct) ---"
grep "open" raw-loopback.txt | awk -F/ '{print $1}' | sort -t/ -k1 -n

echo "--- sorted ALPHABETICALLY (wrong - watch 100 sort before 22) ---"
grep "open" raw-loopback.txt | awk -F/ '{print $1}' | sort

echo "--- service/version pairs ---"
grep "open" raw-loopback.txt | awk '{print $2, $3, $4}'

echo "--- unique services only ---"
grep "open" raw-loopback.txt | awk '{print $2}' | sort -u

# --- 4. the same pipeline against your lab range (if you built one) ---
# (skip this if kr-06 is not done yet)
nmap -sT --top-ports 50 192.168.56.101 -oN raw-vuln01.txt 2>/dev/null || true
grep "open" raw-vuln01.txt | awk -F/ '{print $1, $2}'

# --- 5. write the recon.sh script from this lecture ---
cat > recon.sh <<'SCRIPT'
#!/usr/bin/env bash
set -euo pipefail
TARGET="${1:-}"
OUTDIR="$HOME/aegis/labs/recon-$(date +%Y%m%d-%H%M%S)"
if [[ -z "$TARGET" ]]; then echo "usage: $0 <cidr>" >&2; exit 2; fi
case "$TARGET" in
  192.168.*|10.*|172.1[6-9].*|172.2[0-9].*|172.3[01].*|127.*) ;;
  *) echo "REFUSING: not RFC1918 private space" >&2; exit 3 ;;
esac
mkdir -p "$OUTDIR"
nmap -sn "$TARGET" 2>/dev/null | grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' | sort -u > "$OUTDIR/alive.txt"
echo "[+] $(wc -l < "$OUTDIR/alive.txt") hosts alive"
while read -r h; do
  [[ -z "$h" ]] && continue
  nmap -sT --top-ports 100 -T4 "$h" -oN "$OUTDIR/$h.txt" 2>/dev/null || true
done < "$OUTDIR/alive.txt"
{ echo "RECON $(date -Iseconds) -> $TARGET"
  for f in "$OUTDIR"/*.txt; do [[ "$f" == *alive* ]] && continue
    echo "=== $(basename "$f" .txt) ==="; grep "open" "$f" || echo "  (none)"; done
} > "$OUTDIR/SUMMARY.txt"
echo "[+] $OUTDIR/SUMMARY.txt"
SCRIPT
chmod +x recon.sh

# --- 6. prove the scope guard works (it must REFUSE) ---
./recon.sh 8.8.8.8 ; echo "exit code: $?"

# --- 7. run it for real ---
./recon.sh 127.0.0.0/30
cat ~/aegis/labs/recon-*/SUMMARY.txt | tail -20

Step 6 matters more than it looks. A tool that refuses to scan outside private space by
default is a tool you can run without pre-deciding whether you are allowed to.

Record: your SUMMARY.txt. Compare it against the raw scan later — the pipeline is the skill.

Self-test

  1. Why must variable expansions always be quoted in a shell script?
  2. What are file descriptors 0, 1, 2, and what does 2>/dev/null actually do?
  3. sort your ports alphabetically and identify the ordering bug. Why does it matter?
  4. What do set -euo pipefail's three flags each do?
  5. Your nmap output vanished because you piped it into head and closed the pipe. What should
    you have done instead?
