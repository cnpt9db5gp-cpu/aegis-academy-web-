Network Models, OSI and TCP/IP Stacks

Summary

The theoretical layer stack, with the Neso-style emphasis on what each layer is responsible for
and why the layering exists at all.

Key ideas

  • Layering gives independent evolution: change Wi-Fi without rewriting TCP
  • Each layer provides a service to the one above and uses the one below
  • Peer-to-peer communication between layers on different hosts is an illusion — the bytes
    always traverse the whole stack on both sides
  • Encapsulation on send, decapsulation on receive
  • No layer may skip or reorder — that constraint is why HTTP cannot sit directly on Ethernet
    even when it theoretically could

Terminology

Term Meaning
Layer / layer 7 A level of abstraction in the protocol stack
Service primitive The operation a layer offers upward
Peer protocol The same layer talking across the network
Encapsulation / decapsulation Adding / removing headers
PDU Protocol data unit at that layer
Multiplexing Several higher-layer flows sharing one lower-layer flow
Service data unit The data a service passes up
Peer-to-peer Logical communication between equal layers on different hosts

Kali commands

# --- see the stack in the kernel ---
cat /proc/net/dev
ss --all --summary 2>/dev/null | head
lsmod | head -8

# --- one packet, every layer, as tshark sees it ---
command -v tshark
sudo timeout 10 tshark -i lo -c 1 -V 2>/dev/null | head -45

# --- what each layer is responsible for, observed ---
sudo timeout 8 tcpdump -i lo -n -q "icmp" 2>/dev/null | head -3     # layer 3
sudo timeout 8 tcpdump -i lo -n "arp" 2>/dev/null | head -3          # layer 2
sudo timeout 8 tcpdump -i lo -n "udp port 53" 2>/dev/null | head -3  # layer 4 + 7

# --- encapsulation sizes ---
python3 - <<'PY'
LAYERS = [("Application data", None), ("TCP", 20), ("UDP", 8), ("IP", 20), ("Ethernet", 14)]
for name, hdr in LAYERS:
    print(f"  {name:<18} {'+' + str(hdr) + ' bytes' if hdr else '(the payload)'}")
PY

Field lab

Objective: annotate one real packet across all layers, and be able to identify each header
from bytes alone.

mkdir -p ~/aegis/labs/neso-n-1 && cd ~/aegis/labs/neso-n-1

# --- 1. capture one DNS query and walk it ---
sudo timeout 12 tcpdump -i lo -n -X "udp port 53" -c 2 2>/dev/null | tee 01-packet.txt

# --- 2. the same packet, dissected by the tool ---
if command -v tshark >/dev/null; then
  sudo timeout 12 tshark -i lo -c 1 -O dns -V "udp port 53" 2>/dev/null \
    | grep -E "^Frame|^Ethernet|^Internet|^User Datagram|^Domain" | head -20 | tee 02-dissect.txt
fi

# --- 3. draw the encapsulation yourself ---
cat > 03-layers.md <<'EOF'
# Walking a DNS query down the stack

```
[ Ethernet header 14 ][ IP header 20 ][ UDP header 8 ][ DNS message ]
 dst MAC  src MAC  type    src IP  dst IP  ttl proto    sport dport len  query
 6        6        2       4       4       1  1         2     2     2    ...
```

Read a hex dump in this order:
1. bytes 0-5   destination MAC
2. bytes 6-11  source MAC
3. bytes 12-13 ethertype (0x0800 = IPv4, 0x0806 = ARP, 0x8100 = 802.1Q)
4. bytes 14-33 IP header
5. bytes 34-41 UDP header (or 34-53 for TCP)
6. everything after is the application payload

On the return path the process is identical, in reverse.
EOF
cat 03-layers.md

# --- 4. verify your reading by asking the tool ---
{
  echo "=== confirm each header from the kernel's perspective ==="
  echo "-- layer 2: ARP entries (who resolved whom) --"
  ip neigh show | head -5
  echo
  echo "-- layer 3: routes (who is reachable how) --"
  ip route | head -5
  echo
  echo "-- layer 4: sockets (which local ports are in use) --"
  ss -tulpn | head -8
  echo
  echo "-- layer 7: open a layer 4 conversation and watch it resolve --"
  timeout 5 getent hosts github.com
} 2>&1 | tee 04-layers.txt

# --- 5. why layering matters, practically ---
cat > 05-why.md <<'EOF'
# Why the layering matters to you

1. **Troubleshooting has order.** You fix layers bottom-up. A DNS failure may be an L2 problem.
2. **Attack attribution has order.** "It was an ARP attack" and "it was a DNS attack" are
   claims about different layers and require different evidence.
3. **Tool choice follows the layer.** arp-scan (L2), nmap -sn (L3), nmap -sT (L4), nikto (L7).
   Using the wrong layer's tool is the most common beginner waste.
4. **Encapsulation is how you read a packet.** It is also how you forge one.
EOF
cat 05-why.md

Step 2 is the payoff — seeing the tool's own dissection lines up against your manual reading
of the hex dump.
