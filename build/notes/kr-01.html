Why Kali Exists and What It Actually Is

Summary

Kali Linux is a rolling, Debian-derived Linux distribution built by and for people who
do security testing. Three words in that sentence matter more than the rest.

Debian-derived. Kali is not a new operating system wearing a costume. It is Debian, with a
different set of packages installed by default and a different name on the disk. Every apt,
every .deb, every dpkg behaviour you learn in ordinary Debian applies here unchanged.
Learning Kali is mostly learning Debian with a security-shaped default profile.

Rolling. Kali has no point releases. There is no "Kali 2024.1". There is a continuously
updated APT repository, and what you have installed today is whatever the repository said
yesterday. This is the single most important operational fact about Kali and it is the source
of most beginner breakage — see kr-05.

Built for security testing. Officially, Kali is a distribution for penetration testing and
digital forensics. Kali's own documentation is blunt about who it is not for: it is not a general
purpose desktop or a laptop OS, because it ships with hundreds of tools that some of which are
unsafe on a network you care about (an nmap run against the wrong subnet, a rogue DHCP client,
an open SMB client on a coffee-shop network).

Kali is a toolbox on a live distribution, not an operating system designed to be safe on
untrusted networks. That is why serious operators run tools on Kali and keep their daily
driver OS separate.

The three distributions you will meet

Distribution Made for Use it when
Kali Offensive security testing You are attacking, in a lab or an engagement
Parrot Offensive security plus desktop usability You want a daily driver that also has the tools
BlackArch Arch-based, ~2800 tools You already live on Arch and want maximal coverage

All three ship the same core tools. Kali's real advantage is not the tools — it is that the
tool set, the packaging and the documentation are maintained by the people who write the tools
and the courses. When a tool needs a specific build flag, Kali's package usually already has it.

What is actually inside

Kali ships roughly 3000+ tools, which is terrifying until you learn that they fall into about
a dozen categories:

Category Examples What it is for
Information gathering nmap, maltego, theharvester, dnsenum Map the target before touching it
Vulnerability analysis nikto, searchsploit, nessus Find known flaws in what you found
Web application burpsuite, sqlmap, ffuf, nikto Attack HTTP applications
Password attacks john, hashcat, hydra Crack or spray credentials
Exploitation metasploit, gdb, pwntools, radare2 Turn a flaw into code execution
Post-exploitation mimikatz, impacket, linpeas, bloodhound Move around after access
Sniffing/spoofing wireshark, tcpdump, ettercap, bettercap Watch and manipulate traffic
Forensics volatility, autopsy, foremost, binwalk Recover and analyse evidence
Reporting metasploit, faraday, cutycapt Write it up
Credential attacks hashcat, john, responder Recover secrets

The categories are the durable skill. Tools come and go — set is dead, armitage is gone,
beef is largely abandoned. The categories have been stable for twenty years. Learn the
categories first; the tool is a lookup.

Why this matters to you, specifically

You moved to Kali a few days ago. The most common way people fail here is treating Kali like a
normal desktop and then being confused when:

  • sudo apt update produces hundreds of lines and takes forever (rolling repo, see kr-05)
  • a tool does not work because a library changed underneath it (rolling repo again)
  • nmap triggered your own network's monitoring (it is noisy; see doc-03)
  • they cannot find the tool they read about in a tutorial (it was renamed, or it lives in a
    repo they have not enabled)

None of these are you being stupid. They are the predictable consequences of what Kali is.
Everything in this course is written with that in mind.

Terminology

Term Meaning
Rolling release No versioned point releases; the repo is always "current"
Live distribution Runs from removable media without installing to disk
Offensive Security The company that creates and maintains Kali and its training
PEN-103 The code for the Kali Linux Revealed course/book
APT Advanced Package Tool — Debian's package manager (apt, apt-get, apt-cache)
.deb A Debian package archive
Repository (repo) A server APT pulls package lists and packages from
Default profile The set of packages installed when you first boot the ISO/installed image
Metapackage A package that exists only to depend on a group of other packages

Kali commands

# What version of Kali am I actually running?
cat /etc/os-release

# What kernel, and what architecture?
uname -a

# Where did this repo come from? (the answer to most "my install is broken" questions)
cat /etc/apt/sources.list
ls /etc/apt/sources.list.d/

# How many packages are installed, and how big is the toolset?
dpkg -l | wc -l
dpkg -l | grep -c kali-tools

# Which metapackage groups exist? This IS the tool taxonomy.
apt-cache search kali-tools | grep '^kali-tools' | head -30

# What tools does a metapackage contain, without installing it?
apt-cache depends kali-tools-information-gathering
apt-get install --dry-run kali-tools-web

# Is this thing a Kali package? (searchs names, descriptions and installed files)
apt-file search "bin/nmap"      # needs: sudo apt install apt-file && sudo apt-file update
dpkg -S /usr/bin/nmap

# How much disk am I using on the toolset?
du -sh /usr/share/nmap /usr/share/wordlists /usr/share/seclists 2>/dev/null

Field lab

Objective: prove to yourself that Kali is Debian, understand what your toolset is made of,
and produce a snapshot of your own installation.

Scope: your own machine. No network scanning of anything.

mkdir -p ~/aegis/labs/kr-01 && cd ~/aegis/labs/kr-01

# 1. Identity
uname -a | tee identity.txt
cat /etc/os-release >> identity.txt

# 2. Prove it is Debian underneath
dpkg --print-architecture >> identity.txt
apt-cache policy | head -20 >> identity.txt

# 3. Enumerate the toolset categories - this is the taxonomy, printed
apt-cache search --names-only '^kali-tools-' | cut -d- -f3 | sort -u | tee categories.txt
wc -l categories.txt

# 4. Count installed tooling
dpkg -l | grep -c '^ii' >> identity.txt

# 5. Check the size of Kali's shared data (wordlists, nmap scripts, metasploit)
du -sh /usr/share/wordlists /usr/share/seclists /usr/share/nmap /usr/share/metasploit-framework \
  2>/dev/null | tee datavol.txt

Expected observations

  • dpkg --print-architecture returns amd64 — you are on Debian's package system
  • categories.txt lists ~15-20 categories, matching the table above
  • datavol.txt shows the data directories are large — this is the part of Kali that is
    genuinely valuable and often overlooked

Record: paste the output of categories.txt into your scratchpad. When you reach Tier 3 and
run searchsploit, you will understand where that data came from.

Self-test

  1. Why is Kali's rolling release a common source of breakage for new users?
  2. Name three categories from the Kali tool taxonomy and give one tool from each.
  3. Why is running Kali as a daily driver OS on an untrusted network discouraged?
  4. What is a Debian metapackage, and how would you see what one contains without installing it?
  5. dpkg -S /usr/bin/nmap — what question does that answer, and what does an empty result mean?
