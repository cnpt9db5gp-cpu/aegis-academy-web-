Your First Session: Terminal, User, and HOME

Summary

Your first interactive session on a Linux machine is a conversation between three parties: you
(the shell, reading what you type), the shell (a program that interprets your line and asks
the kernel to do things), and the kernel (which owns the hardware and decides what is allowed).

Almost every "this doesn't work" moment on a new Linux install traces back to a misunderstanding
about which of those three is responsible for what.

The three-layer model

   you type:  ls -la /etc
        ↓
   SHELL      reads the line, splits it into words, expands globs and variables,
              finds `ls` on PATH, waits for it to finish
        ↓
   KERNEL     resolves the path, opens files, reads directories, enforces permissions
        ↓
   HARDWARE   the disk

The practical consequence: when a command does not exist, that is the shell's problem. When a
command runs and gives "Permission denied", that is the kernel's problem. Knowing which layer
is complaining tells you where to look.

Your identity on the machine

whoami        # nwpcs
id            # uid=1000(nwpcs) gid=1000(nwpcs) groups=1000(nwpcs),27(sudo),...
echo $HOME    # /home/nwpcs
echo $USER    # nwpcs

Note groups= above. Being in the sudo group is what lets you become root temporarily. On
Kali your default user is a non-root user with sudo — this is correct and deliberate. A
terminal where the prompt is root@kali all the time is a machine that will lose data.

Prompt anatomy

nwpcs@kali:/home/nwpcs$ █
 └──┬──┘ └┬┘ └──────┬─────┘ └┬┘
   user   host      cwd      prompt
  • user — who the shell thinks you are
  • host — the machine name
  • cwd — your working directory, where relative paths resolve
  • $ — you are unprivileged. # would mean root.

The cwd is the piece beginners misread most. cat /etc/passwd works from anywhere (absolute
path). cat passwd only works if there happens to be a passwd in your current directory.

Getting oriented in ten commands

pwd              # where am I
whoami           # who am I
uname -a         # what machine
cat /etc/os-release   # what distribution
ls -la            # what's here (all files, long)
df -h .           # how much space is left on this filesystem
free -h           # how much memory
ps aux | head     # what is running
ss -tulpn         # what is listening on the network
history | tail    # what did I just do

The ten commands you will use every single day

# 1. Where am I?
pwd

# 2. What's in here?
ls -la

# 3. Change directory (absolute or relative)
cd /etc
cd ..
cd -

# 4. Make and remove
mkdir -p ~/aegis/labs/tier0
touch notes.txt
rm notes.txt
rm -r ~/aegis/labs/scratch        # -r recursive. ALWAYS read the path twice.

# 5. Read a file
cat /etc/passwd
less /etc/passwd                 # q to quit, / to search
head -20 /etc/passwd
tail -f /var/log/syslog          # follow, live. Ctrl+C to stop

# 6. Copy and move
cp file.txt file.bak
cp -r dir/ dir-copy/
mv old new

# 7. Find
find . -name "*.conf"
find / -perm -4000 -type f 2>/dev/null      # SUID files
which nmap; command -v nmap                 # where is this tool?

# 8. File permissions
chmod +x script.sh
chmod 600 secrets.txt
ls -l secrets.txt

# 9. Disk and users
df -h
du -sh ~/Downloads
sudo chown -R nwpcs:nwpcs ~/aegis

# 10. Pipes - the real power of a shell
ps aux | grep -v grep | grep systemd
cat /etc/passwd | cut -d: -f1
ls -la ~/aegis/labs/kr-01 | wc -l

Terminology

Term Meaning
Shell The command interpreter: bash, zsh, fish
Terminal (TTY) The character-device interface giving you a line-oriented session
Kernel Owns hardware, memory and permissions; the only privileged layer
Userspace Everything that is not the kernel — your programs
UID 0 root; the identity with no restriction
sudo Run one command as another user, with the group membership as the gate
PATH The ordered list of directories searched for an executable
Process A running program, with a PID and an owner
stdin / stdout / stderr File descriptor 0 / 1 / 2
Exit code 0 means success; anything else means failure. Scripts depend on this.

Field lab

Objective: become fluent with orientation, paths, permissions and pipes — and produce a map
of your own machine.

mkdir -p ~/aegis/labs/kr-03 && cd ~/aegis/labs/kr-03

# --- Identity and location ---
{
  echo "=== IDENTITY ==="
  whoami; id; echo "HOME=$HOME"; echo "SHELL=$SHELL"
  echo
  echo "=== SYSTEM ==="
  uname -a
  cat /etc/os-release | head -3
  echo
  echo "=== PATH ==="
  echo $PATH | tr ':' '\n'
} | tee 01-orientation.txt

# --- Prove cwd matters ---
cd /tmp
echo "now in: $(pwd)"
ls passwd          # will fail: no passwd in /tmp
cat /etc/passwd | head -2   # absolute path always works
cd ~/aegis/labs/kr-03

# --- Permissions, hands on ---
echo "secret" > secret.txt
ls -l secret.txt             # -rw-r--r--
chmod 600 secret.txt
ls -l secret.txt             # -rw-------
chmod 644 secret.txt

# --- The 20 most recent sudo uses: a real forensic finding on your own box ---
sudo -l
sudo grep -i "authentication failure" /var/log/auth.log 2>/dev/null | tail -20 \
  > 02-auth-failures.txt || echo "(auth.log not readable or empty)" > 02-auth-failures.txt
wc -l 02-auth-failures.txt

# --- What is listening right now? ---
ss -tulpn | tee 03-listening.txt
# Read it: which of these ports do you recognise? Which are 0.0.0.0 (world-reachable)?

# --- Pipes: extract structured data ---
ps -eo user,pid,comm --sort=-pid | head -15 | tee 04-processes.txt
cat /etc/passwd | cut -d: -f1,7 | grep -v nologin | grep -v false | head -20

# --- A real enumeration habit: find everything SUID ---
find / -perm -4000 -type f 2>/dev/null | tee 05-suid.txt
wc -l 05-suid.txt
echo "Read these. Every one is a privilege-escalation candidate on a real target."

Do not skip 05-suid.txt. You will run the identical command in pr-02 against your lab
VM and it is how real escalation works.

Record: in your scratchpad, note the listening ports you did not recognise, and the first
three SUID binaries. Both become relevant in Tier 1 and Tier 3.

Self-test

  1. A command prints bash: foo: command not found. Which layer is complaining, and how do you
    check whether foo exists?
  2. Why does cat passwd fail in /tmp but cat /etc/passwd work?
  3. What is the difference between $ and # in a shell prompt, and what does it tell you?
  4. Why does rm -r deserve more respect than rm?
  5. You ran tail -f /var/log/syslog and cannot get your prompt back. What did you do to cause
    this and how do you exit?

Connected knowledge

Shell → Terminal & TTY → File Descriptors → Pipes & Redirection.
