MAC Addressing, ARP and the Switching Table

Summary

How a host actually finds "who has that IP?" — and how that question, being unauthenticated,
produces the most useful Layer 2 attack there is.

Key ideas

  • MAC address: 48 bits, OUI + NIC-specific. Locally administered bit for virtual MACs
  • The ARP cache is a local shortcut so you do not ask for every frame
  • ARP request is a broadcast: "who has 192.168.56.101? tell 192.168.56.5"
  • ARP reply is unicast and unsolicited by design — any host may send one at any time
  • The switch CAM table is learned from the source address of every frame it sees
  • ARP spoofing = send ARPs claiming someone else's IP, poisoning every cache in the broadcast
    domain

Terminology

Term Meaning
OUI First 3 bytes: vendor identifier
ARP request / reply Broadcast query / unicast answer
ARP cache Host's IP→MAC table
ARP table Sometimes a separate, older table in Linux
CAM table Switch's MAC→port table
ARP poisoning Forging ARPs to intercept traffic
Gratuitous ARP Unsolicited ARPs announcing a change
Static ARP entry A manually pinned entry (defensive)
ARP scan Probing to enumerate live hosts

Kali commands

# --- the ARP cache, on this machine ---
ip neigh show

cat /proc/net/arp

# --- entries stuck in a bad state mean something odd ---
ip neigh show | grep -E "FAILED|INCOMPLETE"

# --- populate it and watch ---
ip neigh flush all 2>/dev/null
ping -c1 192.168.56.1 >/dev/null 2>&1
ip neigh show | head

# --- arp tools ---

Field lab

Objective: populate and read an ARP cache, then observe a real ARP exchange on the wire.

# --- PRE-FLIGHT: this lab needs root, so authenticate ONCE, HERE, first ---
# `sudo something &` backgrounds the password PROMPT along with the command.
# With no terminal attached to answer it, sudo fails - and `2>/dev/null`
# then throws away the only clue. The result is a capture file that was
# never written, followed by a screenful of "no such file".
#
# `sudo -v` validates the credential in the FOREGROUND, where you can see
# and answer the prompt. It caches for ~15 minutes, so every backgrounded
# `sudo` below is prompt-free and actually runs.
if ! sudo -v; then
  echo "  sudo is unavailable or the password was wrong - stop here." >&2
  echo "  Everything below needs root. Nothing will be captured." >&2
  exit 1
fi
mkdir -p ~/aegis/labs/ccna-02 && cd ~/aegis/labs/ccna-02

# --- 1. empty it, then fill it deliberately ---
{
  echo "=== flush ==="
  sudo ip neigh flush all 2>/dev/null
  ip neigh show | head
  echo "  (entries: $(ip neigh show | wc -l))"
  echo
  echo "=== generate traffic to specific neighbours ==="
  for h in 192.168.56.1 127.0.0.1; do ping -c1 -W1 $h >/dev/null 2>&1; done
  echo "=== ARP cache after ==="
  ip neigh show
} 2>&1 | tee 01-arp.txt

# --- 2. decode /proc/net/arp (MAC is little-endian in the kernel table) ---
echo
echo "=== /proc/net/arp, raw ==="
head -4 /proc/net/arp
echo "--- decoded ---"
awk 'NR>1 {split($4,a,":"); printf "  %-16s flags=%s mac=%02x:%02x:%02x:%02x:%02x:%02x\n",
  $1, $3,
  strtonum("0x" substr(a[1],7,2)), strtonum("0x" substr(a[1],5,2)),
  strtonum("0x" substr(a[1],3,2)), strtonum("0x" substr(a[1],1,2)),
  strtonum("0x" a[2]), strtonum("0x" substr(a[3],7,2))}' /proc/net/arp

# --- 3. WATCH THE EXCHANGE (the core of this lecture) ---
# terminal 1:
#   sudo tcpdump -i vboxnet0 -n -e arp
# terminal 2:
#   ip neigh flush all; ping -c1 192.168.56.1
echo
echo "Run in two terminals:"
echo "  T1: sudo tcpdump -i vboxnet0 -n -e arp"
echo "  T2: ip neigh flush all && ping -c1 192.168.56.1"
echo
echo "You will see: ARP request (who has X?) BROADCAST, then ARP reply UNICAST."
echo "Both are unsigned. Either could be forged by anyone on the segment."

# --- 4. record it ---
sudo timeout 12 tcpdump -i vboxnet0 -n -e arp -c 10 2>/dev/null | tee 02-arp-traffic.txt &
TCAP=$!
sleep 1
ip neigh flush all 2>/dev/null
ping -c2 -W1 192.168.56.1 >/dev/null 2>&1
sleep 3; kill $TCAP 2>/dev/null; wait 2>/dev/null
cat 02-arp-traffic.txt

# --- 5. THE DEFENCE, and why it breaks forwarding ---
echo
echo "=== defensive: static ARP entries ==="
sudo ip neigh add 192.168.56.1 lladdr 02:00:00:00:00:01 dev vboxnet0 nud permanent 2>/dev/null \
  && echo "  pinned 192.168.56.1" || echo "  (no vboxnet0 on this host - expected on a laptop)"
ip neigh show
sudo ip neigh flush dev vboxnet0 2>/dev/null || true

# --- 6. an ARP scan of your own lab segment (authorised only) ---
if ip -br addr show vboxnet0 >/dev/null 2>&1; then
  echo "=== scanning your own host-only lab network ==="
  sudo arp-scan --interface=vboxnet0 --localnet 2>/dev/null | tee 03-arpscan.txt
  echo "Every line here is a host on an isolated network you own."
else
  echo "No host-only adapter on this machine - build the lab first (docs/LAB-SETUP.md)."
fi

Step 3 is the one to actually perform in two terminals. Watching a broadcast request and a
unicast reply, with the MAC visible in the destination field, is the moment ARP stops being a
table in a textbook.

Record: 02-arp-traffic.txt and 03-arpscan.txt.
