Enumeration with linpeas and Manual Verification

Summary

Enumeration is 80% of a successful engagement. This lecture is the habit: run an automated tool
first, then verify every finding by hand before believing it.

linpeas is the best Linux enumeration script available. But a finding you cannot explain is a
finding you cannot report. The skill is the manual verification.

Key ideas

  • Always enumerate first. Nothing else works without knowing what you have.
  • linpeas colours results by severity; read the colour, then confirm the finding
  • Manual equivalents: id, sudo -l, ps, ss, env, mount, cat /proc/1/cmdline
  • Verify, do not trust. A tool that reports a "vulnerability" that does not exist wastes
    more time than no tool.
  • Record findings in a structured format from the start

Terminology

Term Meaning
Enumeration Building the full picture of a system
linpeas Automated Linux privilege escalation enumerator
sudo -l List permitted sudo rules — the highest-value single command
/proc Live process state, readable
Capability Specific authority in CapEff
World-writable -o+w — writable by anyone
Abuse Turning a misconfiguration into access
Triage Deciding what matters first

Field lab

Objective: run a full enumeration of your own machine, verify each automated finding by hand,
and produce a structured note.

mkdir -p ~/aegis/labs/pr-01 && cd ~/aegis/labs/pr-01

# --- 1. the automated pass ---
if command -v linpeas >/dev/null; then
  linpeas 2>/dev/null | tee 01-linpeas.txt
elif [ -x ./linpeas.sh ]; then
  ./linpeas.sh 2>/dev/null | tee 01-linpeas.txt
else
  echo "linpeas not installed. Fetch it, then re-run this lab:"
  echo "  pipx install linpeas  ||  wget -O linpeas.sh https://github.com/peass-ng/linpeas/releases/latest/download/linpeas.sh"
fi
echo "linpeas output: $(wc -l < 01-linpeas.txt 2>/dev/null || echo 0) lines"

# --- 2. the manual pass, item by item ---
{
  echo "================ IDENTITY ================"
  id
  echo "groups: $(groups)"
  echo
  echo "================ PRIVILEGE ================"
  echo "sudo rules:"
  sudo -n -l 2>/dev/null || sudo -l 2>&1 | head -20
  echo
  echo "capabilities:"
  grep -E "Cap(Inh|Prm|Eff|Bnd|Amb)" /proc/self/status
  echo
  echo "sudoers files:"
  sudo ls -la /etc/sudoers /etc/sudoers.d/ 2>/dev/null
  echo
  echo "================ SYSTEM ================"
  cat /etc/os-release | head -3
  uname -a
  echo
  echo "================ NETWORK ================"
  ss -tulpn
  echo
  echo "ip route:"; ip route
  echo "interfaces:"; ip -br addr
  echo
  echo "================ PROCESSES ================"
  ps aux --sort=-%mem | head -12
  echo
  echo "PID 1:"; tr '\0' ' ' < /proc/1/cmdline; echo
  echo
  echo "================ FILESYSTEM ================"
  mount | head -12
  echo
  echo "writable in /etc (escalation candidates):"
  find /etc -writable -type f 2>/dev/null | head -15
  echo
  echo "SUDO BINARIES:"; find / -perm -4000 -type f 2>/dev/null | head -15
  echo
  echo "recently modified in /etc:"
  find /etc -xdev -type f -mtime -7 2>/dev/null | head -10
  echo
  echo "================ SCHEDULED TASKS ================"
  crontab -l 2>/dev/null || echo "(no user crontab)"
  sudo crontab -l -u root 2>/dev/null
  ls -la /etc/cron.d/ /var/spool/cron/crontabs/ 2>/dev/null
  systemctl list-timers --all --no-pager 2>/dev/null | head -8
  echo
  echo "================ CREDENTIALS ON DISK ================"
  echo "history files:"
  ls -la ~/.bash_history ~/.python_history 2>/dev/null
  echo "config files mentioning secrets:"
  sudo grep -ril "password\|secret\|api_key" /etc /opt /srv 2>/dev/null | head -10
  echo "ssh keys:"
  ls -la ~/.ssh/ 2>/dev/null
  echo
  echo "================ ENVIRONMENT ================"
  env | sort
  echo
  echo "LD_PRELOAD=${LD_PRELOAD:-<empty>}"
  cat /etc/ld.so.preload 2>/dev/null || echo "/etc/ld.so.preload absent (good)"
} 2>&1 | tee 02-manual.txt

# --- 3. VERIFY: compare the automated and manual passes ---
{
  echo "=== does linpeas flag anything the manual pass confirms? ==="
  echo "Manual findings to check by hand:"
  echo "  [1] sudo rules listed above      -> actually usable? try one with -n"
  echo "  [2] SUID binaries               -> any that are unusual for your distro?"
  echo "  [3] world-writable in /etc      -> can you write it as your user?"
  echo "  [4] cron/systemd jobs          -> do they run as root, from a writable path?"
  echo "  [5] credentials in configs      -> do they actually work?"
} | tee 03-verify.txt

echo "=== TEST sudo -n on each rule (no password prompt, so it is safe to probe) ==="
sudo -n true 2>/dev/null && echo "  passwordless sudo: YES - that is the finding" || echo "  no blanket passwordless sudo"
sudo -n -l 2>/dev/null | tail -5

echo "=== TEST write access to the writable-in-/etc findings ==="
find /etc -writable -type f 2>/dev/null | head -3 | while read -r f; do
  if [ -w "$f" ]; then echo "  WRITABLE NOW: $f"; else echo "  not writable: $f"; fi
done

# --- 4. same enumeration against your misconfigured lab VM ---
# (from pr-04 / kr-06) - run linpeas there and compare the output.
# The differences between the two reports ARE the misconfigurations.

# --- 5. structured findings file ---
cat > 04-findings.md <<'EOF'
# Enumeration findings - <hostname> - <date>

| # | Finding | Evidence | Exploitable? | Verified how |
|---|---|---|---|---|
| 1 | | | | |
| 2 | | | | |

## Verdict
One line: is there a path to root, and what is it?
EOF
echo "template written to 04-findings.md - fill it in from 02-manual.txt"

Step 3 is the point of the whole lecture. sudo -n -l costs nothing and tells you whether a
rule is real. Copy-pasting linpeas output into a report without testing is how engagements fail
at the debrief.
