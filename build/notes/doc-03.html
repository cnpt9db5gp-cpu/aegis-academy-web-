First Contact: Scanning Your Own Loopback Interface

Summary

Your first real tool run. We will scan 127.0.0.1 — your own machine, where there is no legal
question at all — and learn to read the output the way an operator does.

Scanning yourself is not a compromise. It is how you learn the output format before the stakes
are real, and it frequently reveals services you forgot you had running.

What nmap actually does

   nmap -sT -p- 127.0.0.1
          │   └── every one of the 65535 ports
          └── TCP connect scan: complete the handshake, then close

nmap sends a probe and classifies the response:

Response Meaning
SYN / SYN,ACK Port open, something is listening
RST Port closed, host is up
ICMP unreachable Port filtered by firewall
No response Filtered/dropped — host may be down

The scan types

Type Mechanism Speed Stealth Needs root
-sT Full TCP connect slow none no
-sS Half-open (SYN only) fast good yes
-sU UDP probe very slow n/a yes
-sA ACK fast good yes
-sn Ping sweep, no ports fast good yes

-sT is the default and needs no privileges, which is why it is the right beginner choice.
On your own loopback, stealth is irrelevant.

Reading the output

PORT     STATE  SERVICE     VERSION
22/tcp   open   ssh         OpenSSH 9.2p1 Debian 2+deb12u2 (protocol 2.0)
80/tcp   open   http        Apache httpd 2.4.49 ((Debian))
443/tcp  closed ssl
  • PORT — the port and protocol
  • STATE — open / closed / filtered
  • SERVICE — nmap's guess from nmap-services
  • VERSION — banner-derived, and the most valuable column in the whole output

Kali commands

# --- 1. a host is up? ---
ping -c 3 127.0.0.1
ip -br addr show lo

# --- 2. fastest scan: which ports are open? ---
nmap -sT -p- 127.0.0.1

# --- 3. what is it running? (version detection) ---
nmap -sV -sT -p- 127.0.0.1

# --- 4. default NSE scripts: the free reconnaissance ---
nmap -sV -sC -p- 127.0.0.1

# --- 5. fast, common ports only ---
nmap -sT -T4 --top-ports 100 127.0.0.1

# --- 6. your own range (if kr-06 is built) ---
sudo nmap -sn 192.168.56.0/24
sudo nmap -sV -sC -p- 192.168.56.101

# --- 7. UDP is a different world (slow, and mostly "open|filtered") ---
sudo nmap -sU --top-ports 20 127.0.0.1

# --- 8. save it in every format you might need ---
nmap -sV -p- 127.0.0.1 \
  -oN scan.txt   # human readable
  -oX scan.xml   # for reports/tools
  -oG scan.gnmap # machine parseable (grep-able)

Always use -oN or -oG. Re-scanning because you lost the output is a habit that will cost
you an hour one day.

# --- 9. parse the saved scan instead of re-running ---
grep "open" scan.txt
grep "open" scan.gnmap | awk '{print $2}'
awk '/open/{print $4}' scan.gnmap | sort -u

Field lab

Objective: complete a full localhost assessment, learn the output formats, and discover
something you forgot was running.

mkdir -p ~/aegis/labs/doc-03 && cd ~/aegis/labs/doc-03

# --- 0. confirm the target is legitimately yours ---
ip -br addr show lo
echo "Scanning 127.0.0.1 - loopback, unambiguously self-owned."

# --- 1. before you scan: what do you think is running? ---
ss -tulpn | tee 01-before-scan.txt
echo "Predict the open ports. Then check."

# --- 2. full TCP port scan, all output formats ---
nmap -sT -p- 127.0.0.1 \
     -oN 02-full.txt -oX 02-full.xml -oG 02-full.gnmap 2>&1 | tail -5

# --- 3. read it ---
echo "=== open ports ==="
grep "open" 02-full.txt
echo
echo "=== just port numbers ==="
grep "open" 02-full.txt | awk -F/ '{print $1}' | sort -n | tr '\n' ' '
echo; echo
echo "=== services + versions ==="
grep "open" 02-full.txt | awk '{print $2, $3, $4, $5}'

# --- 4. fast scan for comparison - same answer, much faster ---
nmap -sT -T4 --top-ports 100 127.0.0.1 -oN 03-top100.txt 2>/dev/null
echo "full scan ports:     $(grep -c open 02-full.txt)"
echo "top100 scan ports:   $(grep -c open 03-top100.txt)"
diff <(grep "open" 02-full.txt | awk -F/ '{print $1}' | sort -n) \
     <(grep "open" 03-top100.txt | awk -F/ '{print $1}' | sort -n) \
  && echo "identical - top100 covers everything you care about here"

# --- 5. version detection and default scripts ---
nmap -sV -sC -p- 127.0.0.1 -oN 04-version-scripts.txt 2>/dev/null
echo "=== versions ==="
grep "open" 04-version-scripts.txt | awk '{print $2, $3, $4, $5}'
echo
echo "=== NSE script findings (the interesting part) ==="
sed -n '/PORT /,$p' 04-version-scripts.txt | grep -E "^\||^_|NSE" | head -20

# --- 6. banner grabbing by hand - what nmap does under the hood ---
for p in 22 80 8080; do
  timeout 3 bash -c "echo | nc -v 127.0.0.1 $p" 2>&1 | head -2
done

# --- 7. UDP: a different protocol, a different result ---
sudo nmap -sU --top-ports 10 127.0.0.1 -oN 05-udp.txt 2>/dev/null
grep -E "open|closed|filtered" 05-udp.txt | head -12
echo "UDP shows 'open|filtered' constantly - absence of evidence is not evidence of absence."

# --- 8. the assessment, written up ---
{
  echo "LOCALHOST ASSESSMENT"
  echo "Date:      $(date -Iseconds)"
  echo "Target:    127.0.0.1 (loopback, self-owned)"
  echo "Scanner:   $(nmap --version | head -1)"
  echo
  echo "=== SERVICES EXPOSED ==="
  grep "open" 02-full.txt | awk '{printf "  %-16s %-10s %s\n", $2, $3, $4}'
  echo
  echo "=== OBSERVATIONS ==="
  echo "  - services bound to 127.0.0.1 are unreachable from the network (good)"
  echo "  - any 0.0.0.0 binding IS reachable from the network (check ss -tulpn)"
  echo "  - versions above are candidates for searchsploit (doc-01)"
} | tee 06-assessment.txt

The finding worth acting on: if ss -tulpn showed anything bound to 0.0.0.0 in
doc-02, you have just confirmed a real exposure on your own laptop. Close it now.

Record: your 06-assessment.txt, and specifically the versions column. Those are your first
input to searchsploit.

Self-test

  1. What is the difference between open, closed and filtered, and what causes each?
  2. Why is -sS (SYN scan) faster than -sT (connect scan), and why does it need root?
  3. What does the VERSION column tell you, and why is it the most valuable column?
  4. Why do UDP scans return open|filtered so often?
  5. Why should you always use -oN/-oG instead of re-running a scan?
