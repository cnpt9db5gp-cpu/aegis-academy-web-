Reading a Tool's Documentation Like an Operator

Summary

A security tool you cannot configure is a blunt instrument. Kali ships thousands of tools, and
almost none of them can be learned from memory — they are learned from --help, man pages, and
one careful reading of what options actually do.

This lecture teaches a repeatable method for extracting exactly what you need from documentation,
and how to combine that with offline databases (searchsploit, nmap NSE scripts) to make
decisions quickly.

The documentation hierarchy

1. tool --help              fastest, usually complete enough
2. man <tool>               the full manual, searchable
3. <tool> --help | less      when the manual is enormous (nmap, msfconsole)
4. the project's own docs    for anything unusual (CVE, blog post, man page of a man page)
5. the source                for when the documentation is wrong, which happens

A repeatable method: five questions, every tool

# 1. what does it actually do?
nmap --help | head -20

# 2. what are the scan types?
nmap --help | grep -A2 'SCAN TYPES'

# 3. what are the most important options?
man nmap | col -b | grep -E '^\s+-(sS|sT|sV|sC|p|P)' | head

# 4. what does the local database know?
man nmap | grep -i nse
ls /usr/share/nmap/scripts/ | wc -l

# 5. what does it output, and in what format?
man nmap | grep -A3 'OUTPUT'

nmap as the worked example

# the scan types, straight from help
nmap --help | sed -n '/SCAN TYPES/,/TIMING/p' | head -30

# timing templates: -T0 paranoid .. -T5 insane
nmap --help | sed -n '/TIMING TEMPLATES/,/^$/p'

# the two flags you will use every single time
#   -sV  version detection
#   -sC  default NSE script set
man nmap | col -b | grep -B1 -A3 '\-sV'

# output formats
nmap --help | grep -A6 'OUTPUT'

# read an NSE script - it is readable Python
head -40 /usr/share/nmap/scripts/vulners.nse
grep -E 'portrule|ports|description' /usr/share/nmap/scripts/smb-vuln-ms17-010.nse

Reading one NSE script teaches you more than reading the nmap manual, because it shows you
what the tool is actually doing — including its assumptions and blind spots.

searchsploit as a research tool, not a magic box

# by product and version
searchsploit "openssh 9.2"

# by CVE
searchsploit CVE-2021-44228

# by technique - often the most useful mode
searchsploit --keyword=kerberoast
searchsploit --keyword="privilege escalation"
searchsploit --keyword=eternalblue

# exclude noisy results
searchsploit openssh -t linux-exploit

# show the full path so you can read the source offline
searchsploit -p 42366
searchsploit --id=42366

# all Exploit-DB entries with their paths
ls /usr/share/exploitdb/files_exploits.csv 2>/dev/null && head -3 /usr/share/exploitdb/files_exploits.csv

searchsploit --id=N and then read the PoC source is the most under-used security habit.
Most exploits are 50 lines of Python, and reading 50 lines teaches you the vulnerability better
than any course.

metasploit: docs inside the tool

msfconsole -q -x "help; exit"
msfconsole -q -x "search type:exploit name:smb; exit"
msfconsole -q -x "use exploit/multi/handler; info; exit"
msfconsole -q -x "use auxiliary/scanner/smb/smb_enum; options; exit"

# read the module's source - the real documentation
sed -n '1,40p' /usr/share/metasploit-framework/modules/auxiliary/scanner/smb/smb_enum.rb

# search by CVE
msfconsole -q -x "search cve:CVE-2017-0144; exit"

Kali commands

# --- find the doc for anything, fast ---
apropos nmap
man -k "packet capture"
whatis nmap
man 5 nmap                 # section 5 = file formats

# nmap has separate man sections worth knowing
man nmap                   # main
man nmap-services          # the port/service database
man nmap-protocols

# tool self-documentation
nmap --help
python3 -c "import socket; help(socket.socket)"
gdb --help | head
john --list=formats | head

# read source when docs fail
apt-get source nmap         # needs deb-src lines

Field lab

Objective: build a personal cheatsheet for three core tools, entirely from their own
documentation.

mkdir -p ~/aegis/labs/doc-04 && cd ~/aegis/labs/doc-04

# --- 1. nmap: extract the parts that matter ---
{
  echo "=== NMAP CHEATSHEET ==="
  echo
  echo "--- scan types ---"
  nmap --help | sed -n '/SCAN TYPES/,/TIMING TEMPLATES/p' | grep -E '^\s+-s' | head -12
  echo
  echo "--- timing templates ---"
  nmap --help | sed -n '/TIMING TEMPLATES/,/^$/p' | grep -E '^\s+-T' | head
  echo
  echo "--- the four flags I use most ---"
  echo "-sV version detection"
  echo "-sC default scripts"
  echo "-p- all ports"
  echo "-oN/-oG save output"
  echo
  echo "--- how many NSE scripts exist? ---"
  ls /usr/share/nmap/scripts/*.nse | wc -l
  echo
  echo "--- which ones are vulnerability scripts? ---"
  ls /usr/share/nmap/scripts/ | grep -c '^vuln'
} | tee 01-nmap-cheatsheet.txt

# --- 2. read a script's logic, not just its output ---
echo "=== smb-vuln-ms17-010.nse ==="
cat /usr/share/nmap/scripts/smb-vuln-ms17-010.nse
echo
echo "=== how many vuln scripts, and what do they cover? ==="
ls /usr/share/nmap/scripts/vuln-*.nse | sed 's|.*/||' | head -25

# --- 3. searchsploit, all five modes ---
{
  echo "=== by product ==="; searchsploit "openssh 9.2p1" | head -8
  echo "=== by CVE ==="; searchsploit CVE-2017-0144 | head -8
  echo "=== by technique ==="; searchsploit --keyword=kerberoast | head -8
  echo "=== by platform ==="; searchsploit openssh -t linux-exploit | head -8
  echo "=== full paths, so you can read the PoC ==="; searchsploit -p 42873 | head -4
} | tee 02-searchsploit.txt

# --- 4. READ an exploit's source - the best documentation there is ---
FIRST=$(searchsploit -p 42873 --raw 2>/dev/null | head -3)
echo "raw (truncated) preview:"
echo "$FIRST"
echo
echo "Full source is on disk here:"
find /usr/share/exploitdb -name "42873*" -o -name "*EternalBlue*" 2>/dev/null | head -3

# --- 5. metasploit module documentation ---
msfconsole -q -x "search type:aux name:smb_enum; info; exit" 2>/dev/null \
  | sed -n '1,40p' | tee 03-msf-info.txt

# --- 6. the man page sections worth knowing ---
{
  echo "=== man section 1 (commands) ==="; apropos -s 1 capture | head -5
  echo "=== man section 5 (file formats) ==="; apropos -s 5 passwd | head -5
  echo "=== man section 8 (system admin) ==="; apropos -s 8 nmap | head -5
} | tee 04-man-sections.txt

# --- 7. write YOUR cheat sheet ---
cat > ~/aegis/NMAP-CHEATSHEET.md <<'EOF'
# My nmap cheatsheet

## Everyday
- `nmap -sV -sC -p- TARGET -oN out.txt`      full scan, keep the output
- `nmap -sT -T4 --top-ports 100 TARGET`     fast triage
- `sudo nmap -sn 192.168.56.0/24`           host discovery

## When quiet
- `nmap -sS -T2 -p- TARGET`                half-open, slow
- `nmap -sA`                               firewall bypass trick

## Parsing
- `grep open out.gnmap | awk '{print $2}'`
- `nmap --script vuln --script-args safe TARGET`
EOF
cat ~/aegis/NMAP-CHEATSHEET.md

Step 4 is the one that changes how you learn. Reading a 60-line proof-of-concept tells you
the exact mechanism of a vulnerability — often clearer than any lecture, because it is the
vulnerability and nothing else.

Record: keep ~/aegis/NMAP-CHEATSHEET.md and add equivalents for john, curl and grep
as you meet them.

Self-test

  1. What are the five documentation sources, in order of speed?
  2. Why is reading an NSE script more educational than running it?
  3. searchsploit --keyword= is more useful than product search in what situation?
  4. What does searchsploit -p <id> give you that a web search does not?
  5. Why does searchsploit -p <id> --raw matter for learning rather than just copying?
