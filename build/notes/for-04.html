File Carving and Hidden Data

Summary

Every file system loses data. A file that is deleted leaves its content on the disk until
overwritten. The discipline is knowing where data can hide — in slack space, in unallocated
clusters, in alternate data streams, inside other files — and how to extract it without corrupting
the evidence.

The framing: the file system's view of a file is not the only view of
its bytes. NTFS has slack, streams, and resident data; a PNG can
contain an entire ZIP; an email client stores attachments in its own
format.

Companion to for-02 (timeline) and for-01 (get the image first).
All work is on a read-only working copy.

Where data hides

  ON THE DISK, UNALLOCATED
    SLACK SPACE (NTFS)
      the last cluster of a file. A 3 KB file in a 4 KB cluster has
      1 KB of slack, which contains whatever was there before. The
      file system never touches it. Deleted data lands here.

    UNALLOCATED CLUSTERS
      clusters freed by a deletion, before anything reused them.
      The richest source of deleted files, and the first thing
      overwritten by normal use.

    THE $MFT's RESIDENT DATA
      files under ~700 bytes are stored inside their own $MFT entry
      rather than in a cluster. A deleted resident file's content is
      still in the $MFT until the entry is reused.

  INSIDE OTHER FILES (carving)
    APPENDED   a JPEG with a ZIP appended past the EOI marker
    PREPENDED   a ZIP with a GIF before the PK signature
    EMBEDDED    an Office document with an OLE object inside it
    A PNG WITH A ZIP INSIDE, which is how many polyglots work

  IN METADATA
    ALTERNATE DATA STREAMS (NTFS)
      every file has a $DATA stream plus named streams:
        file.txt:hidden              an arbitrary stream
        file.txt:Zone.Identifier      the MOTW
      ADS are invisible in Explorer, invisible to `cat`, and they
      survive copying with some tools and not others.

    THE MFT ITSELF
      $MFT is a file. Its size is in its own $MFT entry. Parsing it
      with a full parser beats grepping.

    THE USN JOURNAL
      $UsnJrnl:$J is a change journal, tens of MB, recording every
      file create/rename/delete. It is evidence in its own right.

  INSIDE THE OS'S OWN DATABASES
    the $MFT, $LogFile, $Secure, $UsnJrnl
    Event logs, Prefetch, SRUM/DATABASE, Amcache, ShimCache
    browser SQLite databases, the jump lists, LNK files
    Recycle Bin, $Recycle.Bin's own $I/$R pairs
    hiberfil.sys, pagefile.sys, swapfile.sys

# --- 1. slack and unallocated ---
cat > 01-slack.sh <<'EOF'
#!/usr/bin/env bash
# Slack and unallocated space. Read-only against a working copy.
IMG="${1:?usage: ./01-slack.sh <working-copy.dd> [offset-bytes]}"
OFF="${2:-0}"
echo "=== the file system, which tells you the slack size ==="
fsstat -o "$OFF" "$IMG" 2>&1 | grep -iE "cluster size|block size|sector size" | sed 's/^/  /'
echo "  ^ slack is the difference between cluster size and file size."
echo "    A 4 KB cluster and a 3 KB file leaves 1 KB of slack, which the"
echo "    file system never touches."
echo
echo "=== the unallocated space, as raw bytes to a file ==="
blkls -o "$OFF" "$IMG" > work/unalloc.bin 2>/dev/null \
  && ls -la work/unalloc.bin | sed 's/^/  /'
echo "  (blkls writes unallocated clusters. On a real disk this is GBs.)"
echo
echo "=== what is IN there? (carving, covered in 02) ==="
echo "  bulk_extractor -o work/carved -S 8KB work/unalloc.bin"
echo
echo "=== the MFT's own resident data (small deleted files) ==="
icat -o "$OFF" "$IMG" 0 2>/dev/null | head -c 1024 | xxd | head -6 | sed 's/^/  /'
echo "  ^ the MFT's first 1024 bytes. Resident file content lives here."
EOF
chmod +x 01-slack.sh

# --- 2. carving ---
cat > 02-carve.sh <<'EOF'
#!/usr/bin/env bash
# Carving: find files by their magic bytes, in unallocated space.
# The tools do this well; the KNOWLEDGE is knowing what each misses.
IMG="${1:?usage: ./02-carve.sh <unalloc.bin or working-copy.dd>}"
mkdir -p work/carved

echo "=== 1. bulk_extractor - feature-based, finds text too ==="
echo "  (installed on this box)"
bulk_extractor -o work/carved -S 8KB "$IMG" 2>&1 | tail -5 | sed 's/^/  /'
echo
echo "  WHAT IT PRODUCES:"
echo "    carved/    files found by signature"
echo "    feature_files/  TEXT: emails, URLs, passwords, credit-card-like"
echo "    telephone-numbers/  cookie-jar-like strings"
echo "    wordlist/  a wordlist built from the text it found"
echo "  The FEATURE FILES are the point. A carving tool that only"
echo "  finds JPEGs misses an entire C2 URL in a .txt."
echo
echo "=== 2. scalpel / foremost - signature-only, fast ==="
echo "  (scalpel is installed; foremost is not)"
scalpel -c scalpel.cfg "$IMG" -o work/carved-scalpel 2>&1 | tail -5 | sed 's/^/  /'
echo
echo "=== 3. binwalk - EMBEDDED files inside other files ==="
echo "  (installed)"
echo "  binwalk work/carved/report.doc    # what is inside this file"
echo "  binwalk -e work/carved/firmware.bin  # EXTRACT the embedded files"
echo
echo "  binwalk is for EMBEDDING, not carving. A firmware image with a"
echo "  squashfs and a JFFS2 inside it, or a ZIP with a PDF inside,"
echo "  is binwalk's job."
echo
echo "=== 4. what every carver misses ==="
echo "    - files with a damaged header (a JPEG with a broken SOI)"
echo "    - files split across a fragment (carving works per-run)"
echo "    - data inside a file's slack, not at a file boundary"
echo "    - encrypted or compressed content that happens to contain"
echo "      a signature at the wrong offset"
echo "  A carver finds CANDIDATES. Confirm with 'file' and with a"
echo "  viewer before you call something a JPEG."
echo
echo "=== 5. confirm the carved output ==="
file work/carved/* 2>/dev/null | head -15 | sed 's/^/  /'
EOF
chmod +x 02-carve.sh

# --- 3. ADS, and the other hiding places ---
cat > 03-hideouts.sh <<'EOF'
#!/usr/bin/env bash
# The places data hides that are not "deleted files".
IMG="${1:?usage: ./03-hideouts.sh <working-copy.dd> [offset]}"
OFF="${2:-0}"
echo "=== ALTERNATE DATA STREAMS ==="
echo "  NTFS gives every file a \$DATA stream plus named streams."
echo "  Explorer will not show them. cat will not read them."
echo "  They are the classic hiding place, and they are STILL there."
echo
echo "  enumerate with sleuthkit (ls -l shows *:name for streams):"
fls -o "$OFF" -r -p -l "$IMG" 2>/dev/null | grep -E '\*:' | sed 's/^/  /' | head -20
echo
echo "  read one:"
echo "    icat -o $OFF '$IMG' <inode> 'hidden' > out.bin"
echo
echo "  Zone.Identifier is the MOTW. Its presence means the file came"
echo "  from the internet. Its ABSENCE on a downloaded file is itself"
echo "  a finding (it was stripped, which requires a tool)."
echo
echo "=== $MFT, $LogFile, \$Secure, \$UsnJrnl ==="
for f in '$MFT' '$LogFile' '$Secure' '$UsnJrnl:\$J' '$Recycle.Bin'; do
  inum=$(fls -o "$OFF" -r -p "$IMG" 2>/dev/null | grep -F "$f" | head -1 \
         | sed -E 's/.*\(([0-9]+)\).*/\1/')
  if [ -n "$inum" ]; then
    sz=$(icat -o "$OFF" "$IMG" "$inum" 2>/dev/null | wc -c)
    printf "  %-18s inode %-8s %s bytes\n" "$f" "$inum" "$sz"
  fi
done
echo "  ^ these are FILES in the file system. They are large, they"
echo "    contain structured history, and they survive deletion of"
echo "    the things they describe."
echo
echo "=== THE RECYCLE BIN ==="
echo "  \$Recycle.Bin\\S-1-5-21-...\\\$I0000001.TXT is the METADATA"
echo "  (original path, size, deletion time, in binary)"
echo "  \$Recycle.Bin\\S-1-5-21-...\\\$R0000001.TXT is the CONTENT"
echo "  Delete with Shift means the bytes are still there."
echo
echo "=== THE JUMP LISTS ==="
echo "  %APPDATA%\\Microsoft\\Windows\\Recent\\AutomaticDestinations"
echo "  LNK files that record what was opened FROM Explorer, including"
echo "  files that were opened and then deleted."
echo "  These are the best 'what did this user do' source on disk."
echo
echo "=== THE OS DATABASES ==="
for d in 'Windows/System32/winevt/Logs' \
         'Windows/Prefetch' \
         'Windows/AppCompat/Programs/Amcache.hve' \
         'Windows/AppCompat/Programs/ShimCache' \
         'Windows/System32/config/SYSTEM' \
         'Windows/System32/config/SOFTWARE' \
         'Windows/System32/config/SAM' \
         'Windows/System32/windowscache' \
         'Windows/System32/config/SOFTWARE' \
         'Users' ; do
  inum=$(fls -o "$OFF" -r -p "$IMG" 2>/dev/null | grep -i -F "$d" | head -1 \
         | sed -E 's/.*\(([0-9]+)\).*/\1/')
  [ -n "$inum" ] && echo "  present: $d (inode $inum)"
done
echo
echo "  Every one of those is parsed by a different tool. The EXIF in"
echo "  a JPEG, the SQLite in a browser history, the EVT in the event"
echo "  logs: each needs its own parser, and no generic tool does all."
EOF
chmod +x 03-hideouts.sh

# --- 4. offline: ADS, demonstrated ---
python3 - <<'PY' 2>&1 | tee 04-ads.txt
print("  === alternate data streams, and why they are a real hiding place ===\n")
print("  EVERY NTFS FILE HAS AT LEAST ONE STREAM:")
print()
print("    report.docx:\$DATA           the content you see")
print("    report.docx:Zone.Identifier  where it came from (the MOTW)")
print("    report.docx:anything         arbitrary, up to the volume's limit")
print()
print("  WHY THEY MATTER:")
print()
print("    1. Explorer DOES NOT SHOW THEM. A stream named 'hidden' is")
print("       invisible in the file properties, in a directory listing,")
print("       and to `cat file`.")
print()
print("    2. Size tools report only \$DATA. A 400 KB file with 40 MB in")
print("       an ADS reports as 400 KB.")
print()
print("    3. They survive certain copies. Copying with Explorer or")
print("       robocopy preserves them; some tools and some archive")
print("       formats do not. So a file that 'lost' its stream on")
print("       transfer is evidence it WAS transferred.")
print()
print("    4. THE MOTW IS THE USEFUL ONE EVEN WHEN HARMLESS:")
print("       Zone.Identifier holds the download URL.")
print("         Contents: \"[ZoneTransfer]\"")
print("         ZoneId=3")
print("         HostUrl=https://cdn.example.com/payload.exe")
print("       ZoneId 3 = internet. ZoneId 4 = restricted.")
print("       A downloaded executable with ZoneId=3, next to a file")
print("       with no Zone.Identifier at all, means someone stripped it.")
print()
print("  === THE DETECTION ===")
print()
print("    enumerate:  icat <image> <inode> 'Zone.Identifier'")
print("    or:         getfattr -d -m - file (on a live Linux mount)")
print("    or:         fls -l <image> | grep ':'")
print()
print("  === THE MOTW AS A FINDING ===")
print()
print("  NOT: 'there are ADS on the system.'")
print()
print("  YES: 'Executables in C:\\Users\\<user>\\Downloads lack the")
print("       Zone.Identifier alternate data stream that Windows")
print("       attaches to every downloaded file. Every other downloaded")
print("       executable in the same directory has it. The streams")
print("       were removed, which requires a tool and intent.'")
print()
print("  That is a finding. The first version is trivia.")
PY
cat 04-ads.txt

# --- 5. the confirmation step ---
cat > 05-confirm.md <<'EOF'
# Confirming a carve

A carver produces CANDIDATES. A candidate is not a finding.

THE CONFIRMATION CHAIN, in order:
1. file work/carved/xyz.1
"the signature matched" - that is all you know so far

2. exiftool work/carved/xyz.1
   does the internal metadata agree with the extension?
   a "JPEG" whose Exif says a different make and model is either
   a mis-named file or something with a header prepended

3. open it in a viewer (or: strings | head)
   does it render? is there a JPEG comment marker? do the
   dimensions in the header match what renders?

4. check the offset
   binwalk shows where the signature was found. A JPEG at
   offset 0 is a JPEG. A JPEG at offset 2,000,000 in a .doc is
   an EMBEDDED object, and that is a different finding with a
   different meaning.

5. hash it, and record the offset it came from
   "carved from unallocated space at offset 0x4A2F000" is a
   reproducible statement. "found a JPEG somewhere" is not.


```bash
# the confirmation, as commands
file work/carved/xyz.1
exiftool work/carved/xyz.1 | head -20
binwalk work/carved/xyz.1
sha256sum work/carved/xyz.1
echo "offset: from the bulk_extractor/scalpel log, or binwalk's output"

  AND THE HONEST FRAMING WHEN YOU CANNOT CONFIRM:
    "A 2.3 MB region at unallocated offset 0x4A2F000 begins with a
     valid JPEG SOI marker and contains a complete JFIF APP0 segment,
     but the image data is truncated. This is consistent with a
     partially-overwritten or partially-recovered JPEG. It is
     recorded as an artefact of unknown origin rather than as a
     recovered file."

  That sentence is longer than "found a broken jpg" and infinitely
  more useful to whoever reads the report.

EOF
cat 05-confirm.md
```

Step 4 is the deliverable: the alternate data stream demonstration, and the reframing at the
bottom. "There are ADS on the system" is trivia. "Executables in Downloads lack the
Zone.Identifier stream that every other downloaded file has — the streams were removed, which
requires a tool and intent" is a finding. Same evidence, different sentence.

05-confirm.md is the discipline note: a carver produces candidates, and the honest
framing when you can't confirm one is a specific sentence rather than "found a broken jpg".
