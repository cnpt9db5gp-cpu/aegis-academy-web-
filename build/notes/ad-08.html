Detection: Signing, LDAP Policies and Logging

Summary

Every note in this course ends with a finding. This one is the other half: what a defender needs
to see one happening, and why most environments have none of it.

The framing that makes it actionable: detection is a set of specific
events with specific values. Not "monitor Active Directory". These
seven event IDs, with these filter values, cover the entire tier.

The seven events that matter

  4662  Directory Service Access. The DCSync detection.
        Filter: ObjectType=domainDNS AND the ObjectAccess UNKNOWN GUID is
        one of the three replication rights.

  4663  DS Replica. Anyone enumerating the domain at volume.
        Filter: a user running this in bulk.

  5136  Directory object MODIFIED. The early-warning system.
        Filter: objectClass in (domainDNS, user, computer, group) AND
        the attribute changed in (sPN, msDS-AllowedToDelegateTo,
        msDS-UserDoesNotNeedPreAuth, msDS-SupportedEncryptionTypes,
        servicePrincipalName, member, nTSGeneralInfo).
        A new sPN or a delegation flag appearing is an ATTACK, not a
        change. This is the earliest reliable signal you have.

  4624  Logon. Filter: LogonType in (3, 9) from an unusual source;
        LogonType 9 (NewCredentials) is pass-the-hash over WinRM;
        LogonType 2 (Interactive) on a server is unusual.

  4672  Special privileges assigned at logon. Filter: SeDebugPrivilege,
        SeImpersonatePrivilege, SeTcbPrivilege.
        ANY 4672 with SeDebugPrivilege from a workstation is worth
        an immediate alert.

  4688  Process creation. Filter: mimikatz, or rundll32 with
        comsvcs.dll + MiniDump, or any PowerShell with -enc/-nop,
        or a service creation (7045).

  4768/4769/4771  Kerberos: TGT request (4768) with a
        RC4-encryption type (23) from a host that normally uses AES
        (17/18), TGS request (4769) with an unusual encryption type,
        and pre-authentication failed (4771) in volume.

The policy controls that generate the detections

  AUDIT POLICY - must be enabled, most are not by default:

    DC Audit Policies > DS Access
      Audit Directory Service Access    : SUCCESS, FAILURE   <- 4662
      Audit Directory Service Changes   : SUCCESS           <- 5136
    DC Audit Policies > Object Access
      Audit File System                 : SUCCESS           <- NTDS/SAM reads
    DC Audit Policies > Privilege Use
      Audit Sensitive Privilege Use    : SUCCESS           <- 4679 token assign
      Audit Other Privilege Use Events  : SUCCESS           <- 4672

  ADVANCED AUDIT POLICY > Audit Credential Validation
      Audit Kerberos Authentication Service : SUCCESS       <- 4768/4769/4771
      Audit Kerberos Service Ticket Operations : SUCCESS

  Log file sizes: the Security log must be large enough that a week of
  4663 enumeration does not roll it. Most default to 20 MB and lose
  the attack.

  Advance audit policy: DIRECTORY SERVICE ACCESS must be Force Subcategory
  settings to override, or a local policy overrides it.

The SMB and LDAP relay controls

  THE CONTROLS, and the event that proves each is off:

  SMB SIGNING REQUIRED
    enables Microsoft network client/server digital signing
    proves it: 4769 Kerberos with ticket encryption 0x7 (RC4) is the
    fallback to NTLM; more directly, look at the GPO result. A host
    that authenticates with NTLM when SMB signing is "required" for
    that host is misconfigured.

  LDAP SIGNING REQUIRED
    enables LDAP client signing
    without it, an LDAP relay gets you authentication.

  LDAP CHANNEL BINDING (KB5012122)
    signed TLS with channel binding. This is what stopped the main
    relay vector in 2020 and it is now default-on for Windows Server
    2022 and patched everywhere.

  "LONG LOGON TICKETS" / "Kerberos extended protection"
    DC-side: Set "KDC-force AES, and for NTLM, the KDC will not issue
    to servers that don't support extended protection"
    this closes KDC-coerced NTLM downgrade, which was CVE-2020-1350's
    sibling class.

  THE COMMON FINDING: these are set "required" but with an exception
  list, and the exceptions are the vulnerable hosts.

Building the detections

-- KQL: the DCSync alert (4662 + the three GUIDs)
SecurityEvent
| where EventID == 4662
| where ObjectType == "domainDNS"
| where ObjectAccess in (
    "1131f6aa-9c07-11d1-f79f-00c04fc2dcd2",   -- Replicating Directory Changes
    "1131f6ad-9c07-11d1-f79f-00c04fc2dcd2",   -- ...In Filtered Set
    "89e95b76-444d-4c62-991a-0facbeda640c")   -- DS-Replication-Get-Changes
| project TimeGenerated, SubjectUserName, SubjectDomainName, IpAddress, WorkstationName

-- KQL: roast preparation - someone is setting up Kerberoasting
SecurityEvent
| where EventID == 5136
| where ObjectClass in ("user", "computer")
| where AttributeLDAPDisplayName in (
    "servicePrincipalName",
    "msDS-AllowedToDelegateTo",
    "msDS-UserDoesNotNeedPreAuth",
    "msDS-SupportedEncryptionTypes",
    "msDS-SecurityHistory")
| project TimeGenerated, ObjectDN, SubjectUserName, IpAddress, AttributeValue

-- KQL: enumeration at volume (a network map being built)
SecurityEvent
| where EventID == 4663
| summarize Hits = count() by SubjectUserName, IpAddress, bin(TimeGenerated, 5m)
| where Hits > 500

-- KQL: pass-the-hash and credential dumping
SecurityEvent
| where (EventID == 4624 and LogonType in (3, 9))
    or (EventID == 4672 and PrivilegeList has "SeDebugPrivilege")
    or (EventID == 7045)
| project TimeGenerated, EventID, SubjectUserName, IpAddress, LogonType, ServiceFileName, PrivilegeList

-- KQL: the relay signal - NTLM where it should be Kerberos
SecurityEvent
| where EventID == 4769
| where ServiceName == "cifs" or ServiceName == "ldap" or ServiceName == "http"
| where TicketEncryptionType == 0x7
| summarize Count = count() by IpAddress, ServiceName
| where Count > 20

Reporting to a client who cannot see any of it

## F-xx · Active Directory attacks would not be visible to your SIEM

Risk
  The engagement reached domain administrator. Not one of the required
  events was being logged with a value your SIEM could alert on. The
  three directory replication events that would identify a DCSync are
  not logged. Directory object modifications are not logged, so the
  creation of the service principal name used for roasting would not
  have been visible. Credential validation events are logged but at
  the default verbosity, which does not include the ticket encryption
  type, so an RC4 downgrade would not have appeared.

  The practical effect: an attacker who followed the same path we did
  would have had no telemetry to alert on, at any point, on any host.

Evidence
  Enumeration of your Advanced Audit Policy settings on DC01 and DC02,
  and a review of the Security event log contents for the engagement
  window. See Appendix A for the full policy export.

Business impact
  Mean time to detect and respond to a domain compromise is
  unbounded. This is the finding that would have mattered most if
  another actor had been present.

Remediation
  1. Enable Audit Directory Service Access (Success/Failure) and
     Directory Service Changes (Success) on both DCs    [Security, Immediate]
  2. Enable Audit Credential Validation with the Verbose success
     setting                                        [Security, Immediate]
  3. Raise the Security log size to [X] MB with rollover to external
     storage                                       [Security, Immediate]
  4. Implement the four alerts in Appendix B          [Security, 1 sprint]
  5. Verify with a test: the alerts in Appendix B fire on a known
     benign action, and log forward.
