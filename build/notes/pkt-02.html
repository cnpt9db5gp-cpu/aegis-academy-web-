Wireshark Display Filters and Protocol Dissection

Summary

tcpdump stores; Wireshark interprets. Display filters are how you turn 50,000 captured packets
into the five that answer your question.

Key ideas

  • Two-stage workflow: capture with BPF, then read with display filters
  • Display filter syntax: proto.field op value, e.g. tcp.port == 445
  • Comparators: ==, !=, >, <, contains, matches (regex), in
  • Follow streams is the single most useful feature: reassemble the whole conversation
  • Expert info annotates anomalies the dissector understands
  • Statistics → Conversations / Endpoints answer "who talked to whom, how much"

Terminology

Term Meaning
Display filter Filter applied when reading a capture
Protocol field A parsed field like tcp.flags.syn
Conversation filter tcp.stream eq 3
Follow stream Reassemble one TCP conversation
Expert info Analyzer warnings (checksum, retransmit)
Endpoints Unique hosts in a capture
I/O graph Volume over time
Name resolution Turning IPs into names (off by default, correctly)
Dissector The code that parses one protocol

# --- PRE-FLIGHT: this lab needs root, so authenticate ONCE, HERE, first ---
# `sudo something &` backgrounds the password PROMPT along with the command.
# With no terminal attached to answer it, sudo fails - and `2>/dev/null`
# then throws away the only clue. The result is a capture file that was
# never written, followed by a screenful of "no such file".
#
# `sudo -v` validates the credential in the FOREGROUND, where you can see
# and answer the prompt. It caches for ~15 minutes, so every backgrounded
# `sudo` below is prompt-free and actually runs.
if ! sudo -v; then
  echo "  sudo is unavailable or the password was wrong - stop here." >&2
  echo "  Everything below needs root. Nothing will be captured." >&2
  exit 1
fi
command -v wireshark tshark editcap capinfos

# --- capture a usable file ---
sudo tcpdump -i lo -w /tmp/base.pcap -s 0 2>/dev/null &
TC=$!; sleep 1
( nc -l -p 8080 >/dev/null 2>&1 & ); sleep 1
for i in $(seq 1 4); do echo "hello $i" | timeout 2 nc 127.0.0.1 8080 2>/dev/null; done
sleep 4; kill $TC 2>/dev/null; wait $TC 2>/dev/null

# --- tshark: the CLI dissector ---
capinfos /tmp/base.pcap 2>/dev/null | head -8
tshark -r /tmp/base.pcap -q -z io,phs              # protocol hierarchy
tshark -r /tmp/base.pcap -q -z conv,tcp            # conversations
tshark -r /tmp/base.pcap -q -z endpoints,ip

# --- display filters ---
tshark -r /tmp/base.pcap -Y "tcp.port == 8080"
tshark -r /tmp/base.pcap -Y "http" 2>/dev/null
tshark -r /tmp/base.pcap -Y "tcp.flags.syn == 1 and tcp.flags.ack == 0"
tshark -r /tmp/base.pcap -Y "ip.src == 127.0.0.1"
tshark -r /tmp/base.pcap -T fields -e frame.number -e ip.src -e ip.dst -e tcp.srcport -e tcp.dstport 2>/dev/null | head -8

# --- the GUI, when you want to click ---
wireshark /tmp/base.pcap &
echo "  In the GUI: Display Filter box (top left), Follow TCP Stream (right click a packet)"

Field lab

Objective: answer three real questions from one capture using display filters.

# --- PRE-FLIGHT: this lab needs root, so authenticate ONCE, HERE, first ---
# `sudo something &` backgrounds the password PROMPT along with the command.
# With no terminal attached to answer it, sudo fails - and `2>/dev/null`
# then throws away the only clue. The result is a capture file that was
# never written, followed by a screenful of "no such file".
#
# `sudo -v` validates the credential in the FOREGROUND, where you can see
# and answer the prompt. It caches for ~15 minutes, so every backgrounded
# `sudo` below is prompt-free and actually runs.
if ! sudo -v; then
  echo "  sudo is unavailable or the password was wrong - stop here." >&2
  echo "  Everything below needs root. Nothing will be captured." >&2
  exit 1
fi
mkdir -p ~/aegis/labs/pkt-02 && cd ~/aegis/labs/pkt-02

# --- 1. build a capture with several distinct conversations ---
sudo tcpdump -i lo -n -w base.pcap -s 0 2>/dev/null &
TC=$!; sleep 1
( nc -l -p 8080 >/dev/null 2>&1 & )
( nc -l -p 9090 >/dev/null 2>&1 & )
sleep 1
for i in $(seq 1 3); do echo "http-ish $i" | timeout 2 nc 127.0.0.1 8080 2>/dev/null; done
for i in $(seq 1 3); do echo "other $i"   | timeout 2 nc 127.0.0.1 9090 2>/dev/null; done
ping -c2 127.0.0.1 >/dev/null 2>&1
dig +short localhost @127.0.0.1 >/dev/null 2>&1
sleep 5; kill $TC 2>/dev/null; wait $TC 2>/dev/null
ls -la base.pcap

# --- 2. Q1: what protocols are in here at all? ---
echo "=== Q1: protocol hierarchy ==="
tshark -r base.pcap -q -z io,phs 2>/dev/null | head -20 | tee 01-phs.txt

# --- 3. Q2: who talked to whom, and how much? ===
echo
echo "=== Q2: TCP conversations ==="
tshark -r base.pcap -q -z conv,tcp 2>/dev/null | head -12 | tee 02-conv.txt

# --- 4. Q3: show me every packet of one conversation, with fields ---
echo
echo "=== Q3: extract structured fields ==="
tshark -r base.pcap -Y "tcp.port in {8080,9090}" \
  -T fields -e frame.number -e ip.src -e tcp.srcport -e ip.dst -e tcp.dstport \
             -e tcp.flags.syn -e tcp.flags.fin -e frame.len 2>/dev/null \
  | head -15 | tee 03-fields.txt

# --- 5. follow one conversation, reassembled ---
echo
echo "=== the 8080 conversation, reassembled as one stream ==="
stream=$(tshark -r base.pcap -Y "tcp.port == 8080" -T fields -e tcp.stream 2>/dev/null | head -1)
echo "  stream id: $stream"
tshark -r base.pcap -q -z "follow,tcp,ascii,$stream" 2>/dev/null | head -25 | tee 04-follow.txt
echo
echo "Follow Stream is the feature that turns 40 scattered packets into a readable conversation."

# --- 6. expert info: what did the dissector notice? ---
echo
echo "=== expert analysis ==="
tshark -r base.pcap -q -z expert 2>/dev/null | head -12 | tee 05-expert.txt

# --- 7. the filter vocabulary, written out ---
cat > 06-filters.md <<'EOF'
# Display filter cheat sheet (Wireshark / tshark syntax)

## comparison
==   !=   >   <   >=   <=
contains "x"        matches /regex/

## protocols
ip  tcp  udp  arp  icmp  dns  http  tls  ssh  smb

## fields (the useful ones)
ip.src  ip.dst  ip.ttl  ip.len
tcp.srcport  tcp.dstport  tcp.stream
tcp.flags.syn  tcp.flags.ack  tcp.flags.fin  tcp.flags.reset
tcp.window_size_value  tcp.len
udp.srcport  udp.dstport
http.host  http.request.uri  http.response.code
dns.qry.name

## combinations
tcp.port == 445
tcp.flags.syn == 1 and tcp.flags.ack == 0        # half-open
ip.addr == 192.168.56.101
ip.ttl < 20
http.response.code >= 500
tcp.stream eq 3
tcp.port in {22, 80, 443}

## excludes
not arp
!(tcp.port == 22)

## following one conversation
tcp.stream eq 0
-follow tcp -i 0
EOF
cat 06-filters.md

# --- 8. GUI, if you want to click ---
echo
echo "GUI: wireshark base.pcap"
echo "  1. Display Filter box, top left. Try: tcp.port == 8080"
echo "  2. Right-click a packet > Follow > TCP Stream"
echo "  3. Statistics menu > Conversations / Endpoints / I/O Graph"
echo "  4. Expert Information tab, bottom pane"

Step 5 is the one that changes everything. Follow Stream turns a wall of hex into a
readable conversation, and it is how you read an exfiltration or a C2 channel.
