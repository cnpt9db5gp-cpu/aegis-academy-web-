Concurrency and Threads

Summary

Concurrency is where the abstraction of "one process, one logical thread of control" breaks down.
When several threads or processes touch shared state, the interleaving of their operations decides
the outcome — and an attacker can influence that interleaving.

Two practical threads for this course:

  1. Understand race conditions, because they are a real privilege escalation class (pr-03)
  2. Understand desynchronisation, because it is the root cause of HTTP request smuggling
    (Tier 4) and of cache attacks

Processes vs threads

Processes Threads
Memory Isolated address spaces Shared
Creation cost fork() is expensive Cheap
Communication IPC: pipes, sockets, shared memory Shared variables
Failure Contained One thread can corrupt everything
Security Strong boundary Weak boundary

A crash or memory corruption in a thread can take down the whole process, because the address
space is shared.

The race window

// NOT thread-safe
int balance = 1000;

void withdraw(int amount) {
    if (balance >= amount) {      // check
        balance -= amount;        // use
    }
}

Two threads can both pass the check before either updates, and both withdraw. In POSIX terms this
is a data race — and the C standard makes it undefined behaviour, so the compiler is free to
optimise the check away entirely.

Fixes, and their cost

pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

void withdraw(int amount) {
    pthread_mutex_lock(&lock);
    if (balance >= amount) balance -= amount;
    pthread_mutex_unlock(&lock);
}
Mechanism Guarantees Risk
Mutex Mutual exclusion Deadlock if lock order is inconsistent
Atomic ops Single instruction (compare-and-swap) Limited to small operations
Semaphore Counting permits More complexity
Lock-free (CAS loops) No blocking Subtle, easy to get wrong
Files lock (flock) Cross-process Advisory only

Deadlock is the price of locks: hold A, wait for B; hold B, wait for A. The cure is a strict,
global lock ordering.

Inter-process shared memory

// map a file into both processes' address space
int fd = open("/tmp/shared", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);
void *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);

Shared memory is fast and has no access control — anything that can open the file can read
and write it. In practice, shared-memory services (/dev/shm, /run/shm) are a recurring local
privilege escalation vector on multi-user machines.

Concurrency in security, concretely

  1. Race conditions — symlink swaps, temp files, check-then-act in shell scripts
  2. TOCTOU — covered in os-07
  3. Request smuggling — two HTTP parsers disagree about message boundaries
  4. Side channels — another thread's timing reveals a secret
  5. Thread injection — ptrace into a multithreaded target, where each thread has its own stack

Field lab

Objective: demonstrate a real data race, detect it automatically, and inspect shared memory.

mkdir -p ~/aegis/labs/os-08 && cd ~/aegis/labs/os-08

# --- 1. count threads vs processes ---
{
  echo "=== processes: $(ps -e --no-headers | wc -l) ==="
  echo "=== threads:    $(ps -eLf --no-headers | wc -l) ==="
  echo
  echo "=== my threads ==="
  ls /proc/self/task | wc -l
  echo
  echo "=== busiest threads ==="
  top -H -b -n1 2>/dev/null | head -12
} > 01-threads.txt; cat 01-threads.txt

# --- 2. A REAL DATA RACE, and how to catch it ---
cat > race.c <<'EOF'
#include <pthread.h>
#include <stdio.h>
static int counter = 0;
static void *worker(void *arg) {
    for (int i = 0; i < 100000; i++) counter++;   /* read-modify-write, not atomic */
    return NULL;
}
int main(void) {
    pthread_t t[4];
    for (int i = 0; i < 4; i++) pthread_create(&t[i], NULL, worker, NULL);
    for (int i = 0; i < 4; i++) pthread_join(t[i], NULL);
    printf("counter = %d (expected 400000)\n", counter);
    return 0;
}
EOF
gcc -O0 -g race.c -o race -lpthread
echo "=== normal build ==="
./race | tee 02-race.txt

gcc -O0 -g -fsanitize=thread race.c -o race-tsan -lpthread
echo "=== ThreadSanitizer build (the correct answer) ==="
./race-tsan 2>&1 | grep -A4 "WARNING: ThreadSanitizer" | head -12 | tee -a 02-race.txt

echo
echo "The race is real: counter < 400000 means updates were lost."
echo "TSan names the exact source line. Always build with it during development."

# --- 3. the fix ---
cat > safe.c <<'EOF'
#include <pthread.h>
#include <stdio.h>
#include <stdatomic.h>
static _Atomic int counter = 0;
static void *worker(void *arg) {
    for (int i = 0; i < 100000; i++) atomic_fetch_add(&counter, 1);
    return NULL;
}
int main(void) {
    pthread_t t[4];
    for (int i = 0; i < 4; i++) pthread_create(&t[i], NULL, worker, NULL);
    for (int i = 0; i < 4; i++) pthread_join(t[i], NULL);
    printf("counter = %d (always 400000)\n", counter);
    return 0;
}
EOF
gcc -O0 -g safe.c -o safe -lpthread && ./safe | tee -a 02-race.txt

# --- 4. shared memory has no ACL by default ---
{
  echo "=== /dev/shm ==="
  ls -la /dev/shm/
  df -h /dev/shm | tail -1
  echo
  echo "=== SysV IPC on this box ==="
  ipcs -m 2>/dev/null | head -5
  ipcs -s 2>/dev/null | head -5
  echo
  echo "=== write something into shared memory and read it back ==="
  python3 - <<'PY'
import mmap, os
path = "/dev/shm/aegis-demo"
fd = os.open(path, os.O_CREAT | os.O_RDWR, 0o666)
os.ftruncate(fd, 4096)
m = mmap.mmap(fd, 4096, mmap.MAP_SHARED, mmap.PROT_READ | mmap.PROT_WRITE)
m[0:11] = b"AEGIS-SHARED"
print("  written:", bytes(m[0:11]).decode())
os.close(fd)
PY
ls -la /dev/shm/aegis-demo
echo "  ^ mode 666: any local user can read and write it. That is the risk."
rm -f /dev/shm/aegis-demo
} | tee 03-shmem.txt

# --- 5. ptrace into a threaded process ---
sleep 600 & BGPID=$!
echo "thread count of $$ : $(ls /proc/$$/task | wc -l)"
echo "thread count of PID : $(ls /proc/$BGPID/task 2>/dev/null | wc -l)"
echo "each thread has its OWN stack - which is why buffer overflows differ per-thread"
kill $BGPID 2>/dev/null

Step 2 is the exercise that changes how you write code. Run it, see counter come out under
400000, then read the ThreadSanitizer report naming the exact line. Every multithreaded daemon you
will audit in Tier 5 needs this check.

Record: 02-race.txt — the TSan output. Compare its line number precision with a manual
review; you would probably never have found it by reading.
