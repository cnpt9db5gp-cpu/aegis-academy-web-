Basics of OS: Computer System Operation & Storage Structure

Summary

Before algorithms and scheduling, a Neso-style foundation lecture: what a computer is made of,
what an OS manages, and how storage is structured. Security-relevant conclusions arrive
immediately — the OS is the trusted intermediary on every trust boundary you test later.

Key ideas

  • Hardware: CPU (registers, ALU, control unit), memory hierarchy (registers → cache → RAM →
    disk), I/O devices, buses.
  • OS as resource manager: decides who gets the CPU, how much memory, which device.
  • OS as virtual machine: provides an abstract machine (files, processes, sockets) so programs
    do not touch hardware directly.
  • Memory hierarchy: the reason caching exists, and the reason cache timing is a side channel.
  • Storage structure: registers → cache → main memory → secondary storage. Each is a
    performance layer with a different trust story.

Terminology

Term Meaning
ALU Arithmetic logic unit; performs operations
Register Fastest, smallest CPU storage
Cache Small fast memory, hierarchy between CPU and RAM
DMA Direct memory access; devices bypass the CPU
System call Program → kernel request
Kernel mode Ring 0, full privilege
User mode Ring 3, restricted
Bootstrap The firmware that loads the kernel
Firmware Software baked into hardware (UEFI, BIOS)

Kali commands

lscpu | grep -E "^CPU|Model name|L1d|L2|L3"
ls -la /sys/devices/system/cpu/cpu0/cache/ 2>/dev/null
cat /proc/cpuinfo | grep -m1 "model name"
free -h; swapon --show
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT
# the boot chain, in order
cat /proc/cmdline
dmesg | head -5            # kernel ring buffer = boot messages
ls /sys/firmware/efi 2>/dev/null || echo "booted via legacy BIOS path"

Field lab

Objective: read the machine's hardware inventory and the boot chain from the running system.

mkdir -p ~/aegis/labs/neso-os-1 && cd ~/aegis/labs/neso-os-1
{
  echo "=== CPU ==="; lscpu | grep -E "Architecture|^CPU\(s\)|Thread|Core|Model name|L1d|L2|L3"
  echo; echo "=== cache hierarchy ==="
  for c in /sys/devices/system/cpu/cpu0/cache/index*; do
    [ -d "$c" ] && echo "  level=$(cat $c/level 2>/dev/null) type=$(cat $c/type 2>/dev/null) size=$(cat $c/size 2>/dev/null)"
  done
  echo; echo "=== memory ==="; free -h; swapon --show
  echo; echo "=== storage ==="; lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT
  echo; echo "=== boot chain ==="
  echo "firmware: $([ -d /sys/firmware/efi ] && echo UEFI || echo legacy-BIOS)"
  echo "cmdline:  $(cat /proc/cmdline)"
  echo "--- first kernel messages ---"; dmesg 2>/dev/null | head -8
  echo; echo "=== who may talk to devices directly? ==="
  ls -la /dev/mem /dev/kmem 2>/dev/null
  grep -E "DMA|dma" /proc/iomem 2>/dev/null | head -3
} 2>&1 | tee 01-hardware.txt

Expected: every row is a real hardware fact, and /dev/mem is root-only — the OS controlling
direct hardware access, exactly as described.
