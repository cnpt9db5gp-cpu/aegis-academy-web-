MAC Protocols, CSMA/CD and Switching

Summary

How a shared medium became a switched one, and the attack surface each stage introduced.

Key ideas

  • CSMA/CD: listen, transmit, detect collision, back off exponentially. Historical — switched
    Ethernet made it unnecessary
  • Collision domain: a hub shares one; a switch gives one per port; full duplex removes it
  • Broadcast domain: unchanged by switching; only routers and VLANs split it
  • Store-and-forward vs cut-through trade latency for reliability
  • STP/RSTP prevents loops, and its own design creates a well-known hijack opportunity
  • Port security, MAC limits and DHCP snooping exist because the Layer 2 threat model is weak

Terminology

Term Meaning
CSMA/CD Carrier sense multiple access with collision detection
Backoff Exponential random wait after a collision
Collision domain Where frames can collide
Broadcast domain Where broadcasts propagate
Store-and-forward Buffer the whole frame before forwarding
Cut-through Forward as soon as the destination is known
STP / RSTP Spanning tree; prevents switching loops
BPDU Bridge protocol data unit
Root bridge The elected STP reference
Port security Limit MAC addresses per port

# --- 2. the switch learning algorithm, run by hand ---
python3 - <<'PY' | tee 02-learning.txt
MAC_TABLE = {}      # mac -> port

def switch_receive(frame_src, dst, ingress_port):
    """Learn from the SOURCE. Forward based on the DESTINATION."""
    if frame_src not in MAC_TABLE:
        action = "LEARN (new entry)"
    else:
        action = f"known -> port {MAC_TABLE[frame_src]}"
    MAC_TABLE[frame_src] = ingress_port

    if dst in MAC_TABLE:
        out = f"forward to port {MAC_TABLE[dst]}"
    elif dst == "ff:ff:ff:ff:ff:ff":
        out = "FLOOD to every other port  <- broadcasts are never controlled"
    else:
        out = "FLOOD (destination not yet known)"
    print(f"  src={frame_src} dst={dst} in=port{ingress_port}  {action}; {out}")

print("=== normal traffic ===")
switch_receive("aa:bb:cc:00:00:01", "aa:bb:cc:00:00:02", 1)
switch_receive("aa:bb:cc:00:00:02", "aa:bb:cc:00:00:01", 2)
print()
print("=== an unknown unicast, then a broadcast ===")
switch_receive("aa:bb:cc:00:00:03", "aa:bb:cc:00:00:09", 3)
switch_receive("aa:bb:cc:00:00:03", "ff:ff:ff:ff:ff:ff", 3)
print()
print("=== the security consequences, mechanically ===")
print("1. Learning is from the SOURCE and is unauthenticated -> forge the source, own the table.")
print("2. Flooding happens for unknown destinations -> MAC flood forces everything to flood.")
print("3. Broadcasts always flood -> ARP poisoning reaches every host in the domain.")
PY

# --- 3. MAC flooding, conceptually, and why STP exists ---
cat > 03-macflood.md <<'EOF'
# MAC flooding and why STP exists

## Loops are fatal without a control protocol
Two switches connected by two cables, each forwarding a broadcast, form a loop.
Frames multiply without bound until the link saturates. Real networks need
Spanning Tree to disable redundant paths.

## MAC flooding attacks the other side of that same trade
A switch has a fixed-size CAM table. Filling it with thousands of fake source
addresses makes it unable to learn, so it falls back to flooding unknown
destinations - and everything the attacker sends becomes visible to everything.

**Lab-only demonstration:** tools exist for this (`yersinia -p dos`).
Only ever against hardware you own.

## The defensive side
- Port security: cap the MAC count per port
- DHCP snooping: bind IP-to-MAC to a port
- Dynamic ARP inspection: reject ARP whose source MAC does not match the port
- Monitor for a sudden drop in switch CPU or a CAM table that never fills
EOF
cat 03-macflood.md

# --- 4. STP BPDUs, and the reason STP is a security concern ---
cat > 04-stp.md <<'EOF'
# Spanning Tree Protocol as an attack surface

STP elects a root bridge using BPDUs sent to the reserved multicast address
01:80:c2:00:00:00, from the bridge ID (priority + MAC), with a path cost
and a timer set by the root.

**The attack is structural, not a bug:** BPDUs are unauthenticated and
unencrypted, so anything that can speak on the segment can participate.

Consequences:
1. Claim a lower bridge ID and become root -> dictate the topology.
2. Claim lower cost paths -> redirect traffic through the attacker.
3. Send BPDUs continuously -> force constant topology reconvergence (DoS).

Mitigations: BPDU Guard, Root Guard, PortFast on edge ports, and
authentication where the platform supports it.

**General lesson:** any protocol in which participation is discovered by
broadcasting is trusting whoever answers first. That is the same shape as
rogue DHCP and evil-twin WiFi.
EOF
cat 04-stp.md

{
  echo "=== interface statistics ==="
  ip -s link | head -20
  echo
  echo "=== collisions, if reported ==="
  for i in /sys/class/net/*/statistics; do
    n=$(basename $(dirname $i))
    printf "  %-8s collisions=%s carrier_errors=%s rx_errors=%s\n" "$n" \
      "$(cat $i/collisions 2>/dev/null || echo n/a)" \
      "$(cat $i/carrier_errors 2>/dev/null || echo n/a)" \
      "$(cat $i/rx_errors 2>/dev/null || echo n/a)"

} 2>&1 | tee 05-counters.txt
