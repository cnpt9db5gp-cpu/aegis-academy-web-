Certificates

Summary

A certificate says: this public key belongs to this name, and I, a certificate authority, vouch
for it. The lecture's argument is about the machinery around that sentence — validation, name
handling, revocation, and what happens when a CA is wrong or compromised.

Key ideas

  • Chain of trust: leaf → intermediate → root, each signing the one below
  • A browser ships a root store; the chain terminates there
  • Validation must check: chain to a trusted root, name match, validity dates, revocation,
    key usage, and critical extensions
  • Name matching has been a rich source of bugs: wildcards, null bytes in CN, IDN
    normalisation, and SANs superseding CN entirely
  • Revocation barely works in practice (OCSP stapling, CRLs) — browsers soft-fail
  • Compromised CAs are the catastrophic failure: one rogue CA can forge any certificate
  • Certificate pinning reduces reliance on the public PKI

The validation checklist

A client MUST check, before trusting a certificate:

  1. Chain builds to a root in the local trust store
  2. Validity dates include now
  3. Name matches the hostname being connected to (SAN, not CN)
  4. Not revoked (and, if revocation cannot be checked, behave consistently)
  5. Basic constraints: the CA can sign; the leaf cannot
  6. Key usage / extended key usage permits this use (serverAuth)
  7. Critical extensions are understood

A client that skips any of these has a vulnerability, not a lenient policy.

Name matching, where it goes wrong

"*.example.com"  matches  a.example.com        -> should match
"*.example.com"  matches  a.b.example.com      -> SHOULD NOT match
"www.example.com.evil.com"                      -> obviously a different name
CN="victim.com\0evil.com"   (null byte truncation) -> a historical vulnerability
IDN: "аpple.com" with a Cyrillic 'а'             -> homograph, different name

Modern clients: SAN only. CN is ignored unless there is no SAN at all.
Wildcards match exactly one label. Any deviation is a bug.

When the PKI fails

Failure Impact
Rogue CA certificate forge any certificate
Miss-issued certificate mis-issuance for one domain
CA compromise same as rogue
Validation bug in a client universal MITM
Revocation not checked revoked certs still work

The PKI is a distributed trust system, and its weakest point is the
largest number of parties who can issue: roughly a hundred roots, each of
which can delegate.

Terminology

Term Meaning
Certificate CA-signed binding of a public key to an identity
Chain of trust leaf → intermediate → root
Root CA Self-signed, trusted directly
Intermediate CA Signed by a root, signs leaves
Trust store The set of roots a client trusts
SAN Subject Alternative Name; the modern name mechanism
CN Common Name; obsolete for hostnames
Wildcard certificate *.example.com
Revocation CRL and OCSP; withdrawing a compromised certificate
Stapling The server presenting the OCSP response itself
CT log Certificate Transparency; public log of all issuances
Wildcard abuse *.co.uk style certificates

# --- expiry hygiene on your own box ---
{
  echo "=== certificates expiring within 30 days on this machine ==="
  find /etc/ssl /etc/ssl/private /usr/local/share/ca-certificates -name "*.crt" -o -name "*.pem" 2>/dev/null \
  | head -50 | while read -r f; do
      end=$(openssl x509 -enddate -noout -in "$f" 2>/dev/null | cut -d= -f2)
      [ -z "$end" ] && continue
      days=$(( ( $(date -d "$end" +%s 2>/dev/null || echo 0) - $(date +%s) ) / 86400 ))
      [ "$days" -lt 30 ] && printf "  %-50s %4s days\n" "$f" "$days"
    done
  echo "  (empty = nothing expiring soon)"
} 2>&1 | tee 01-expiry.txt

{

# --- 2. the leaf, and the fields a client checks ---
{
  echo "=== LEAF CERTIFICATE ==="
  echo | timeout 15 openssl s_client -connect $T:443 -servername $T 2>/dev/null \
    | openssl x509 -noout -subject -issuer -dates 2>/dev/null | sed 's/^/  /'
  echo
  echo "=== extensions a client must verify ==="
  echo | timeout 15 openssl s_client -connect $T:443 -servername $T 2>/dev/null \
    | openssl x509 -noout -text 2>/dev/null \
    | sed -n '/X509v3 extensions/,/Signature Algorithm/p' \
    | grep -E "Basic Constraints|Key Usage|Extended Key|Subject Alternative|Authority Info|CRL" | sed 's/^/  /'
} 2>&1 | tee 02-leaf.txt

# --- 3. SAN, which is what the hostname is actually matched against ---
{
  echo "=== SUBJECT ALTERNATIVE NAMES ==="
  echo | timeout 15 openssl s_client -connect $T:443 -servername $T 2>/dev/null \
    | openssl x509 -noout -ext subjectAltName 2>/dev/null | fold -w 76 | sed 's/^/  /'
  echo
  echo "  CN is ignored when a SAN exists. Every hostname must appear here."
} 2>&1 | tee 03-san.txt

# --- 4. name matching, done correctly ---
python3 - <<'PY' | tee 04-name-matching.txt
import fnmatch, re

def match(hostname, pattern):
    """A correct wildcard match: one label only, case-insensitive, IDN-normalised."""
    h = hostname.lower().rstrip(".")
    p = pattern.lower().rstrip(".")
    if p == h:
        return True
    if not p.startswith("*."):
        return False
    # a wildcard covers exactly ONE label
    return fnmatch.fnmatch(h, p) and h.count(".") == p.count(".")

cases = [
    ("a.example.com",      "*.example.com",  True),
    ("a.b.example.com",    "*.example.com",  False),   # two labels - must NOT match
    ("example.com",        "*.example.com",  False),   # bare domain - must NOT match
    ("www.example.com",    "www.example.com",True),
    ("WWW.Example.COM",    "www.example.com",True),    # case insensitive
    ("evil-example.com",   "*.example.com",  False),
    ("www.example.com.evil.com", "*.example.com", False),
]
print("  %-26s %-18s %-8s %s" % ("HOSTNAME","PATTERN","EXPECT","ACTUAL"))
for host, pat, want in cases:
    got = match(host, pat)
    print("  %-26s %-18s %-8s %-6s %s" % (host, pat, want, got, "ok" if got == want else "MISMATCH"))
print()
print("  Two lessons a naive implementation gets wrong:")
print("    a.b.example.com must NOT match *.example.com   (one label only)")
print("    example.com must NOT match *.example.com either (the domain itself is excluded)")
PY
cat 04-name-matching.txt

# --- 5. build your own certificate and see each field ---
{
  echo "=== generating a certificate and reading every field ==="
  openssl req -x509 -newkey rsa:2048 -keyout lab.key -out lab.crt -days 30 -nodes \
    -subj "/C=US/ST=California/L=SF/O=AEGIS/OU=Lab/CN=aegis-lab.local" \
    -addext "subjectAltName=DNS:aegis-lab.local,DNS:*.aegis-lab.local,IP:127.0.0.1" 2>/dev/null

  echo "--- subject ---"; openssl x509 -in lab.crt -noout -subject | sed 's/^/  /'
  echo "--- issuer (self-signed, so identical) ---"; openssl x509 -in lab.crt -noout -issuer | sed 's/^/  /'
  echo "--- validity ---"; openssl x509 -in lab.crt -noout -dates | sed 's/^/  /'
  echo "--- SANs ---"; openssl x509 -in lab.crt -noout -ext subjectAltName | sed 's/^/  /'
  echo "--- fingerprint (the pinning value) ---"; openssl x509 -in lab.crt -noout -fingerprint -sha256 | sed 's/^/  /'
  echo "--- key usage ---"; openssl x509 -in lab.crt -noout -text | grep -A1 "Key Usage" | sed 's/^/  /'
} 2>&1 | tee 05-my-cert.txt

# --- 6. serve it, and connect properly ---
cat > tlsserve.py <<'PY'
import ssl, socket, threading, os
ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
ctx.load_cert_chain("lab.crt", "lab.key")
srv = socket.socket(); srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("127.0.0.1", 8445)); srv.listen(1)
def serve():
    c,_ = srv.accept()
    with ctx.wrap_socket(c, server_side=True) as s:
        s.sendall(b"aegis lab\n")
threading.Thread(target=serve, daemon=True).start()
import time; time.sleep(8)
srv.close()
PY
python3 tlsserve.py & SRV=$!
sleep 1
{
  echo "=== connecting with VERIFICATION (should fail: not in the trust store) ==="
  timeout 5 openssl s_client -connect 127.0.0.1:8445 -servername aegis-lab.local 2>&1 \
    | grep -iE "verify return code|verify error" | head -3 | sed 's/^/  /'
  echo
  echo "=== trusting it explicitly (the correct fix) ==="
  timeout 5 openssl s_client -connect 127.0.0.1:8445 -CAfile lab.crt -servername aegis-lab.local 2>&1 \
    | grep -iE "verify return code|Verification" | head -3 | sed 's/^/  /'
  echo "  0 = verified against the CA we supplied. That is trust, explicitly granted."
  echo
  echo "=== and with the CA in the system store, any client trusts it ==="
  echo "  (do NOT do this outside a lab: a trusted root can forge anything)"
} 2>&1 | tee 06-verify.txt
kill $SRV 2>/dev/null

# --- 7. the PKI's structural weakness ---
cat > 07-pki.md <<'EOF'
# The PKI's structural weakness

The system works by trusting a small number of roots. Each root can
**delegate** to intermediates. Each intermediate can issue certificates.

**The number of parties who can issue a certificate for your domain is much
larger than the number of roots.** Roughly a hundred roots, thousands of
intermediates, and hundreds of thousands of delegated domains.

Consequences:
- one compromised root can forge any certificate
- one buggy intermediate can mis-issue for many brands
- revocation exists precisely because revocation is the only remedy, and it
  barely works: browsers soft-fail on OCSP failure, because failing closed
  breaks the internet more often than attacks do

Mitigations layered on top:
- **Certificate Transparency** (public logs; CT monitoring for unexpected issuance)
- **Short-lived certificates** (reduces the exploitation window)
- **Pinning** (bypasses the PKI for known keys)
- **HSTS preload** (removes the CA from the path for known sites)
- **DANE / DNSSEC** (binds the expected certificate to the DNS name)

The direction of travel is fewer, shorter-lived, more transparent
certificates, with pinning and CT doing the work the PKI was supposed to.
EOF
cat 07-pki.md

Step 6 is the point: a self-signed certificate fails verification until you explicitly
trust it with -CAfile. That is the PKI working correctly — trust is granted, never assumed.
