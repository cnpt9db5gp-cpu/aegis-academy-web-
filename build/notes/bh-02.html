Reading the Graph: Sessions, Groups and ACLs

Summary

A graph is only useful if you can ask it questions. This note is the query set: what each edge
type means, what it enables, and which queries answer "where is the weak point".

The framing: most graphs are read by scrolling a list of paths, and
that is the wrong way round. Find the paths you can take, then check
what is behind each edge.

The edge types, and what each one actually gives you

  MEMBERSHIP (edge_group)
    USER@DOMAIN  ->  GROUP@DOMAIN
    Direct authority. If you are the user, you are the group's rights.

  MEMBER OF (transitive)
    The graph materialises the closure. A path
      user -> "IT Staff" -> "Domain Admins"
    means the user is a Domain Admin, two hops from a group you may
    never have heard of.

  HAS SESSION (SessionLoop)
    USER -> COMPUTER, with a TIMESTAMP.
    THE MOST IMMEDIATELY EXPLOITABLE EDGE.
    If alice is authenticated to WEB01 and you can relay that
    authentication, you are alice on WEB01 without any credential.
    It is also the edge that turns into pass-the-hash trivially: read
    the hash out of that session on that host.

  ADMIN TO (LocalAdmin)
    PRINCIPAL -> COMPUTER, local administrators.
    If you are the principal, you are SYSTEM on that host.

  GENERICALL / GENERICWRITE / WRITEDACL / WRITEOWNER
    PRINCIPAL -> OBJECT
    GenericAll       - full control of the object
    GenericWrite     - can write most attributes, INCLUDING the
                       script path on a computer, and the SPN on a
                       user (so: roast it)
    WriteDACL        - can rewrite the ACL. Equivalent to GenericAll,
                       because you can just grant yourself GenericAll
    WriteOwner       - take ownership, then the above
    ValidatedWrite   - conditional write; famous for
                       UserIsMemberOfState (ad-07)

  WRITESPN
    PRINCIPAL -> USER
    can add an SPN to that account -> make it roastable -> if you have
    a low-privilege session somewhere, this is a lateral move that
    needs no credential.

  READGMSAPASSWORD
    PRINCIPAL -> GROUP
    read the gMSA's managed password. gMSA passwords are 120 chars of
    random, so reading one is a total compromise of that service
    account's rights - and gMSAs are usually NOT in Domain Admin.

  DCSYNC
    PRINCIPAL -> DOMAIN
    can replicate the directory. NOT the same as Domain Admin
    membership, and usually the more surprising finding.

  ALLOWEDTODELEGATE
    PRINCIPAL -> SPN
    can get a service ticket for that SPN as any user.
    Together with unconstrained delegation (edge to the domain), this
    is a path to any user's ticket.

  GENERICALL on a GROUP
    principal -> group. Can add themselves, or change the group's
    membership, or delete it.

  DCSync on a COMPUTER
    computer -> domain. A machine account that can replicate the
    directory. This is the shortcut that hand audits miss, because
    nobody reads computer objects.

  SQLADMIN / ADCSESCAPE / DCO
    database-specific privileges in the BloodHound SQL/ADCS plugins.

  DCSync via GPO
    principal -> GPO, and the GPO's scope contains a DC.
    Write on a GPO is domain compromise (ad-07).

The queries

-- 0. a helper, and a caveat about labels
-- Labels are 'TYPE@DOMAIN' in UPPERCASE. 'Domain Admins@LAB.INTERNAL'.
-- Getting the case wrong returns zero rows and reads as "no path".

-- 1. shortest path from alice to Domain Admins
WITH RECURSIVE p(from, to, depth) AS (
  SELECT 'ALICE@LAB.INTERNAL', 'DOMAIN ADMINS@LAB.INTERNAL', 0
  UNION ALL
  SELECT e.source, p.to, p.depth+1
  FROM edge_acl e JOIN p ON e.target = p.from
  WHERE p.depth < 8
)
SELECT * FROM p WHERE from = 'ALICE@LAB.INTERNAL' AND depth > 0;

-- 2. every principal that can DCSync (NOT the same as Domain Admin)
SELECT DISTINCT source, target FROM edge_acl WHERE type = 'DCSync';

-- 3. every principal with delegation, and to what
SELECT DISTINCT source, target FROM edge_acl
WHERE type IN ('AllowedToDelegate','AllowedToDelegateTo');

-- 4. principals with an SPN (the roast list)
SELECT name FROM users WHERE serviceprincipalname IS NOT NULL;
SELECT name FROM computers WHERE serviceprincipalname IS NOT NULL;

-- 5. SPNs you can WRITE to a user (lateral roasting, no credential)
SELECT DISTINCT source, target FROM edge_acl WHERE type = 'WriteSPN';

-- 6. readGMSAPassword (a 120-char password you can read)
SELECT DISTINCT source, target FROM edge_acl WHERE type = 'ReadGMSAPassword';

-- 7. the sessions (SessionLoop), with timestamps
SELECT source, target, time FROM sessions ORDER BY time DESC;

-- 8. who is local admin where
SELECT DISTINCT source, target FROM edge_acl WHERE type = 'AdminTo';

-- 9. every path to a SPECIFIC high-value target, not Domain Admin
--    (a SQL admin, an Exchange admin, a backup admin)
WITH RECURSIVE p(from, to, depth) AS (
  SELECT 'ALICE@LAB.INTERNAL', 'DOMAIN ADMINS@LAB.INTERNAL', 0
  UNION ALL
  SELECT e.source, p.to, p.depth+1
  FROM edge_acl e JOIN p ON e.target = p.from
  WHERE p.depth < 8
)
SELECT * FROM p WHERE from='ALICE@LAB.INTERNAL' AND depth > 0;

Reading a path, not just seeing one

  The path is the finding. But the REPORT is the analysis of the path:

  Path:
    alice@lab -> MEMBER OF -> "Helpdesk"@lab
               -> GENERICALL -> "IT Support"@lab
               -> GENERICWRITE -> svc-deploy@lab
               -> MEMBER OF -> "Domain Admins"@lab

  What each edge means, in the context of the attack:
    MEMBER OF Helpdesk          - the starting point. alice is a helpdesk
                                   user: a normal account, no admin.
    GENERICALL on "IT Support"  - alice can rewrite the IT Support group.
                                   She can add HERSELF to it.
    GENERICWRITE on svc-deploy  - whoever is in IT Support can set any
                                   attribute on the deploy service
                                   account, including an SPN. That makes
                                   it roastable. Then, with a wordlist,
                                   the password. (ad-04)
    MEMBER OF Domain Admins     - the account the path reaches is a
                                   domain admin.

  THE RECOMMENDATION, which must be SPECIFIC:
    1. Remove the GENERICALL on "IT Support". It should be Read, not
       Full Control. Who granted it, and why, in 2019?
    2. Separate the deploy service account from Domain Admins. A
       service account that deploys code should be able to deploy to
       servers, not administer the domain.
    3. Constrain what service accounts can be GenericWrite'd.

  WHY THIS IS BETTER THAN "review your ACLs":
    because it names the two edges, names the accounts, and gives the
    two actions that break the path. "Review your ACLs" is unfalsifiable.

The questions that find things

  1. WHAT IS THE SHORTEST PATH, AND WHAT IS THE EDGE?
     A 1-hop path is a bug. A 5-hop path is a design problem, and the
     LAST edge is usually the bug regardless of the length.

  2. IS THE WIN CONDITION DCSYNC OR DOMAIN ADMIN?
     Both matter. DCSync is usually the more surprising one and often
     the shorter one.

  3. IS THERE A COMPUTER ON THE PATH?
     A computer account in the path means you can read its hash from
     wherever it is currently authenticated - no domain traffic needed.

  4. IS THERE A WRITE ON A GPO THAT LINKS TO A DC?
     That is domain compromise without touching a DC.

  5. WHAT IS THE UAC ON EACH EDGE?
     'GENERICALL' at the end of a path you found by enumeration is a
     finding. 'GENERICALL' in a path you found by exploiting is a
     different (worse) finding, and it is the one that is in scope.

  6. CAN THE PATH BE WALKED WITH WHAT I ALREADY HAVE?
     If you are currently alice, and the path from alice is 3 hops,
     you have 3 hops to take. If it is 1 hop to DCSync, you are done.
     The graph tells you how many things you need to do, not just
     that you can.

The graph's own failure modes

  1. TRUNCATION
     A collection that errored out on 30% of objects produces a graph
     with missing edges. A missing path is not evidence of no path.
     ALWAYS check: users count vs ldapsearch, Domain Admins membership
     non-zero, no errors in the collector log.

  2. STALENESS
     A graph from hour 1 is wrong by hour 8. AD changes during an
     engagement (that is part of what you are doing). Collect at the
     start AND the end.

  3. LABEL CASE
     BloodHound labels are UPPERCASE. 'domain admins@lab.internal'
     returns nothing and looks like 'no path'. This is the single most
     common analysis error.

  4. CLUSTER BOUNDARIES
     BloodHound can group principals into clusters for the GUI. A
     cluster is NOT an equivalence of rights - it is a similarity
     heuristic. Never report 'these 400 principals have the same
     privileges' from a cluster.

  5. READ-BASED, NOT WRITE-BASED
     The graph shows what the ACLs PERMIT. It does not show what is
     enforced elsewhere (a PAW, a jump host, a conditional access
     policy, a network control). A path that crosses a firewall
     boundary is still a path in the graph.
     -> You must overlay the NETWORK map on the GRAPH map. The
        intersection is the real finding.

  6. THE PATH IS NOT A PLAN
     See bh-03. The graph says WHERE. The execution needs the
     credential, the host, and the method.

Terminology

Term Meaning
Edge A typed, directed relationship in the graph
Member / MemberOf Group membership; the graph materialises the closure
HasSession A user is authenticated to a computer now
AdminTo A principal is a local admin on a computer
GenericAll / GenericWrite Full or broad control of an object
WriteDACL Can rewrite the ACL; equivalent to full control
WriteSPN Can add an SPN; makes an account roastable
ReadGMSAPassword Can read a gMSA's managed password
DCSync Can replicate the directory
AllowedToDelegate Can get tickets for an SPN as any user
Cluster A UI similarity grouping; NOT a rights equivalence
Truncation A partial collection producing false negatives
Staleness A graph from earlier is not the graph now
Path length Hops from a starting principal to the target

# --- 1. build a realistic graph, then query it ---
cat > graph.py <<'PY'
#!/usr/bin/env python3
"""A miniature AD graph and the queries that matter.

You do not need BloodHound to understand it. Once you can see the
edges on a 40-node graph, the tool is just this with 40,000 nodes.
"""
from collections import defaultdict, deque
import sys

class Graph:
    def __init__(self):
        self.out = defaultdict(list)
        self.label = {}
        self.props = {}

    def p(self, name, kind, **props):
        self.label[name] = kind
        self.props[name] = props
        self.out.setdefault(name, [])
        return name

    def e(self, src, kind, dst):
        self.out[src].append((kind, dst))
        self.out.setdefault(dst, [])

    def path(self, src, dst, maxd=8):
        q, seen = deque([(src, [])]), {src}
        while q:
            n, p = q.popleft()
            if n == dst: return p
            if len(p) >= maxd: continue
            for kind, t in self.out[n]:
                if t not in seen:
                    seen.add(t); q.append((t, p + [(kind, t)]))
        return None

    def who_can(self, dst, maxd=6):
        back = defaultdict(list)
        for s, es in self.out.items():
            for kind, t in es: back[t].append((s, kind))
        res, q, seen = {}, deque([(dst, 0)]), {dst}
        while q:
            n, d = q.popleft()
            if d >= maxd: continue
            for s, kind in back[n]:
                res.setdefault((d, s), kind)
                if s not in seen: seen.add(s); q.append((s, d+1))
        return res

g = Graph()
DA  = g.p("DOMAIN ADMINS@LAB.INTERNAL", "group")
IT  = g.p("IT SUPPORT@LAB.INTERNAL", "group")
HD  = g.p("HELPDESK@LAB.INTERNAL", "group")
al  = g.p("ALICE@LAB.INTERNAL", "user", kind="helpdesk")
bo  = g.p("BOB@LAB.INTERNAL", "user", kind="helpdesk")
er  = g.p("ERIN@LAB.INTERNAL", "user", kind="it")
sv  = g.p("SVC-DEPLOY@LAB.INTERNAL", "user", spn="HTTP/deploy.lab.internal",
          delegated=True, groups="DOMAIN ADMINS@LAB.INTERNAL")
wb  = g.p("WEB01@LAB.INTERNAL", "computer", sessions=["ALICE@LAB.INTERNAL"])
dc  = g.p("DC01@LAB.INTERNAL", "computer", isdc=True)
wl  = g.p("WLS01@LAB.INTERNAL", "computer")
gmsa= g.p("GMSA-FILES@LAB.INTERNAL", "user", isgmsa=True)

g.e(al, "MEMBER OF", HD)
g.e(bo, "MEMBER OF", HD)
g.e(er, "MEMBER OF", IT)
g.e(sv, "MEMBER OF", DA)
g.e(HD, "GENERICALL", IT)            # Helpdesk can rewrite IT Support
g.e(IT, "GENERICWRITE", sv)         # IT Support can add an SPN to svc-deploy
g.e(wb, "HAS SESSION", al)          # alice is authenticated to WEB01
g.e(wb, "ADMINTO", er)              # erin is local admin on WEB01
g.e(wl, "DCSYNC", dc)               # a COMPUTER can replicate the directory
g.e(al, "READGMSAPASSWORD", gmsa)    # alice can read the gMSA password

def show(title, items):
    print(f"\n{'='*70}\n{title}\n{'='*70}")
    for line in items: print(line)

show("THE GRAPH", [f"  {s:<28} --{k:<16}--> {t}" for s in sorted(g.out)
                   for k, t in g.out[s]])

show("QUERY 1: shortest path ALICE -> DOMAIN ADMINS", 
     [f"  {n:<28} --{k}-->" for k, n in (g.path(al, DA) or [])] or ["  (none)"])

show("QUERY 2: who can DCSync (not the same as Domain Admin)",
     [f"  {s:<28} depth {d}  (last edge: {k})"
      for (d, s), k in sorted(g.who_can(dc).items()) if k == "DCSYNC"])

show("QUERY 3: who can DELEGATE",
     [f"  {s:<28} -> {t}" for s in sorted(g.out) for k, t in g.out[s]
      if k == "GENERICWRITE" and g.props.get(t, {}).get("delegated")])

show("QUERY 4: who can READ a gMSA password",
     [f"  {s:<28} can read {t}" for s in sorted(g.out) for k, t in g.out[s]
      if k == "READGMSAPASSWORD"])

show("QUERY 5: SESSIONS - the most immediately exploitable edges",
     [f"  {t} is authenticated to {s} (NOW)" for s in sorted(g.out)
      for k, t in g.out[s] if k == "HAS SESSION"])

show("READING THE ALICE PATH, not just seeing it",
     [f"  MEMBER OF {HD}      - the starting point: alice is a normal",
      "                         helpdesk user, no admin, nothing special",
      f"  GENERICALL on {IT}   - she can rewrite the IT Support group, so",
      "                         she can add HERSELF to it",
      f"  GENERICWRITE on {sv} - IT Support can set any attribute on the",
      "                         deploy service account, including an SPN.",
      "                         That makes it roastable. Then a wordlist.",
      f"  MEMBER OF {DA}      - the account at the end is a domain admin",
      "",
      "  THE RECOMMENDATION, which must be specific:",
      "    1. Remove GENERICALL on 'IT Support' - it should be Read, not",
      "       Full Control. Who granted it, and why, in 2019?",
      "    2. Separate the deploy service account from Domain Admins - a",
      "       service account that deploys code should deploy to servers,",
      "       not administer the domain.",
      "    3. Constrain which service accounts can be GenericWrite'd.",
      "",
      "  This is better than 'review your ACLs' because it names the two",
      "  edges, names the accounts, and gives two actions that break the path."])

cat > 02-queries.sql <<'EOF'
-- BloodHound collections are SQLite. These are the queries.
-- Labels are UPPERCASE: 'DOMAIN ADMINS@LAB.INTERNAL'. Getting the case
-- wrong returns zero rows and reads as "no path exists" - the single
-- most common analysis error.

-- 0. what is in here?
SELECT 'users' t, COUNT(*) n FROM users
UNION ALL SELECT 'computers', COUNT(*) FROM computers
UNION ALL SELECT 'groups', COUNT(*) FROM groups
UNION ALL SELECT 'sessions', COUNT(*) FROM sessions;

-- 1. shortest path alice -> Domain Admins
WITH RECURSIVE p(from, to, depth) AS (
  SELECT 'ALICE@LAB.INTERNAL', 'DOMAIN ADMINS@LAB.INTERNAL', 0
  UNION ALL
  SELECT e.source, p.to, p.depth + 1
  FROM edge_acl e JOIN p ON e.target = p.from
  WHERE p.depth < 8
)
SELECT * FROM p WHERE from = 'ALICE@LAB.INTERNAL' AND depth > 0;

-- 2. who can DCSync (NOT the same set as Domain Admin membership)
SELECT DISTINCT source, target FROM edge_acl WHERE type = 'DCSync';

-- 3. delegation - unconstrained and constrained
SELECT DISTINCT source, target FROM edge_acl
WHERE type IN ('AllowedToDelegate', 'AllowedToDelegateTo');

-- 4. WriteSPN - make any account roastable, with no credential
SELECT DISTINCT source, target FROM edge_acl WHERE type = 'WriteSPN';

-- 5. ReadGMSAPassword - a 120-char password you can just read
SELECT DISTINCT source, target FROM edge_acl WHERE type = 'ReadGMSAPassword';

-- 6. GenericWrite/All on USERS (the roast/setup surface)
SELECT source, target FROM edge_acl
WHERE type IN ('GenericWrite','GenericAll','WriteDACL')
  AND target IN (SELECT objectid FROM users);

-- 7. sessions (SessionLoop) - who is where, now
SELECT source, target, time FROM sessions ORDER BY time DESC LIMIT 100;

-- 8. local admin (LocalAdmin collection)
SELECT DISTINCT source, target FROM edge_acl WHERE type = 'AdminTo';

-- 9. computers that can reach Domain Admin (a computer can be dumped)
WITH RECURSIVE p(from, to, depth) AS (
  SELECT 'DOMAIN ADMINS@LAB.INTERNAL', 'DOMAIN ADMINS@LAB.INTERNAL', 0
  UNION ALL
  SELECT e.source, p.to, p.depth + 1 FROM edge_acl e JOIN p ON e.target = p.from
  WHERE p.depth < 6
)
SELECT DISTINCT from FROM p WHERE depth > 0 AND from LIKE 'COMPUTER%';

-- 10. Validate: the group graph is not truncated
SELECT COUNT(*) FROM edge_group WHERE memberof = 'DOMAIN ADMINS@LAB.INTERNAL';
-- if 0, the collection failed; "no path" is not a finding.
EOF

# The graph is not the network

```text
  A BloodHound path says "alice CAN reach Domain Admin".
  It does not say "alice CAN reach it from where she is".

  The graph models AUTHORISATION. The network models REACHABILITY.
  A path is exploitable only if every hop is also a network path.

  THE OVERLAY:
    1. take the BloodHound path: alice -> svc-deploy -> Domain Admins
    2. take the network map: where is alice's session?
       (the HasSession edge tells you the host)
    3. is svc-deploy reachable FROM THAT HOST?
       if svc-deploy is in a segment alice's host cannot route to,
       the path is still a finding (it is still a privilege
       escalation) but it needs a pivot, and the pivot may be
       blocked.

  WHY THIS MATTERS FOR THE REPORT:
    "alice can reach Domain Admin" and "alice can reach Domain Admin
     from her workstation, in three network hops, using one pivot"
     are different findings with different remediations.

  THE CONVERSE, which is more common and more valuable:
    the graph shows NO path from alice, but the NETWORK shows she can
    reach a host where a privileged user IS logged in.
    That is a relay opportunity, not a graph path. Sessions and
    network reachability combine into something neither shows alone.

  THE OVERLAY, AS A DELIVERABLE:
    draw the network (segments, firewalls, which host is in which)
    and draw the graph (who can reach what)
    and put them side by side.
    The finding is in the INTERSECTION.

  WHAT DOES NOT APPEAR IN EITHER:
    - PAWs (a host that only admins can log into)
    - Conditional Access / Azure AD policies
    - Jump hosts (a host you must go through, and what it logs)
    - Application-layer authorisation that is not in the ACLs
    - The fact that the deploy pipeline DEPLOYS the thing you need
      to compromise, so you do not need to escalate at all

EOF
cat 03-overlay.md
rm -f graph.py
```

Step 1 is the deliverable: a 10-node graph where alice is an ordinary helpdesk user with
a three-hop path to Domain Admin, and the script then reads that path back as a paragraph of
analysis with two specific remediation actions. That is the difference between "alice can reach
Domain Admin" (unfalsifiable) and "remove GENERICALL on IT Support; it should be Read, not Full
Control" (a fix).

It also surfaces the two edges people miss: a computer account with DCSync (in no group list
anywhere) and alice reading a gMSA password — a 120-character random credential that is
useless to brute-force and completely defeated by one ACL.
