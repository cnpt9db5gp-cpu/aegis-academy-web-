Version Control (Git)

Summary

Git is not just for source code — it is a content-addressed, cryptographically signed audit
log, and you already use it for your own progress. For security work it matters for three
specific reasons: tracking configuration changes on a target, maintaining your own tooling and
scripts, and being able to reconstruct the exact state of a system at a point in time.

You have already committed AEGIS four times. This lecture is about the commands that make you
fluent rather than adequate.

The three states

working tree  --git add-->  staging area  --git commit-->  repository
     ^                                                   |
     |<--------------- git checkout / git restore --------|

Almost every git confusion is one of: which state am I in, and did I stage the change I thought
I staged?

git status              # the single most useful command
git diff                # working tree vs staging
git diff --staged       # staging vs last commit

The commands that matter

git init
git clone <url>
git add -A                      # stage everything (respects .gitignore)
git add notes/ms-01.md          # or be specific - better habit
git commit -m "message"
git log --oneline --graph --decorate
git log -p notes/ms-01.md       # every change to one file, forever
git show <sha>
git diff HEAD~1 HEAD -- notes/

git switch -c tier2             # new branch (modern git; git checkout -b also works)
git switch main
git merge tier2

# undo, in order of preference
git restore notes/ms-01.md               # discard working tree change
git restore --staged notes/ms-01.md      # unstage
git commit --amend                      # fix the last commit message
git revert <sha>                        # undo a COMMITTED change, safely (new commit)
# git reset --hard = the dangerous one. Know it exists; prefer revert.

Ignore files, properly

cat > .gitignore <<'EOF'
transcripts/
labs/
*.pcap
*.mem
__pycache__/
EOF
git check-ignore -v somefile.pcap     # prove the rule is working

git check-ignore -v is the command that tells you why something was or was not ignored. It
saves twenty minutes whenever a file mysteriously refuses to be added.

Security-relevant git usage

On a target you have access to: if the target uses git, the history is evidence and possibly
secrets.

# Finding exposed .git directories (a real web vulnerability class)
ffuf -u http://TARGET/FUZZ -w /usr/share/seclists/Discovery/Web-Content/raft-small-words.txt \
     -mc 200,301,302 -fc 404
curl -s http://TARGET/.git/HEAD          # if this returns ref: refs/heads/main, you have the source

# If you found a .git directory, reconstruct the repo
curl -s http://TARGET/.git/HEAD
# then use git-dumper: git clone http://TARGET/.git repo

On your own work: never commit real credentials, private keys, or capture files. .gitignore
before the first commit, not after the incident. git log -p | grep -i password finds what you
already committed.

Terminology

Term Meaning
Repository The .git directory: full history of your project
Commit A named snapshot with a message, author and parent
SHA The content hash identifying a commit
Staging area (index) The next commit's contents
Branch A movable pointer to a commit
Remote The named upstream repository (origin)
HEAD The commit your current branch points at
Merge commit A commit with two parents, joining two histories

Kali commands

# --- orient yourself ---
git config --list --show-origin | head -20
git status
git log --oneline | head -10
git count-objects -vH

# --- the daily loop ---
git add -A && git commit -m "wip" && git log --oneline | head -3
git diff --stat

# --- find things later (this is why commit messages matter) ---
git log --all --oneline --grep="subnet"
git log -S "stack-canary" --oneline          # commits that ADD/REMOVE this string
git log -p -- notes/ms-02.md | head -60

# --- undo safely ---
git restore --staged .
git revert --no-edit HEAD

# --- ignore properly ---
echo "*.pcap" >> .gitignore
git check-ignore -v capture.pcap

# --- secret scanning, on yourself ---
git log -p --all | grep -iE '(password|secret|api[_-]?key|BEGIN [A-Z ]*PRIVATE KEY)' | head
git ls-files | grep -E '\.(pem|key|p12|pfx)$'

Off-by-one in the port list, fixed."

# --- 3. branch, change, merge ---
git switch -c experiment
printf "\n## Experiment\n" >> notes/first.md
git commit -am "experiment branch change"
git switch main
printf "\n## Production\n" >> notes/first.md
git commit -am "main branch change"
git merge experiment -m "merge experiment"
git log --oneline --graph --all | head -10

# --- 4. undo, all four ways ---
git restore notes/first.md                                  # discard uncommitted
printf "junk\n" >> notes/first.md && git add -A
git restore --staged notes/first.md                          # unstage
git commit -q --amend -m "amended message"                   # fix last commit
git log --oneline | head -3

cd ~/aegis/labs/ms-04

# --- 5. practice: did you accidentally commit anything sensitive? ---
{
  echo "=== tracked files that look like secrets ==="
  git ls-files | grep -E '\.(pem|key|p12|pfx|env)$|credential|secret' || echo "  none"
  echo
  echo "=== secrets in history ==="
  git log -p --all 2>/dev/null | grep -iE '(password|api[_-]?key|BEGIN [A-Z ]*PRIVATE KEY)' | head || echo "  none"
  echo
  echo "=== ignored correctly? ==="
  touch test.pcap && git check-ignore -v test.pcap
  rm -f test.pcap
} | tee 01-secret-audit.txt

# --- 6. YOUR STUDY TIMELINE from AEGIS ---
cd ~/Projects/aegis-academy
{
  echo "=== AEGIS progress history ==="

  echo
  echo "=== commits per day ==="

  echo
