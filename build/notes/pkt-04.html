TCP Handshakes, Retransmits and Anomalies

Summary

Every TCP conversation has a recognisable shape. Anomalies in that shape are how scans, drops,
injections and evasions look in a capture.

Key ideas

  • Three-way handshake, four-way teardown, and the state in between
  • Retransmission: a SYN resent because no reply came. One is normal; many is a symptom
  • RST: abortive close. Unexpected RSTs mean a firewall, a closed port, or a scanner
  • Half-open connections: SYN seen without the final ACK — a SYN scan's signature
  • Sequence numbers should advance monotonically; a reset or a jump is anomalous
  • Window size 0 means "stop sending", which is backpressure
  • TIME_WAIT accumulation on a port indicates churn or scanning against you

Terminology

Term Meaning
Retransmission An unacknowledged packet sent again
RST Reset; immediate, ungraceful close
Half-open SYN without the completing ACK
Sequence number Byte position counter
ACK number The next byte expected
Window Receive buffer size, used for flow control
Keepalive Probes to detect a dead peer
Zero window Receiver cannot accept more data
TIME_WAIT Waiting 2MSL after close
RTT Round-trip time, observable from the handshake

Kali commands

# --- capture a handshake and read the numbers ---
sudo tcpdump -i lo -n -c 20 "tcp port 9000" 2>/dev/null | head -20

# --- SYN scan detection filters ---
sudo tcpdump -i any -n "tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0"
tshark -i any -Y "tcp.flags.syn == 1 && tcp.flags.ack == 0" 2>/dev/null | head

# --- scan traffic, if any ---
sudo timeout 10 tcpdump -i any -n "tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0" 2>/dev/null \
  | awk '{print $3}' | cut -d. -f1-4 | sort | uniq -c | sort -rn | head

# --- connection state on this host ---
ss -tan state time-wait | wc -l
ss -tan state syn-recv | wc -l
ss -tan state established | wc -l

# --- kernel counters ---
grep -A1 "^Tcp:" /proc/net/snmp | tail -1 | tr ' ' '\n' | head -20
cat /proc/net/netstat | grep -A1 TcpExt | tail -1 | tr ' ' '\n' | grep -iE "retrans|syn|listen" | head

# --- one-shot server to watch a handshake ---
timeout 5 bash -c 'nc -l -p 9000' &
sleep 1; echo hi | timeout 2 nc 127.0.0.1 9000
wait 2>/dev/null

Field lab

Objective: identify handshakes, retransmits and half-opens in a real capture.

# --- PRE-FLIGHT: this lab needs root, so authenticate ONCE, HERE, first ---
# `sudo something &` backgrounds the password PROMPT along with the command.
# With no terminal attached to answer it, sudo fails - and `2>/dev/null`
# then throws away the only clue. The result is a capture file that was
# never written, followed by a screenful of "no such file".
#
# `sudo -v` validates the credential in the FOREGROUND, where you can see
# and answer the prompt. It caches for ~15 minutes, so every backgrounded
# `sudo` below is prompt-free and actually runs.
if ! sudo -v; then
  echo "  sudo is unavailable or the password was wrong - stop here." >&2
  echo "  Everything below needs root. Nothing will be captured." >&2
  exit 1
fi
mkdir -p ~/aegis/labs/pkt-04 && cd ~/aegis/labs/pkt-04

# --- 1. capture a normal conversation ---
sudo timeout 12 tcpdump -i lo -n -w normal.pcap -s 0 "tcp port 9000" 2>/dev/null &
TC=$!; sleep 1
( timeout 8 nc -l -p 9000 >/dev/null 2>&1 & )
sleep 1
echo "hello" | timeout 3 nc 127.0.0.1 9000 2>/dev/null
sleep 4; kill $TC 2>/dev/null; wait $TC 2>/dev/null

echo "=== the packets, with flags spelled out ==="
tshark -r normal.pcap \
  -T fields -e frame.number -e tcp.flags.str -e tcp.seq -e tcp.ack -e tcp.len 2>/dev/null \
  | awk 'BEGIN{printf "  %-5s %-12s %-10s %-10s %s\n","#","FLAGS","SEQ","ACK","LEN"}' | tee 01-flags.txt
echo
cat <<'EOF'
  Look for: SYN (seq=X, len=0), SYN,ACK (seq=Y, ack=X+1), ACK (ack=Y+1), then PSH,ACK.
  The ACK number always acknowledges one more than the peer's sequence number.
  If it does not, the stack is lying to you.
EOF

# --- 2. measure RTT from the handshake, by hand ---
python3 - <<'PY' | tee 02-rtt.txt
import socket, time, statistics

def rtt(host, port, tries=10):
    times = []
    for _ in range(tries):
        s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        s.settimeout(2)
        t0 = time.perf_counter()
        try:
            s.connect((host, port))
            times.append((time.perf_counter() - t0) * 1000)
        except OSError:
            pass
        finally:
            s.close()
        time.sleep(0.05)
    return times

ts = rtt("127.0.0.1", 22)     # SSH, if running
if ts:
    print(f"  TCP connect RTT to 127.0.0.1:22 over {len(ts)} tries")
    print(f"    min {min(ts):.3f} ms   avg {statistics.mean(ts):.3f} ms   max {max(ts):.3f} ms")
else:
    print("  nothing listening on 22 - run: sudo systemctl start ssh")
print()
print("  RTT is used by tcp-syncookies, by Nagle, and by every timing-based")
print("  side channel in this course. Measure it before you rely on it.")
PY

# --- 3. a SYN scan against YOUR OWN loopback, and the signature it leaves ---
echo
echo "=== SYN scan against 127.0.0.1 (authorised, local only) ==="
sudo nmap -sS -p 1-200 --min-rate 2000 127.0.0.1 -oN synscan.txt 2>/dev/null
echo "  open ports found: $(grep -c open synscan.txt)"
echo
echo "=== the packet signature: SYN with no ACK, many ports, one source ==="
sudo timeout 12 tcpdump -i lo -n "tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0" 2>/dev/null \
  | head -12 | tee 03-synsignature.txt
echo
echo "Signature to memorise: same source port 0, many destination ports,"
echo "SYN set and ACK clear. A full connect scan looks nothing like this."

# --- 4. retransmissions and RSTs, both of which appear in normal life ---
{
  echo "=== TCP retransmit counters on this host ==="
  grep -A1 "^TcpExt:" /proc/net/netstat | tail -1 | tr ' ' '\n' | \
    grep -iE "^TcpRetransSegs|^TcpExtTCPSynRetrans" | head -3
  echo "  (column headers: $(grep '^TcpExt:' /proc/net/netstat | tail -1 | tr ' ' '\n' | grep -n RetransSegs | cut -d: -f1))"
  echo
  echo "=== states that indicate recent scanning or churn ==="
  echo "  SYN-RECV (half-open): $(ss -tan state syn-recv 2>/dev/null | tail -n +2 | wc -l)"
  echo "  TIME-WAIT:             $(ss -tan state time-wait 2>/dev/null | tail -n +2 | wc -l)"
} 2>&1 | tee 04-anomalies.txt

# --- 5. the anomaly catalogue ---
cat > 05-anomalies.md <<'EOF'
# TCP anomalies and what they mean

| Observation | Likely cause |
|---|---|
| SYN, no reply, repeated | Port filtered by a firewall, or host down |
| SYN, SYN-ACK, no ACK | SYN scan (half-open), or the client vanished |
| RST immediately on SYN | Port closed, or a stateless firewall rejected it |
| Many SYNs from one source, many ports | Port scan |
| Many SYNs from one source, sequential ports | Sequential scan (nmap default) |
| SYN to many *hosts*, same port | Host sweep / ping sweep |
| Retransmissions with no RST | Packet loss, or a filter dropping silently |
| Window of 0 held open | Application-level DoS (slowloris shape) |
| Sequence numbers not incrementing | Middlebox rewriting, or an evasion attempt |
| Connection to a high port, then nothing | Successful exploit callback - investigate immediately |
| Thousands of TIME_WAIT | Local port exhaustion, or you are being scanned |
EOF
cat 05-anomalies.md

Step 3 is the key exercise — generate a real SYN scan against loopback and see the signature
your IDS would alert on.
