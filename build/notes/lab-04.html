Capture the Traffic, Break the Machine, Document It

Summary

The capstone's practice loop: capture the traffic of an attack you perform against your own lab, run
the attack, and write up what the traffic reveals. That closes the loop between the offensive tier,
the network tier, and the forensics tier.

The framing: an attack you can see on the wire teaches you
something an attack you can only read about does not. The capture is
how you learn what your own exploitation looks like from outside.

The loop

  1. CAPTURE      tshark on the host-only bridge. Before anything.
  2. ATTACK       run one technique, from cap-03 or cap-04.
  3. READ         what does the wire show that the tool did not tell you?
  4. DOCUMENT     the finding, the capture, and the timeline
  5. ATTACK AGAIN with a different technique, and compare the two

  STEP 5 is the one that teaches the most. The same attack with a
  different technique produces a *completely different* capture, and
  that difference is what detection is written against.

cat > 01-capture.sh <<'EOF'
#!/usr/bin/env bash
# Capture the lab's own traffic. Loopback or host-only only.
IF="${1:-lo}"
OUT="${2:-captures/run.pcapng}"
mkdir -p captures

echo "=== 1. is the interface up? ==="
ip -br link show "$IF" | sed 's/^/  /'
echo

echo "=== 2. CAPTURE SETTINGS, and why each matters ==="
cat <<'SETTINGS'
  -i lo            loopback. Nothing leaves the machine.
  -c 500           stop after N packets, so a forgotten capture
                   does not fill the disk
  -w <file>        write to a PCAPNG, not to stdout
  --time戳 --  no, plain: tshark writes capture timestamps by default

  NOTE ON pcapng vs pcap:
    pcapng carries interface metadata, comments, and per-packet
    names. tshark writes pcapng by default. That is better: you can
    record who made the capture and why, in the file itself.

  THE COMMENT TAG, and use it:
    editcap --capture-comment "AEGIS capstone, Kerberoasting of
      svc-backup, operator nwpcs, 2026-10-14" in.pcapng out.pcapng
    Anyone reading the file later learns its provenance without
    needing you. (cd-04 asks for exactly this.)
SETTINGS

echo "=== 3. start the capture ==="
timeout 300 tshark -i "$IF" -c 3000 -w "$OUT" \
  -q "host 192.168.56.10 or host 192.168.56.20" >/dev/null 2>&1 &
CAP=$!
echo "  capture pid $CAP"
sleep 3

echo
echo "=== 4. RUN ONE TECHNIQUE (change this per exercise) ==="
echo "  --- technique: Kerberoasting svc-backup ---"
DC="192.168.56.10"
case "$(echo "$DC" | cut -d. -f1)" in
  192.168.56.*|10.10.10.*) ;;
  *) echo "  REFUSED: $DC not in the lab range"; kill $CAP 2>/dev/null; exit 3 ;;
esac
if command -v GetUserSPNs >/dev/null; then
  GetUserSPNs -dc-ip "$DC" "${AEGIS_CRED:-LAB/alice:Summer2019!}" \
    -request 2>&1 | grep -vE "^\[+\]" | head -8 | sed 's/^/  /'
  echo "  -> captured the TGS-REQs"
else
  echo "  (impacket not installed; run the technique manually from"
  echo "   a second terminal while this capture runs)"
fi

echo
echo "=== 5. stop and annotate ==="
wait $CAP 2>/dev/null
sleep 1
if [ -s "$OUT" ]; then
  command -v editcap >/dev/null && \
    editcap --capture-comment "AEGIS capstone - Kerberoasting svc-backup - nwpcs - $(date -u +%FT%TZ)" \
      "$OUT" "${OUT%.pcapng}-annotated.pcapng" 2>/dev/null
  ls -la captures/ | sed 's/^/  /'
  echo "  sha256:"
  sha256sum captures/* | sed 's/^/    /'
else
  echo "  no capture produced (loopback captures of LAN traffic are"
  echo "  empty - capture on the host-only bridge, not on lo, when"
  echo "  the traffic is between VMs)"
fi
EOF
chmod +x 01-capture.sh

What the wire shows that the tool does not

cat > 02-read.py <<'PY'
#!/usr/bin/env python3
"""Compare two captures of the same objective by DIFFERENT techniques.

This is the exercise that teaches the most: the same result, two very
different captures, and a detection has to work against both.
"""
TECHNIQUES = {
 "A: Kerberoasting": dict(
   precondition="any valid domain account",
   wire=["AS-REQ (preauth encrypted with the user's NT hash)",
         "AS-REP (TGT, encrypted with krbtgt)",
         "TGS-REQ x N, one per SPN, in a burst",
         "TGS-REP x N, encrypted with each service account's ktab",
         "4769-class events, only if Kerberos auditing is enabled"],
   visible_to="a passive network observer: the burst pattern, and the "
              "volume of distinct SPNs requested from one host",
   dc_events="4768/4769 only if Audit Kerberos Authentication Service "
             "is Success (not the default)",
   tool_output="the SPN list and the tickets",
   wire_adds="THE BURST. One host asking for many service tickets in "
             "seconds is the signature, and it is visible to anyone "
             "watching the network, with no Kerberos auditing at all."),
 "B: AS-REP roasting": dict(
   precondition="NOTHING. No account.",
   wire=["AS-REQ (no preauth, so the body contains only a timestamp, "
         "encrypted with the ktab derived from the password)",
         "AS-REP (encrypted with the account's ktab)"],
   visible_to="a passive observer: an AS-REQ from a host to a DC, where "
              "most traffic is the reverse",
   dc_events="fewer than A: one request, one reply. If Kerberos "
             "auditing is off, NOTHING.",
   tool_output="the account name and the encrypted blob",
   wire_adds="almost nothing. This is the quietest attack in the "
             "curriculum, which is exactly why it is the worst."),
}

def render():
    print("  " + "="*78)
    print("  THE SAME OBJECTIVE, TWO TECHNIQUES, TWO CAPTURES")
    print("  " + "="*78)
    for name, t in TECHNIQUES.items():
        print(f"\n  TECHNIQUE {name}")
        print(f"    precondition  : {t['precondition']}")
        print("    on the wire   :")
        for w in t["wire"]: print(f"      - {w}")
        print(f"    visible to    : {t['visible_to']}")
        print(f"    DC events     : {t['dc_events']}")
        print(f"    tool tells you: {t['tool_output']}")
        print(f"    the WIRE adds : {t['wire_adds']}")
    print()
    print("  " + "-"*78)
    print("  THE COMPARISON, and it is the whole exercise:")
    print()
    print("    Kerberoasting is LOUD on the wire and quiet in the logs.")
    print("    AS-REP roasting is quiet in both.")
    print()
    print("    A detection written only against the DC logs catches A and")
    print("    not B. A network detection written against burst patterns")
    print("    catches A and not B.")
    print()
    print("    To catch B you need the attribute, and the attribute is")
    print("    readable ANONYMOUSLY - which means the detection is a query")
    print("    against the directory, not against a log stream:")
    print()
    print("      ldapsearch -x -b <nc> \\")
    print("        '(userAccountControl:1.2.840.113556.1.4.803:=1048576)' \\")
    print("        sAMAccountName")
    print()
    print("    THAT is the finding to give the client: not 'enable more")
    print("    logging' but 'run this query every hour'. It is one line, it")
    print("    needs no licences, and it closes the gap that no amount of")
    print("    log-based detection would.")

if __name__ == "__main__":
    render()
PY
python3 02-read.py 2>&1 | tee 03-compare.txt

Step 3 is the deliverable, and it produces the single best recommendation in the whole
curriculum. Kerberoasting is loud on the wire and quiet in the logs. AS-REP roasting is
quiet in both — it's the quietest attack in the curriculum, which is exactly why it's the
worst.

So a detection written only against DC logs catches one and not the other, and a network
detection written against burst patterns also catches only one. To catch the quiet one you need
the attribute — and the attribute is readable anonymously. The recommendation isn't "enable
more logging"; it's "run this one-line LDAP query every hour". No licences, and it closes a
gap no amount of log-based detection would.
