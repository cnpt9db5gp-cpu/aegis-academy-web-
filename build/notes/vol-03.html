Network and Credential Plugins

Summary

Two plugin groups, one question each: what was this machine talking to, and what
credentials existed here. Both give you direct evidence rather than inference, and both require
authorisation before you run them.

The framing: netscan gives you attribution; credential_dump gives
you compromise. The first is usually fine to run in an engagement.
The second prints every credential on the host and is treated
accordingly.

Companion to ad-05 (credential dumping) and imp-01. This note is
the memory-side version.

Network plugins

VOL="vol.py"; IMG="memory.raw"

# netscan - every TCP connection, with the owning PID
$VOL windows.netscan -f "$IMG"
#   columns: Offset, Proto, LocalAddr, LocalPort, ForeignAddr,
#            ForeignPort, PID, Owner, Created
#   ^ Owner is the PROCESS NAME. That is the join to pslist.
#     "an outbound connection from lsass.exe" is a finding you can
#     act on immediately.

# netstat - the socket table, with state
$VOL windows.netstat -f "$IMG"
#   columns: Offset, Proto, LocalAddr, LocalPort, ForeignAddr,
#            ForeignPort, State, PID, Owner
#   ^ State tells you LISTENING vs ESTABLISHED. An ESTABLISHED
#     outbound to a new address at the time of the capture is the
#     moment of the exfiltration.

# netscan can filter to one process - and you should
$VOL windows.netscan -f "$IMG" --pid 2100
$VOL windows.netscan -f "$IMG" --pid 2100 --dump
#   ^ --dump writes the socket data (the in-memory request and
#     response) to files. That is HTTP bodies, passwords typed into
#     a form, and anything plaintext. Treat the output as evidence.

# What to ask the network plugins

```text
  1. WHICH PROCESS HAS AN OUTBOUND CONNECTION I DO NOT RECOGNISE?
     $VOL windows.netscan -f IMG | grep -v "127.0.0.1\|192.168\|10\.\|172.1"
     then join the PID to pslist. This is question 1 because a
     single unexpected outbound connection with a known process name
     is the fastest finding in memory forensics.

  2. IS A SYSTEM PROCESS TALKING OUT?
     lsass.exe, services.exe, or csrss.exe with an ESTABLISHED
     connection to an external address is credential theft or a
     C2 channel using a system binary. Nothing legitimate does this.

  3. IS THERE A LISTENER THAT SHOULD NOT BE THERE?
     A LISTENING socket on an unusual port, owned by a user process,
     is either an implant or an authorised service nobody told you
     about. Both are worth a question.

  4. WHAT IS THE SESSION MAPPING?
     $VOL windows.getsids -f IMG
     An interactive user session with a connection to an external
     host is a user being phished or an implant running as the user.

  5. IS THE TIMING CONSISTENT?
     netscan's Created timestamp against windows.info's SystemTime.
     A connection created 40 seconds before capture, to an address
     first seen in this session, is an active C2 channel at the moment
     you took the image.

  6. WHAT ABOUT THE DNS CACHE?
     $VOL windows.dumpfiles --pid <pid> IMG     (the resolver cache)
     $VOL windows.registry.printkey --key \
       'ROAMING\MACHINE\SOFTWARE\MICROSOFT\WINDOWS NT\CURRENTVERSION\DNS\CACHE'
     A DNS cache entry for a domain you do not recognise, from a
     process you cannot explain, ties the network finding to the
     host finding.
```
MD

cat > 02-network.sh <<'EOF'
#!/usr/bin/env bash
VOL="${VOL:-vol.py}"; IMG="${1:?usage: ./02-network.sh memory.raw}"
echo "=== 1. every connection, with its owning process ==="
$VOL windows.netscan -f "$IMG" 2>/dev/null | sed 's/^/  /'
echo
echo "=== 2. THE EXTERNAL ONES, which is the actual question ==="
$VOL windows.netscan -f "$IMG" 2>/dev/null \
  | grep -vE "127\.0\.0\.1|0\.0\.0\.0|192\.168\.|10\.[0-9]|172\.1[6-9]\.|172\.2[0-9]\.|172\.3[01]\." \
  | sed 's/^/  /'
echo
echo "  ^ if this is empty, nothing was talking out at capture time."
echo "    That is a finding in itself: it means either the malware"
echo "    was idle, or it was beaconing on a long interval, or the"
echo "    capture was taken while the network was down."
echo
echo "=== 3. the state, which distinguishes a listener from a channel ==="
$VOL windows.netstat -f "$IMG" 2>/dev/null | sed 's/^/  /'
echo
echo "  LISTENING   = a service. Question whether it should exist."
echo "  ESTABLISHED = an active conversation. This is the finding."
echo
echo "=== 4. system processes with connections (the fastest finding) ==="
$VOL windows.netscan -f "$IMG" 2>/dev/null \
  | grep -iE "lsass|services|csrss|winlogon|svchost" | sed 's/^/  /'
echo
echo "  None of these should have an outbound connection to an"
echo "  external address. If one does, either it is an impersonated"
echo "  process (hollowing) or the binary has been replaced."
echo
echo "=== 5. join netscan's PIDs to pslist ==="
$VOL windows.netscan -f "$IMG" 2>/dev/null | awk 'NR>1 && $6!=""{print $6}' | sort -u \
  | while read -r pid; do
    nm=$($VOL windows.pslist -f "$IMG" 2>/dev/null | awk -v p="$pid" '$1==p{print $3}')
    printf "  pid %-6s %s\n" "$pid" "${nm:-NOT IN THE PROCESS LIST}"
  done
echo
echo "  ^ 'NOT IN THE PROCESS LIST' means a socket owned by a process"
echo "    that pslist cannot see. That is DKOM, and it is one of the"
echo "    strongest single findings in memory forensics."
EOF
chmod +x 02-network.sh

Credential plugins, and the authorisation gate

  THE PLUGINS

    windows.credential_dump    lsadump + mimikatz + SAM + DPAPI, all
                              in one. Prints every credential it can
                              find, in plaintext where possible.
    windows.hashdump          the NT hashes only. Same access, less
                              output to handle.
    windows.lsadump           the LSASS secrets only.

  WHAT EACH NEEDS
    Access to LSASS memory. In practice: the acquisition ran as
    SYSTEM or as an administrator, so the memory you have contains
    what that user could read. If you acquired as an admin, you can
    usually read LSASS. If you acquired as SYSTEM, definitely.

  THE AUTHORISATION QUESTION, and it is not a formality:

    These plugins print EVERY CREDENTIAL ON THE HOST, including:
      - every cached domain logon for every user who has ever
        authenticated to this machine
      - the local administrator's hash
      - the machine account's hash (crack it = domain admin
        neighbour at best)
      - DPAPI master keys, which decrypt saved browser passwords and
        stored credentials

    In a client engagement, this is CREDENTIAL EXTRACTION and it needs
    its own ROE clause. It is not implied by "memory forensics".

    In a lab, it is your own lab.

    THE PRACTICAL RULE: run hashdump rather than credential_dump
    unless you specifically need the plaintext. The hashes are a
    demonstrable finding; the plaintext is a liability.

cat > 03-credentials.sh <<'EOF'
#!/usr/bin/env bash
VOL="${VOL:-vol.py}"; IMG="${1:?usage: ./03-credentials.sh memory.raw}"
OUT="${2:-/tmp/aegis-evidence}"; mkdir -p "$OUT"; chmod 700 "$OUT"

cat <<'NOTE'
AUTHORISATION GATE

  These plugins print every credential on the host: cached domain
  logons, the local admin hash, the machine account, and DPAPI
  master keys.

  In a client engagement this is credential EXTRACTION and needs its
  own ROE clause. Confirm it before running anything below.

  In this project they run against YOUR OWN lab.
NOTE
read -r -p "  proceed? [y/N] " go
[ "$go" = "y" ] || { echo "  not run"; exit 0; }

echo
echo "=== 1. the hashes (the demonstrable finding) ==="
$VOL windows.hashdump -f "$IMG" > "$OUT/hashes.txt" 2>/dev/null
wc -l "$OUT/hashes.txt" | sed 's/^/  accounts: /'
head -5 "$OUT/hashes.txt" | sed 's/^/  /'
echo
echo "  ^ NT hashes, every account with a cached logon. THIS IS"
echo "    ALREADY A FINDING: it means the host can be used to crack"
echo "    every user who ever logged into it."
echo
echo "=== 2. what is worth cracking, and what is not ==="
echo "    1. the MACHINE account (\$) -> nearest DC -> real risk"
echo "    2. the local Administrator"
echo "    3. domain admins in the cached logons"
echo "    4. anything that appears in more than one host's dump"
echo "       (the same hash on three hosts means the user is roaming"
echo "        and their password is weak)"
echo
echo "  Use cry-d4's method for the crack. NOT hashcat against the"
echo "  whole dump - triage first."
echo
echo "=== 3. LSASS secrets (what lsadump gives you that hashdump does not) ==="
$VOL windows.lsadump -f "$IMG" > "$OUT/lsadump.txt" 2>/dev/null
head -30 "$OUT/lsadump.txt" | sed 's/^/  /'
echo
echo "  ^ the domain\\password entries are cached logons in"
echo "    PLAINTEXT. A single one is enough to log in as that user"
echo "    with no cracking at all."
echo
echo "=== 4. DPAPI (the per-user credentials) ==="
$VOL windows.registry.hivelist -f "$IMG" 2>/dev/null | grep -i user | sed 's/^/  /'
echo
echo "  the user hives tell you which users were logged on."
echo "  their DPAPI master keys decrypt saved credentials."
echo
echo "=== 5. credential_dump - everything, in one ==="
echo "  NOT RUN by default. Run it only if the ROE says so and if"
echo "  you need the plaintext for a specific demonstration."
echo "  $VOL windows.credential_dump -f '$IMG' > '$OUT/alldump.txt'"
echo
echo "=== HANDLE THESE FILES LIKE NT HASHES ==="
ls -la "$OUT" | sed 's/^/  /'
echo "  encrypt at rest, no email, delete on the ROE date, and say"
echo "  so in the report. credential_dump output is the most"
echo "  sensitive artefact in this entire course."
EOF
chmod +x 03-credentials.sh

Step 4 is the deliverable: the six-plugin join that produces a real finding — netscan gives
a connection and a PID, pslist names the process, the path contradicts the name, a module is
injected, and the DNS cache resolves the destination. Every claim in that sample paragraph is
checkable by the reader from the output you attached.

And the sharpest one: netscan.PID not appearing in pslist is DKOM — a socket owned by a
process that doesn't exist, which is the strongest single finding in memory forensics.

03-credentials.sh puts the authorisation gate before the commands, defaults to
