OS Security: Privilege Separation

Summary

CS161's OS-security block asks how an operating system stays trustworthy while running thousands
of untrusted programs. The lecture's answer is the same one MIT 6.858 reaches, stated as a
design requirement rather than an architecture: the OS must be the only thing you trust, and it
must therefore be as small as it can be.

Companion to mit858-02 and mit858-05. This note is the threat model
against the kernel; those are the mechanisms.

The adversary, precisely

An operating system faces adversaries it cannot trust:

  ordinary processes   - run arbitrary code, deliberately buggy or malicious
  users               - may attempt to read others' data, escalate
  input               - network data reaching a parser
  the hardware         - assume honest
  the OS itself        - if it is compromised, everything is lost

The design goal: a compromise of any userland component must not yield
kernel privilege, because privilege is what the kernel holds.

The mechanisms, and what each buys

Mechanism Boundary strength Survives a kernel bug?
User/kernel rings hardware no
Unix uid/gid + file modes one kernel no
Capabilities fine-grained authority no
chroot filesystem only, not authority no
Namespaces + cgroups per-service view no
Containers namespace isolation no
VM separate kernel yes
Enclave hardware memory isolation yes, modulo side channels

The honest summary: everything up to and including containers shares one
kernel, so a kernel bug defeats all of it simultaneously. Only VM and enclave
survive a kernel compromise, at a cost.

The kernel attack surface

A modern kernel is not small. It exposes:

  ~300 syscall handlers
  dozens of filesystems (proc, sysfs, devtmpfs, netlink, io_uring...)
  thousands of device drivers
  BPF, eBPF, and the verifier
  userfaultfd, io_uring, netfilter

Each is a parser reachable from less-privileged code. That is why kernel
hardening (mit858-18's mitigations, LSMs, user_namespace restrictions) is
the dominant operating-system security work of the last decade.

Secure system call interface

Every system call is a parser with an untrusted argument list. The design rules:

  1. Validate every argument — pointer, length, descriptor, flag combination
  2. Check for integer overflow before allocating count * size
  3. Copy in, never dereference a user pointer directly
  4. Check for overflow on the copy length
  5. Return an error, never crash — a kernel null dereference is full compromise

What CS161 wants you to derive

Given a kernel version and an attacker with the user uid, determine:

  1. Which features are enabled that widen reach? (unprivileged_userns, BPF, io_uring)
  2. What is the shortest path to CAP_SYS_ADMIN?
  3. Is there a published local privesc for that version?
  4. What hardening would close that specific path?

This is exactly the decision tree in pr-05, applied to a kernel rather than a host.

Terminology

Term Meaning
Privilege separation Trusted kernel + untrusted userland
Reference monitor The mandatory mediation point
Ring 0 / ring 3 Kernel / user privilege levels
System call The user-to-kernel parser
Capability Fine-grained, transferable authority
Namespace Isolated kernel view of a resource
cgroup Resource accounting and limits
cBPF / eBPF In-kernel packet filter programs
LSM Linux Security Module; mandatory access control
io_uring Shared ring buffers between kernel and userspace
KPTI Kernel page-table isolation

Kali commands

# --- the kernel attack surface, enumerated on this machine ---
{
  echo "=== SYSCALL SURFACE ==="
  grep -c "^ *[0-9]* " /usr/include/asm/unistd_64.h 2>/dev/null | xargs echo "  syscalls defined:"
  echo "  (each one is a parser reachable from userland)"
  echo
  echo "=== FEATURES THAT WIDEN REACH (T5-05 is the vulnerability surface) ==="
  for s in unprivileged_userns_clone unprivileged_bpf_disabled perf_event_paranoid \
           kptr_restrict userfaultfd; do
    v=$(cat /proc/sys/kernel/$s 2>/dev/null || cat /proc/sys/vm/$s 2>/dev/null || echo n/a)
    printf "  %-32s %s\n" "$s" "$v"
  done
  echo
  echo "=== LSM active? ==="
  cat /sys/kernel/security/lsm 2>/dev/null | sed 's/^/  /'
  ls /sys/kernel/security/ 2>/dev/null | head -6
  echo
  echo "=== KERNEL MODULES (a large, privileged attack surface) ==="
  lsmod | wc -l | xargs echo "  modules loaded:"
  echo
  echo "=== hardening sysctls ==="
  sysctl kernel.randomize_va_space kernel.kptr_restrict kernel.dmesg_restrict 2>/dev/null | sed 's/^/  /'
  echo
  echo "=== io_uring present? (a historically rich source of bugs) ==="
  grep -E "io_uring" /proc/kallsyms 2>/dev/null | head -2 | sed 's/^/  /' || echo "  not visible without root"
} 2>&1 | tee 01-kernel-surface.txt

# --- can unprivileged code reach the kernel surface at all? ---
echo
echo "=== what an unprivileged process can reach ==="
echo "  my identity: $(id)"
echo "  capabilities: $(grep CapEff /proc/self/status | awk '{print $2}')"
capsh --decode=$(grep CapEff /proc/self/status | awk '{print $2}') 2>/dev/null | head -3 | sed 's/^/  /' || \
  echo "  (install libcap2-bin for capsh --decode)"
echo
echo "  Try an unprivileged user namespace:"
unshare -Ur id 2>&1 | sed 's/^/  /'
unshare -Ur sh -c 'grep CapEff /proc/self/status' 2>&1 | sed 's/^/  /'
echo "  ^ inside a user namespace you appear to be root. That is the whole"
echo "    reason most published local privesc chains are gated on this."

python3 - <<'PY' | tee 02-syscalls.txt

# strace your own shell to enumerate what it touches

for name, path in [

    pass
print("  each entry in /proc/<pid>/syscall shows what a process is blocked in")

PY
strace -c -f /bin/ls 2>&1 | tail -12 | sed 's/^/  /' | tee -a 02-syscalls.txt

# --- hardening, measured ---
{
  echo "=== what each control does, and whether it is on ==="
  printf "  %-40s %-12s %s\n" "CONTROL" "VALUE" "INTERPRETATION"
  v=$(cat /proc/sys/kernel/randomize_va_space 2>/dev/null)
  printf "  %-40s %-12s %s\n" "randomize_va_space" "$v" \
    "$([ "$v" = "2" ] && echo 'full ASLR' || echo 'WEAKENED')"
  v=$(cat /proc/sys/kernel/kptr_restrict 2>/dev/null)
  printf "  %-40s %-12s %s\n" "kptr_restrict" "$v" \
    "$([ "$v" -ge 2 ] && echo 'kernel pointers hidden' || echo 'kernel pointers LEAKED')"
  v=$(cat /proc/sys/kernel/unprivileged_userns_clone 2>/dev/null || echo 0)
  printf "  %-40s %-12s %s\n" "unprivileged_userns_clone" "$v" \
    "$([ "$v" = "1" ] && echo 'many privesc chains work' || echo 'chains gated')"
  v=$(cat /proc/sys/kernel/perf_event_paranoid 2>/dev/null)
  printf "  %-40s %-12s %s\n" "perf_event_paranoid" "$v" \
    "$([ "$v" -ge 2 ] && echo 'side-channel hardened' || echo 'profiling OPEN')"
} 2>&1 | tee 03-hardening.txt

Step 1 is the deliverable: a real enumeration of this machine's kernel attack surface —
syscall count, the features that widen reach, active LSMs, module count. That table is the
first thing you check on a kernel target.
