Scheduling and Synchronisation

Summary

Scheduling decides who runs next. Synchronisation decides how concurrent entities cooperate
without corrupting each other's data. Both are security-relevant: a bad scheduler is a
denial-of-service vector, and bad synchronisation is a data race.

Key ideas

  • Scheduling criteria: turnaround, throughput, fairness, response time, priority.
  • Preemptive vs non-preemptive: can the OS interrupt a running process?
  • FCFS — simple, unfair (convoy effect). SJF — optimal average, starves long jobs.
    Round robin — a time slice each. Priority — nice, but needs ageing to avoid starvation.
  • Multilevel feedback queues: approximate SJF adaptively without knowing burst times.
  • Synchronisation: mutexes, semaphores, monitors, condition variables.
  • Producer/consumer — the canonical shared-buffer problem.
  • Deadlock: hold-and-wait, mutual exclusion, no preemption, circular wait.

Security connection: starvation and unfair scheduling are DoS; races are exploitable races.

Terminology

Term Meaning
Preemption OS forcibly interrupting a running process
Time slice / quantum How long a process runs before switching
FCFS First come, first served
SJF Shortest job first
Convoy effect Long job blocks everyone behind it
Starvation A process never gets scheduled
Ageing Boosting priority of waiting processes
Mutex One-at-a-time lock
Semaphore Counting permit
Condition variable Wait for a state change
Deadlock Mutual permanent blocking
Producer/consumer Canonical bounded-buffer problem

Field lab

Objective: measure scheduling fairness, then reproduce a real deadlock.

mkdir -p ~/aegis/labs/neso-os-4 && cd ~/aegis/labs/neso-os-4

# --- 1. how loaded is this machine, and who is using it? ---
{
  echo "=== load average (1, 5, 15 min) ==="
  cat /proc/loadavg
  echo
  echo "=== CPU consumers ==="
  ps -eo pid,ni,pri,stat,pcpu,pmem,comm --sort=-pcpu | head -12
  echo
  echo "=== runnable vs uninterruptible ==="
  ps -eo stat --no-headers | cut -c1 | sort | uniq -c | sort -rn
  echo "  R = runnable, S = sleeping, D = uninterruptible (usually I/O wait)"
} > 01-scheduler.txt; cat 01-scheduler.txt

# --- 2. priority and the limits ---
{
  echo "my policy and priority:"; chrt -p $$ 2>/dev/null
  echo
  echo "raising priority unprivileged:"
  nice -n -5 echo "allowed" 2>&1 | head -1
  echo "lowering priority (always allowed):"
  nice -n 19 echo "  nice -19 set"
  echo
  echo "=== niceness values in use on this box ==="
  ps -eo ni --no-headers | sort -n | uniq -c | tail -5
} 2>&1 | tee 02-priority.txt

# --- 3. FAIRNESS UNDER LOAD: does a nice +19 process still finish? ---
( yes > /dev/null ) & BUSY1=$!
( yes > /dev/null ) & BUSY2=$!
sleep 2
START=$(date +%s%N)
# A task that never yields, to load the box. $! is its PID - capture it, or
# there is no way to stop it later.
nice -n 19 bash -c 'while :; do :; done' &
BUSY1=$!
nice -n 19 bash -c 'while :; do :; done' &
BUSY2=$!
sleep 2
kill "$BUSY1" "$BUSY2" 2>/dev/null
wait "$BUSY1" "$BUSY2" 2>/dev/null     # wait for THOSE, not for everything
nice -n 19 bash -c 'for i in $(seq 1 500000); do :; done; echo "  low-priority task DID finish"'
echo "  wall time: $(( ($(date +%s%N) - START) / 1000000 )) ms"
echo
echo "On a loaded box the niced task still completes. Starvation is prevented by design;"
echo "but it takes longer. That gap is what a resource-exhaustion DoS exploits."
# No bare `wait` here: it waits for EVERY background job, so one job that
# outlives its usefulness hangs the terminal with no way back but ^C.

# --- 4. THE PRODUCER/CONSUMER PROBLEM, WITH AND WITHOUT A MUTEX ---
cat > producer.c <<'EOF'
#include <pthread.h>
#include <stdio.h>
#define N 100000
static int buffer[N];
static int head = 0, tail = 0;
static int produced = 0, consumed = 0;   /* shared, unsynchronised on purpose */

static void *producer(void *_) {
    for (int i = 0; i < N; i++) { buffer[tail] = i; tail = (tail+1) % N; produced++; }
    return 0;
}
static void *consumer(void *_) {
    for (int i = 0; i < N; i++) { int v = buffer[head]; head = (head+1) % N; consumed += v; }
    return 0;
}
int main(void) {
    pthread_t p, c;
    pthread_create(&p, NULL, producer, NULL);
    pthread_create(&c, NULL, consumer, NULL);
    pthread_join(p, NULL); pthread_join(c, NULL);
    printf("expected sum=%d  got sum=%d  %s\n",
           N*(N-1)/2, consumed, consumed == N*(N-1)/2 ? "OK" : "CORRUPTED BY THE RACE");
    return 0;
}
EOF
gcc -O0 -o producer producer.c -lpthread
./producer | tee 03-producer.txt

gcc -O0 -fsanitize=thread -o producer-tsan producer.c -lpthread
./producer-tsan 2>&1 | grep -m1 -A3 "WARNING: ThreadSanitizer" | head -6 | tee -a 03-producer.txt
echo
echo "TSan names the exact conflicting lines. Always use it when writing concurrent code."

# --- 5. DEADLOCK, reliably ---
cat > deadlock.c <<'EOF'
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>
static pthread_mutex_t a = PTHREAD_MUTEX_INITIALIZER;
static pthread_mutex_t b = PTHREAD_MUTEX_INITIALIZER;
static void *t1(void *_) { pthread_mutex_lock(&a); usleep(100000);
                           pthread_mutex_lock(&b); printf("t1 got both\n"); return 0; }
static void *t2(void *_) { pthread_mutex_lock(&b); usleep(100000);
                           pthread_mutex_lock(&a); printf("t2 got both\n"); return 0; }
int main(void) {
    pthread_t x, y;
    pthread_create(&x, NULL, t1, NULL);
    pthread_create(&y, NULL, t2, NULL);
    pthread_join(x, NULL); pthread_join(y, NULL);
    return 0;
}
EOF
gcc -o deadlock deadlock.c -lpthread
echo "=== the hang IS the deadlock (10s timeout) ==="
timeout 10 ./deadlock; rc=$?
[ $rc -eq 124 ] && echo "  timed out = deadlocked, exactly as designed"
echo
echo "Fix: always acquire locks in the same global order. Here t1 takes a->b, so t2 must too."

Step 5 is worth experiencing once. A program that hangs forever with no error message is the
least dramatic and most common failure in concurrent systems — and the same class of bug produces
real service outages.
