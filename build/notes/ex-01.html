Compiling a Vulnerable Target and Auditing Its Protections

Summary

Before you exploit anything you must know what is protecting it. checksec reads a binary and
tells you which mitigations are compiled in. That report dictates your technique — there is no
point writing shellcode for a binary with NX enabled.

Every exploit starts with this file.

Key ideas

  • NX: the stack and heap are not executable. Shellcode must be read() in, or you must ROP
  • PIE: the binary loads at a random base. You need an address leak
  • Stack canary: a random value between locals and the return address. Corrupt it and the
    program aborts before returning
  • RELRO: makes the GOT read-only after relocation. Full RELRO closes the GOT-overwrite route
  • ASLR is not a binary flag — it is a system-wide runtime setting
  • Compile flags let you turn each mitigation off, which is exactly what exploit courses do

The mitigation matrix

Mitigation Flag to disable Check with Symptom when present
Stack canary -fno-stack-protector checksec → "Stack canary: found" *** stack smashing detected *** and SIGABRT
NX -z execstack GNU_STACK RWX cannot jump to address on stack from your shellcode
PIE -no-pie ELF Type: DYN vs EXEC Hardcoded addresses do not work
RELRO -Wl,-z,norelro "Full RELRO" / "No RELRO" GOT is read-only; overwriting fails
Safe stack -fno-stack-safe-stack rarely Canary never appears

Terminology

Term Meaning
NX / DEP Non-executable stack/heap
PIE Position-independent executable; randomised base
ASLR System-wide address randomisation
Stack canary Random guard value before the return address
RELRO RELocations read-only after startup
GOT / PLT Dynamic symbol resolution structures
Lazy binding Resolving a symbol on first call
Stripped Symbol table removed
Static vs dynamic Library code copied in vs resolved at runtime

Kali commands

command -v checksec gcc gdb patchelf

# --- the compiler flags that matter, on one line ---
gcc -g -O0 -fno-stack-protector -no-pie -z execstack vuln.c -o vuln

# --- read the protections ---
checksec --file=./vuln
readelf -h ./vuln | grep Type                    # EXEC = no PIE, DYN = PIE
readelf -lW ./vuln | grep GNU_STACK              # "RWE" = executable stack
readelf -d ./vuln | grep -E "BIND_NOW|FLAGS"     # RELRO
readelf -s ./vuln | grep __stack_chk_fail         # canary support linked in
file ./vuln                                      # stripped or not

# --- is ASLR on for this system? ---
cat /proc/sys/kernel/randomize_va_space          # 0 off, 1 partial, 2 full
sudo sysctl kernel.randomize_va_space=0           # the exploit-lab setting

# --- section layout, which matters for ret2libc ---
readelf -S ./vuln | head -20
objdump -d ./vuln | grep -A3 "<plt>:" | head -20

# --- strip it, to practise static analysis ---
cp ./vuln ./vuln-stripped && strip ./vuln-stripped
file ./vuln ./vuln-stripped
nm ./vuln | wc -l; nm ./vuln-stripped 2>&1 | head -2

Field lab

Objective: compile the same program four ways and produce a definitive comparison of what
each flag changes. This is the reference table you will consult for the rest of Tier 3.

mkdir -p ~/aegis/labs/ex-01 && cd ~/aegis/labs/ex-01

cat > target.c <<'EOF'
#include <stdio.h>
#include <string.h>

void win(void) { puts("you win"); }        /* the goal */

void vuln(const char *input) {
    char buf[64];
    strcpy(buf, input);                   /* the bug */
    printf("got: %s\n", buf);
}

int main(int argc, char **argv) {
    if (argc < 2) { fprintf(stderr, "usage: %s <string> [win]\n", argv[0]); return 1; }
    vuln(argv[1]);
    if (argc > 2 && strcmp(argv[2], "win") == 0) win();
    return 0;
}
EOF

# --- the four builds ---
gcc -Wall -g -O0 -fno-stack-protector -no-pie -z execstack  target.c -o target-weak
gcc -Wall -g -O0 -fno-stack-protector -pie -fPIE -fstack-protector-strong target.c -o target-hardened
gcc -Wall -g -O0 -fstack-protector-strong -pie -fPIE -D_FORTIFY_SOURCE=2 -Wl,-z,relro,-z,now target.c -o target-full
gcc -Wall -g -O0 -fno-stack-protector -no-pie -z execstack -static target.c -o target-static 2>/dev/null || \
  echo "(static build unavailable)"

# --- the audit ---
{
  for b in target-weak target-hardened target-full target-static; do
    [ -f "./$b" ] || continue
    echo "=============================================="
    echo "  $b"
    echo "=============================================="
    file ./$b
    echo "--- checksec ---"
    checksec --file=./$b 2>/dev/null || readelf -lW ./$b | grep -E "GNU_STACK|GNU_RELRO"
    echo
  done
} 2>&1 | tee 01-audit.txt

cat 01-audit.txt

# --- the observable consequences ---
echo
echo "=== consequence 1: canary aborts the program ==="
LONG=$(python3 -c 'print("A"*200)')
for b in target-weak target-hardened target-full; do
  out=$(./$b "$LONG" 2>&1); rc=$?
  printf "  %-16s rc=%-3s %s\n" "$b" "$rc" "$(echo "$out" | head -1 | cut -c1-50)"
done
echo
echo "  '*** stack smashing detected ***' means the canary did its job."

# --- consequence 2: PIE changes where the code lives ---
echo
echo "=== consequence 2: PIE moves the binary between runs ==="
for b in target-weak target-hardened; do
  a=$(objdump -d ./$b 2>/dev/null | grep "<main>:" | head -1 | awk '{print $1}')
  b2=$(objdump -d ./$b 2>/dev/null | grep "<main>:" | head -1 | awk '{print $1}')
  printf "  %-16s main at %s\n" "$b" "$a"
done
echo "  target-weak (no PIE) is always at a fixed address."
echo "  target-hardened (PIE) moves with ASLR on each exec of the *process*."

# --- consequence 3: RELRO and the GOT ---
echo
echo "=== consequence 3: is the GOT writable? ==="
for b in target-weak target-full; do
  echo "  --- $b ---"
  readelf -lW ./$b | grep GNU_RELRO
  readelf -d ./$b | grep -E "BIND_NOW|FLAGS" | head -2
done
echo
echo "  Full RELRO + BIND_NOW = the GOT is mapped read-only after startup."
echo "  Partial RELRO          = the GOT stays writable until the first call resolves."

# --- consequence 4: symbols present or stripped ---
echo
echo "=== consequence 4: does it have symbols? ==="
cp target-weak target-stripped && strip target-stripped
echo "  symbols in target-weak    : $(nm target-weak 2>/dev/null | grep -c ' T ')"
echo "  symbols in target-stripped: $(nm target-stripped 2>/dev/null | grep -c ' T ')"
file target-stripped | sed 's/^/  /'

# --- the build script, because you will rebuild constantly ---
cat > Makefile <<'MAKE'
CC      := gcc
WARN    := -Wall -Wextra
DEBUG   := -g -O0
WEAK    := -fno-stack-protector -no-pie -z execstack
HARD    := -fstack-protector-strong -pie -fPIE
FULL    := $(HARD) -D_FORTIFY_SOURCE=2 -Wl,-z,relro,-z,now

all: target-weak target-hardened target-full

target-weak: target.c
    $(CC) $(WARN) $(DEBUG) $(WEAK) -o $@ $<

target-hardened: target.c
    $(CC) $(WARN) $(DEBUG) $(HARD) -o $@ $<

target-full: target.c
    $(CC) $(WARN) $(DEBUG) $(FULL) -o $@ $<

clean:
    rm -f target-weak target-hardened target-full target-stripped

.PHONY: all clean
MAKE
make clean >/dev/null && make 2>&1 | tail -4
ls -la target-weak target-hardened target-full

# --- the decision table you will actually use ---
cat > 02-decision.md <<'EOF'
# Choosing a technique from a checksec report

| Report | You must |
|---|---|
| No canary, NX off, no PIE | stack shellcode directly |
| No canary, NX **on** | ret2libc or ROP |
| Canary present | first leak the canary (format string or over-read), then exploit |
| PIE | leak a code or libc address first |
| Full RELRO | GOT is read-only; you must target something else (hooks, atexit, vtable...) |
| Partial RELRO | GOT overwrite via ret2libc is available |
| Stripped | you must reverse engineer names yourself (strings + signatures) |

Practical rule: CS:IP Lecture 4 builds the same target and walks you up this
ladder one mitigation at a time. Do it in that order and each step is obvious.
EOF
cat 02-decision.md

Step 1's table is the artefact. 01-audit.txt is your reference for choosing a technique,
