The Kali Directory Layout

Summary

Once you know where Kali keeps its data, the toolset stops being a mystery and starts being
navigable. Every tool in this curriculum is a binary in /usr/bin, but the interesting parts
of Kali — the scripts, the wordlists, the payload templates, the exploits — live in /usr/share
directories that have a consistent, learnable layout.

This is the single highest-value five minutes of orientation you will spend on Kali.

The map

/usr/bin/                     the executables themselves (nmap, john, sqlmap…)
/usr/share/nmap/              nmap scripts, service probes, NSE libraries
/usr/share/nmap/nmap-services  port → service database
/usr/share/nmap/nmap-protocols protocol → port mapping
/usr/share/wordlists/         SecLists: passwords, usernames, directories, web
/usr/share/seclists/          older copy of the same, kept for compatibility
/usr/share/metasploit-framework/
    modules/                  exploits, payloads, aux, encoders, evasion
    data/                     wordlists, targets, documentation
/usr/share/john/              jumbo's wordlists and config files
/usr/share/seclists/Discovery/Web-Content/   directory bruteforce lists
/usr/share/responder/         Responder's config and spoofing lists
/usr/share/impacket/          example scripts and requirements
/usr/share/amap/              protocol mapper data
/usr/share/ettercap/          etterfilter plugins and services
/usr/share/lynis/             auditing scripts (hardening checks)

/var/log/syslog, auth.log     system logs — your own forensic evidence
/var/log/auth.log             authentication history, sudo usage, SSH attempts
/var/log/wtmp, /var/log/btmp  login/logout records and failed attempts
/proc/                        live process state (read-only virtual filesystem)
/etc/passwd, /etc/shadow      user database and password hashes
/etc/apt/                     repository configuration

Why this matters operationally

Three reasons an operator cares:

  1. Discovery is a file read. ls /usr/share/wordlists/ tells you exactly what you can brute
    force. On a target you have compromised, the equivalent directory tells you what the defender
    expects you to try.
  2. Nmap's port knowledge is a file. grep -E '^(http|ssh|mysql)\b' /usr/share/nmap/nmap-services
    gives you every port for a service. When you need a port and cannot remember it, read the
    database instead of guessing.
  3. Metasploit's modules are a browsable database. Not something to memorise — something to
    grep.

Kali commands

# --- the directory map, generated live ---
du -sh /usr/share/* 2>/dev/null | sort -h | tail -20

# --- wordlists: what is actually available ---
ls /usr/share/wordlists/
wc -l /usr/share/wordlists/rockyou.txt 2>/dev/null
ls /usr/share/seclists/ | head -20
find /usr/share/seclists -iname "*directory*" -type d | head

# --- nmap's protocol database: stop memorising ports ---
head -20 /usr/share/nmap/nmap-services
grep -E '\bhttp/https?\b' /usr/share/nmap/nmap-services | head -15
grep -E '\bmysql\b' /usr/share/nmap/nmap-services
grep -E '\bssh\b' /usr/share/nmap/nmap-services

# --- metasploit as a searchable database ---
ls /usr/share/metasploit-framework/modules/exploits/ | head
find /usr/share/metasploit-framework/modules -name "*.rb" | wc -l
grep -rl "eternalblue" /usr/share/metasploit-framework/modules/ 2>/dev/null | head

# --- john's wordlists ---
ls /usr/share/john/
grep -c . /usr/share/john/password.lst 2>/dev/null

# --- the kernel's live view (read-only, never modify) ---
ls /proc/ | head
cat /proc/version
cat /proc/self/status | head -20
ls -l /proc/self/fd/          # this process's open file descriptors

# --- your own authentication history (forensic habit) ---
last -20
sudo lastb 2>/dev/null | head -20    # failed logins

Field lab

Objective: build a reference map of your own toolset that you will use every single day.

mkdir -p ~/aegis/labs/kr-04 && cd ~/aegis/labs/kr-04

# 1. Size of each data directory - what is big, and why
du -sh /usr/share/* 2>/dev/null | sort -h | tail -25 | tee 01-share-sizes.txt

# 2. Your available wordlists, with line counts (this is your brute-force capability)
for f in /usr/share/wordlists/*.txt /usr/share/seclists/Passwords/*.txt; do
  [ -f "$f" ] && printf "%-60s %s\n" "$f" "$(wc -l < "$f")"
done 2>/dev/null | sort -k2 -n | tee 02-wordlists.txt

# 3. Build your own port reference from nmap's database
grep -vE '^#|^$' /usr/share/nmap/nmap-services > 03-ports.txt
echo "=== HTTP ports ==="; grep -E '\bhttps?\b' 03-ports.txt | head -10
echo "=== SMB / Windows ==="; grep -E '\b(smb|netbios|smb2)\b' 03-ports.txt
echo "=== Database ==="; grep -E '\b(mysql|postgres|mssql|oracle|mongo)\b' 03-ports.txt
echo "=== Remote access ==="; grep -E '\b(ssh|rdp|winrm|vnc)\b' 03-ports.txt

# 4. How much exploit code do you have locally?
echo "metasploit modules: $(find /usr/share/metasploit-framework/modules -name '*.rb' 2>/dev/null | wc -l)"
find /usr/share/metasploit-framework/modules/exploits -maxdepth 1 -type d | sed 's|.*/||' | sort | head -30

# 5. Your live kernel state - proof that /proc is a filesystem, not a folder of files
ls /proc/ | grep -E '^[0-9]+$' | wc -l    # running processes
cat /proc/uptime                          # seconds since boot
cat /proc/net/tcp | head -5               # live TCP table in HEX (little-endian!)

# 6. Authentication history on your own box
last -n 10 | tee 06-logins.txt
sudo grep "Accepted\|Failed" /var/log/auth.log 2>/dev/null | tail -20 >> 06-logins.txt

Observation worth having: /proc/net/tcp prints ports in little-endian hexadecimal.
0100007F:1F90 means 127.0.0.1:8080. This trips up everyone once. Decode it like this:

# decode /proc/net/tcp into readable form
printf "%-22s %s\n" "LOCAL" "SERVICE"
awk 'NR>1 && $4=="0A" {
  split($2, a, ":");
  printf "listen  %d.%d.%d.%d:%d\n",
    strtonum("0x" substr(a[1],7,2)), strtonum("0x" substr(a[1],5,2)),
    strtonum("0x" substr(a[1],3,2)), strtonum("0x" substr(a[1],1,2)), strtonum("0x" a[2])
}' /proc/net/tcp

Record: save 01-share-sizes.txt and 02-wordlists.txt. When you start password attacks in
Tier 4, this is your shopping list.

Self-test

  1. Where does Kali keep its wordlists, and why does knowing this matter during an engagement?
  2. Nmap knows that port 3306 is MySQL. Which file told you that?
  3. What does /proc/net/tcp show, and why are the ports in hexadecimal and byte-reversed?
  4. Metasploit's modules live in which directory? How would you grep for a specific CVE's module?
  5. du -sh /usr/share/seclists is 0 bytes on your install. What are two possible reasons and
    how would you fix it?
