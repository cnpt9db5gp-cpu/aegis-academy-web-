File Systems

Summary

A filesystem is three layers that are often confused: the API (open/read/write/stat), the
on-disk format (how bytes are laid out so they survive a reboot), and the implementation
(inodes, directories, allocation, caching).

Security lives in the seams: symlink races, TOCTOU on path lookups, incorrect permission
checks, and recovering deleted files.

The on-disk layout

superblock        filesystem metadata: size, counts, free-block pointers
block 0           unused
inodes            one per file: mode, uid, size, block pointers, timestamps
data blocks       file contents
bitmaps           which inodes and blocks are in use

In xv6 this is ~50 lines in fs.c and you can read the whole thing in an afternoon. That is the
recommended approach — a real, tiny, complete filesystem.

Inodes

An inode holds metadata, not the name:

Field Security relevance
mode Permission bits; setuid/setgid live here
uid / gid Owner identity
nlink Link count — 0 means deleted but still open
size Needed for bounds checks
atime/mtime/ctime Forensics; tampering is anti-forensics

Permissions live in the inode, not the directory entry. That is why hard links share
permissions, and why chmod affects every name pointing at the inode.

Directories

A directory is just a file whose entries are (name, inode number). Consequences:

  • No inherent ordering, no guarantee of uniqueness unless the implementation enforces it
  • . and .. entries are conventional
  • Deletion removes a name; the inode survives while nlink > 0 or a process holds it open

Path resolution

/var/log/syslog
  ↓ resolve "/"      in the root inode's data blocks
  ↓ lookup "var"     in that directory
  ↓ lookup "log"     ...
  ↓ lookup "syslog"

Each step does a lookup and returns an inode. This multi-step nature is the source of the
most important filesystem race:

TOCTOU (time-of-check to time-of-use): a path is validated, then opened. Between the two, an
attacker can replace a component with a symlink.

if (access("/tmp/upload/ok", F_OK) == 0) {     // check
    fopen("/tmp/upload/ok", "w");              // use  <- different state
}

The fix is to operate on file descriptors (openat, O_NOFOLLOW, fstat on the fd) rather
than paths. This is a Tier 1 privilege escalation path and a Tier 4 web path traversal cousin.

Links

Link Points to Survives deletion of the name?
Hard (ln a b) The same inode Yes, while any name remains
Symbolic (ln -s a b) A path string No — becomes dangling

A symlink is attacker-controllable text. Applications that chroot but follow symlinks are
classically escapable, which is why O_NOFOLLOW exists.

Deletion and recovery

rm removes the directory entry. The data blocks become free but are usually not overwritten.
Anything that still holds the inode open keeps reading it.

lsof +L1        # deleted files still held open by processes
ls -l /proc/*/fd | grep deleted
debugfs -R "lsdel" /dev/sda1      # ext inode recovery (lab VM only)

This is the mechanism behind every "I deleted the evidence" failure, and the basis of file
carving in Tier 6.

Permissions and access control

-rwxr-xr--   rwx r-x r--
  │   │   └── others
  │   └────── group
  └────────── owner

Beyond the bits: umask (what new files get), ACLs (per-user exceptions), capabilities
(specific authority), SELinux/AppArmor (mandatory access control).

A complete check must read all four. Most "the file is not writable" bugs in a pentest are
really an ACL or a capability you did not check.

Terminology

Term Meaning
Superblock Filesystem-wide metadata
Inode Per-file metadata record
Block Fixed-size storage unit
Directory A file of (name → inode) entries
Hard link Another name for the same inode
Symlink A file containing a path
TOCTOU Check-then-use race on paths
O_NOFOLLOW Open symlinks as symlinks, do not traverse
openat Open relative to a directory fd — race-resistant
umask Bits stripped when creating files
ACL Per-user permissions beyond owner/group/other
Link count Names pointing at an inode; 0 = unlinked
Carving Recovering files by signature after deletion

Field lab

Objective: demonstrate the three layers and produce a real TOCTOU race.

mkdir -p ~/aegis/labs/os-07 && cd ~/aegis/labs/os-07

# --- 1. the layout ---
{
  echo "=== mounts ==="; findmnt -T / -o TARGET,SOURCE,FSTYPE,OPTIONS | head -3
  echo; echo "=== /etc/passwd stat ==="; stat /etc/passwd
  echo; echo "=== first 5 inodes in /etc ==="; ls -lai /etc | head -6
  echo; echo "=== why can't I read /etc/shadow? ==="
  namei -l /etc/shadow
  getfacl -p /etc/shadow 2>/dev/null | head -6
} > 01-layout.txt; cat 01-layout.txt

# --- 2. hard link vs symlink ---
{
  echo "=== hard link: same inode, survives deleting one name ==="
  ln /etc/hosts hard-link
  stat -c '  inode=%i links=%h name=%n' /etc/hosts hard-link
  rm hard-link; echo "  (hard-link removed; /etc/hosts unaffected)"

  echo
  echo "=== symlink: stores a PATH, breaks when the target moves ==="
  ln -s /etc/hosts soft-link
  stat -c '  inode=%i links=%h name=%n' soft-link
  readlink soft-link
  rm soft-link
} 2>&1 | tee 02-links.txt

# --- 3. THE TOCTOU RACE, written out ---
cat > race.c <<'EOF'
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>

int main(int argc, char **argv) {
    const char *path = argv[1] ? argv[1] : "/tmp/aegis-race/target";

    /* CHECK: does the file look safe? */
    if (access(path, F_OK) != 0) { printf("check: not found\n"); return 1; }
    printf("check: %s exists\n", path);

    /* USE: a different syscall, a different moment, different result */
    FILE *f = fopen(path, "r");
    if (!f) { printf("use: open failed (%s) - the state changed between check and use\n",
                     strerror(errno)); return 2; }
    printf("use: opened successfully\n");
    fclose(f);
    return 0;
}
EOF
sed -i '5a #include <string.h>\n#include <errno.h>' race.c
gcc -o race race.c
mkdir -p /tmp/aegis-race && echo "legitimate content" > /tmp/aegis-race/target
./race /tmp/aegis-race/target

# the race: swap a regular file for a symlink between check and use
mkdir -p /tmp/aegis-race-secret && echo "secret" > /tmp/aegis-race-secret/target
( sleep 0.02; rm -f /tmp/aegis-race/target; ln -s /tmp/aegis-race-secret/target /tmp/aegis-race/target ) &
for i in $(seq 1 200); do ./race /tmp/aegis-race/target >/dev/null 2>&1; done
wait
echo "200 attempts made; the race window is real even if you did not win it."
echo "The fix is not 'retry faster' - it is openat() + O_NOFOLLOW on a directory fd."
rm -rf /tmp/aegis-race /tmp/aegis-race-secret

# --- 4. the correct pattern ---
cat > race-safe.c <<'EOF'
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
int main(int argc, char **argv) {
    int dir = open(argv[1], O_RDONLY | O_DIRECTORY);
    if (dir < 0) { perror("open dir"); return 1; }
    /* operate relative to the fd, and refuse to follow symlinks */
    int fd = openat(dir, "target", O_RDONLY | O_NOFOLLOW);
    if (fd < 0) { printf("refused: %s\n", strerror(errno)); return 2; }
    char buf[128]; ssize_t n = read(fd, buf, sizeof(buf)-1);
    if (n > 0) { buf[n] = 0; printf("read: %s", buf); }
    close(fd); close(dir);
    return 0;
}
EOF
gcc -o race-safe race-safe.c
mkdir -p /tmp/aegis-safe && echo "legitimate" > /tmp/aegis-safe/target
./race-safe /tmp/aegis-safe
rm -f /tmp/aegis-safe/target && ln -s /etc/passwd /tmp/aegis-safe/target
./race-safe /tmp/aegis-safe        # O_NOFOLLOW blocks the swap
rm -rf /tmp/aegis-safe

# --- 5. deleted but still open ---
sudo bash -c 'rm -f /var/log/dpkg.log' 2>/dev/null
echo "held-open deleted files on this box:"
sudo lsof +L1 2>/dev/null | head -5
echo "(a process holding an fd keeps reading deleted data - this is how 'deleted' files are recovered)"

Step 3 versus step 4 is the whole lesson. Retrying is not a fix; openat + O_NOFOLLOW is.
You will write this exact pattern again in Tier 4 (path traversal) and Tier 6 (evidence).

Record: race.c and race-safe.c side by side. That contrast is the whole lecture.
