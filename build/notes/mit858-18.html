CPU Timing Attacks

Summary

Lecture 18 is the capstone: an attacker with no bug to exploit, no key to steal, and often no
code execution at all — just the ability to measure time. Spectre and Meltdown made speculative
execution a universal memory-disclosure primitive.

Key ideas

  • Side channels: secrets leak through time, cache state, power, or contention
  • Timing attacks: measure how long an operation takes, infer a secret-dependent branch
  • Speculative execution: the CPU executes past a bounds check or a permission check, and the
    result leaks via cache
  • Meltdown: speculative read of kernel memory, then a fault; flush+reload recovers it
  • Spectre: speculative execution poisons a branch predictor or a register
  • The mitigations all cost performance — the industry accepted the cost
  • The lesson: physical properties become security properties once data depends on them

The three ingredients

1. a secret-dependent operation
2. an observable side effect of that operation
3. the ability to measure the side effect

You need all three. Remove any one and the attack fails.

Timing attacks without speculation

The classic demonstration: find a secret with a byte-at-a-time comparison.

def is_secret_byte_correct(secret_guess):
    return secret_guess == SECRET[0]        # early return

# An attacker measuring the time per guess learns how many
# leading bytes matched - then brute-forces 256 values per byte

This requires no kernel bug, no speculative execution, and no memory access
privilege. It requires only the ability to time a remote operation, which is
why constant-time code (constant-time) exists.

Spectre v1, in four steps

  1. The CPU speculatively executes a branch it predicted will be taken
  2. That speculation reads memory the branch should not have read
  3. The result stays in a register or cache line
  4. The branch is mispredicted, the speculation is squashed — but the cache is not

Attack variants: bounds-check bypass (array[i] where i is out of range),
indirect branch misprediction, and return-oriented programming variants.

Meltdown

  1. A user-space instruction speculatively reads kernel memory
  2. A subsequent access faults, but the speculative read already happened
  3. The value left a cache footprint
  4. Flush+Reload from user space recovers it

Meltdown is an architectural bug (privilege check after the memory access);
Spectre is a microarchitectural bug (speculative execution past a check).

Mitigations and their costs

Mitigation Against Cost
KPTI / Meltdown mitigation Meltdown 5-20% on some workloads
IBRS / STIBP Spectre v2 smaller
retpolines / IBPB Spectre v2 branch prediction disabled
lfence in bounds checks bounds-check Spectre serialising instruction
ASLR + KASLR address guessing negligible
constant-time code timing channels harder to write, easy to get wrong

Note the asymmetry: KPTI prevents Meltdown by making kernel memory
unmapped in user space, which is a large architectural cost. There is no
complete fix for Spectre v1 — the mitigation is probabilistic.

Terminology

Term Meaning
Side channel Leaking secrets via observable side effects
Timing attack Inferring secrets from execution time
Speculative execution Executing instructions before they are known to be needed
Branch predictor Hardware guess about which branch will be taken
Spectre Speculative execution poisons a predictor or register
Meltdown Speculative read of kernel memory
KPTI Kernel page-table isolation
IBPB / retpolines Indirect-branch mitigations
Flush+Reload Reading another process's cache access via timing
Constant-time Code whose timing does not depend on secrets

# --- a timing measurement you can do without any tool ---
python3 - <<'PY' | tee 02-timing.txt
import time, statistics

def work(n):
    s = 0
    for i in range(n): s += i * i
    return s

def measure(n, reps=200):
    ts = []
    for _ in range(reps):
        t0 = time.perf_counter_ns(); work(n); ts.append(time.perf_counter_ns() - t0)
    return min(ts)

print("  measuring execution time by workload size:")
prev = None
for n in (1000, 10000, 100000, 1000000):
    t = measure(n)
    print(f"    n={n:<9} {t/1e6:9.3f} ms" + (f"   delta {(t-prev)/1e6:.3f} ms" if prev else ""))
    prev = t
print()
print("  The measurement is stable and repeatable. That stability is exactly what")
print("  makes timing attacks practical: the signal exceeds the noise.")

# --- the early-exit timing attack, demonstrated ---
cat > 03-early-exit.py <<'PY'
#!/usr/bin/env python3
"""Recover a secret byte by byte using timing. No kernel bug required."""
import time, secrets, statistics

SECRET = secrets.token_bytes(4)

def check(guess: bytes) -> bool:
    """Returns False at the first mismatching byte."""
    for a, b in zip(SECRET, guess):
        if a != b:
            return False
    return True

def timeit(fn, arg, reps=2000):
    ts = []
    for _ in range(reps):
        t0 = time.perf_counter_ns(); fn(arg); ts.append(time.perf_counter_ns() - t0)
    return statistics.median(ts)

def recover() -> bytes:
    found = b""
    while len(found) < len(SECRET):
        base = timeit(check, found + b"\x00")
        best, best_t = None, -1
        for candidate in range(256):
            t = timeit(check, found + bytes([candidate]))
            if t > best_t:
                best_t, best = t, candidate
        found += bytes([best])
        print(f"    recovered so far: {found.hex()}  (baseline {base} ns, best {best_t} ns)")
    return found

if __name__ == "__main__":
    print(f"  secret      : {SECRET.hex()}")
    print("  recovering by timing (this is the whole attack):")
    got = recover()
    print(f"  recovered   : {got.hex()}")
    print(f"  correct     : {got == SECRET}")
PY
python3 03-early-exit.py | tee 04-early-exit.txt
rm -f 03-early-exit.py

# --- cache state is observable: the core of every cache attack ---
{
  echo "=== the cache hierarchy an attacker measures ==="
  for i in /sys/devices/system/cpu/cpu0/cache/index*; do
    [ -d "$i" ] || continue
    printf "  L%s %-8s size=%-8s line=%s\n" \
      "$(cat $i/level 2>/dev/null)" "$(cat $i/type 2>/dev/null)" \
      "$(cat $i/size 2>/dev/null)" "$(cat $i/coherency_line_size 2>/dev/null)"
  done
  echo
  echo "  Smaller share of cache = faster access = detectable difference."
  echo "  mit858-07 (enclaves) is the hardware version of this problem."
} 2>&1 | tee 05-cache.txt

Step 4 is the demonstration: it recovers a random 4-byte secret purely by timing, with no
kernel bug, no speculative execution and no memory access privilege. That is the lecture's point
in 20 lines of Python.
