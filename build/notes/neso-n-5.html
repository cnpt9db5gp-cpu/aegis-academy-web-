Transport Layer: TCP and UDP

Summary

Ports, sockets, connection state and reliability. Transport is where "is it open" is decided and
where half the network attack surface lives.

Key ideas

  • Ports name applications; the 4-tuple (src ip, src port, dst ip, dst port) identifies a flow
  • TCP: connection-oriented, reliable, ordered, congestion-controlled, stateful
  • UDP: connectionless, no guarantees, 8-byte header, used by DNS, DHCP, QUIC
  • Sockets are the kernel objects; every flow is one
  • Port states (LISTEN, SYN_SENT, ESTABLISHED, TIME_WAIT) are what you read when diagnosing
  • Well-known vs ephemeral: knowing the range tells you whether a port is a service or a
    leftover client socket

Terminology

Term Meaning
Port 16-bit application identifier
4-tuple The fields that uniquely identify a TCP flow
Socket Kernel object for an endpoint
Reliable / ordered TCP's delivery guarantees
Congestion control TCP's backpressure mechanism
Ephemeral port Client's temporary source port
Well-known ports 0-1023
Registered ports 1024-49151
Half-close One direction shut, the other still open
Port reuse SO_REUSEADDR

# --- 4. scan the ephemeral range question ---
cat > 04-loopback-ports.md <<'EOF'
# Why `nmap -p- 127.0.0.1` shows hundreds of ports

Those are almost all **ephemeral client sockets** created by local programs and
browser connections, not listening services. The kernel picked those source ports
temporarily.

Lesson for reading scans:
- `ss -tuln state listening` is the authoritative list of services.
- A `nmap -sT` scan sees whatever has a bound socket, including transient clients.
- When assessing a target, confirm with a listening-socket query before reporting
  "open port" findings, or you will report noise.

## The defensive side
`net.ipv4.ip_local_port_range` controls the ephemeral range. Widening it slightly
makes source-port exhaustion harder, and SYN cookies (`net.ipv4.tcp_syncookies`)
protect against SYN floods without a full connection.
EOF
cat 04-loopback-ports.md
echo
n=$(ss -tuln state listening 2>/dev/null | tail -n +2 | wc -l)
e=$(ss -tan 2>/dev/null | grep -c ESTAB)
echo "  this host: $n listening services, $e established connections"
echo "  A full -p- scan of loopback will report hundreds of the latter."

# --- 5. SYN cookies, and why they exist ---
{
  echo "=== SYN flood protection on this host ==="
  echo "  syncookies : $(cat /proc/sys/net/ipv4/tcp_syncookies 2>/dev/null || echo n/a)"
  echo "  (1 = enabled: the server encodes state in the ISN instead of keeping a table)"
  echo "  tcp_synack_retries: $(cat /proc/sys/net/ipv4/tcp_synack_retries 2>/dev/null)"
  echo "  tcp_max_syn_backlog: $(cat /proc/sys/net/ipv4/tcp_max_syn_backlog 2>/dev/null)"
} 2>&1 | tee 05-syncookies.txt
