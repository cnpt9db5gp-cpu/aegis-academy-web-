Kernel Exploits and Knowing When Not To

Summary

A kernel exploit is the last resort, not the first. This lecture covers when it is justified, how
the privilege-escalation decision tree actually works, and how to study Dirty Pipe as the
canonical modern walkthrough.

Key ideas

  • Escalation order: credentials → misconfiguration → SUID/service abuse → PATH/cron →
    kernel exploit. Most engagements never need step 4.
  • Kernel exploit preconditions: a known local privilege boundary to cross. If you are already
    root, there is nothing to escalate.
  • Finding a kernel bug: uname -r → identify version → searchsploit linux kernel <version>
    → check for a local privesc PoC
  • Dirty Pipe (CVE-2022-0847): an arbitrary write to the page cache as root, and the cleanest
    modern kernel exploit to study
  • Modern kernels restrict unprivileged user namespaces, which breaks many published privesc
    chains — you must check, not assume

Terminology

Term Meaning
Kernel exploit A bug in the kernel used to gain root
Local privilege escalation Already on the box, becoming root
uname -r Exact kernel version string
Dirty Pipe CVE-2022-0847, page-cache write as root
Page cache Kernel's file-content cache
User namespace Lets an unprivileged user fake UID 0 in a namespace
Exploit chain Several bugs combined into one escalation
KASLR Kernel address space layout randomisation
Privesc Abbreviation for privilege escalation

# --- the identification step ---
uname -r

# --- is a published exploit available? (offline) ---

searchsploit -t linux-exploit | head -20

# --- are the preconditions met? ---
echo "=== unprivileged user namespaces ==="
cat /proc/sys/kernel/unprivileged_userns_clone 2>/dev/null || echo "  (sysctl absent - modern default)"
sysctl kernel.unprivileged_userns_clone 2>/dev/null
echo "  value 1 = allowed (most published privesc chains work)"
echo "  value 0 = blocked (most chains are dead)"
unshare -Ur echo "  userns test: WORKS" 2>/dev/null || echo "  userns test: BLOCKED"

echo
echo "=== can I even test an exploit? ==="
echo "  kernel exploits need: root in a namespace, a matching kernel, and care."
echo "  NEVER test a kernel exploit on a machine you care about."
id -u

# --- the Dirty Pipe reference material ---
echo "=== CVE-2022-0847 ==="
searchsploit CVE-2022-0847
echo
echo "The bug: a data pipe whose PIPE_BUF_FLAG_CAN_MERGE was cleared fails to"
echo "check that the buffer is still a pipe. A one-byte overwrite into an"

# --- kernel hardening on this box ---
{
  echo "=== kernel self-protection settings ==="
  for s in kptr_restrict dmesg_restrict yama/ptrace_scope perf_event_paranoid; do
    printf "  %-28s %s\n" "$s" "$(cat /proc/sys/kernel/${s/\//\/} 2>/dev/null || sysctl -n kernel.${s//\//.} 2>/dev/null)"
  done
  echo
  echo "=== unprivileged bpf / perf (common privesc surface) ==="
  sysctl kernel.unprivileged_bpf_disabled 2>/dev/null
  sysctl kernel.perf_event_paranoid 2>/dev/null
} 2>&1 | head -15 | tee 01-kernel-hardening.txt

Field lab

Objective: build the escalation decision tree, apply it to this machine, and study Dirty
Pipe's mechanism from the source.

mkdir -p ~/aegis/labs/pr-05 && cd ~/aegis/labs/pr-05

# --- 1. the decision tree, executed against this machine ---
cat > decide.sh <<'EOF'
#!/usr/bin/env bash
# Walk the escalation ladder from cheapest to most destructive.
# Print the FIRST step that succeeds. That is your path.
set -uo pipefail
LABEL="$1"

echo "=== ESCALATION DECISION TREE: $LABEL ==="
echo

echo "[0] Am I already root?"
if [ "$(id -u)" -eq 0 ]; then echo "    YES -> nothing to escalate."; exit 0; fi
echo "    no (uid=$(id -u))"
echo

echo "[1] Do I have a usable sudo rule?"
if sudo -n -l >/dev/null 2>&1; then
  echo "    YES - passwordless sudo available. Read it:"
  sudo -n -l | grep -vE "^$" | sed 's/^/      /'
else
  echo "    no passwordless sudo (may still have rules needing a password)"
fi
echo

echo "[2] Are there readable credentials that log in as someone privileged?"
c=$(sudo awk -F: 'length($2)>3 {print $1}' /etc/shadow 2>/dev/null | wc -l)
echo "    accounts with real hashes: $c"
grep -rilE "(password|passwd|secret)[[:space:]]*[=:]" ~/.bash_history ~/.ssh 2>/dev/null | head -3 | sed 's/^/      /'
echo

echo "[3] SUID / SGID binaries"
n=$(find / -perm -4000 -type f 2>/dev/null | wc -l)
echo "    $n SUID binaries found. Any unowned or unusual ones?"
comm -23 <(find / -perm -4000 -type f 2>/dev/null | sort) \
         <(dpkg -S $(find / -perm -4000 -type f 2>/dev/null) 2>/dev/null | cut -d: -f1 | sort -u) | head -3 | sed 's/^/      unowned: /'
echo

echo "[4] Writable service / cron artefacts"
echo "    world-writable dirs:"; find / -xdev -perm -o+w -type d 2>/dev/null | grep -vE '^/(proc|sys|dev|run|tmp|var/tmp)' | head -3 | sed 's/^/      /'
echo "    writable in /etc:";   find /etc -writable -type f 2>/dev/null | head -3 | sed 's/^/      /'
echo "    PATH dirs writable by me:"
IFS=: read -ra P <<< "$PATH"; for d in "${P[@]}"; do [ -d "$d" ] && [ -w "$d" ] && echo "      $d"; done
echo

echo "[5] Kernel exploit - LAST RESORT"
echo "    kernel: $(uname -r)"
echo "    userns: $(unshare -Ur true 2>/dev/null && echo allowed || echo BLOCKED)"
echo "    candidates (offline):"
searchsploit "linux kernel $(uname -r | cut -d- -f1)" 2>/dev/null | head -3 | sed 's/^/      /'
echo
echo "=== STEP 5 is only justified if 1-4 all failed ==="
EOF
chmod +x decide.sh && ./decide.sh "$(hostname)" | tee 02-decision-tree.txt

# --- 2. the Dirty Pipe mechanism, in your own words, from the primitives ---
cat > dirtypipe-notes.md <<'EOF'
# Dirty Pipe (CVE-2022-0847) - mechanism notes

## The bug in three layers

1. **Data pipes copy into an arbitrary page-cache page.** A normal pipe holds up to 16 pages of
   kernel memory. `splice()` moves those pages to/from a file. When a pipe is full, the kernel
   sets PIPE_BUF_FLAG_CAN_MERGE on every page but the first.

2. **Write() is supposed to refuse non-first pages.** `write()` must not modify a pipe page
   without CAN_MERGE, or it would corrupt kernel data. That check exists.

3. **The flag can be cleared, and the check is skipped.** `F_SETPIPE_SZ` clears CAN_MERGE.
   A page whose flag was cleared is still in a pipe (so `pipe_buffer_operations` still routes
   writes to it), but `write()` no longer refuses. If you can place a *page-cache page* into a
   pipe - by splicing from a file you own - you can write one byte anywhere in the page cache.

## Why that equals root

The page cache is where the kernel stores file *contents*. Overwriting the page containing
`/etc/passwd` changes the file. Overwriting the page containing a setuid binary's contents
changes that binary. Root achieved, with no memory corruption at all.

## Why it is the perfect teaching example

- The vulnerability class is a missing check on a flag (logic bug, not memory corruption)
- The path from bug to root is short, well documented, and provable
- It shows that "kernel exploits" are not all raw pwnage
- It explains why `unprivileged_userns_clone=0` mitigates many published chains

## Preconditions (check before you try anything)

- Kernel 5.8 to 5.16.11 / 5.10.x < 5.10.102 / 5.15.x < 5.15.41
- Ability to create a pipe and splice a page-cache page into it (needs a file you can open)
- Must be UNPRIVILEGED (that is the point)
- Works with pipes only; sockets and shmem took different paths
EOF
cat dirtypipe-notes.md | tee 03-dirtypipe.txt

# --- 3. check whether this machine is even vulnerable (read-only, safe) ---
{
  echo "=== is this kernel in the vulnerable range? ==="
  k=$(uname -r)
  echo "  running: $k"
  case "$k" in
    5.8*|5.9*|5.10*|5.11*|5.12*|5.13*|5.14*|5.15*|5.16*)
      echo "  range 5.8-5.16 -> MAY be vulnerable; check the patch level" ;;
    *)  echo "  outside 5.8-5.16 -> not affected by Dirty Pipe" ;;
  esac
  echo
  echo "  Patch levels that fix it: 5.10.102, 5.15.41, 5.16.9, 6.0.8"
  echo "  Kali is rolling: almost certainly patched."
} | tee -a 03-dirtypipe.txt

# --- 4. why a kernel exploit is the LAST step, argued ---
cat > 04-why-not-first.md <<'EOF'
Reasons to escalate in this order:

1. **Risk** - a kernel exploit can crash or corrupt the machine you are testing
2. **Stealth** - SUID abuse and a stolen credential leave far less residue than a kernel attack
3. **Portability** - your exploit is version-specific; the misconfiguration is not
4. **Detection** - kernel exploits trip EDR and leave forensic artefacts everywhere
5. **Reporting** - "this box had passwordless sudo" is a finding the client can fix.
   "your kernel was old" is a finding they will close in a week and be vulnerable again.
EOF
cat 04-why-not-first.md

echo
echo "=== final: your ordered action list from the decision tree ==="
sed -n '/^\[/p' 02-decision-tree.txt | sed 's/^/  /'

Step 1 is the deliverable: a decision tree you can run against any Linux target. In a real
engagement you will run it and find a credential or a sudo rule at step 1 or 2, and never touch
step 5.
