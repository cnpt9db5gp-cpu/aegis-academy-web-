Routers, the Default Gateway and Routing Tables

Summary

A router moves packets between different networks using a longest-prefix match against its
routing table. Understanding the lookup, and the fact that routers strip Layer 2 and rebuild it at
each hop, explains why L2 attacks stay inside a segment and L3 attacks can cross the internet.

Key ideas

  • Default route (0.0.0.0/0) is the fallback when nothing more specific matches
  • Longest prefix wins — this is the entire routing algorithm
  • At each hop: L2 frame is removed, TTL decremented, L3 header consulted, new frame built
  • TTL is why traceroute works: increment it until the packet expires
  • Default gateway = the router's interface on your subnet
  • Routing tables are read from: ip route, route -n, and on the target /proc/net/route

Terminology

Term Meaning
Router Layer 3 forwarder between networks
Routing table Destinations → next hop → interface
Default route 0.0.0.0/0, the catch-all
Longest prefix match Most specific matching route wins
Next hop Where the packet goes next
TTL Hop limit, decremented per router
Gateway Default gateway on your subnet
Metric Preference between equal-length routes
Hop One router traversal

import socket, struct
def ttl_probe(dst, ttl):
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.setsockopt(socket.IPPROTO_IP, socket.IP_TTL, ttl)
    s.settimeout(1.0)
    try:
        s.sendto(b"aegis", (dst, 33434)); s.recv(1024); return "*"
    except socket.timeout: return "timeout"
    except OSError: return "unreachable"
    finally: s.close()

Field lab

Objective: read a real routing table, prove longest-prefix match, and trace a path.

mkdir -p ~/aegis/labs/ccna-04 && cd ~/aegis/labs/ccna-04

# --- 1. the tables ---
{
  echo "=== ip route ==="
  ip route
  echo
  echo "=== /proc/net/route (kernel's copy) ==="
  cat /proc/net/route
  echo
  echo "=== IPv6 routes ==="
  ip -6 route 2>/dev/null | head
} 2>&1 | tee 01-routes.txt

# --- 2. longest prefix match, demonstrated ---
python3 - <<'PY' | tee 02-lpm.txt
import ipaddress

TABLE = [
    ("0.0.0.0/0",        "10.0.0.1"),       # default
    ("192.168.56.0/24",  "192.168.56.1"),   # specific
    ("192.168.56.128/25","192.168.56.129"), # MORE specific
    ("192.168.56.64/26", "192.168.56.65"),
]

def lookup(dst):
    a = ipaddress.ip_address(dst)
    best = None
    for cidr, nh in TABLE:
        n = ipaddress.ip_network(cidr)
        if a in n:
            if best is None or n.prefixlen > best[0].prefixlen:
                best = (n, nh)
    return best

for dst in ["8.8.8.8", "192.168.56.1", "192.168.56.200", "192.168.56.130", "192.168.56.70"]:
    r = lookup(dst)
    print(f"  {dst:<18} -> via {r[1]:<16} (matched {r[0]})")
print()
print("Note 192.168.56.200 uses the /25, not the /24. Longest prefix wins.")
PY

# --- 5. a TTL probe loop, no traceroute needed ---
python3 - <<'PY' | tee 03-ttl-probe.txt
import socket
def probe(dst, ttl):
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.settimeout(0.8)
    try:
        s.setsockopt(socket.IPPROTO_IP, socket.IP_TTL, ttl)
        s.sendto(b"\x00\x00\x00\x00", (dst, 33434))
        s.recv(1024); return "reply"
    except socket.timeout: return "*"
    except OSError: return "!"
    finally: s.close()
print("  TTL:  " + "  ".join(f"{t:>4}" for t in range(1, 9)))
print("  path: " + "  ".join(f"{probe('192.168.56.1', t):>4}" for t in range(1, 9)))
print("  A star means a router decremented TTL to 0 and sent an ICMP time-exceeded back.")
PY

Step 2 is the concept that causes the most real-world mistakes. A route list that looks right
can still send traffic somewhere unexpected if a more specific route exists. Always check with
ip route get <target>, never by reading the table alone.
