Static and Dynamic Routing, OSPF

Summary

Depth on how routers decide, and what goes wrong when an adversary joins the conversation.

Key ideas

  • Static route: a configured next hop. Predictable, auditable, does not scale
  • Dynamic routing: routers exchange information and converge. Scalable, larger trust surface
  • Distance-vector (RIP): share whole tables with neighbours; slow convergence, split horizon
  • Link-state (OSPF): share a topology database and compute shortest paths; fast, scalable
  • EIGRP sits between: advanced distance-vector, proprietary, Cisco
  • Administrative distance: the tiebreaker between sources, before metric is even considered

Terminology

Term Meaning
Static route Manually configured path
Dynamic routing Learned automatically
Convergence Time until all routers agree
Distance-vector Advertise distance to each network (RIP, EIGRP)
Link-state Advertise the local topology (OSPF)
Metric / cost Preference between equivalent paths
Administrative distance Trust ranking of a routing source
Area OSPF grouping for scaling
LSA The unit of link-state information
Default route The catch-all entry

# Requires root; uses a private routing table so your system routes are untouched.
if [ "$(id -u)" -eq 0 ] || sudo -n true 2>/dev/null; then
  sudo bash -c '
    T=aegis-test
    ip route add table $T 10.0.0.0/8 dev lo 2>/dev/null
    ip route add table $T 10.1.0.0/16 dev lo 2>/dev/null
    ip route add table $T 10.1.2.0/24 dev lo 2>/dev/null
    ip route add table $T 10.1.2.5/32 dev lo 2>/dev/null
    echo "=== the test table ==="
    ip route show table $T
    echo
    echo "=== which route wins for each destination ==="
    for d in 10.9.9.9 10.1.9.9 10.1.2.9 10.1.2.5; do
      printf "  %-12s " $d
      ip route get $d table $T 2>/dev/null | grep -oE "^[0-9.]+|[0-9.]+/[0-9]+" | head -1
      echo
    done
    ip route flush table $T
  ' 2>&1 | tee 01-lpm-real.txt
else
  echo "needs root to create a private routing table - run with sudo" | tee 01-lpm-real.txt

# --- 2. same thing, pure logic, no root needed ---
python3 - <<'PY' | tee 02-lpm.txt
import ipaddress
TABLE = [("10.0.0.0/8", "lo"), ("10.1.0.0/16", "lo"),
         ("10.1.2.0/24", "lo"), ("10.1.2.5/32", "lo"), ("0.0.0.0/0", "gw-ISP")]
def lookup(dst):
    a = ipaddress.ip_address(dst); best = None
    for c, dev in TABLE:
        n = ipaddress.ip_network(c)
        if a in n and (best is None or n.prefixlen > best[0].prefixlen):
            best = (n, dev)
    return best
print("  destination    matched           via")
for d in ["10.9.9.9","10.1.9.9","10.1.2.9","10.1.2.5","8.8.8.8"]:
    n, dev = lookup(d)
    print(f"  {d:<14} {str(n):<17} {dev}")
print()
print("A /32 host route beats the /24 that contains it. That is why")
print("a single pinned route overrides an entire subnet.")
PY

# --- 3. a deliberately broken route, to see what failure looks like ---
cat > 03-broken-routes.sh <<'EOF'
#!/usr/bin/env bash
# Add a blackhole route, prove the traffic dies, then remove it.
# Requires root. Uses a table-local route so system routing is untouched.
set -uo pipefail
T=aegis-blackhole
VICTIM=203.0.113.10      # TEST-NET-3, guaranteed not to exist

sudo ip route add table $T blackhole 203.0.113.0/24
echo "=== route installed ==="
sudo ip route show table $T

echo
echo "=== with the blackhole, lookup returns a dead route ==="
sudo ip route get $VICTIM table $T 2>&1 | sed 's/^/  /'

echo
echo "=== removing it restores the default path ==="
sudo ip route flush table $T
sudo ip route get $VICTIM 2>&1 | sed 's/^/  /' || echo "  (no route - isolated network)"
EOF
chmod +x 03-broken-routes.sh
sudo -n true 2>/dev/null && ./03-broken-routes.sh 2>&1 | tee 03-blackhole.txt \
  || echo "needs sudo - run ./03-broken-routes.sh as root" | tee 03-blackhole.txt

# --- 4. OSPF, if your lab has any ---
cat > 04-ospf-notes.md <<'EOF'
# OSPF, practically

## Adjacency formation (the attack surface)
1. Hello packets are sent to 224.0.0.5 every few seconds on each interface.
2. Neighbours agree on the area, the timer values, and the network type.
3. An adjacency forms: both sides exchange their full LSDB.
4. Each router runs SPF and installs routes.

Any host that answers Hello packets becomes a routing participant.
That is the whole vulnerability: **participation is trust**.

## Hardening
- OSPF authentication: simple password (weak), MD5 (legacy), or cryptographic (preferred)
- `passive-interface` on user-facing ports — stops Hello sending entirely
- Area design: user segments in a stub/totally-stubby area
- Separate management: do not run a routing protocol on a user network

## Detecting a rogue adjacency
- Compare the neighbour list against the expected device inventory
- Monitor for LSAs referencing unexpected router IDs
- Check for an unexpected cost change on any prefix
EOF
cat 04-ospf-notes.md
