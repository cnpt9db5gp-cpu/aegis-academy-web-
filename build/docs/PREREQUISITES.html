Prerequisites

AEGIS assumes you are on Kali Linux. It does not assume you have
installed anything beyond that.

docs/LAB-SETUP.md covers the VM range. This file covers the host
tools — the things that make individual labs work. Without them a lab
does not fail gracefully; it stops halfway with command not found, and
for a first-timer that reads as "the material is wrong" rather than "I
missed an install step".

Check what you are missing at any time:

python3 tools/check_prereqs.py

That list is derived from the notes, not maintained by hand — every
command the labs invoke is extracted and resolved against $PATH. So it
cannot drift out of date the way a hand-written list would.

Install the four that block labs

Tool Labs affected Install
gdb os-02, os-04, ex-02, lo-05, ms-05 sudo apt install gdb
strace os-01, os-03, ms-05 sudo apt install strace
jq pkt-05 sudo apt install jq
yara for-06 sudo apt install yara

Kali carries all four in its standard repos. gdb is the one that will
bother you most: five labs across the OS, exploit and reverse-engineering
tracks assume it, and it is also how you read disassembly in os-04.

Volatility 3 (the whole memory-forensics tier)

Volatility is not in Kali's repos in a usable form. Install it
isolated with pipx, which keeps it out of the system Python:

pipx install volatility3

Then check it:

vol.py --help

If vol.py is not on your PATH after that:

~/.local/bin/vol.py --help          # or add ~/.local/bin to PATH

Tier 6 (tier index 6 in the app: vol-01 … vol-04) depends on this.
It is the single largest optional dependency in AEGIS — 4 notes plus
cd-03, which uses it for triage. Everything else in that tier
(for-01 … for-07) works with the sleuthkit tools Kali already ships.

Already on a stock Kali box

Verified present on this machine, and used by the labs:

nmap tshark tcpdump nc wireshark openssl xxd
fls mmls icat blkls            # sleuthkit
binwalk exiftool bulk_extractor scalpel
sqlite3 php hydra sqlmap nikto
msfconsole msfvenom              # metasploit-framework

If you are unsure whether the forensic tools are really there:

for t in fls mmls icat blkls exiftool binwalk scalpel; do
  printf '%-16s %s\n' "$t" "$(command -v $t || echo MISSING)"
done

The VM range (optional, but most of Tier 5+ needs it)

Several labs target hosts that do not exist on a bare machine:
Metasploitable 2/3, a Windows domain controller, Juice Shop. Those labs
are written against 192.168.56.0/24 and 10.10.10.0/24 on a
VirtualBox host-only network.

Nothing in AEGIS will touch those ranges until you build them. The
labs that need them are listed in docs/LAB-SETUP.md, and every script
that touches the network calls ~/aegis/bin/scope-guard.sh, which
refuses anything outside RFC1918 and exits 3.

This box has no VirtualBox, QEMU or Docker, so those labs were not run
during verification. They are checked statically only.

What "verified" means here, honestly

Check Coverage
check_shell_blocks.py all 467 shell blocks — do they parse, is any heredoc left open
run_labs.py the runnable subset, executed in a sandboxed HOME
check_prereqs.py every command the labs invoke, resolved against $PATH

Static checks cover everything. Execution covers only what runs without
VMs. A lab that needs Metasploitable has never been run — treat Tier 5
and 6 labs as unproven until you have the range up, and expect to fix
small things when you do.

That asymmetry is deliberate and worth keeping in mind: the notes are
written to be true, but "written to be true" and "exercised end to end"
are different claims, and only the first one currently holds for the VM
labs.
