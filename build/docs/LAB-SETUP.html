Lab Range Setup

Your practice range is what makes every exercise in AEGIS legal. Build it once, snapshot it, reuse it forever.

Target topology

        ┌─────────────────────────────────────────────┐
        │  host: Kali (this machine)                  │
        │  runs AEGIS, nmap, metasploit, wireshark     │
        └───────────────────┬─────────────────────────┘
                            │  host-only / isolated network
        ┌───────────────────┴─────────────────────────┐
        │  VULN-01   Metasploitable3  (Ubuntu)         │  services: ssh, apache,
        │                                              │  samba, mysql, vsftpd, tomcat
        │  VULN-02   DVWA / Juice Shop (web targets)    │  http://localhost:8081
        │  VULN-03   Windows + AD (later, Tier 5)      │  needs 2 vCPU + 4GB each
        │  VULN-04   Ubuntu + misconfigs (Tier 1 privesc)
        └─────────────────────────────────────────────┘

Requirements

  • Kali with enough resources: 8GB RAM minimum, 16GB comfortable. 4 VMs at 1GB each is fine.
  • VirtualBox (already on Kali) or QEMU/KVM.
  • Host-only network adapter — do not bridge these to your LAN or the internet.

1. Create an isolated host-only network

# list current host-only interfaces
ip -br addr show | grep vboxnet || true

# VirtualBox GUI: Tools > Manage > Host-only Networks > Create
# or via CLI:
VBoxManage hostonlyif create
VBoxManage hostonlyif ipaddr vboxnet0 192.168.56.1

Assign the second adapter of each VM to vboxnet0 (Host-only). Keep the NAT adapter for updates if you want,
or disconnect it entirely for full isolation.

2. Stand up the vulnerable hosts

Metasploitable3 (the workhorse)

# download the OVA/zip from SourceForge, then:
VBoxManage import "metasploitable3_ubuntu_v4.4.6-64.zip" \
  --name vuln01 --vsys 0 --register
VBoxManage modifyvm vuln01 --memory 1024
VBoxManage modifyvm vuln01 --nic1 hostonly --hostonlyif vboxnet0
VBoxManage modifyvm vuln01 --natpf1 "web,tcp,,8080,,80"

Start it, find the DHCP address, then:

ip neigh | grep -i incomplete       # or check the VM console
nmap -sV -p- 192.168.56.101        # this IS your first reconnaissance exercise

Snapshot immediately once it has booted:

VBoxManage snapshot vuln01 take "baseline-clean" --description "freshly imported, unpatched"

Reverting is one command, which is the whole point:

VBoxManage snapshot vuln01 restore "baseline-clean"

Web targets

Target Why
DVWA SQLi, XSS, file upload, command injection with a low skill floor
OWASP Juice Shop Modern SPA stack — DOM XSS, insecure deserialisation, IDOR
WebGoat Guided lessons for the PortSwigger-equivalent web track

All run in Docker or as small VMs on localhost:8081+.

Tier 1 privilege-escalation box

A plain Ubuntu VM where you intentionally misconfigure it:

sudo chmod -R 777 /etc/cron.d
sudo cp /bin/bash /tmp/rootshell && sudo chmod u+s /tmp/rootshell
sudo chmod o+w /etc/passwd

Then run the enumeration labs in linux-privesc-doctrine against it. Snapshot when you get a clean run.

Tier 5 domain lab (later)

Two Windows Server VMs with one promoted to Domain Controller (AD DS + DNS). Install BloodHound, Impacket
and Resolver on Kali. This is a weekend of setup — defer it until Tier 5.

3. Capture traffic from the start

# on the Kali box, capture everything on the host-only interface
sudo tcpdump -i vboxnet0 -w ~/labs/captures/session.pcap -s 0

Your Tier 2 packet-analysis labs all point at captures like this.

4. Snapshots are your undo key

Snapshot name When
baseline-clean immediately after import, before touching anything
mid-exercise before a destructive step, so you can rewind
solved after you successfully complete a lab — the reference you compare against

5. Keeping Kali and the range separate

Your Kali host is the attacker. The range is the target. Do not run intentionally vulnerable
services on Kali itself — if Kali gets compromised mid-exercise, you lose your toolchain and your progress
host at the same time.
